### [should-fix] G1 — the `idle` clause at :302 wrongly covers reviews
- File: `docs/workflow/control-plane.md:302`
- Severity: should-fix
- Source: qs-review-edge-case-hunter (also noted by the fix #01 implementer)
- Description: the sentence now reads "a listed `done` means the turn
  finished, whatever the kind of session, and so does `idle` in either
  field … For a single-turn review, 'turn finished' is 'review over'
  (`reviewpilot._session_move`, #421)". `_session_move`
  (`reviewpilot.py` ~:199) checks only `done`; a review session that ends
  its turn `idle/working` stays `running` until `REVIEW_TTL_S`.
- Proposed fix: scope the clause to nodes ("for a node — `nodes.refresh` —
  so does `idle` in either field"), and say `_session_move` reads only
  `done`, so a review listed `idle/working` is not seen as over (follow-up,
  G5).

### [should-fix] G2 — Waking: the early `tool resume` error code
- File: `docs/workflow/control-plane.md:663`
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: the text says the early call "is refused (`INVALID_STATE`,
  recorded as a failed call)". Through `run_recorded` the guard's error
  becomes `call.fail(...)` → `CpError("TOOL_FAILED", …,
  result={"error": "INVALID_STATE", …})` (tools.py ~:565/:646): the caller
  sees `TOOL_FAILED` (exit 1), and a replay of the key returns
  `TOOL_FAILED` "this key already failed; retry with a new key"
  (`_finished`, ~:412). An orchestrator matching `INVALID_STATE` / exit 8
  never matches.
- Proposed fix: "an earlier call fails `TOOL_FAILED` (exit 1) with
  `result.error: INVALID_STATE` and spends its key: retry with a new key".
  Check against the error table (~:915). Also add "(while the daemon
  runs)" after the watchdog's `LIVENESS_EVERY_S` clause (edge-case nice #6).
