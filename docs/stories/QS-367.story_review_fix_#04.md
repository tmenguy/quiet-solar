## Findings to fix

### [should-fix] S1 — Doc-token test mislabels the `deep` IDs as `build`
- File: `tests/qs/docs/test_model_policy_doc_tokens.py:7-8` (module
  docstring), `~:46` (`test_harness_md_carries_ac8_build_tokens` name +
  docstring)
- Severity: should-fix
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter
- Description: both docstrings call `claude-opus-5-5` / `claude-opus-5.5`
  "the `build` model IDs". `HARNESS_MODELS` maps those to `deep`; `build` is
  `claude-opus-4-8` / `claude-opus-4.8`. The test also never checks the real
  `build` IDs, so name and docstring claim more than is asserted.
- Proposed fix: rename to `test_harness_md_carries_ac8_model_tokens`; say
  "the `deep` model IDs" in both docstrings; additionally assert the `build`
  row is present in the normalised harness.md text (`` `build` `` together
  with `claude-opus-4-8` and `claude-opus-4.8`).

### [nice-to-have] N1 — Huge digit run escapes the "pure and total" parser
- File: `scripts/qs/launchers/claude.py:~98-107` (regexes / `int()`), `~:151`
  (call outside the `try`)
- Severity: nice-to-have (pathological, but it breaks the "never break a
  handoff" contract)
- Source: qs-review-edge-case-hunter
- Description: `int(match.group(n))` raises `ValueError` for > 4300 digits
  on Python ≥ 3.11, and the `check_cli_floor(...)` call sits outside the
  `try`, so it escapes `build_payload`. Confirmed with `'9'*5000 + '.1.1'`.
- Proposed fix: bound the groups to `\d{1,9}` in both regexes **and** move
  the `check_cli_floor(...)` call inside the `try` (keeping the widened
  `except`). Add one parametrize row with a 5000-digit run asserting `None`
  / silence.

### [nice-to-have] N2 — Two tests discard `recorded`
