### [should-fix] AA1 — Fold `_is_discharge_floor_command` into `_command_to_values`
- File: `custom_components/quiet_solar/ha_model/battery.py:81`
  (`_command_to_values`), `:304` (`_is_discharge_floor_command`),
  consumers at `:123` (write path) and `:153` (probe path)
- Severity: should-fix (design coherence; no behavior change intended)
- Source: user (author review of the final diff)
- Description: `_command_to_values` is the single authority mapping a
  command to entity values, yet the snap semantics of the discharge
  value — "is this the safety floor (snap up) or a restore/max (snap
  down)?" — is re-derived at both consumers via a separate static
  predicate. That splits one piece of command semantics across two
  functions: a future command added to `_command_to_values` could
  silently get the wrong snap direction if `_is_discharge_floor_command`
  is not updated in lock-step, and nothing forces write and probe to
  agree beyond both remembering to call the same predicate.
- Proposed fix: Have `_command_to_values` emit the snap semantics
  alongside the value — e.g. add a key
  `"max_discharging_power_snap_up": bool` to the returned dict (or make
  the discharge entry a small value+snap_up pair, whichever reads
  cleaner against the existing `dict[str, Any]` contract and the
  `set_charge_from_grid` key handling). Both consumers (:123 write,
  :153 probe) read the flag from the dict instead of calling the
  predicate; delete `_is_discharge_floor_command`. Update the
  `set_max_discharging_power(..., snap_up=...)` call chain only as far
  as needed — the public setter keeps its `snap_up` parameter (external
  callers default to False, unchanged).
- Constraints:
  - Pure refactor: NO behavior change. All existing tests must pass
    with zero expected-value edits (they pin the semantics; if any
    fails, the refactor is wrong — fix the refactor, not the test).
  - Do NOT touch `_number_entity_target`'s U1/U2 write policy or the
    comparison semantics.
  - One new test pinning the single-source-of-truth property: for each
    command in the mapping, the snap flag emitted by
    `_command_to_values` matches the documented semantics
    (CMD_GREEN_CHARGE_ONLY / CMD_FORCE_CHARGE -> floor -> snap up;
    CMD_GREEN_CHARGE_AND_DISCHARGE -> restore -> snap down).
  - Update docs/agents/concepts/ha-battery.md if it names
    `_is_discharge_floor_command`.
