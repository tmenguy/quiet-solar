## Findings to fix

### [should-fix] S1 — The #04 S4 leftover proof can rmtree a live, moved worktree
- File: `scripts/qs/cleanup_worktree.py` (`_abandoned_worktree_gitdir`,
  ~334–365)
- Source: qs-review-blind-hunter. The edge-case-hunter confirmed that a
  worktree moved with `mv` (not `git worktree move`) or copied passes the
  check.
- Description: the proof only checks that the `.git` file's `gitdir:`
  resolves under `<common>/worktrees/`. A worktree moved with plain `mv`
  keeps a live admin dir (`<common>/worktrees/<id>` still exists and is
  registered under the old path). Its new path looks unregistered
  (`absent`), so the proof passes and the directory, uncommitted work
  included, is rmtree'd.
- Proposed fix: also require that the admin dir **no longer exists**,
  i.e. `not Path(os.path.realpath(gitdir)).exists()`. A genuine leftover
  from a partially failed `git worktree remove` has its admin dir already
  deleted by git, so the existing chmod-555 retry test must stay green.
- Tests to add:
  - A real worktree whose directory is `mv`'d to a new path, then
    `cleanup_worktree.py --work-dir <new path> --issue N --force` →
    refused, directory and its contents intact.
