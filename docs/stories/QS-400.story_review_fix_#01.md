## Fix

| # | Source | Where | Fix |
|---|---|---|---|
| 1 | edge-case 1 | `integrate_item.py` `cmd_drop` / `read_state` | A scratch whose `.git` is missing or corrupt (still registered) can still be dropped: the state, status and snapshot reads fail soft (`git_unreadable: true`), then `remove_scratch`. Before this fix, `drop` answered `stale-scratch` and told the user to drop. |
| 2 | edge-case 2 | `integrate_item.py` `checkout_of` | A registration of `QS_<N>` whose directory is gone is skipped. Before this fix it blocked `check` / `move` with `git-failed`; now `move` falls back to `update-ref`. |
| 3 | edge-case 3 | `integrate_item.py` `unmerged_files`, `dirty_files`, `_conflict_markers` | Paths are read with `-z`, unquoted. The marker grep uses `:(literal)` pathspecs, so a non-ASCII conflicted file is scanned too. |
| 4 | blind-hunter 2, edge-case 4 | `control_plane/items.py` `item-cleanup` | `discard_unintegrated` without `delete_branch` → `USAGE` before the claim. The step order becomes `cleanup`, then `drop_scratch`, so a refused cleanup (`action_required` / `error`) never destroys a live scratch. The two steps do not depend on each other. On a retry with a new key, the cleanup is idempotent (worktree absent, branch absent). This deviates from AC 12's "drop before cleanup" — see the story note. |
| 5 | edge-case 5 | `cleanup_worktree.py` `_cleanup_item` | A detached item worktree removed with `--force` reports its HEAD as `detached_head`: the undo point (`git branch <name> <sha>`). |
| 6 | blind-hunter 5 | `cleanup_worktree.py` branch step | The tip is read **before** the count, and the count runs on that tip, so `deleted_tip` is the commit proven integrated. |
| 7 | edge-case 6 | `integrate_item.py` `remove_scratch` | `worktree remove -f -f`, so a locked scratch is removed too. A registration that survives the prune → `drop-failed`. |
| 8 | edge-case 7 | `integrate_item.py` `main` | An `OSError` (rmtree, ENOSPC, the lock file) → JSON `io-failed`, exit 1, instead of a traceback. |
| 9 | edge-case 8 | `integrate_item.py` `cmd_move` | A failed `--ff-only` re-reads `QS_<N>`: if it moved → `deliverable-moved`, the documented recovery. |
| 10 | edge-case 9 | `integrate_item.py` `gate_timeout_s` | `isascii()` too: a non-ASCII digit no longer raises. |
| 11 | blind-hunter, acceptance 3 | `integrate_item.py` | `--issue` / `--item` use `utils.positive_int` (one grammar). |
| 12 | blind-hunter | `setup_task.py` `_setup_item` | The error `detail` joins stdout and stderr: `worktree-setup.sh` prints its `Error:` lines on stdout. |
| 13 | blind-hunter | `worktree-setup.sh` integration check | The registration listing goes into a variable first, so `grep -q` cannot SIGPIPE the pipeline under `pipefail`. |
| 14 | acceptance 1 | story §8 / §9 | Document `drop` on an unregistered leftover (`not_a_worktree`), and the `item-cleanup` step order (fix 4). |

## Rejected

| Source | Finding | Why |
|---|---|---|
| blind-hunter 1 | the gate inherits the lock fd; a daemonizing descendant would hold it | Spec decision (story §8, round 12): the gate's top process holds the lock, which covers a SIGKILLed watchdog. `--impacted` starts no daemon (no `dmypy`). Listed as an attention point. |
| blind-hunter 3, CodeRabbit | anchor the undo points with `refs/qs/dropped/...` | Rejected in plan round 9 (C10 → S1): no `refs/qs/dropped`. The undo points follow cleanup's `deleted_tip` convention, and gc keeps unreachable objects for 2 weeks. |
| blind-hunter 4 | the post-gate clean check counts untracked files | Checked: every gate by-product (`.coverage`, `coverage.xml`, `htmlcov/`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/`, `.testmondata*`, `.lane_check_cache`, `venv`) is gitignored. |
| blind-hunter (nice) | the gate timeout keeps no output | Draining the pipe after `killpg` can hang if a descendant escaped the group. `wait()` as specified. |
| blind-hunter (nice) | `_resume` answers `conflicts` after the resolution commit; `conflict` rows not deduplicated | As specified: the phase stays `conflicts`, and `finish` decides; the start rows are a log of attempts by design (§9 "Records"). |
| blind-hunter (nice) | the misuse refusals in `cleanup_worktree.py` exit 0 | As specified: exit 0 for every status, as the task path. |
| blind-hunter (nice) | `--harness claude-code` hard-coded | As specified (§9 table). |
| blind-hunter (nice) | `killpg` after a normal exit could hit a reused pgid | Negligible window, and it bounds stragglers that would hold the lock. Kept. |
| edge-case 10 | check for a missing venv in `prepare` | `gate` reports `no-venv`, and `<MAIN>/venv` always exists in practice. Not worth a new error on `prepare`. |
| edge-case 11 | leading zeros in the issue number | Pre-existing task-path behaviour; every caller passes an `int`. |
| CodeRabbit | overlap checks, `--no-verify` | Out of scope: footprints were dropped from epic #369 (`cb68cbb3`); `--no-verify` is a documented convention (D2). |
