  reaped row's late launch is listed, `reserve` adopts it and launches
  nothing, yet the pre-check ran first and refused it (`USAGE`, claim
  released, a live session left behind a `reaped` row). The pre-check still
  resolves outside the transaction, but its refusal is raised inside
  `reserve_tx` only after the adopt branch — before a re-take or a new row.
  Tests: `test_a_takeover_that_adopts_a_late_launch_ignores_a_policy_refusal`,
  `test_a_takeover_that_relaunches_still_needs_the_policy`. control-plane.md's
  spawn row says so.
- **BH-S1 — the same-tree pin could never fail** (conftest had already
  imported `models`): the test now drops `models` from `sys.modules` first.
- **AA-N2 — `make_deps` never imports `models`** is now pinned
  (`test_make_deps_never_imports_the_policy`).
- **AA-N3 — recovery after a launch-time failure** is exercised: the same key
  is `TOOL_FAILED`, a new key `CONFLICT`, `--replace` supersedes and launches.
- **EC-N3 / BH-N5 — the purity scan** uses `rglob` and allows an absolute
  `control_plane` self-import.
- **BH-N3 / BH-N4 — wording:** the "byte-identical" claims name the `model=`
  override; the D1 comment names `qs-node` as the only Control-Plane-launched

- **AA-S1 — gate evidence** is recorded in the PR body.
