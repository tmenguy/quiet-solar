### [must-fix] M2 (+N1) — floor save: write only the live floor, take `time` as a parameter
- File: `custom_components/quiet_solar/ha_model/charger.py:2567-2591` (`update_to_be_saved_extra_device_info`), `custom_components/quiet_solar/home_model/load.py:572` and `:1805`, `custom_components/quiet_solar/ha_model/car.py:367`, `custom_components/quiet_solar/sensor.py:794`
- Severity: must-fix
- Source: qs-review-edge-case-hunter (M2), qs-review-blind-hunter (N1)
- Description:
  - The save currently writes `self._boot_attached_car_best_score or self._saved_attached_car_best_score` when no live floor exists. `_saved_*` only moves to `_boot_*` in `device_post_home_init`, which runs once per home lifetime (`QSHome.finish_setup` is guarded by `_init_completed`, home.py:2189). A charger rebuilt later (options change / config-entry reload / enabled after boot) keeps the loaded tuple in `_saved_*` forever and re-writes it with its original `saved_at` on every save, even after an unplug → a stale floor can be restored at a later restart (breaks AC6).
  - The boot slot was never meant to be persisted back. The story's reason ("necessary from the 1st restart") is wrong: the value is read once at entity restore and lives in memory; re-writing only protects a 2nd restart inside the boot window — a rare case the maintainer accepts as a risk.
  - `saved_at` uses `datetime.now(tz=pytz.UTC)` inside the save method instead of an injected `time` — not reproducible, inconsistent with the rest of the code.
- Proposed fix:
  - Change the signature to `update_to_be_saved_extra_device_info(self, data_to_update: dict, time: datetime)` on every definition (`load.py:572`, `load.py:1805`, `car.py:367`, `charger.py:2567`) and pass `time` from `QSDeviceSensorData.async_update_callback(self, time)` in `sensor.py:794`. Update all callers in tests (~54 call sites).
  - Charger save: payload = `(self.car.name, self._attached_car_best_score, time)` if `self.car is not None and self._attached_car_best_score`, else `None` (all three keys written as `None`). Never read `_boot_attached_car_best_score` nor `_saved_attached_car_best_score` in the save.
  - Keep load → `_saved_*` → transfer in `device_post_home_init` → `_boot_*` → consume in `attach_car` as is. A never-transferred `_saved_*` is now inert.
  - No max-age cap on `saved_at` (maintainer decision).
  - Tests: remove `test_floor_pending_value_rewritten_and_survives_second_reboot` and the "save between load and attach → tuple re-written with original saved_at" case; add a test that a save while not attached (incl. during the boot window with a pending value, and on a charger whose `_saved_*` was never transferred) writes `None`; replace the "force `saved_at` after save" workaround in the persist/restore tests with the injected `time`; `test_floor_saved_with_current_clock_while_attached` asserts `saved_at == time`.
  - Story: update the persistence section (lines ~143-145) and AC6 (line ~241): drop "survives a 2nd restart inside the boot window" and list it under accepted risks; "survives saves made before the attach" stays true (value is in memory). Update `docs/agents/concepts/charger-budgeting.md` if it describes the re-write.

### [should-fix] S1 — pin lifetime: survive-unplug and bypass gaps
- File: `custom_components/quiet_solar/ha_model/charger.py:4129` (unplug branch of `check_load_activity_and_constraints`), `charger.py:3633-3668` (`_compute_best_car`), `custom_components/quiet_solar/ha_model/car.py:2969-2977` (`user_set_selected_charger_by_name`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: the PR makes pins (`USER_ORIGINATED_CAR_NAME` on the charger) far more common; three pre-existing gaps now matter:
  - (a) the unplug branch only clears `USER_ORIGINATED_CAR_NAME` inside `if self.car:` — if the pinned car was already taken by another charger, the pin survives the unplug and W1 later pulls the car back via "user_selection";
  - (b) W2 only sees chargers in `active_chargers` (requires `is_plugged(for_duration=CHARGER_CHECK_STATE_WINDOW_S)`); while W1 is `unavailable` > 15 s, W2 can win W1's pinned car and `detach_car()` it from W1 with the pin left in place;
  - (c) `user_set_selected_charger_by_name` clears the pin only on `orig_charger`; if the car is not attached, a stale pin on another charger stays.
- Proposed fix:
  - (a) Move `self.clear_user_originated(USER_ORIGINATED_CAR_NAME)` out of `if self.car:` so a real unplug always clears it.
  - (b) In `_compute_best_car`, skip (score 0 / do not consider) a car pinned via `USER_ORIGINATED_CAR_NAME` on another enabled charger (`qs_enable_device is not False`) that is not in `active_chargers`.
  - (c) In `user_set_selected_charger_by_name`, clear `USER_ORIGINATED_CAR_NAME` on every charger of the home whose pin equals `self.name`, except the newly chosen charger.
  - One test per gap (a, b, c), using real chargers/cars.

### [should-fix] S2 — entity restore replay must not pin the pair
- File: `custom_components/quiet_solar/ha_model/car.py:360-365` (D3 hook), `custom_components/quiet_solar/select.py:82` (+ `QSSimpleSelectRestore.async_added_to_hass`, ~397), `custom_components/quiet_solar/switch.py:284-287` (+ `QSSwitchEntityWithRestore.async_added_to_hass`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter, qs-review-blind-hunter
- Description: the select/switch restore replays the setter with `for_init=True`, but the car lambdas drop the flag (`user_set_next_charge_target(option)`, `setattr` for the bump setter). HA re-adds an entity without reloading the config entry when its entity_id is renamed or its registry entry updated; if the car is attached then, the replay pins the charger to the car with no user action. The current safety relies on an implicit boot-ordering invariant.
- Proposed fix:
  - Thread `for_init` through `user_set_next_charge_target` and the bump setter down to the D3 hook.
  - When `for_init` is True, skip ONLY the charger pin (`charger.set_user_originated(USER_ORIGINATED_CAR_NAME, ...)`). Do NOT change the car's own `set_user_originated` replay behaviour (out of scope).
  - Replace the comment about the boot-ordering invariant with the explicit guard; keep `test_boot_replay_before_attach_does_not_pin`.
  - New test: car attached, replay the select and the bump switch restore with `for_init=True` → `USER_ORIGINATED_CAR_NAME` stays `None`; same calls with `for_init=False` still pin.
