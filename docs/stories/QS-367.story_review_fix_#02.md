## Findings to fix

### [should-fix] S1 — `build_payload` shells out to the host `claude` in every launcher test
- File: `tests/qs/launchers/conftest.py` (new autouse fixture);
  `tests/qs/launchers/test_claude_launcher.py:478-506` (BOM test asserting
  `"warning:" not in err`), `:1567-1618` (S4 tests)
- Severity: should-fix
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter, qs-review-acceptance-auditor
- Description: `_warn_if_cli_below_floor()` at `claude.py:~601` runs
  unconditionally, so ~55 `build_payload` call sites (plus next_step /
  setup_task tests routed through the launcher) spawn the real `claude
  --version`. On a machine whose CLI is < 2.1.280 — exactly the machines S4
  targets — `test_bom_prefixed_settings_are_parsed_and_merged` fails on an
  unrelated stderr `warning:`; on slow hosts every launcher test pays a Node
  start-up. CI is green only because `claude` is absent there.
- Proposed fix: add an **autouse** fixture in `tests/qs/launchers/conftest.py`
  that monkeypatches `scripts.qs.launchers.claude._warn_if_cli_below_floor`
  to a no-op (module attribute, so `build_payload`'s lookup sees it). Let the
  three S4 end-to-end tests opt out by restoring the real function
  (`monkeypatch.setattr(claude_launcher, "_warn_if_cli_below_floor",
  <original>)` captured at import time in the conftest, or a small
  `real_cli_floor_guard` fixture that undoes the autouse patch) before
  installing their own `_patch_claude_version`. Verify: with the autouse
  fixture active and `subprocess.run` patched to raise
  `AssertionError("must not be called")`, the BOM test and a plain
  `build_payload` call pass; the S4 tests still exercise the guard.

### [should-fix] S2 — `UnicodeDecodeError` escapes the floor guard and breaks the handoff
- File: `scripts/qs/launchers/claude.py:~121-130` (`_warn_if_cli_below_floor`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: `subprocess.run(..., text=True)` decodes strictly; a `claude`
  shim writing a non-UTF-8 byte raises `UnicodeDecodeError` (a `ValueError`),
  which the `except (OSError, subprocess.SubprocessError)` does not catch. It
  propagates through `build_payload` into `next_step.py` / `setup_task.py`,
  violating the "guard must never block" contract. Reproduced on Python
  3.14 with a child writing `b"2.1.1 \xff\n"`.
- Proposed fix: pass `errors="replace"` (and `encoding="utf-8"`) to
  `subprocess.run`, **and** widen the except to `(OSError, ValueError,
  subprocess.SubprocessError)` as belt-and-braces. Add a launcher test next
  to `test_build_payload_silent_on_cli_timeout` whose fake raises
  `UnicodeDecodeError("utf-8", b"\xff", 0, 1, "invalid start byte")` and
  asserts silence + unchanged payload.

### [should-fix] S3 — harness.md still claims frontmatter "decides the model on every surface"
- File: `docs/workflow/harness.md:~195-199`;
  `tests/qs/docs/test_model_policy_doc_tokens.py:~704-710`
  (`test_harness_md_omits_settings_pinned_model_claim`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: the settings-pin section still says the writer "does **not**
  pin `model`: the agent's frontmatter decides the model on every surface and
  beats a user-level settings `model` … a `/model` choice … is effectively
  session-scoped for a pipeline agent". E7 established the opposite for the
  GUI main session (the picker decides). Round-1 S5 fixed the same claim in
  `_write_phase_agent`'s docstring but not here; the N9 doc test only bans
  the literal `settings-pinned`, so the old wording slips through.
- Proposed fix: reword `harness.md:195-199` — the settings pin fixes the
  **agent**; frontmatter decides the model on the CLI (`--agent`) surface
  and for sub-agents; the GUI main session's model comes from the picker, so
  the handoff names `phase_model`. Extend
  `test_harness_md_omits_settings_pinned_model_claim` to also assert
  `"on every surface" not in text`.

### [should-fix] S4 — Floor-warning text hardcodes `deep` / `claude-opus-5-5`
- File: `scripts/qs/launchers/claude.py:~98-105` (`check_cli_floor` message)
- Severity: should-fix
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter
- Description: the version comes from `models.CLAUDE_CLI_FLOOR` but the
  model name in the warning is a separate literal, so a future `deep` bump
  (or a custom `floor=`) leaves the message naming the wrong model — the
  exact drift the constant was meant to prevent.
- Proposed fix: interpolate `models.HARNESS_MODELS["claude"]["deep"]` (or
  `models.model_for("claude", "deep")`) into the message. Adjust the
  existing parametrized tests to assert the interpolated ID rather than a
  literal, and add one case that monkeypatches the `deep` row and asserts
  the message follows.

### [should-fix] S5 — `_gui_blocks` cuts at an unindented fence, so indented blocks run to EOF
- File: `tests/qs/agents/test_orchestrator_handoff.py:~326-338` (`_gui_blocks`),
  used by `test_gui_block_carries_picker_fallback_clause` (`~:392-416`) and
  `test_gui_block_names_required_tokens`
- Severity: should-fix (promoted from nice-to-have: it undermines the
  round-1 S2/S3 assertions for two orchestrators)
- Source: qs-review-edge-case-hunter
- Description: the helper slices each block at `"\n```"`. In the rendered
  `qs-create-plan.md` and `qs-diagnose-task.md` the closing fence is
  indented (`"   ```"`), so the "block" extends to end-of-file and the
  fallback-clause / required-token checks scan the whole tail of the file.
  Removing the `Pick model` bullet from those two GUI blocks would not fail
  the test if the same words appear anywhere later.
- Proposed fix: cut at `re.search(r"\n[ \t]*```", chunk)` instead of
  `chunk.find("\n```")`. Add a unit test for `_gui_blocks` with an indented
  fence fixture asserting the block ends at the fence. Re-run the suite to
  confirm all 9 blocks still carry every required token when properly
  bounded.

### [nice-to-have] N1 — `check_cli_floor` misses prefixed / banner / stderr version output
- File: `scripts/qs/launchers/claude.py:~93` (regex), `~:130` (`proc.stdout` only)
- Severity: nice-to-have
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter
- Description: `re.match(r"\s*(\d+)\.(\d+)\.(\d+)", …)` returns `None` for
  `v2.1.278`, for an "Update available…" banner line before the version, or
  for `Claude Code 2.1.278`; and only stdout is read. Result: no warning for
  a CLI that really is below the floor.
- Proposed fix: `re.search(r"(?<![\d.])(\d+)\.(\d+)\.(\d+)", text)`; parse
  `proc.stdout or proc.stderr`. Add parametrize rows for `"v2.1.279"`,
  `"Update available\n2.1.278 (Claude Code)"`, and `"Claude Code 2.1.278"`.
