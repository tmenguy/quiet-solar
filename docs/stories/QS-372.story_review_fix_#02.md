### [must-fix] M1 — `implement_routing` tells the agent to run the label commands itself
- File: `scripts/qs/agent_templates/_macros.md.j2:30-44` (`implement_routing`),
  `tests/qs/agents/test_handoff_macro.py` (`test_implement_variant_routes_by_declared_target`)
- Severity: must-fix
- Source: qs-review-blind-hunter + qs-review-edge-case-hunter + qs-review-acceptance-auditor (all three)
- Description: after "**STOP** and print", the text says "Then apply
  exactly one of these concrete, runnable commands:" and "remove the wrong
  one" — imperatives addressed to the orchestrator. An agent (esp. the
  #369 autonomous loop) can pick a label itself and continue — the exact
  inference QS-321/D3 forbid, and outside review-task's edit scope. The
  message's "(see the commands below)" also points at a bash block the
  agent is never told to print. Both `--add-label` commands share one
  fence (copying it applies both labels → the both-labels state).
  `--remove-label target:<wrong>` is not pasteable (`<wrong>` is a shell
  redirect). A hard `context.py` failure (non-zero exit / no JSON) is not
  covered.
- Proposed fix — rewrite the post-fence part of the macro so the user is
  the subject and the agent is forbidden to act:
  - "Print the commands below to the user as well. **Do NOT run any of
    them yourself** — the target label is the user's declaration
    (QS-321). The user runs exactly one:" followed by **two separate
    one-line ```bash fences** (`gh issue edit {{issue}} --add-label target:factory`,
    `gh issue edit {{issue}} --add-label target:product`).
  - "If `labels` already carries **both** target labels, tell the user to
    remove the wrong one — `gh issue edit {{issue}} --remove-label target:factory`
    or `gh issue edit {{issue}} --remove-label target:product` (the one that
    is wrong; concrete labels only)."
  - "If `context.py` exits non-zero / prints no JSON, or returned empty
    `labels` and `title`, the `gh` lookup itself failed — say so and ask
    the user to retry or name a variant."
  - "After printing, wait for the user: …" (replaces "Then wait for the user").
  - Keep the printed message line and its stable prefix unchanged.
  - Test: assert "Do NOT run any of them yourself" present, "Then apply
    exactly one" absent, `target:<wrong>` absent, both concrete
    `--remove-label` commands present, the two `--add-label` commands in
    **separate** fences (no fence contains both), "exits non-zero" clause
    present — both harnesses, create-plan and review-task.
  - Update the story's "Code review #01" note (or add "Code review #02")
    to reflect the final wording.
