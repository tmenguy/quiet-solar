### [should-fix] #1 — Double-fire logs a false second INFO line on the unplug and "no car" exits
- File: `custom_components/quiet_solar/ha_model/charger.py:3598-3605` (`_clear_leaked_person_target_if_needed`)
- Severity: should-fix (log correctness, not state)
- Source: qs-review-edge-case-hunter
- Description: on unplug (`:3717` → `reset()` at `:3725`) and "no car"
  (`:3780` → `reset()` at `:3781`) the explicit pre-reset clear fires
  first (41 → `None`), then the round-6 clear at the top of `reset()`
  fires again while `_constraints` are still live, so
  `_has_live_person_constraint()` is `True` again. Its log argument
  `self.car.get_car_target_SOC()` lazily materialises `car_default_charge`,
  and the second line reports it as a leak. Verified on head with
  `pytest tests/test_qs352_person_target_leak.py::test_unplug_with_live_person_constraint_clears_leaked_target -o log_cli=true --log-cli-level=INFO`:
  ```
  charger.py:3599 ... car Tesla M3 clearing leaked person charge target 41% to default on detach
  charger.py:3599 ... car Tesla M3 clearing leaked person charge target 80.0% to default on detach
  ```
  Same pair on `test_no_car_selected_with_live_person_constraint_clears_target`;
  reset-button and disable exits correctly log once. End state (`None`)
  is correct — but the second line claims a person leak of 80 % that
  never existed and would mislead the next diagnosis.
- Proposed fix: make the helper idempotent on the field it clears —
  `if self._has_live_person_constraint() and self.car._next_charge_target is not None:`
  — keeping the `:3717` / `:3780` explicit calls (plan #05 asked to retain
  them; removing them is outside the constraint). Pin it: in the existing
  caplog unplug test (`tests/test_qs352_person_target_leak.py:383`, which
  sets INFO capture but never counts) assert exactly **one** record
  containing `"clearing leaked person charge target"`; same assertion on
  `test_no_car_selected_with_live_person_constraint_clears_target`. Both
  assertions red-first (they fail with 2 records on head) — record per
  rule 2.
