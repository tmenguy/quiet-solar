### [should-fix] S1 — Claude handoff has no STOP for "no usable payload"
- File: `scripts/qs/agent_templates/_macros.md.j2` (Claude branch of `handoff`, the "Parse the JSON…" paragraph)
- Severity: should-fix
- Source: qs-review-blind-hunter + qs-review-edge-case-hunter (merged)
- Description: only the `error`-key case is covered. If `next_step.py`
  exits non-zero / prints no JSON (argparse `parser.error`, exit 2,
  stderr only) or the JSON lacks `handoff_text`, the agent has no

  already covers the equivalent.

  command exits non-zero or prints no JSON, if the JSON contains an
  `error` key, or if it has no `handoff_text`, STOP and print the raw
  output verbatim. Otherwise print the report below, …". Keep the phrase
  "If it contains an `error` key" semantically present — check
  `test_claude_sites_stop_on_launcher_error` (tests/qs/agents/test_handoff_macro.py)
  and update its needle if the wording changes; add an assertion that
  every Claude site carries the `handoff_text`-missing STOP (count == sites).

### [should-fix] S2 — STOP message suggests a non-runnable command; conflicting labels loop; unvalidated variant name
- File: `scripts/qs/agent_templates/_macros.md.j2:19-32` (`implement_routing`), `tests/qs/agents/test_handoff_macro.py:262-289`
- Severity: should-fix
- Source: qs-review-edge-case-hunter (#1 + nice-to-have #5)
- Description: `gh issue edit {{issue}} --add-label target:factory or target:product`
  is not runnable as pasted (stray `or` / label args) and breaks the
  repo rule that printed commands carry only concrete labels. When the
  issue carries **both** target labels, "Add one" loops forever. "If they
  name a variant, use it" accepts any phase name (e.g. `review-task`).
- Proposed fix: keep the stable prefix `Cannot pick the implement variant:`
  (child 3 of #369 detects it) and rewrite the message/prose:
  - Message (one line in the ```text fence):
    `Cannot pick the implement variant: issue #{{issue}} has no single target:* label. Label it with exactly one of target:factory or target:product (see the commands below), or tell me which variant to run.`
  - Then, below the fence, the two concrete commands as separate
    ```bash blocks or inline code: `gh issue edit {{issue}} --add-label target:factory`
    and `gh issue edit {{issue}} --add-label target:product`; plus: "If
    the issue already carries both target labels, remove the wrong one
    (`gh issue edit {{issue}} --remove-label target:<wrong>`). If
    `context.py` returned empty `labels` and `title` too, the `gh` lookup
    failed — say so and ask the user to retry or name a variant."
  - "if they name `implement-task` or `implement-setup-task`, use it;
    any other answer → ask again."
  - Update the AC4 test (`test_implement_variant_routes_by_declared_target`)
    to pin the new message literal (still containing the prefix), the two
    separate concrete commands, the both-labels remedy, and the
    variant-name restriction; assert no `" or target:product)"` inside a
    command.
  - Record the deviation from the story §4 literal in the story file
    (short note under Adversarial Review Notes, "Code review #01").
