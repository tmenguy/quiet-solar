## Findings to fix

### [must-fix] R3-1 — a re-polled stale `off` is taken as proof of an unplug
- File: `custom_components/quiet_solar/ha_model/charger.py:~5164-5180` (`_car_unplugged_since`), callers `_lift_boot_user_pin_if_car_unplugged` (~3599) and `_restore_boot_attached_car_best_score` (~5115)
- Severity: must-fix
- Source: qs-review-edge-case-hunter (reproduced with two throwaway tests on HEAD 1d8542c2)
- Description: every probed entity is auto-polled; `update_states(time)` → `add_to_history(entity_id, time)` stamps the sample with the poll time (`device.py:~1345`), and `home.finish_setup` runs `root_device_post_home_init` then `update_states` (`home.py:~2218-2223`); the recorder reload likewise uses `last_changed` = boot time. So a car plug sensor that already read `off` before the save (the incident's own symptom — ID.buzz reports `off` while plugged, AC5a) gets a fresh `('off', boot_time)` sample ≥ `saved_at`. Result after any restart: the user pin on that car is lifted (Twingo steals W1 again — the incident returns, a regression vs. pre-#02) and the floor is refused (contradicts AC6a "restored unless a valid `off` is recorded since `saved_at`" in its intended meaning: a real unplug).
- Proposed fix:
  - Proof of unplug = a real **transition**: a valid `STATE_OFF` sample at/after `since` whose previous **valid** (non-`None`) sample is `STATE_ON`. `get_state_history_data` already includes the sample in force at the window start — walk the samples in time order. An `off` with no earlier valid sample (recorder history not loaded yet) is NOT proof; since the check runs at every boot-window decision, a genuine unplug is still caught once history loads.
  - Strengthen it by persisting the car's plug reading at save time: in `update_to_be_saved_extra_device_info(data, time)`, store the attached/pinned car's raw plug state (`on` / `off` / `None`) next to the floor and the pin saved_at (new key(s) in `const.py`, validated on load like the others). If the saved reading was `off` (or unknown) and no `on → off` transition is seen since, there is no proof → keep pin / restore floor. If the saved reading was `on` and the first valid sample after `since` is `off`, that IS proof even without a pre-window `on` sample in history. Implement whichever combination keeps both rules simple and testable; document the rule in the helper docstring.
  - Tests (real history + a real poll via `add_to_history(entity, time)` with `hass.states.get` returning the state, as the reviewer's repro did):
    - stuck `off` before the save, re-polled `off` after boot → pin kept AND floor restored (both callers);
    - `on` before the save, `off` after boot → pin lifted AND floor refused;
    - `on` before, hole (`None`) then `off` after boot → lifted / refused;
    - history not loaded yet (only the post-boot `off`), saved reading `on` → lifted; saved reading `off`/missing → kept.
  - Existing rows `off_before_save_only` / `off_before_saved_at_only` keep passing.
  - Update the story (AC6a wording, AC7e, Risks) and `docs/agents/concepts/user-override.md` / `charger-budgeting.md`.

- File: `custom_components/quiet_solar/ha_model/charger.py:~4259-4262` (`check_load_activity_and_constraints`, `is_not_plugged` branch)

- Source: qs-review-blind-hunter (confirmed by the orchestrator: the branch is level-triggered on `is_not_plugged(for_duration=CHARGER_CHECK_STATE_WINDOW_S)`, the pre-PR clear was inside `if self.car:` which only runs once per unplug because `reset()` detaches)
- Description: since #01 S1a moved the clear outside `if self.car:`, it runs every cycle while the charger stays unplugged → a car (or `CHARGER_NO_CAR_CONNECTED`) chosen on the charger card while the charger is unplugged is wiped within one cycle; pre-selection before plugging no longer works. Keep S1a's case (pinned car taken by another charger, then W1 physically unplugged → pin cleared). Tests: S1a test still green; choose a car / `CHARGER_NO_CAR_CONNECTED` on an unplugged charger, run several cycles still unplugged → choice kept; then plug → honoured; plugged → unplugged edge → cleared. Update the R2-8 test (`test_unplug_clears_a_no_car_choice`) to drive a real plugged → unplugged edge, and the R2-8 docs wording.
