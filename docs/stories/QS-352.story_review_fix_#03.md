user-originated marker via `clear_all_user_originated()`; pin it with a
test and state it in the story. Do **not** add a `had_person_ct` gate to
the removal-branch restore.

### [should-fix] #2 — Car-switch / "no car" paths do not clear the leaked target
- File: `custom_components/quiet_solar/ha_model/charger.py:3707-3735`
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: the leak is cleared only on *physical* unplug (`:3648`).
  Two other exits detach the car and wipe its person constraint but leave
  `_next_charge_target` at the person value: `:3717` (`best_car is None`,
  user selected `CHARGER_NO_CAR_CONNECTED`) → `reset(keep_commands=True)`
  → `detach_car()`; `:3735` (`best_car is not self.car`) → `detach_car()`
  then `:3759` `clean_constraints…(load_param=best_car.name, for_full_reset=True)`
  → `reset()`. Neither `QSChargerGeneric.reset`, `detach_car` nor
  `QSCar.reset` touches the field, and once the constraints are wiped the
  person marker is unrecoverable. Reproduces: leak 41 live on car A →
  user changes the charger's car select to car B (or "no car"); A's
  select / autonomy sensor shows 41 for the whole detached period,
  self-healing only on A's next attach cycle.
- Proposed fix: hoist the unplug clear into a helper
  `_clear_leaked_person_target_if_needed()` =
  `if self._has_live_person_constraint(): <log>; self.car.clear_next_charge_target()`
  and call it (i) in the unplug branch (replacing the inline block at
  `:3648-3655`), (ii) immediately before `self.reset(keep_commands=True)`
  at `:3717`, (iii) immediately before `self.detach_car()` at `:3735` —
  all three before the constraints are wiped. Add
  `test_car_switch_with_live_person_constraint_clears_target` (after
  `_run_step1`, make `get_best_car` return a second real car, run a
  cycle, assert `car._next_charge_target is None`) and
  `test_no_car_selected_with_live_person_constraint_clears_target`
  (`get_best_car → None`). Both red first.

### [should-fix] #3 — Removal-branch restore reverts a marker-less non-default target on replug — pin as intended (option a)
- File: `custom_components/quiet_solar/ha_model/charger.py:4275-4278`,
  `tests/test_qs352_person_target_leak.py:439`, `docs/stories/QS-352.story.md` (Observable behaviour change)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: unlike the unplug clear and the early restore, the
  removal-branch restore is not gated on `_has_live_person_constraint()`;
  it fires whenever no person constraint is kept, `user_target is None`
  and `int(get_car_target_SOC()) != int(car_default_charge)`. A
  marker-less non-default value has one non-person source: unplug's
  `clear_all_user_originated()` drops the `charge_target_percent` marker
  while `_next_charge_target` survives. Pre-PR that value stuck across
  unplug/replug; post-PR the first plugged cycle reverts it to default
  ("restoring default charge target 80% (was 55%)"). The existing
  `test_unplug_no_person_constraint_preserves_target` pins 55 *at unplug*
  but the next plugged cycle destroys it, so the "preserve" guarantee is
  hollow and the behaviour change is unpinned and undocumented.
- Proposed fix (option a — locked in triage): keep the code as is. Add
  `test_replug_without_marker_reverts_to_default`: user sets 55 (both
  primitives), unplug cycle (marker wiped, `_next_charge_target == 55`),
  replug cycle → assert the spy is awaited once with the default and
  `car._next_charge_target == car.car_default_charge`. Extend
  `test_unplug_no_person_constraint_preserves_target` with a trailing
  comment that the value survives *only until replug* (or rename to
  `…_at_unplug`). Add one line to the story's "Observable behaviour
  change" section: "A hand-picked next-charge target with no live user
  marker no longer survives an unplug/replug cycle — it reverts to the
  car default on the first plugged cycle (intentional; unplug already
  wipes every user-originated marker)."
