## Root cause

`render_all`'s contract is that **any** render failure must funnel
through `render_agents.RenderError`, because the handoff guard in
`next_step.py` (~line 238) catches only `ImportError` and `RenderError`
to uphold the documented invariant "a render failure must NEVER break a
handoff" (`next_step.py:203-204`). Review-fix #02 (S3) wrapped only the
`jinja2.TemplateError` family. But `jinja2.FileSystemLoader.get_source`
raises **non-jinja2** exceptions on several load failure modes
(`UnicodeDecodeError` ⊂ `ValueError`, `PermissionError`/`FileNotFoundError`
⊂ `OSError`), which escape `except jinja2.TemplateError`, escape
`render_all`, and break the handoff. All four findings below are that
same leak at different boundaries and are fixed together.

## Findings to fix

### [must-fix] M1 — load-time non-jinja2 loader exceptions escape `render_all`
- File: `scripts/qs/render_agents.py:349`
- Severity: must-fix
- Source: qs-review-edge-case-hunter
- Description: The `get_template()` guard catches only
  `jinja2.TemplateError`. A `*.md.j2` containing a non-UTF-8 byte raises
  `UnicodeDecodeError` (a `ValueError`); a template file that exists but
  is unreadable (mode 000) raises `PermissionError` (an `OSError`).
  Both escape the guard, escape `render_all`, and are not caught by the
  handoff guard in `next_step.py` → the handoff crashes. Verified
  empirically by the reviewer.

### [should-fix] S4 — render-time twin (extends/include parents)
- File: `scripts/qs/render_agents.py:362`
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: `template.render()` re-enters the loader at render time to
  resolve `extends`/`include` parents (e.g. `_base.md.j2`). The same
  non-`TemplateError` loader exceptions (`UnicodeDecodeError`, `OSError`)
  raised while loading a parent/partial escape the render-time
  `except jinja2.TemplateError` as well.

### [should-fix] S5 — TOCTOU between glob and load
- File: `scripts/qs/render_agents.py:349`
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: A `*.md.j2` removed between `_discover_stems`' glob and the
  load raises `FileNotFoundError`/`OSError` (not `TemplateError`) →
  escapes → breaks the handoff. Occurs under a concurrent render or a
  cleanup process deleting a template mid-run.

### [nice-to-have] N9 — glob over an unreadable templates dir
- File: `scripts/qs/render_agents.py:339`
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: `_discover_stems` calls `templates_path.glob(...)` outside
  any try. An unreadable templates dir is either a silent no-op (macOS
  yields `[]`) or an uncaught `PermissionError` on other platforms.
  Surface the empty-stems case as a degradation and wrap the glob.

## Proposed fix (single coherent change)

At the two loader boundaries in `render_all` — the `env.get_template()`
call (~line 349) and the `template.render()` call (~line 362) — widen
the caught set from `jinja2.TemplateError` to
`(jinja2.TemplateError, OSError, ValueError)` (or catch `Exception`) and
re-raise as `render_agents.RenderError` with a message naming the stem,
so every load- and render-time failure funnels through `RenderError`.
For N9, wrap the `_discover_stems` glob so a load failure there also
surfaces as `RenderError` (or an explicit degradation), rather than a
silent no-op or an uncaught `PermissionError`.

After this, the handoff guard's `ImportError`/`RenderError` catch
genuinely covers every render failure mode, closing the invariant gap
that review-fixes #02 and #03 have been chasing.
