## Findings to fix

### [should-fix] The `parallel:` split is described as "redundant" on HA ≥ 2026.10, but it still matters for latency
- File: `config/configuration.jinja:299-304` (comment #3 in the "FOUR THINGS HERE LOOK TIDYABLE. NONE ARE" block), mirrored in `tests/test_config_jinja_rendering.py:27-32` (module docstring bullet "A cloud-side exception aborts the script…", the "defense-in-depth" sentence)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: On HA 2026.10+, `continue_on_error` wraps pyatmo's plain `Exception` subclasses in `HomeAssistantError` and swallows them. So the split is no longer needed for **exception isolation**. But the split is still what runs the cloud write **concurrently** with the 10 s mirror-confirmation `wait_template` (both are sibling branches of the same `parallel:` block). Flattening the cloud step would make it run before the wait. Then the diagnostic wait would only start after the cloud call returns: up to `ClientTimeout(total=20)` (`custom_components/netatmo/pyatmo/auth.py:45,190`), and longer under tenacity's Retry-After loop on `ApiTooManyRequestError` (`auth.py:153-159`). The "unconfirmed" notification would be delayed by the cloud latency. Calling the split "redundant" in a block whose whole purpose is to warn against tidying invites exactly that regression.
- Proposed fix (comment-only, rendered output must stay byte-identical):
  - `config/configuration.jinja` comment #3: drop "so the split is redundant on current HA". Say instead that the cloud write sits alone in its own `parallel:` branch for two reasons:
    - (i) **latency**, on all HA versions: a slow, retrying (429 Retry-After) or hung cloud call must not delay the 10 s confirmation wait / diagnostic;
    - (ii) **exception isolation**: needed on HA ≤ 2026.8, defense-in-depth since HA 2026.10, where `continue_on_error` also swallows pyatmo's plain `Exception` subclasses (wrapped in `HomeAssistantError`; a cloud failure is then only a script ERROR log line).
  - Keep the `{#- … -#}` 80-column comment framing. Keep "See QS-436."
  - `tests/test_config_jinja_rendering.py` module docstring: make the same correction. The split keeps the diagnostic's timing independent of cloud latency (always), and its exception isolation is defense-in-depth on current HA. Keep the note that the exception path is exercised by the mutation case.
