## Findings to fix

### [should-fix] SF-1 — Pass 2 still contains the exact tie class SF-A removed from pass 1
- File: `custom_components/quiet_solar/ha_model/home.py:2548-2550` (`_finalize_cost_matrix`,
  pass-2 offset `n*E_max + 1.0`) and `:2693`
  (`compute_and_set_best_persons_cars_allocations`); the false claim is in the
  rewritten comment `custom_components/quiet_solar/const.py:473-482`.
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: A `-1`/`-2` sentinel on a *preferred* car costs `E_max + 1.0`; a
  covered-unplugged *non-preferred* car costs `0.0 + (n*E_max + 1.0)`. These are
  equal whenever `(n-1)*E_max == 0`, i.e. **`E_max == 0`** (the "everyone
  covered" state const.py:479 calls dominant) **or `n == 1`**. Pass 2 is the pass
  that ships whenever the gap ≤ 1000 Wh, so the tie reaches production output and
  the pick depends on `self._cars` order. Verified through
  `_finalize_cost_matrix` + `hungarian_algorithm` + the real gate with two
  repros (E_max==0 two-person; E_max>0 single-person with a `-2` unreadable-SOC
  preferred car — `-2` is common in normal use). Pre-existing on `main`, but this
  commit's new const.py block now *asserts* "a strictly ordered set of offsets"
  that "orders strictly below the `-1`/`-2` sentinels **and** the pass-2 offset"
  — a claim that is false for the sentinel-vs-offset pair.
- Proposed fix (option B — behaviour): make the pass-2 preferred-car offset
  strictly dominate the largest base spread. The reviewer's minimal correct
  condition is `preferred_car_penalty > (max_base - min_base) = E_max + 1.0`. The
  current pass-2 offset `n*E_max + 1.0` only meets it strictly for
  `n >= 2 AND E_max > 0`; make it strict for all `n >= 1` and `E_max >= 0`
  (e.g. an additive absolute epsilon on top of the `E_max`-relative offset, or a
  `max(...)` floor — implementer picks the minimum-diff form that preserves the
  existing pass-2 behaviour for `n >= 2, E_max > 0`). Then update the const.py
  comment so the asserted ordering is actually true. Add a regression pin that
  drives the two repros (E_max==0 multi-person; single-person `-2` preferred)
  through the real pipeline and asserts an order-independent result for all car
  orders, with the pass-2 branch confirmed adopted via `caplog`
  ("using preferred-car assignment").

### [nice-to-have] N-4 — Plugged penalty applies only in the `-3` branch, not `-1`/`-2`
- File: `custom_components/quiet_solar/ha_model/home.py:2551-2555` (`_finalize_cost_matrix`)
- Severity: nice-to-have (behaviour fix in-PR per user option B)
- Source: qs-review-edge-case-hunter
- Description: The plugged-covered penalty is applied only in the `-3` (covered)
  branch, never in `-1` (no/far-future forecast) or `-2` (car data error). Those
  persons also need no charging, yet their cells price a plugged and an unplugged
  car identically, so a no-forecast person can be handed a plugged car while an
  unplugged one sits free (order-dependent) — the exact "wasting a plugged-in
  car" the docstring (`home.py:2530-2533`) says the penalty prevents. Repro:
  one person `p_leave_time is None`, cars `[plugged, unplugged, unplugged,
  plugged]` -> pick flips with `self._cars` order.
- Proposed fix (option B — behaviour): apply the plugged-covered penalty in the
  `-1` and `-2` branches as well (the same absolute `PLUGGED_COVERED_CAR_PENALTY_WH`
  nudge on a plugged car), so a no-need person prefers an unplugged car
  regardless of order. Keep it strictly below the sentinel offsets (the SF-1 fix
  must hold simultaneously). Add a regression pin for the `-1`/`-2` plugged-vs-
  unplugged order-independence. Update the docstring/const comment to state the
  penalty now covers all no-need branches.
