### [must-fix] R3-M1 — the debounced boot wipe never fires in the realistic case
- File: `custom_components/quiet_solar/ha_model/charger.py:3683-3684`, `:3698-3701` (`_lift_boot_user_pin_if_car_unplugged`), `:5385-5388` (`_car_unplugged_since`, `back_on_at` → `time` fallback)
- Severity: must-fix (regression of fix #02 R2-S2: it voids fix #01 S1)
- Source: qs-review-edge-case-hunter (reproduced with a throwaway probe) + qs-review-coderabbit ("Major · Functional Correctness", same defect)
- Description: the guard sets `self._boot_user_pin = None` on the first (undebounced)
  proof, and the debounced check for the store wipe runs in the same decision, measuring
  an ongoing off as `time - off_stamp`. The recorder is down while HA is down, so the
  first "off" sample is stamped when HA first polls after the restart; the guard runs
  every load cycle (~7 s), so the first proof arrives 0–7 s after that stamp — always
  below `CHARGER_CHECK_STATE_WINDOW_S` (15 s). The store is kept, the guard is disarmed,
  and nothing re-checks: the car stays frozen with its pre-restart pin/target/hold and
  gets no person constraint at the next plug — the scenario fix #01 S1 was meant to fix.
  The live unplug branch cannot recover it (charger A has no car attached once the pin
  is lifted). The existing tests miss it because they stamp the "off" sample 15 min into
  the downtime, which cannot happen while the recorder is stopped.
- Proposed fix: keep the pin lift immediate and unchanged (QS-416 contract). Decouple the
  car-store decision from `_boot_user_pin`: when the pin is lifted but the off is not yet
  debounced, record a pending car-store check (car name + the same `saved_at` /
  `plug_at_save` proof inputs) that is re-evaluated at the following decisions until it
  settles: wipe once the off has lasted `CHARGER_CHECK_STATE_WINDOW_S`; drop the pending
  check (keep the store) if a later "on" ends the off span first, if
  `car.has_user_action_since_boot()` becomes true, or when the boot window / a bounded
  retry horizon ends. Make sure the re-evaluation runs on the call path(s) that keep
  firing while the charger has no car attached. Red test (realistic timing): off sample
  stamped < 15 s before `time` (after the simulated restart), then later cycles with
  repeated "off" samples every ~7 s → `user_frozen` cleared once the off reaches 15 s.
  Move the existing S1 / flap-then-sustained tests to realistic stamps too (or add
  realistic variants) and keep the flap and post-boot-action tests green.
