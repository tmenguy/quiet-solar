## Findings to fix

### [should-fix] R2-S1 — the S1 exemption carries an idle hold-off's OFF-time as ON runtime
- File: `custom_components/quiet_solar/ha_model/bistate_duration.py:1132-1150`
- Severity: should-fix
- Source: qs-review-edge-case-hunter (round 2, reproduced with a scratchpad probe)
- Description: the S1 exemption (`not is_override`) matches every
  USER_OVERRIDE constraint, including `TimeBasedHoldOffConstraint` (the
  user-OFF idle override, QS-256). Its `current_value` counts wall-clock time
  held OFF, not run time. So a mode switch inside the margin of a hold-off's
  end seeds the new constraint with OFF-time. The probe got
  `current_value == 14160.0` on the new ON constraint after a 3h56 hold-off.
  a27bfefd had dropped this case; e4f5c22d reintroduced it.
- Proposed fix (minimal, margin-scoped): restrict the S1 exemption to ON
  overrides. A hold-off inside the margin is skipped like any finished cycle:
  `... and not (is_override and not isinstance(c, TimeBasedHoldOffConstraint))`
  (`TimeBasedHoldOffConstraint` is already imported). Keep it readable, e.g. a
  local `carries_runtime_in_margin` bool. Do NOT change behavior outside the
  margin: a hold-off carried there is pre-existing on main (see follow-up F-A).
  Update the QS-390 comment at the skip site and the concept-doc
  "Common mistakes" entry (`docs/agents/concepts/bistate-duration-devices.md`).
- Test: a regression test beside
  `test_s1_override_runtime_in_margin_is_carried_on_mode_switch`: a hold-off
  override ending within the margin, a mode-string switch, and the new
  constraint NOT seeded with OFF-time (`current_value == 0`). Red first against
  HEAD, record the verbatim FAILED line, then fix. S1 must stay green.
