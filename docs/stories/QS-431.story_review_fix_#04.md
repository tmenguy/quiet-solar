## User scope decision (2026-10-27) — remove the boot-time car-store wipe

Rounds 2, 3 and 4 each found a regression in the same feature: wiping the car's user
store (and thus the freeze) when the QS-416 boot guard infers, from the car's cloud
plug-sensor history, that the car was unplugged while HA was down (fix #01 S1 →
#02 R2-S1/R2-S2 → #03 R3-M1). Round 4's must-fix: a stale "off" from the car's cloud
sensor right after a plain restart now wipes the store of a car that never left its
charger (regression against `main`). The underlying problem — inferring an unplug during
the downtime from an unreliable cloud sensor — is not part of the diagnosed incident.

Asked to choose, the user ruled: **"yes 1. : I don't care it will never really happen ,
document it , it is very hard to properly fix, so don't fix it"**. Decision: remove the
boot-time wipe entirely, document the limitation, **no fix and no follow-up issue**.
