## Findings to fix

### [should-fix] S1 — `check_translations` SKIPs when `strings.json` / the generator is missing, but CI goes red
- File: `scripts/qs/quality_gate.py:1088-1098` (+ comment at `.github/workflows/pr-quality.yml:194-199`)
- Source: qs-review-edge-case-hunter
- Description: both paths are in `_CHEAP_TRANSLATIONS_PATHS`, so deleting either one triggers the gate. But `check_translations` then returns `passed: True` ("SKIP (no strings.json)" / "SKIP (no generate script)"). CI runs `bash scripts/generate-translations.sh`, which fails in both cases. The workflow comment also claims that "absent strings.json" failures agree between local and CI, which is false today.
- Proposed fix: make both missing-file branches return `passed: False` with a clear `detail`: "custom_components/quiet_solar/strings.json is missing — CI's translations step will fail" and "scripts/generate-translations.sh is missing — CI's translations step will fail". Emit `FAIL (no strings.json)` / `FAIL (no generate script)`. Update the existing tests that pin the SKIP behaviour and add a test for each FAIL path. Keep the workflow comment; it becomes true.

### [should-fix] S2 — Tool-gate trigger misses `.pyi` stubs and new tool-config files
- File: `scripts/qs/quality_gate.py:1719-1758` (`_CHEAP_TOOL_CONFIG_PATHS`, `_impacted_cheap_gate_names`)
- Source: qs-review-edge-case-hunter (+ blind-hunter nice-to-have on `.pyi`)
- Description: adding `mypy.ini` / `.mypy.ini` / `setup.cfg` / `ruff.toml` / `.ruff.toml` at the root, or a `ruff.toml` / `pyproject.toml` under `custom_components/`, can change the CI verdict. So can a package `.pyi` stub. None of them triggers the tool gates today, so the gate prints SKIP and exits 0.
- Proposed fix: select the tool gates when any of these is true:
  - (a) a path starts with `custom_components/quiet_solar/` and ends with `.py` or `.pyi`;
  - (b) the path is `custom_components/__init__.py`;
  - (c) the path is in `{"pyproject.toml", "requirements.txt", "requirements_test.txt"}`;
  - (d) the basename is in `{"pyproject.toml", "ruff.toml", ".ruff.toml", "mypy.ini", ".mypy.ini", "setup.cfg"}` and the path is at the repo root (no `/`) or under `custom_components/`.

  Replace the "verified: no mypy.ini … exists" comment with one explaining that these files would *override* the root config if added. Extend `test_trigger_table` with rows for `mypy.ini`, `.ruff.toml`, `setup.cfg`, `custom_components/quiet_solar/ruff.toml`, `custom_components/quiet_solar/foo.pyi` and `custom_components/__init__.py` (all → tools). Add a negative row for `docs/ruff.toml` (→ nothing). Update the trigger-rule wording in `check_impacted`'s docstring and in any doc that lists the trigger (CLAUDE.md / AGENTS.md / project-rules.md / testing-layers.md / the template), but only where those docs enumerate the trigger files.
