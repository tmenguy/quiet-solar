### [should-fix] H1 — Bad file input is detected only after `launch_at` is written (spawn/resume); a non-UTF-8 file blocks the key
- File: `scripts/qs/control_plane/tools.py` — `check_files` (~:356-369),
  `_launch` (~:914-924), spawn `start` (~:1026), resume `start` lambda
  (~:1116/1122)
- Source: blind-hunter (should-fix) + edge-case-hunter
- Description: `check_files` only checks that the bytes are readable.
  The UTF-8 decode happens in `arg_file_text`, inside `start()`. By then
  `_launch` has already written `launch_at`. So a non-UTF-8 prompt,
  or a file deleted before a takeover, leaves three things behind:
  - a `spawning` row with `launch_at` set and nothing launched;
  - a claim that stays `started` because there are outputs;
  - a fixed file that gives CONFLICT, because the digest changed.

  A replay inside `LAUNCH_SETTLE_S` then waits out `identify` for a
  launch that never happened.
- Proposed fix:
  1. `_read_files` / `check_files` decode every cached file as UTF-8,
     so a fresh call fails with USAGE before `claim()` and before any
     effect.
  2. In spawn's and resume's `launch` step, read the text with
     `arg_file_text` **before** calling `_launch`, so `launch_at` is
     written only once the input is known good.
  3. In `claim()`'s `current is None` (fresh insert) branch, raise USAGE
     when any `*_file` argument is missing from the cache. This closes
     the race where an in-flight holder released its claim between
     `replay()` and `claim()`; it is edge-case-hunter's
     nice-to-have, folded in here.
- Tests:
  - A fresh spawn with a non-UTF-8 prompt gives USAGE, with no node row,
    no claim and no `launch_at`.
  - A takeover after `reserve` with the file deleted gives USAGE, with
    `launch_at` still NULL. Restoring the file and replaying the same key
    launches once.
  - The fresh-insert race with a missing file gives USAGE.

### [should-fix] H2 — The G4/G18 escalation can kill a healthy or newer daemon, and a zombie counts as alive
- File: `scripts/qs/control_plane/daemon.py` (~:215-311: `_stop_old`,
  `ensure`, `stuck`), `docs/workflow/control-plane.md` (the `tick_hooks`
  seam row and the daemon section)
- Source: blind-hunter + edge-case-hunter
- Description: round 2's escalation introduced three regressions.
  - **(a)** `stuck` checks only `not older`, so it also matches a
    **newer**-schema lease. Older code would SIGTERM/SIGKILL a newer
    daemon, fail to migrate down, and write the backoff sidecar.
  - **(b)** The heartbeat is written only between tick hooks. A
    healthy daemon inside a long hook (child 14's `gh` / CI calls) looks
    frozen, so after `STALE_AFTER_S` it gets SIGTERM and then SIGKILL,
    in the middle of an effect.
  - **(c)** A daemon that died while its `Popen` parent (a long `wait`)
    is still running stays a zombie. `kill(pid, 0)` and `ps` report it
    alive, so `ensure` loops to `restart_pending` / `stale_alive`, where
    before it just started a new daemon.
- Proposed fix:
  - **(a)** `stuck` requires `lease.schema_version == target`. A newer
    lease is never signalled; existing behaviour there: the new daemon
    exits with `held_elsewhere`, and commands get `SCHEMA_TOO_NEW`.
  - **(b)** The daemon beats its lease before **and after** each tick
    hook, not only once per tick.
    - Document in the `tick_hooks` seam row: "a tick hook must return
      within `STALE_AFTER_S` or beat the lease itself".
    - Optionally expose a `beat()` callable to hooks. Keep it
      minimal: only add it if it costs nothing to the frozen surfaces.
  - **(c)** Make the singleton flock the deciding signal. Check
    whether `db.file_lock(<db>.daemon.lock, exclusive=True, timeout=0)`
    can be taken:
    - before signalling;
    - inside both wait loops (after SIGTERM, after SIGKILL).

    If it can be taken, the old daemon is gone (zombie, crash or unknown
    `ps`): release the lock at once and start the new daemon. This also
    shrinks the "`ps` permanently unknown" limit noted in Conventions.
    Update that note.
  - Also: inside the SIGTERM wait loop, return early when
    `probe.alive(old_pid, start) is False`.
- Tests:
  - (a) A newer-schema stale but alive lease gets no signal.
  - (b) The heartbeat is written around each tick hook. A hook that
    sleeps past the old window, with beats around it, is never killed.
  - (c) A zombie (probe says alive, flock free) leads straight to
    `started`/`restarted` with no SIGKILL.
  - The flock is free mid-wait, so the wait breaks early.
  - The probe reports dead mid-wait, so the wait breaks early.
