### [must-fix] #1 — The real car-select handler never reaches any of the three clears
- File: `custom_components/quiet_solar/ha_model/charger.py:3428-3435`
  (`user_set_selected_car_by_name`), `detach_car()`
- Severity: must-fix
- Source: qs-review-edge-case-hunter
- Description: the user path for "change the charger's car select to B
  / to No car" — the scenario round-3 finding #2 described — calls
  `self.detach_car()` synchronously at `:3433` with the constraints still
  live and no clear. By the next planning cycle `self.car` is already
  `None`, so at the "no car" exit (`:3767`) `_has_live_person_constraint()`
  returns `False` (`:3565`) and at `:3774` the `elif self.car:` car-switch
  branch is skipped entirely; `reset()` / `clean_constraints…(for_full_reset=True)`
  then wipe A's person constraint and the marker is gone. Probed on head:
  step-1 leak (41 on car A) → `await charger.user_set_selected_car_by_name(CHARGER_NO_CAR_CONNECTED)`
  (or `"ID.buzz"`) → one cycle → `car._next_charge_target == 41`,
  constraints 0. The round-3 tests pass only because they mock
  `get_best_car` (the allocation-driven switch) and never drive the
  select handler.
- Proposed fix: add the clear at the **top of `detach_car()`**:
  `if self.car is not None: self._clear_leaked_person_target_if_needed()`
  before `self._last_attached_car = self.car`. This also covers the other
  direct detach callers (`attach_car` `:4514`, cross-charger `get_best_car`
  `:3227`/`:3401`, `home.py:2082/2093`, `QSCar.detach_charger`). **Keep**
  the two explicit pre-`reset()` calls at `:3704` (unplug) and `:3767`
  ("no car" cycle exit): `AbstractLoad.reset` (`load.py:451`) wipes
  `_constraints` *before* `QSChargerGeneric.reset` reaches `detach_car`
  (`:2903-2904`), so a clear inside `detach_car` is a guaranteed no-op on
  those two paths. The explicit call at `:3787` (car-switch cycle exit,
  immediately before `detach_car()`) becomes redundant and may be
  removed. `self.car` (`:2287`) and `_constraints` (`load.py:419`) both
  exist before the constructor's `reset()` (`:2333`), so the helper is
  safe there. Add two **red-first** tests driving the handler (mock
  `update_charger_for_user_change`):
  `test_select_no_car_with_live_person_constraint_clears_target` and
  `test_select_other_car_with_live_person_constraint_clears_target`,
  each asserting `car._next_charge_target is None` after the following
  cycle. Add a one-line comment on the two existing round-3 tests that
  they cover the allocation-driven switch only.
