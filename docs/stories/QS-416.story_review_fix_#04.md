## Findings to fix

### [should-fix] R4-1 — persisted pin survives an unplug during downtime when the charger is unplugged at boot
- File: `custom_components/quiet_solar/ha_model/charger.py:~4285-4321` (`check_load_activity_and_constraints`, `is_not_plugged` branch), `:~3711` (only caller of `_lift_boot_user_pin_if_car_unplugged`, inside `_compute_best_car`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter (reproduced: `/private/tmp/claude-501/-Users-tmenguy-Developer-homeassistant-quiet-solar-worktrees-QS-416/be261e20-a41d-488c-8633-2a7c9ed2e5dc/scratchpad/test_r4_repro.py` passes on HEAD = defect present)
- Description: the boot pin guard only runs from `_compute_best_car`, reached only from the plugged branch. If the charger reads not-plugged at boot, R3-2's `unplug_edge` is False (first unplugged cycle after boot is not an edge, no car attached), so nothing clears the pin, and `reset_boot_data()` then disarms the guard even though the on→off proof was available. The pin then survives until the next real plug/unplug: the next car plugged into W1 is ignored and the absent pinned car is attached via "user_selection" — the incident inverted. Worsened by this PR (every user action on the attached car now creates a persisted pin; R3-2 removed the unconditional clear that masked it).
- Proposed fix: keep R3-2's edge rule. At the top of the `is_not_plugged` branch (before `unplug_edge` is computed), call `self._lift_boot_user_pin_if_car_unplugged(time)`. It only acts while `_boot_user_pin` is armed and uses the same on→off transition rule, so a stale re-polled `off` keeps the pin and pre-selections on an unplugged charger are unaffected. Regression test = the reviewer's repro inverted (move it into `tests/test_qs416_car_charger_association.py`, real cars/chargers): pin lifted during the boot window while W1 is unplugged; hours later B plugs into W1 and B is attached. Plus a guard row: stale `off` (saved reading `off`) with W1 unplugged at boot → pin kept.
