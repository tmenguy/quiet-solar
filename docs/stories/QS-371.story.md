## Problem

`python scripts/qs/quality_gate.py --impacted` is the mandatory pre-commit
gate, yet a green run does not predict a green CI. In QS-349 review round 9
found the CI job **"Ruff Lint & Format"** red (`ruff format --check` failing
on 3 files) although implement had run `--impacted` green before every
commit.

Root cause (verified in source, `scripts/qs/quality_gate.py`):

- `main()` short-circuits `--impacted` with `sys.exit(check_impacted())`
  (l.3495) **before** the full-gate path that runs the cheap gates
  (l.3580–3615).
- `check_impacted()` (l.2354–2495) runs: tooling probe → orphan-shard reap →
  `was_incremental = _testmon_baseline_warm()` → testmon DB hygiene → lane
  check (l.2454) → `early_exit_paths = _impacted_early_exit_paths()`
  (l.2457, **unconditional** — its only call site) → warm-baseline non-`.py`
  early exit (l.2458) → diff-base ladder → testmon pass + diff-cover
  (+ self-heal retry). It never calls `check_ruff_lint`,
  `check_ruff_format`, `check_mypy` or `check_translations`.
- CI (`.github/workflows/pr-quality.yml`) runs `ruff check`,
  `ruff format --check` and `mypy` on `custom_components/quiet_solar/`, plus
  the translations value-check (`bash scripts/generate-translations.sh`,
  **failing on a generator error**, then `git diff --exit-code` on
  `translations/`) in the `Tests (100% Coverage)` job, on **every** PR.
  `--impacted` itself is **not** run by any CI job
  (`grep -rn impacted .github/` → nothing).
- Secondary parity gap: the local `check_translations` **ignores the
  generator's exit code** (l.1092–1093, "may fail for unrelated
  integrations" — stale: the script only handles quiet_solar). An
  unresolvable `[%key:…%]` makes the generator exit 1 before writing
  (`generate_translations.py` l.62–64), `en.json` is unchanged, and the
  local check passes while CI is red. The CI workflow comment (l.~194)
  records this as a "deliberate asymmetry"; this issue's Expected removes
  it.

So lint / format / type / stale-translation errors surface only in CI or in
a later review round — every one an extra implement/review loop iteration,
which is exactly what epic #369 is trying to remove.

## Goal

A green `--impacted` means the cheap checks CI runs — `ruff check`,
`ruff format --check`, `mypy`, and the translations check when relevant —
will not fail on this change set, while `--impacted` stays fast.
Whole-repo coverage stays CI's exclusive job.

The guarantee holds for the tree `--impacted` sees, under three stated
conditions (R5, R6): the committed tree equals the worktree, the branch is
up to date with `main` (CI checks the PR merge ref), and the venv matches
the requirements pins.

### Measured costs (2026-09-25, this worktree)

| Check | First run in this worktree | Re-run (`.mypy_cache` warm) |
| --- | --- | --- |
| `ruff check custom_components/quiet_solar/` | ~0.02 s | ~0.02 s |
| `ruff format --check custom_components/quiet_solar/` | ~0.02 s | ~0.02 s |
| `mypy custom_components/quiet_solar/` | ~5.0 s | ~0.2 s |

(The first mypy run was the first in this worktree; whether a
`.mypy_cache` pre-existed was not recorded. AC14 re-measures both on the
real smoke and records them in the PR body.)

The cheap gates run concurrently **with each other**, then (serially) the
testmon pass starts. Added wall-clock ≈ mypy: **+≤ ~5 s cold, sub-second
warm**, and only on change sets that trigger them (D3). Running mypy in a
thread alongside the testmon pass was considered and rejected: it competes
with xdist for CPU and adds join/ordering complexity to save ≤ 5 s once
per fresh worktree.

## Design

### D1 — Reuse the existing check functions; same target and pins as CI

`check_ruff_lint(fix=False)` (l.1030), `check_ruff_format(fix=False)`
(l.1046), `check_mypy()` (l.1063) and `check_translations()` (l.1077)
target the same `SRC_DIR` = `custom_components/quiet_solar/` with the same
flags as the CI steps, and the translations one invokes the same entry
point (`scripts/generate-translations.sh`). Their result `name`s are
exactly `"ruff_lint"`, `"ruff_format"`, `"mypy"`, `"translations"`
(verified). Tool versions come from the same pins on both sides: CI and
the local venv both install `requirements_test.txt` (`ruff==0.15.6`,
`mypy==1.20.0`). **What is guaranteed:** same command, same target, same
pinned versions (given an up-to-date venv, R6). No new command lines are
written.

Gates run on the **whole package**, exactly like CI — no per-changed-file
filtering. A package already red on `main` makes `--impacted` red too;
that is a real CI red, not a false positive (R4).

`_run_cheap_gates_parallel(specs)` (l.1109) is called **as-is, unmodified**:
it takes `list[tuple[callable, kwargs, gate_names]]`, returns an unordered
`list[dict]`, and synthesizes a `{"name", "passed": False, "detail": "",
"stderr": "<exception>: …"}` dict per gate when a callable raises. With
`fix=False` both ruff gates are read-only, so running them concurrently is
safe (the full gate's serialized ruff pair exists only for `--fix` write
races).

`_run` (l.150) only captures output, never prints; each check function
prints only its own `_emit(<name>, "running" | "checking" | "PASS" |
"FAIL" | "SKIP …")` status lines. The tool output (`detail` / `stderr`) is
printed **only** by `_impacted_cheap_checks` (D2.4), so nothing is
duplicated. Concurrent status lines may interleave — each is a single
`print`, so lines never tear.

### D1b — Failure dicts carry `stderr`; translations generator failure FAILs

- `check_ruff_lint`, `check_ruff_format`, `check_mypy` add
  `"stderr": result.stderr.strip()[-500:] if not passed else ""` — the
  same convention as `detail`. Motive: a broken `pyproject.toml` or a
  missing tool (rc 127, message on stderr only) otherwise yields a FAIL
  with an empty reason. Effect on the full gate: text mode unchanged;
  `--json` failure output gains a `stderr` field for these three gates —
  harmless, `check_pytest` results and the exception-synthesized dicts
  already carry one. No test compares a whole tool dict (verified); the
  cache is written only on pass.
- `check_translations`: capture `gen = _run(["bash", str(gen_script)])`;
  if `gen.returncode != 0` → `_emit("translations", "FAIL (generator
  failed)")` and return `{"name": "translations", "passed": False,
  "detail": "scripts/generate-translations.sh failed — check strings.json
  for an unresolvable [%key:...%] reference", "stderr":
  gen.stderr.strip()[-500:]}` (verified: the generator writes its
  `ERROR: missing reference …` line and any traceback to **stderr**,
  `generate_translations.py` l.63). Delete the stale "unrelated
  integrations" comment. Applies to the full gate too — it becomes exactly as strict as
  CI — a deliberate full-gate behaviour change, to be named in the PR body.
  Update (comment only, no step change; `.github/**` is in the
  implement-setup-task edit scope) the `.github/workflows/pr-quality.yml`
  comment block (l.~189–199) that describes the "deliberate asymmetry": the two now
  agree on generator failures as well as staleness. No test pins the old
  behaviour or comment (verified by grep).

### D2 — `_impacted_cheap_checks(paths: list[str] | None) -> list[str]`

Returns the failed gate names **ordered by `_CHEAP_GATE_ORDER`** (`[]` =
all passed or none applicable). In `quality_gate.py`:

1. `names = _impacted_cheap_gate_names(paths)` (D3). **Hard guard:** if
   `names` is empty → `_emit("cheap-checks", "SKIP (no package .py / lint-config / translations-source change)")`
   and return `[]` **without** calling `_run_cheap_gates_parallel`
   (`ThreadPoolExecutor(max_workers=0)` raises `ValueError`).
2. Build `specs` **inside the function on every call**, looking the check
   functions up as module globals (as `main` does at l.3607–3612), so test
   `patch.object(quality_gate, "check_mypy", …)` applies. Map:
   `ruff_format → (check_ruff_format, {"fix": False})`,
   `ruff_lint → (check_ruff_lint, {"fix": False})`,
   `mypy → (check_mypy, {})`, `translations → (check_translations, {})`.
3. Sort the results by the module constant
   `_CHEAP_GATE_ORDER = ("ruff_format", "ruff_lint", "mypy", "translations")`.
   `main`'s inline literal `gate_order = ["ruff_format", "ruff_lint", "mypy", "translations"]`
   (l.3590, used at l.3615 — same four names, same order, verified) is
   replaced by this constant so the two cannot drift.
4. For each failing result: emit **every line** of its `detail` then of its
   `stderr` (skipping empty ones) as `_emit(<gate name>, ln)` — `_emit`
   prefixes only one line per call, so multi-line tool output must be split
   with `splitlines()`. Then, if the gate has one, a single hint line from
   `_CHEAP_GATE_HINTS: dict[str, str]` — the command that reproduces / fixes
   it:
   - `ruff_format` → `fix: venv/bin/ruff format custom_components/quiet_solar/`
   - `ruff_lint` → `rerun: venv/bin/ruff check custom_components/quiet_solar/ (add --fix to auto-fix)`
   - `mypy` → `rerun: venv/bin/python -m mypy custom_components/quiet_solar/`
   - `translations` → no hint (its `detail` already says what to do).
5. `_emit("cheap-checks", "PASS")` or
   `_emit("cheap-checks", f"FAIL ({', '.join(failed)})")`; return `failed`.

This is a new, small printer on purpose: the full gate's `_output_results`
(l.1150) is a whole-run formatter (header, JSON mode, cache/scope banner),
not a per-gate detail printer, and does not fit `--impacted`'s `_emit`
line format.

Side effects: none beyond the tools themselves, **except** the translations
regeneration (D6).

### D3 — Trigger: `_impacted_cheap_gate_names(paths: list[str] | None) -> list[str]`

Pure function, no I/O; returns names in `_CHEAP_GATE_ORDER`. Input: the path
list `_impacted_early_exit_paths()` already computes (merge-base–scoped
union of worktree, committed, staged and untracked paths; deletions are
listed by `git diff --name-only`; renames list both sides after D3b).
**`None` (git failure / unknown) → all four gates** (fail-closed).

- **`ruff_format`, `ruff_lint`, `mypy`** iff any path:
  - starts with `custom_components/quiet_solar/` and ends with `.py`, **or**
  - is exactly one of: `pyproject.toml`, `requirements.txt`,
    `requirements_test.txt` (tool config / pins — verified: no `mypy.ini`,
    `ruff.toml`, `.ruff.toml`, `setup.cfg`, `tox.ini` exists).

  Deliberately **not** triggers: `.github/workflows/pr-quality.yml` and
  `scripts/qs/quality_gate.py`. Neither can change the ruff/mypy verdict on
  the package, and re-running the *old* local mirror proves nothing about a
  *new* CI command (round-3 SG3-1; the v3 addition is reverted). Changes to
  the gate's own check commands are proven by `tests/test_quality_gate.py`
  and the AC15 smoke.
- **`translations`** iff any path is one of the generator's inputs:
  `custom_components/quiet_solar/strings.json`, anything under
  `custom_components/quiet_solar/translations/`,
  `scripts/strings_from_homeassistant.json`,
  `scripts/generate_translations.py`, `scripts/generate-translations.sh`.
  Verified: the generator reads only `strings.json` and
  `scripts/strings_from_homeassistant.json` (`generate_translations.py`
  l.22–24, 96–97) — no package `.py` — so a `.py`-only change cannot make
  `en.json` stale.

Everything else (docs, other `scripts/`, `tests/`, `.claude/`, UI assets…)
triggers nothing — CI does not lint those paths either — and the doc-only
early exit stays near-instant. These rules are written out in full **only
here and in the `check_impacted` docstring**; every other doc refers to the
docstring.

### D3b — `--no-renames` in `_impacted_early_exit_paths`

`git diff --name-only` uses rename detection by default, so
`git mv custom_components/quiet_solar/x.py legacy/x.py` lists only
`legacy/x.py`: the trigger would skip while CI mypy can fail on the broken
imports. The three `git diff` rungs become **exactly** (flag after `-z`, so
the existing prefix match `("git","diff","--name-only","-z")` at l.~4602 /
4619 and the `cmd[-1] == "HEAD"` lookup at l.~4636 keep working):

```python
["git", "diff", "--name-only", "-z", "--no-renames", merge_base]
["git", "diff", "--name-only", "-z", "--no-renames", merge_base, "HEAD"]
["git", "diff", "--name-only", "-z", "--no-renames", "--cached", merge_base]
```

This only **adds** source paths to the union. The union has exactly two
consumers — the non-`.py` early exit and the new trigger — so the early
exit can only become stricter, the trigger only fire more; both
consistent with the function's fail-closed contract. Documented in its
docstring. No other git call in the file changes.

### D4 — Placement and aggregation (decision A: run everything, then aggregate)

`check_impacted()` becomes:

```python
    if _emit_lane_check(_check_lane_targets()):
        return 1
    early_exit_paths = _impacted_early_exit_paths()          # l.2457, unchanged position
    cheap_failed = _impacted_cheap_checks(early_exit_paths)   # NEW, inserted here
    rc = _check_impacted_tail(early_exit_paths=early_exit_paths, was_incremental=was_incremental)
    return _with_cheap(rc, cheap_failed)
```

- `was_incremental` is already bound earlier in `check_impacted`
  (`= _testmon_baseline_warm()`, before `_ensure_testmon_db_safe()`),
  unchanged.
- **`_check_impacted_tail(*, early_exit_paths: list[str] | None,
  was_incremental: bool) -> int`** — keyword-only; the current l.2458–2495
  body moved verbatim (warm-baseline non-`.py` early exit, diff-base ladder,
  `_run_impacted_pass`, self-heal retry). Its only free variables are those
  two (verified); `base`, `verdict`, `ran_select_all`, `retry_verdict` are
  local to it. It keeps calling the same module-level seams
  (`_testmon_baseline_warm`, `_resolve_diff_base`, `_is_ci`,
  `_run_impacted_pass`, `_rebuild_testmon_baseline`) by the same names, so
  existing `patch.object` tests keep working. The early-exit rationale
  comment block (l.~2423–2444, QS-290 S-4 / warm-baseline) moves with it,
  above `if _testmon_baseline_warm():`; the lane comment (l.~2445–2453) stays
  with `_emit_lane_check`. No other change to the moved code.
- **`_with_cheap(rc: int, cheap_failed: list[str]) -> int`** — `cheap_failed`
  is the failed-names list (empty = OK):
  - `rc == 0 and cheap_failed` →
    `_emit("impacted", f"FAIL (cheap checks failed: {', '.join(cheap_failed)})")`,
    return 1;
  - `rc != 0 and cheap_failed` →
    `_emit("impacted", f"note: cheap checks also failed: {', '.join(cheap_failed)}")`,
    return `rc`;
  - otherwise return `rc`.
  The final line makes the verdict visible at the tail of the output even
  after the non-`.py` exit printed its PASS lines or testmon scrolled the
  cheap-check FAIL away. Non-zero codes keep their meaning (1
  test/coverage fail, 4 no base in CI).
- **No early return on a cheap-check failure**: the tail still runs, so one
  run surfaces every problem.
- The cheap checks run **before** the non-`.py` early exit, so a
  `pyproject.toml`-only change set is still linted/type-checked.
- **Before the cheap checks, unchanged:** exit 3 (testmon/diff-cover not
  importable) and the lane-check failure (exit 1). The lane failure is a
  missing/inconsistent task declaration fixed out-of-band (issue labels),
  not a code defect, so short-circuiting it does not hide anything the
  developer would fix in the same edit.
- **Missing ruff/mypy binary** → `_run` returns rc 127 with the message on
  stderr (or the executor synthesizes an exception dict) → FAIL with the
  message shown (D1b) → exit **1**. The tooling probe is **not** extended;
  exit 3 stays testmon/diff-cover only.
- The local "no diff base → skip diff-coverage → 0" branch goes through
  `_with_cheap` too (offline dev still gets lint/type feedback).
- No `_is_ci()` special case: `--impacted` is not run in CI.

Docstrings: the module docstring's `--impacted` option text (l.23–28) and
exit-code line 1 (l.47) gain "… OR a CI-mirrored cheap check (ruff lint /
ruff format / mypy / translations) failed". `check_impacted`'s docstring
gets the new pipeline, the D3 trigger rules, and its "Ordering consequence"
paragraph (l.2361–2366) is updated: a non-`.py` change set that triggers
cheap checks can now return 1.

### D5 — No `--fix` under `--impacted` (decision C)

`--impacted` stays mutually exclusive with `--fix`. The hints (D2.4) give
the command.

### D6 — Translations check side effect is accepted

`check_translations()` regenerates `translations/en.json` in place when
stale and returns FAIL ("Stage the updated file") — same as the full gate
today; the trigger limits it to change sets that touch a generator input.

## Acceptance criteria

1. **AC1 — format failure caught.** Package `.py` in the change set, stubbed
   `check_ruff_format` failing, tail would return 0 → `check_impacted()`
   returns **1**; stderr contains every `detail` line prefixed
   `[ruff_format]`, the `ruff format` hint, `[cheap-checks] FAIL (ruff_format)`,
   and the **last** stderr line is `[impacted] FAIL (cheap checks failed: ruff_format)`.
2. **AC2 — lint and mypy failures caught.** Same as AC1 for `ruff_lint` and
   `mypy`, each independently; with two failing, names appear in
   `_CHEAP_GATE_ORDER` order.
3. **AC3 — aggregate, don't fail fast.** On a cheap-check failure the tail
   (and `_run_impacted_pass`) still runs; a simultaneous tail rc 1 → **1**
   with the `note: cheap checks also failed` line.
4. **AC4 — verdict matrix at the entry point.** Parametrized over tail
   outcomes with cheap checks failing: early-exit 0 → 1; local-no-base
   0 → 1; pass 0 → 1; self-heal-retry pass 0 → 1; tail 1 → 1;
   CI-no-base 4 → 4. With cheap checks passing, every tail rc is returned
   unchanged and no `[impacted] FAIL (cheap…` / `note:` line is emitted.
   (`_with_cheap` is covered through this matrix — no separate unit tests.)
5. **AC5 — config-only change set checked.** Only `pyproject.toml` changed,
   warm baseline: ruff lint/format + mypy run before the non-`.py` early
   exit; failing mypy → **1** (and the tail line); all passing → **0** via
   the early exit.
6. **AC6 — doc-only stays fast.** Only `docs/**` / other `scripts/**` /
   `tests/**` / UI-asset paths, or `[]` → `_run_cheap_gates_parallel`
   **not called**, SKIP line emitted, returns `[]`.
7. **AC7 — trigger table.** Tool gates iff a package `.py` or one of the
   three exact config paths (D3) is present (`pr-quality.yml` and
   `scripts/qs/quality_gate.py` select nothing); `translations` iff one of the
   five generator-input paths is present; a translations-only change set
   selects `translations` alone.
8. **AC8 — fail-closed on unknown paths.** `paths is None` → all four gates.
9. **AC9 — renames visible.** Real-git tests in `TestImpactedEarlyExitPaths`
   using the fixture's committed `mod.py`: `git mv mod.py legacy/mod.py`
   (staged-only variant and committed variant); premise asserted first
   (`"mod.py"` absent from a plain rename-detecting `git diff --name-only`
   of that state), then `"mod.py" in paths`. Plus
   `test_all_diff_rungs_disable_rename_detection` (exactly three `git diff`
   calls, each containing `--no-renames` right after `-z`).
10. **AC10 — failure detail never empty.** Parametrized over
    `check_ruff_format` / `check_ruff_lint` / `check_mypy`: a failing tool
    check with empty stdout and non-empty stderr (`_run` patched) → dict has
    `"name" == "<gate>"` and that `stderr`; the same test with rc 0 → both
    `detail` and `stderr` are `""` (covers both ternary outcomes); the
    `--impacted` printer shows the stderr; a synthesized-exception dict prints its `stderr`; translations
    failure prints its detail and no hint.
11. **AC11 — translations generator failure FAILs.** `_run` patched to rc 1
    for the generator → `check_translations()` returns `passed: False` with
    the generator stderr, even though `en.json` is unchanged.
12. **AC12 — existing behaviour intact.** All existing `TestCheckImpacted*`,
    `TestImpactedEarlyExitPaths`, `TestImpactedNonPyEarlyExit`,
    `TestCheckImpactedSelfHeal`, `TestLaneCheckImpactedCallSite`,
    `TestImpactedCli` tests stay green and none spawns real ruff/mypy
    (module autouse stub, task 2); the full gate still orders its cheap
    results as before.
13. **AC13 — docs say what `--impacted` now runs.** `CLAUDE.md`,
    `AGENTS.md`, `docs/workflow/project-rules.md`,
    `docs/agents/concepts/testing-layers.md`,
    `scripts/qs/agent_templates/qs-implement-setup-task.md.j2` (body **and**
    both frontmatter descriptions) and the two docstrings describe
    `--impacted` as including the CI-mirrored cheap checks; every
    non-`.py` "checks nothing" / "no-op" statement carries the exception.
    Pins use the unique literal `Exception (QS-371)` (the shared phrase
    "CI-mirrored cheap checks" also appears in task-5 sentences and the
    frontmatter, so it cannot prove the exception is present): once in the
    project-rules "Non-Python change sets" section, and **twice** (both body
    sites) in the rendered implement-setup-task agent.
14. **AC14 — gate green, and the new code actually tested.**
    `python scripts/qs/quality_gate.py --impacted` (the cheap checks SKIP
    on this branch — no trigger path; AC15 runs them for real),
    `python scripts/qs/quality_gate.py --quick tests/test_quality_gate.py`
    (`--impacted` ignores that file by path, l.2137, and `scripts/qs` is
    outside `--cov`), `python scripts/qs/quality_gate.py --quick tests/qs`,
    and a branch-coverage check of the new code over the **whole file**:
    `venv/bin/python -m pytest tests/test_quality_gate.py --cov=scripts/qs --cov-branch --cov-report=term-missing -p no:cacheprovider`
    (**implementation note:** prefix it with
    `COVERAGE_FILE=<scratch>/.coverage` — run bare, it overwrites the
    worktree's accumulated `.coverage` with *branch* data, and the next
    `--impacted` (`--cov-append`) then dies with "Can't combine statement
    coverage data with branch data"; recovery was a testmon baseline rebuild)
    — no missing lines/branches inside `_impacted_cheap_gate_names`,
    `_impacted_cheap_checks`, `_with_cheap`, `_check_impacted_tail`,
    `check_impacted`, the changed lines of `check_ruff_lint` /
    `check_ruff_format` / `check_mypy` / `check_translations`, and the
    `_impacted_early_exit_paths` rungs. There is no fail-under anywhere

    raw-`pytest` grammar rule makes `quality_gate.py` the single entry point,
    but no gate mode can measure `scripts/qs` coverage (`--quick` /
    `--impacted` use `--cov=custom_components/quiet_solar`); this one-off
    verification command is therefore explicitly authorized for this task
    only — not an inner-loop habit, and review/verify must not flag it.
15. **AC15 — real smoke** (in the implement-setup-task edit scope), run

    1. Baseline: real `--impacted` → `[cheap-checks] SKIP (…)` (no package

## Risks

- **R1 — existing suites spawning real ruff/mypy.** Mitigated by the
  module-level autouse stub (task 2), landed with task 3.
- **R2 — mypy cold cost (~5 s)** on the first triggering `--impacted` of a
  fresh worktree. Acceptable against the testmon pass (10–25 s); warm runs
  are sub-second. Re-measured in AC15.
- **R3 — translations regeneration mutates the worktree.** Accepted (D6),
  same as the full gate; limited by the trigger.
- **R4 — `main` already red on ruff/mypy** (e.g. after a dependency bump)
  makes every triggering `--impacted` red on unrelated changes. Accepted:
  it matches CI, which would be red too; the output names the gate and the
  rerun command.
- **R5 — tree mismatch.** ruff/mypy read the working tree, as testmon
  already does: with partial staging (a fix left unstaged) `--impacted` can
  be green while the committed tree fails CI, and an untracked scratch
  `.py` under the package can fail locally only. CI also checks the PR's
  merge ref (branch + current `main`), so a branch behind `main` can pass
  locally and fail CI. Accepted, documented; the pipeline's implement
  agents commit whole change sets.
- **R6 — stale venv.** A change set that bumps `ruff==` / `mypy==` in
  `requirements_test.txt` triggers the checks, but they run the installed
  (old) versions. Accepted: reinstall the venv
  (`pip install -r requirements_test.txt`) after a pin bump; out of scope
  to automate.
