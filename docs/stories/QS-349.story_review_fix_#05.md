## Findings to fix

### [should-fix] V1 — Exact-match probe vs device-side step quantization of the non-aligned domain-bound write
- File: `custom_components/quiet_solar/ha_model/battery.py:154-158` (probe comparison), `:251` (landed value)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: The U1/U2 policy correctly writes non-step-aligned values
  at the domain bounds (HA core validates only min/max), but a number
  entity whose backing integration quantizes set values to its
  advertised `step` (Modbus-scaled registers, ESPHome numbers, several
  inverter integrations) echoes the step-aligned neighbor instead.
  Reproduces: F=1100, configured max=1200, entity `{step: 500, max:
  6000}` → green-only writes 1200 (non-aligned) → device stores 1000 →
  probe expects exactly 1200 (int equality at :156), reads 1000, returns
  False every check cycle → eternal relaunch, climbing counter, eventual
  false lost-control episode. Pre-PR the window was any non-aligned
  value; the U1/U2 rework re-opens it specifically at the domain bounds.
- Proposed fix: Do not touch the write policy. In the probe comparison,
  accept a read-back within one entity step (in W, i.e. the converted
  `snap_step_w`) of the expected landed value when a step is present —
  or at minimum when the expected value is a non-aligned domain bound;
  keep exact match when no step is advertised. Test: entity fixture that
  echoes the step-aligned floor of any written value → command confirms
  (no eternal retry); exact-match behaviour preserved for step-less
  entities.

### [nice-to-have] V2 — Direction-aware under-delivery warning tolerance
- File: `custom_components/quiet_solar/ha_model/battery.py:253-260`
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: The U3 warning is silent for shortfalls up to one full
  step in both directions, but on the snap-UP path a landed < request
  can never come from step quantization (ceil only goes up) — it always
  means an external cap is binding, so the tolerance hides a real
  safety-floor shortfall. Reproduces: floor 1100 W, kW entity
  `{step: 0.5, max: 0.8}` → landed 800 W, shortfall 300 W < tol 500 W →
  no warning; the house is silently guaranteed 800 instead of 1100.
- Proposed fix: Make `tol` direction-aware — one step only for the
  direction the snap can legitimately produce (above on snap-up, below
  on snap-down), ~1.0 W for the opposite direction. Test: the 1100/0.8 kW
  shape warns. Keep coherence with V1's new probe tolerance (probe
  tolerance is about device echo; warning tolerance is about
  request-vs-landed divergence — document the distinction in the helper
  docstring if both land).

### [nice-to-have] V3 — Range clamps for capacity / SOC percents
- File: `custom_components/quiet_solar/home_model/battery.py:36-46`
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: U8 coerced `capacity`/SOC percents to finite floats but
  not to sane ranges. `battery_capacity: -7000` (finite) yields negative
  `get_value_full`/`get_value_empty` and inverted solver trajectories;
  `battery_min_charge_percent: 150` (or min > max) makes
  `min_soc > max_soc`, so `get_charger_power`'s headroom math goes
  negative — the exact hand-edited-entry threat model U8 addressed for
  the non-numeric case.
- Proposed fix: Clamp `capacity >= 0`, SOC percents to [0, 100], and
  enforce `min_charge_SOC_percent <= max_charge_SOC_percent` (swap or
  floor-to-min), same one-time-init posture as the floor clamp at
  :66-71. Tests: negative capacity, percent 150, min > max.

### [nice-to-have] V4 — Floor normalization rounds after the clamp (fractional configured max)
- File: `custom_components/quiet_solar/home_model/battery.py:66-71`
- Severity: nice-to-have
- Source: qs-review-blind-hunter (not independently confirmed by the
  repo-aware passes — verify, then fix)
- Description: `float(round(min(max(0.0, cfg), self.max_discharging_power)))`
  rounds after the clamp: with a fractional configured max (e.g. 1499.5)
  a floor >= max rounds to 1500.0, leaving
  `min_discharging_power > max_discharging_power` by < 1 W — a sub-watt
  break of the floor <= max invariant that "floor wins upward" then
  propagates to the write.
- Proposed fix: Re-clamp after rounding (or round the max first), plus a
  fractional-max pinning test (1499.5 → floor lands <= 1499.5-derived
  bound, invariant holds).

### [nice-to-have] V5 — Divergence-warned set: typing, growth, no re-warn
- File: `custom_components/quiet_solar/ha_model/battery.py:59`
- Severity: nice-to-have
- Source: qs-review-blind-hunter
- Description: `self._number_divergence_warned: set[tuple]` is loosely
  annotated (`tuple` = `tuple[Any, ...]`), grows unbounded, and never
  re-warns if a divergence disappears and later recurs.
- Proposed fix: Annotate precisely (e.g.
  `set[tuple[str | None, int, bool]]`) and clear the entry (or the set)
  on a successful probe confirm so a recurring divergence warns again.
