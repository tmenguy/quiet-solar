# QS-423 — Review sessions: stop finished sessions (no dangling processes), plus T13 re-run follow-ups

- Issue: [#423](https://github.com/tmenguy/quiet-solar/issues/423)
- Lane: bug × factory (`target:factory` → `implement-setup-task`)
- Parent epic: [#369](https://github.com/tmenguy/quiet-solar/issues/369) (`docs/epics/QS-369.md`, "#423 becomes high priority, done right after #424")

## Problem

This task covers four follow-ups: items 1–3 come from #421's T13 re-run, item 4 from #424's planning. Item 4 comes first (maintainer, 2026-10-20: no dangling processes).

1. **`auto` is no guard.** `docs/workflow/control-plane.md` presents `REVIEW_PERMISSION_MODE = "auto"` as the fallback if `dontAsk` fails, and says it is "unverified" whether `auto` keeps the guard. The T13 probe ran `reviews.launch_args("auto", …)`, and every one of these ran: writes outside `in/`, `touch /tmp/…`, `snapshot > ~/x`, `; touch`, `$(touch)` and backticks.
2. **The review agents do not state `finding open`'s vocabulary.** Review V3 first sent `severity: high/medium` and `category: integration`, and got 6 `USAGE` errors before it corrected itself. Step 5 of the `review_session` macro (`scripts/qs/agent_templates/_macros.md.j2`) lists the keys but not the values they accept.
3. **Cosmetic:** the stderr tail kept in `reviews.error` can start mid-word (`de\` in …`). The cut is `liveness.bg_failure`'s `output[-budget:]`. `bg_failure` caps its text at `ERROR_MAX`, so the later `[-ERROR_MAX:]` in `reviews.close_locked` never cuts it again.
4. **Review sessions are never stopped.** A review session handles a single turn. Its `claude --bg` process should end with the review, but it never does. Once the review reaches `finished` (the session called `review finish`), or the pilot moves it to `abandoned` / `failed`, the process stays alive, idle and listed `done`. Example: V3 of 2026-10-17 still had a live pid on 2026-10-18. Nothing in `reviews.py` or `reviewpilot.py` calls `claude stop`; `control-plane.md` even says "No `claude stop`" in the pilot's step 2. #424's live checks:
   - L1: a listed `done` is a finished turn of a live process.
   - L1/L2: a live session is listed whether idle or busy.
   - L3/L9: a stopped or killed session leaves the default listing.

## Goal

The review pilot stops a closed review's session on its next tick (`PILOT_EVERY_S` = 30 s), best-effort. This is the accepted reading of the issue's "when the review reaches `finished` / `abandoned` / `failed`". The pilot acts on the state the review reached; nothing stops the session inside the transition itself (see Design 4).

The step keeps the tick-hook contract (`ticks.py`):
- every subprocess has a timeout of at most `HOOK_SUBPROCESS_S` and is followed by a beat;
- work per tick is bounded by a time budget (`HOOK_SUBPROCESS_S`);
- the step runs after the pilot's launches.

Worst case, `stop_closed` takes about 60 s in one tick: a 20 s listing, then stops started within a 20 s budget, the last of which may itself take 20 s. That happens only while closed sessions are listed and `claude stop` is slow. The beats keep the daemon live, and the later hooks of that tick (`hook_route`, …) wait at most that long.

The three smaller items are fixed alongside.

## Design

### 4. Stopping closed review sessions (first)

**Who stops it: the review pilot, not `review finish`.**
- `review finish` runs inside the session's own Bash tool call, so stopping the session there would kill it mid-call.
- The daemon's pilot already lists sessions and owns review liveness, so one mechanism there covers all three terminal states.
- Stopping right after `finish`'s commit is safe: `cli._review_finish` only returns `reviews.finish`'s answer for printing after the commit, and nothing reads it.

**Facts this relies on (verified in the code):**
- `finished_at` is set on every terminal move: `close_locked` sets it for `failed` / `abandoned`, `finish` for `finished`. It is a `clock_mod.iso` string. `clock_mod.stamp(clock, plus=<float seconds>)` is `iso(clock.now() + timedelta(seconds=plus))`, the same fixed-width format, so comparing the two as strings is sound, as in `_launch_move`.
- `launch_name` = `qs-review-<db tag>-<review id>` is unique per review in a DB.
  - A pilot retry (`retry_failed`) creates a **new** review (new id, new name), so the earlier attempt's row stays `failed` and keeps its own name.
  - Only a DB restore that rewinds the id counter could reuse a name, and the session it would then match is a stale one that should be stopped anyway. So name matching needs no `cwd` check.
- A review can end `failed` with `session_id` NULL while its session is alive. Path: `_launch`'s `claude --bg` times out (124) → `_identify` never sees the name under a known listing → `StepFailed` → `_guarded` moves the review to `failed` with no session recorded. The session can appear in the listing later.
- Review sessions are never resumed across reviews.
- `schema_reviews.CLOSED = ("finished", "failed", "abandoned")` exists.
- In production `activeloop.make_seams` always sets `popen=subprocess.Popen`; it is `None` only in tests.
- The daemon's clock is `clock_mod.SystemClock`, whose `now()` reads `datetime.now(UTC)` live, so a time budget measured with `clock.now()` holds in production; in tests the `FakeClock` moves only on `advance()`.
- A review can also end `finished` with `session_id` NULL (`_identify`'s "finished before it was ever listed" branch); the name branch covers it too.

**New constant**, defined in `scripts/qs/control_plane/reviewpilot.py` itself (next to the existing `schema_reviews` import, which gains `CLOSED`; `schema_reviews` is not changed):
- `STOP_WINDOW_S = 7 * 24 * 3600`: how long after `finished_at` a closed review stays a candidate. This bounds the query and the in-memory state.

No count cap: the per-tick time budget (step 5) bounds the work, and fast successful stops should all go out at once.

**New `_State` fields** (all pruned to the window ids at every run; `_reset_for_tests` already rebuilds `_State`):
- `stopped: set[str]`: review ids confirmed gone;
- `attempts: dict[str, int]`: stops sent per review id, used for fair ordering;
- `stop_logged: set[tuple[str, int]]`: `(review id, exit code)` pairs already logged. The log line carries the stderr tail, so `_log_once` (keyed on the full text) cannot dedupe it.

**`liveness.ClaudeCli.stop(agent_id, timeout: float = 30)`**: a new `timeout` keyword.
- Its default keeps `tools._stop_superseded` unchanged.
- It returns a `runner.RunResult`. The runner maps a timeout to 124 and an `OSError` to 127.
- It can still raise for an input the runner does not map (a NUL in the target makes `subprocess.run` raise `ValueError`); `stop_closed` handles any exception (step 5).
- `FakeClaude` inherits `stop`, so in tests the stops land in `FakeRunner.calls` with their `timeout`.

**New step `stop_closed(conn, clock, seams) -> list[str]`**, which returns the review ids it sent a stop to (a test convenience; the hook ignores it). It changes no `reviews` / `alerts` / `messages` row and never calls `db.write`; its only writes are `daemon.beat`'s heartbeats.

1. **Candidates (one read):**
   - The query: `SELECT id, name, session_id, launch_at FROM reviews WHERE state IN <CLOSED> AND launch_at IS NOT NULL AND finished_at >= ? ORDER BY finished_at, id`, with `state IN` built from `CLOSED` and the parameter `clock_mod.stamp(clock, plus=-STOP_WINDOW_S)`.
   - `launch_at IS NOT NULL` keeps only reviews whose `claude --bg` ran.
   - Prune the three `_State` fields to the returned ids. The candidates are the returned rows not in `_state.stopped`.
2. **No candidates:** no listing; return.
3. **Listing:** `listing = seams.claude.try_agents(timeout=ticks.HOOK_SUBPROCESS_S)`, then `daemon.beat(conn, clock)`, whatever the result. If the listing is unknown (`None`), return: nothing is stopped or marked, and the next tick retries.
4. **Match per candidate**, computed for **every** candidate before any stop is sent. The matches are every listed agent with a non-empty target (`a.id or a.session_id`) that either has the row's `session_id` (when the row has one) or has the row's `name` (a full scan). Matching by name as well catches a duplicate fork next to the identified session, as `tools._stop_superseded` stops every same-named launch. Because `launch_name` is unique per review, a name match never hits another review's session.
5. **Stop.** Order the matched candidates with a **stable** `sorted(…, key=lambda r: attempts.get(r["id"], 0))` over the query's `ORDER BY finished_at, id`: fewest attempts first, so candidates that keep failing never starve newer ones. Then, for each match:
   - **When to stop issuing stops:** once `(clock.now() - started).total_seconds() >= ticks.HOOK_SUBPROCESS_S`, where `started = clock.now()` is taken after the listing's beat. The budget limits only the stops; step 6 still checks every candidate.
   - **The call:** `res = seams.claude.stop(found.id or found.session_id, timeout=ticks.HOOK_SUBPROCESS_S)`. **Any exception** it raises becomes `res = RunResult(127, "", str(exc))`, a failed stop (`reviewpilot.py` adds `from .runner import RunResult`). Then `daemon.beat(conn, clock)` and `attempts[rid] += 1`.
   - **A non-ok `res`** is ignored and the candidate stays a candidate. On the first failure with a given exit code (a `(rid, res.returncode)` pair not yet in `stop_logged`), write one stderr line: `[cp-review-pilot] review <rid>: claude stop exited <code>: <liveness.word_tail(res.stderr.strip(), 200)>` (item 3's helper, so this new tail does not start mid-word either).
6. **Done.** A candidate for which step 4 found no match (decided from step 4's matches, never by re-scanning the listing after the stops) is added to `_state.stopped`. A stopped or killed session leaves the default listing (L3/L9), so a review with a `session_id` costs one extra listing after its stop.
   - **Exception:** a candidate without a `session_id` is marked done only once `row["launch_at"] <= clock_mod.stamp(clock, plus=-REQUEST_TTL_S)`. Before that its session may still appear late (exit 124, the launch-settle limit). `REQUEST_TTL_S` (600 s) is the pilot's own upper bound for a launch to be over, far above `nodes.LAUNCH_SETTLE_S`. Such a candidate keeps costing one listing per tick until then (at most about 20 ticks); accepted.
   - A daemon restart starts with an empty `_State` and spends one listing to re-confirm the window's reviews.

The listed `status` / `state` is ignored on purpose. A `finished` review's session may still be writing its last chat message, which nothing uses: the hand-back is in the DB. An `abandoned` one (TTL) may be busy. In both cases the review is closed and its token void, so the session is stopped.

**Hook wiring** (`review_pilot_hook`): `stop_closed(conn, clock, seams)` is called **last**, after `drain`. The `popen is None` early return stays as it is: with no `popen` seam the hook returns before `stop_closed`, which is acceptable because production always sets it. So every hook-level test of the stop (AC6, the activeloop guard test) runs with a `popen` seam set. The module docstring's step list gains "4. **Stop closed review sessions** …".

**Accepted trade-offs:**
- In a tick where one review is open **and** another is closed, the pilot lists twice: once in `close_dead`, once in `stop_closed`. This happens only while candidates exist.
- A review closed more than `STOP_WINDOW_S` ago, while the daemon was down that whole time, is never stopped. This limit is documented.

### 3. A tail that starts on a word boundary (`bg_failure` only)

**`scripts/qs/control_plane/liveness.py`: new `word_tail(text: str, limit: int) -> str`.** It applies these rules in order:

1. `limit <= 0` → `""`.
2. `len(text) <= limit` → `text`.
3. `cut = text[-limit:]`. If the character before the cut is whitespace (the cut fell on a boundary), return `cut.lstrip() or cut` (one expression, no separate branch).
4. Otherwise drop everything up to and including the first whitespace run of `cut`. If what remains is non-empty and not only whitespace, return it.
5. Otherwise (no whitespace, or a partial token followed only by trailing whitespace such as a final `\n`) return the raw `cut`.

The result is always `<= limit`, and never empty when `text` is non-empty and `limit > 0`.

**`bg_failure`:** `tail = word_tail(output, budget)` replaces `output[-budget:] if budget > 0 else ""`, because rule 1 covers `budget <= 0`. Every existing `bg_failure` guarantee holds: the head first, the hint whole, the length `<= limit`. Nodes' `spawn` / `resume` failure text also comes from `bg_failure` and gets the same tail. `reviews.close_locked` is **unchanged**, and so are `control-plane.md`'s "output tail" mentions, which remain accurate.

## Acceptance criteria

AC1–AC5 call `stop_closed` directly. AC6 goes through `review_pilot_hook`, with a `popen` seam set.

1. **AC1 (item 4, finished, over three ticks):** a `finished` review with `launch_at` set, whose session is listed by `session_id` as `agent("S-1", id="short-1")`:
   - tick 1: one listing and exactly one `claude stop short-1` with `timeout == ticks.HOOK_SUBPROCESS_S`;
   - tick 2: the test sets `listing = []`, so one listing, no stop, and `"V1" in reviewpilot._state.stopped`;
   - tick 3: no listing and no stop.
2. **AC2 (item 4, abandoned / failed / name match):**
   - `abandoned` (listed busy) and `failed` with `launch_at` set are stopped the same way.
   - A `failed` review with `session_id` NULL, and likewise a `finished` one (the "finished before it was ever listed" path), is stopped through **every** listed agent of its name (two same-named agents give two stops). A same-named agent with no `id` and an empty `session_id` (`agent("", "n")`) gets no stop and does not raise.
   - A row **with** a `session_id` whose session is listed next to a same-named fork gets two stops. It is marked done only once neither is listed.
   - Such a candidate that is absent on tick 1 and listed on tick 2 is stopped on tick 2 when tick 2 comes before the TTL.
   - TTL boundary: absent with `launch_at` = now − (`REQUEST_TTL_S` − 1), it stays a candidate; absent with `launch_at` = now − `REQUEST_TTL_S`, it is marked done.
3. **AC3 (item 4, no work):** a terminal review with `launch_at` NULL causes no listing and no stop; so does one with `finished_at` just outside `STOP_WINDOW_S`, while one just inside is a candidate. With no candidates at all, `stop_closed` takes no listing.
4. **AC4 (item 4, best-effort):**
   - A `claude stop` exiting non-zero (1, and 124) does not raise; the other candidates are still stopped, and the review is retried next tick.
   - Two failing ticks with the same exit code give exactly one stderr line `review <rid>: claude stop exited <code>: …`; a different code gives a second line.
   - A `fake_runner.on(["claude", "stop"], …)` rule whose callable raises `ValueError("embedded null byte")` counts as a failed stop: it is logged as `review <rid>: claude stop exited 127: embedded null byte`, and `stop_closed` does not raise.
   - An unknown listing (`try_agents` → `None`) stops and marks nothing, and the events are exactly `["list", "beat"]`.
5. **AC5 (item 4, tick-hook contract and fairness):**
   - One shared `events` list records the calls: `monkeypatch.setattr(daemon, "beat", …)` appends `"beat"`, `fake_claude.before_list` appends `"list"`, and a `fake_runner.on(["claude", "stop"], …)` rule appends `"stop"` and removes the stopped agent from `pw["claude"].listing`. With two listed candidates and a budget that is not reached, the test asserts exactly `events == ["list", "beat", "stop", "beat", "stop", "beat"]`.
   - The listing uses `timeout == HOOK_SUBPROCESS_S`.
   - Budget: with three listed candidates, a fourth closed review with a `session_id` that is **not** listed (latest `finished_at`), and a stop rule that advances the fake clock by `HOOK_SUBPROCESS_S`: tick 1 sends exactly one stop, the fourth is in `_state.stopped` after tick 1, and none of the three listed ones is.

- A persisted `stopped_at` column; it would need a schema migration, and the in-memory state plus the window are enough.
- A grace period before stopping a `finished` session (see the review notes).
- `reviews.close_locked`'s error cut, and the `control-plane.md` "output tail" wording.
- Stopping idle **nodes** (6a / 7's job), and the orchestrator-lease side of `done`.
- Removing `auto` from `launch_args`.
