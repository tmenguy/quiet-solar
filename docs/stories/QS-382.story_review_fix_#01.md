Three maintainer decisions taken during triage apply across findings:

- **D1 — Unproven halves are handed to a child.** Where a mechanism's
  success condition was only half exercised (#1, #6), the record names the
  child that inherits the proof (the child owning the run / orchestrator
  lifecycle — child 5 "a run as the unit" and/or child 6 "start-up resumes
  or opens a run"; check the decomposition table and pick the one whose
  scope matches) and says that child **may ask the maintainer for a live
  try** if it needs one.
- **D2 — Permission-mode hold is conditional, not a manual round.**
  Delivery works when orchestrator and node share a permission mode. A
  human approval is needed **only** to reach a node that was escalated to
  `bypassPermissions` — a situation the orchestrator can detect because it
  did the escalating. Record it that way (tag stays `none` for the normal
  case) and state the design hint: **the state DB records each node's
  permission mode** so a restarted orchestrator knows which nodes need the
  human step (or avoids it).
- **D3 — State DB stores node identity in full.** Per node: **name + full
  session id + short id**. Stated as a hard requirement for the child owning
  the state DB (child 5), not a hint.
- **D4 — Discovered tasks: the maintainer decides.** The orchestrator
  collects discovered / follow-up tasks and presents the now / later / drop
  choice to the maintainer. Autonomy may be revisited later if it happens
  too often.

Preserve the epic's conventions: every statement carries its provenance
(maintainer vs assistant, dated); the `## Decomposition` table is parsed by
