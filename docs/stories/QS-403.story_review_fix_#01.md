## Findings to fix

### [should-fix] EC-1 — `current_charge is None` bypasses the guard: the callback still completes the constraint
- File: `custom_components/quiet_solar/ha_model/charger.py` (`is_car_charged` guard; callback `constraint_update_value_callback_soc`)
- When the command is idle/off, the callback passes `result=None`. `is_car_charged` then forces `result = target_charge`, and the callback tests `ct.is_constraint_met(result)` → COMPLETED. This is the same symptom through a sibling path, and it breaks the maintainer's objective.
- The person path is NOT affected: with `None`, `is_car_charged` already returns `(False, …)`.
- Fix: when `current_charge is None`, the guard reads the raw SOC sensor (`self.car.get_car_charge_percent_raw_sensor(time)`) to decide. If it is trusted and far below target, skip the force: `result` stays `None` and the constraint continues.
- Red test: `test_soc_callback_idle_command_does_not_complete_when_car_stops_at_51`.
