# QS-440 — The node's catch-up as a tested Control Plane command: the prose state machine moves into Python

Issue: [#440](https://github.com/tmenguy/quiet-solar/issues/440) · Parent epic: #369 (wave 5) ·
Lane: feature-factory · Target: factory. Runs right after #425 (merged, PR #435, `3f854655`) and
before #437, so #437's live check exercises the catch-up as it will stay.

## Problem

The node's catch-up with `main` is a state machine written as prose in
`scripts/qs/agent_templates/qs-node.md.j2`: build step 7 (items 1–7), start-up rule 5 (four
ordered resume cases), the `catchup` / `base_merge` fields of `round.json`, step 6's routing to
step 7 / step 8, step 8's resume, the `catchups` clause of "Blocking" and the pending-fix clauses
of "The `fix` protocol". The node can be reaped between any two side effects (the counter, the
fetch, the merge, the record, the gate, the resolution review, the push, the `round.json`
writes) and each resume re-derives from prose what was already done.

PR #435 needed review fix plans #06–#11 for this section alone; each round found one more
reap/resume path, each fix added clauses, each clause opened paths. Nothing executes them: the
tests in `tests/qs/test_render_agents.py` only pin wording (~25 tests, lines ~1395–1870).

## Goal

The catch-up's **decisions and git effects** live in one tested Python module of the Control
Plane, `scripts/qs/control_plane/catchup.py`, reached as `cp.py catchup <op>`. The node calls it
at each decision point and does what it answers; the template keeps "call it, do what it says,
report the outcome". The LLM work stays the node's and its sub-agents': resolving conflicts, the
gate and fixes (`qs-node-implementer`), the resolution review (`qs-node-edge-case`), triage,
`tool push`, reports.

**Rollout assumption.** No node has run live yet (#437 is the first live check), so no
`round.json` of the old shape exists anywhere: there is no migration path.

## Design

### D1 — A command group, not a keyed tool

`cp.py tool <name>` runs through `run_recorded`: a finished key **replays its recorded result**
(`docs/workflow/control-plane.md` "Tools"). A catch-up call is a state-machine step whose answer
must reflect what changed since the last call (a reap, a commit, a push), so a recorded replay is
the wrong primitive; a per-call key suffix would make every call a fresh claim, keep none of
`run_recorded`'s value and add a `tool_calls` row per decision. The catch-up is a new
**write-kind command group** `cp.py catchup <op> --task T --token TOKEN`, registered in `cli.py`'s
command table like `round start`.

- **Handlers**: `_write(io, catchup.<op>, io.deps.runner, io.deps.clock, token=…, task_id=…, …)`.
  `_write` (`cli.py:494`) only opens the connection (after `connection(io, "write")`'s schema
  check); `catchup.py` opens its own short `db.write` transactions and plain reads; **no DB
  transaction is held across a git call**. Signatures: `step(conn, run: runner.Runner, clock, *,
  token, task_id, trigger_from, seq, head, implemented, inv, reviewed) -> dict`;
  `base`, `fixes`, `done`, `unblock` take `(conn, run, clock, *, token, task_id)`. The `clock`
  stamps `block.at` (`db.now(clock)`); the deadline has its own seam (below).
- **Arguments**: `--from` (`dest="trigger_from"`, `choices=("conflict", "done")`); `--seq`
  (`type=cli._sql_id`); `--head` / `--reviewed` a **full lowercase** sha (`[0-9a-f]{40}` or
  `[0-9a-f]{64}`, its own regex — `gitread.SHA_RE` accepts abbreviations —, `USAGE` otherwise: an
  abbreviation would never compare equal to `HEAD`); `--implemented` (`choices=("green", "red")`)
  **requires** `--inv` (`type=cli._sql_id`: the node's `inv` of that implementer invocation, the
  report's identity); `--inv` without `--implemented` is `USAGE`. (No gate key: it decides
  nothing; the node names it in its own `blocked` summary.)
- **The op deadline**: `CATCHUP_OP_DEADLINE_S` = 300 from the handler's entry (before item 1
  below, so the bound holds even when the token `db.write` waits), measured with
  `time.monotonic` through a module-level seam `catchup._monotonic = time.monotonic` (tests patch
  `catchup._monotonic`, never `time.monotonic`, so `db.file_lock`'s own spin is untouched; `db.file_lock`
  is the precedent for a direct monotonic read; a wall-clock jump neither fails nor
  extends an op). Each git call's timeout is min(`CATCHUP_GIT_TIMEOUT_S`, the time left); no time
  left — or, before a `git fetch` / `git merge`, less than `CATCHUP_MIN_LEFT_S` = 60 s left (a merge
  killed midway can leave an `index.lock`) — → `TOOL_FAILED` ("op deadline"), not started, nothing
  more written. So the deadline is the lock's real
  upper bound: an orphaned op releases it within the node's `BUSY` budget (6 × 60 s, D7) and well
  inside the 600 s Bash timeout.
- **Order inside every op** (no runner call before item 3 — the `test_cli_wide.py` sweeps assert
  it):
  1. `tokens.require(conn, token, kinds={"run", "node"}, task_id=T)` and the task row, in one
     `db.write`: `STALE_TOKEN` / `STOPPED` / `CONFLICT` as for every node write, for **every**
     op, the read-only ones included; terminal (`tasks.TERMINAL`) → `INVALID_STATE`; a work item
     → `INVALID_STATE` (`tools._not_an_item`); `worktree` / `branch` NULL → `INVALID_STATE`
     (`tools._need`).
  2. `Path(worktree).is_dir()` else `INVALID_STATE`; `(worktree / ".qs-node").mkdir(exist_ok=True)`
     (no `parents`: a stale path never grows a tree); then `db.file_lock(<worktree>/.qs-node/
     catchup.lock, exclusive=True, timeout=0)` held for the whole op, git included; not obtained
     → `CpError("BUSY")` (exit 6; `file_lock` yields `False`, never raises).
  3. Step 0 of D4 (`catchup step` only), then the op.
- **Why the lock** (kept against round 2's scope note): the token re-check stops a *superseded*
  generation, not two calls of the *same* one — a call whose Bash was killed while its Python
  runs on, then the node's retry — and both could count or merge; git's `index.lock` does not
  cover `catchup.json`.
- **Token re-check**: right before each `catchup.json` write, a short `db.write` re-runs
  `tokens.require`, so a generation superseded mid-call writes nothing (`STALE_TOKEN`).
- **Answers**: every op prints one JSON object — `{"ok": true, "next": <verb>, …}`, `{"ok": true,
  "base": …}` or `{"ok": true, "unblocked": …}` — or the `CpError` payload `{"ok": false, "error":
  <code>, "detail": …}` (`errors.py`).

### D2 — Who owns which state

Two writers of one file (`round.json`, which the node rewrites whole from its context at every
step) would lose updates, so the catch-up state moves to its own file. No other code reads
`round.json` / `pending.json` / `base_merge` (only the template and its render pins).

- **`.qs-node/catchup.json`** — new, owned by Python, **never written by the node** (a template
  rule). `.qs-node/` is gitignored (`tests/qs/test_gitignore_node_dir.py`), so the implementer's
  commits cannot carry it. Written atomically: a temp file from `tempfile.mkstemp(dir=.qs-node,
  prefix=".catchup.json.", suffix=".tmp")` (unlike a fixed `.partial`, a SIGKILL leftover never
  collides), then `backups.py`'s fsync → `os.replace` → best-effort directory fsync sequence
  (`backups._fsync` imported); an `OSError` → `TOOL_FAILED`, the temp file unlinked, the old
  file intact. Shape:

  ```json
  {"version": 1, "catchups": 0, "max_seq": 0, "catchup": null, "base_merge": null,
   "last": null, "done_report": null}
  ```

  - `catchups` — catch-ups counted since the last `done` or the unblock of a `catchups` block.
  - `max_seq` — the highest trigger `seq` seen (D2's trigger rule).
  - `catchup` — the catch-up in progress, or `null`:
    `{"from": "conflict"|"done", "trigger": {"from", "seq", "head"}, "head": <sha>, "counted": bool, "merge": <sha>|null,
    "clean": bool|null, "green": <sha>|null, "reviewed": <sha>|null, "misses": [<kind>, …],
    "intake": [<inv>, …], "block": null|{"cause": "catchups"|"misses", "detail", "at"}}` —
    `from` is the catch-up's **own decision field, pinned at creation** (3b's stale / done
    branch and the pre-check read it); `trigger` is the `round.json` trigger it answers to, which
    the adopt rule re-binds **whole** to the call's, so `last.trigger` always equals what
    `round.json` holds;
    `head` the pushed head it started from; `green` the `HEAD` a green gate was reported on;
    `reviewed` the `HEAD` the resolution review covered; `misses` the kinds (`"merge not
    committed"`, `"gate red"`) reported since its start or the last `misses` unblock, at most 2;
    `intake` the `inv` of every report taken in (a retried call reuses its `inv`, a new
    implementer invocation always has a new one — so two keyless reports at an unchanged `HEAD`
    are still two misses); `block` the sticky block, replayed until unblocked.
  - `base_merge` — `null` or `{"merge": <sha>, "head": <sha>}`: the merge commit of the last
    pushed catch-up and the head that push made. **Consumed** when the ledger holds a `build`
    round of the task whose `base_sha` equals `base_merge.merge` (the `rounds` table: no write, no
    reap window). It survives `done`, a stale conflict and a rotation (the file is the
    worktree's, not the generation's).
  - `last` — `{"trigger", "kind": "wait"|"done"|"fixes", "answer": <the wait answer>|null}`: how
    the last catch-up ended. A `wait` is replayed verbatim (a stale wait leaves no trace in the
    repository; a pushed one must be replayed with the head it pushed); a `done` / `fixes` is
    recomputed by step 5 only (never the bound, never a merge).
  - `done_report` — `null` until step 5's first `done` write, then the highest `reports.id` of
    the task at that write (`0` when it has none); validated as `None | int ≥ 0`; D6 counts only a report with a higher id (ids are monotonic: no clock ties, no
    wall-clock steps back).
  - A missing file is the empty state above (a missing file while a catch-up was under way is
    caught by D4 step 2's start guards). An unparseable file, another `version`, or a field of the
    wrong type (one validation function, one branch) → `INVALID_STATE`: the node blocks `error`,
    and the maintainer repairs or deletes the file (`control-plane.md` says so); Python never
    silently resets a counter.
- **`round.json`** (the node's): its `catchup` field shrinks to the **trigger** `{"from", "seq",
  "head"}` or `null`; a new counter `triggers` (never reset). Before its first call of a
  catch-up, the node writes, in one write, `step: catchup`, `triggers` + 1 and `catchup` =
  `{"from": <the trigger>, "seq": <the new triggers>, "head": <round.json's head>}`. **The trigger
  is never rewritten on a resume.** `catchups`, `base_merge` and the old `catchup` object leave
  `round.json`.
- **`pending.json`** stays the node's (it appends acked `fix` payloads and rewrites the file).
  Python only **reads** it: a JSON list of objects, each with an integer `finding_id` (a `bool`
  refused) and `level` ∈ `code` / `plan`; **other keys allowed** (`what`, …); anything else →
  `INVALID_STATE`, the same for every op that reads it. Missing → empty. An entry is **open** when
  its `finding_id` is a finding of this task whose `state` is `open` (a direct `SELECT id, state
  FROM findings WHERE task_id = ? AND id IN (…)`); an unknown id, another
  task's, or a closed one is **dropped**. De-duplicated by `finding_id` (first kept). Answers
  carry whole entries.

**The trigger makes every call replayable.** Each `catchup step` carries `round.json`'s trigger;
two triggers are equal when `from`, `seq` and `head` all are. A reap after the node's trigger
write and before the call, or after the call and before the node acts on its answer, re-issues
the same call: the resume is "re-run the call in `round.json`". The cases:

| `catchup` in progress | call's trigger | outcome |
|---|---|---|
| yes | equal to `catchup.trigger` | continues |
| yes | another, `seq` > `catchup.trigger.seq` | **adopted**: one write (fault `catchup.after_adopt`), `catchup.trigger` = the call's (whole), `catchup.from` kept; never a second count, never a second merge; done even when `block` is set |
| yes | another, `seq` ≤ `catchup.trigger.seq` | `INVALID_STATE` ("a trigger older than the catch-up in progress"; an equal `seq` with another `from` / `head` can only be a corrupt `round.json`: each trigger write increments `triggers`) |
| no | equal to `last.trigger` | `last`: a `wait` replayed; a `done` / `fixes` recomputed by step 5 |
| no | `seq` ≤ `max_seq`, not `last`'s | `INVALID_STATE` ("a trigger older than the last one": a lost or regressed `round.json`) |
| no | `seq` > `max_seq` | a new catch-up (D4 step 2) |

The adopt rule closes every path where the node's `round.json` lost or replaced the trigger
mid-catch-up: the catch-up in progress always finishes first, under the `from` it was started
with, and its final answer is stored under the trigger `round.json` now holds (so a reap after it
replays). `(from, head)` alone cannot identify a trigger: a stale conflict at head H followed by a
real conflict at the same H must be two catch-ups; hence `seq`.

### D3 — The ops and the answers

| op | arguments | answers |
|---|---|---|
| `catchup step` | `--from conflict\|done --seq N --head SHA [--implemented green\|red --inv I] [--reviewed SHA]` | `implement`, `review`, `push`, `wait`, `fixes`, `done`, `blocked` |
| `catchup base` | — | `{"base": <sha>\|null}` (D5) |
| `catchup fixes` | — | `fixes` (D5) |
| `catchup done` | — | step 8's resume: `done` or `fixes` (D6) |
| `catchup unblock` | — | `{"unblocked": <cause>\|null}` (D4 step 1) |

`--implemented` reports that the implementer returned (its gate verdict, with its `inv`); `--reviewed
SHA` that the resolution review of `SHA` and its triage are done. Both are **reports**, given
only on the call right after an `implement` / `review` answer. A **retry** of that call (after
`TOOL_FAILED` or `BUSY`) repeats it exactly, reports included (intake is idempotent); a
**resume** after a reap re-runs the trigger flags only, and Python decides from the repository
and the file. A report on a call with no catch-up in progress (it starts a new one, or replays /
recomputes `last`) is ignored. `--head` initialises
`catchup.head` and is part of the trigger.

**The answer vocabulary** (closed; one verb, one action; the payloads carry no instruction text):

| `next` | fields | the node does |
|---|---|---|
| `implement` | `mode` ∈ `gate` \| `resolve` \| `finish`; `fixes` (the open code-level `pending.json` entries) | `inv` + 1, `qs-node-implementer` with the mode's existing instruction — `gate` → "gate only; fix on top of the merge if red", `resolve` → "resolve the merge conflicts" (with both sides' intents: the contract and `git log HEAD..origin/main`, as today), `finish` → "finish the open merge" — and the fixes; resolve its `fixed` findings after its commit; then the call plus `--implemented <gate> --inv <inv>` — `inv` is `round.json`'s counter, written (+ 1) **before** the launch and never reset in the worktree, so a new invocation never reuses a reported `inv`; a `{"stopped": true}` return → "Stop", no report call |
| `review` | `head`, `diffs` (a list of command strings, each a `git show --remerge-diff …` or `git diff …`) | `qs-node-edge-case` on them, its findings on the latest build round (no `round start`), triage; then the call plus `--reviewed <head>` |
| `push` | `head` | `tool push` under build step 2's key rule (`task:<T>:push:<head>:a<attempt>`, the attempt from `round.json`'s `attempts`); then the call. A failed push follows the node's error rule (one retry under the next attempt, then blocked `error`) |
| `wait` | `head`, `catchup_head` (bool) | one `round.json` write: `catchup` = `null`, `step: wait`; with `catchup_head` also `head`, `pushed_at` = `wait_from` = now, and a `cr: trigger` → `cr: skipped` ("head moved"); without it (a stale conflict) `head`, `pushed_at` and `wait_from` are kept. No CodeRabbit request is made for a catch-up head. Then the wait loop |
| `fixes` | `open` (entries), `drop` (finding ids) | the `drop` entries leave `pending.json`; the `fix` protocol on `open` (`catchup` = `null` in that write) |
| `done` | `left` (in order, a subset of `digest`, `report`, `state`), `objections` (entries), `drop` | `catchup` = `null` and `step: done` in one write, then each item of `left`; each `objections` entry → "a `fix` after done"; the `drop` entries leave `pending.json` |
| `blocked` | `cause` ∈ `catchups` \| `misses` \| `error`; `detail` | "Blocking" with that cause, the detail in the summary |

A resolution review's accepted findings are not fixed inside the catch-up: they stay open in the
build phase, the catch-up head is pushed, and after its wait step 6 sees them in
`convergence.build.blocking` → the next build round (`--base` from `catchup base`). The node
calls `catchup step --from done` only when nothing blocks (step 6), so a task never reaches done
with an open resolution-review finding, and the review cannot loop inside a catch-up. A fix
already on `HEAD` after a reap (the implementer committed it, the node had not resolved it) is
handed out again: the implementer reads the code before changing it, so it is a no-op it reports
`fixed`.

### D4 — The decision procedure (`catchup step`)

**Persist before answer**: every state change is written (and the token re-checked) before the
answer that depends on it is printed. Every git effect is either observable afterwards
(`MERGE_HEAD`, the merge lookup, the remote branch) or preceded by a write.

**Git**: one helper in `reviews._Git`'s pattern — the `runner` seam, `cwd` = `task.worktree`, a
timeout per call (`CATCHUP_GIT_TIMEOUT_S` = 120), `env_remove` = `gitread.ENV_REMOVED` (the
inherited repository-location variables only, so the node's `GIT_SSH_COMMAND` / `GIT_ASKPASS` /
config variables still apply to `fetch` and `ls-remote`), `env_extra` = `{"GIT_TERMINAL_PROMPT":
"0"}` (a credential prompt fails fast). A failure raises `CpError("TOOL_FAILED", <cmd>,
tail=tools.tail(res))` (never `tools.StepFailed`: this is not a tool step). Exit codes:

| command | meaning exits | anything else (124 included) |
|---|---|---|
| `git symbolic-ref --short HEAD` | 0 (the branch); 1 / 128 → `INVALID_STATE` ("detached or not on the branch") | `TOOL_FAILED` (124, 127, …) |
| `git rev-parse HEAD` / `<sha>^1` / `^2` | 0 | `TOOL_FAILED` |
| `git rev-parse -q --verify MERGE_HEAD` | 0 open, 1 not open | `TOOL_FAILED` |
| `git cat-file -e <sha>^{commit}` | 0 known locally, non-zero (not 124 / 127) unknown | `TOOL_FAILED` |
| `git merge-base --is-ancestor A B` (both known) | 0 yes, 1 no | `TOOL_FAILED` |
| `git fetch origin main` | 0; a ref-lock stderr (`cannot lock ref`, `Unable to create '…lock'`) → `BUSY` (the shared ref store is contended: the node's `catchup` `BUSY` rule absorbs it) | `TOOL_FAILED` |
| `git ls-remote origin refs/heads/<branch>` | 0 (empty output: no remote branch) | `TOOL_FAILED` |
| `git log -1 --first-parent --merges --format=%H A..HEAD` | 0 (empty: none) | `TOOL_FAILED` |
| `git merge --no-ff --no-edit origin/main` | 0 clean; non-zero with `MERGE_HEAD` open: conflicts | `TOOL_FAILED` (a dirty tree the merge touches, a lock), nothing written |

No retry loop and no sleep inside Python: a `TOOL_FAILED` falls under the node's generic rule
(retry the same call once, then blocked `error`), and a retry is safe (intake is idempotent). The
merge runs the repository's own merge hooks (the Control Plane installs none: its hook is
`pre-push`). A `catchup step` can run several git calls, so the template makes it a long call
("Long calls": the Bash `timeout` 600000); a Bash kill is one more reap, which the procedure
absorbs.

Notation: `remote` = the `ls-remote` sha (or none); "pushed" = `remote` = `HEAD`; "remote ahead" =
`remote` set, ≠ `HEAD`, and either unknown locally (`cat-file -e` fails: Python never fetches the
task branch, so a GitHub "Update branch" or a bot commit is not in the object store, and an
unknown commit cannot be an ancestor of `HEAD`) or known and not an ancestor of `HEAD`.

0. **Preconditions** (`catchup step` only): `git symbolic-ref --short HEAD` = `task.branch`, else
   `INVALID_STATE`.
1. **The trigger rule** (D2's table), then, with a catch-up in progress:
   - `catchup.block` set → answer `blocked` with the recorded cause and detail, whatever the
     report (until `catchup unblock`).
   - `--implemented`: its `--inv` = the last of `intake` → the report is ignored (a retried call
     never counts twice); an `--inv` already in `intake` but not its last, or not in it and ≤
     max(`intake`), is impossible in normal running (`inv` only grows, a retry repeats the latest
     report) → `INVALID_STATE` ("inv regressed": a lost `round.json`), so a regressed counter can
     never silently drop misses. Otherwise, when `merge` is `null`,
     the merge lookup of step 3c runs first; a foreign merge there → `blocked(error)`, nothing
     written. Then a miss is counted when the lookup found nothing (`"merge not committed"`,
     whatever `MERGE_HEAD` says) or the gate is `red` (`"gate red"`), at most one per report
     (both at once → `"merge not committed"`); a
     `green` gate with `merge` set (by now) records `green` = `HEAD`. **One write**: the lookup's
     merge record if any, `misses`, `green`, the `inv` appended to `intake` (fault
     `catchup.after_intake`). `misses` reaching 2 → in that write `block` = `{"cause": "misses",
     "detail": "<kind 1>, then <kind 2>", "at"}`; answer
     `blocked(misses)`.
   - `--reviewed SHA`: `SHA` = `HEAD` → one write, `reviewed` = `SHA` (fault
     `catchup.after_reviewed`); otherwise ignored.
   - **`catchup unblock`** (its own op, under the same lock): `block.cause` `catchups` →
     `catchups` = 0, `counted` stays false (the next call re-runs step 2); `misses` → `misses` =
     `[]`; `block` = `null`; one write (fault `catchup.after_unblock`). No catch-up or no block →
     `{"unblocked": null}`, no write.
2. **A new catch-up, or a catch-up with `counted: false`** (that one always re-runs this step):
   - **start guards** (on every count — a new catch-up and a `counted: false` re-run alike):
     `MERGE_HEAD` open → `blocked(error, "a merge is open outside a catch-up")`; `HEAD` ≠ the
     call's `--head` → `blocked(error, "HEAD is not the pushed head")`. Neither counts nor
     writes.
   - **pre-check** (`from: done` only — the call's `from` for a new catch-up, `catchup.from` for
     a re-run): `last` is a pushed `wait` (`catchup_head: true`) whose `head` = `HEAD`, **and**
     `base_merge` unconsumed with `base_merge.head` = `HEAD` (the catch-up just before this one,
     whose own wait ended green, with no build round started since — a round that added no
     commit would otherwise leave `HEAD` = `last.head`) → step 5 without a fetch; otherwise `git fetch origin main` (fault
     `catchup.after_fetch_precheck`), and `origin/main` an ancestor of `HEAD` → step 5. Neither
     counts.
   - **the bound**: `catchups` ≥ `node_policy.MAX_CATCHUPS` (3) → one write, `catchup` with
     `counted: false`, `head` = `--head`, `block` = `{"cause": "catchups", …}` (fault
     `catchup.after_bound`); answer `blocked(catchups)`, no merge. Else one write: `catchups` +
     1, `max_seq` = max(`max_seq`, `seq`), and `catchup` = a fresh one (`from` and `trigger` =
     the call's) for a new catch-up, or — a `counted: false` re-run — the same `catchup.from`
     and `catchup.trigger` with `counted: true`, `head` = `--head` and every other field
     emptied (fault `catchup.after_count`). **Every write that records a trigger** (in `catchup` or in
     `last`: the bound, the count, the adopt, the stale, the push, step 5's writes) also sets
     `max_seq` = max(`max_seq`, its `seq`); a guard's `blocked` writes nothing, so a retried call
     with the same `seq` meets the same guard.
3. **The merge** (catch-up in progress, `merge` `null`):
   - a. `MERGE_HEAD` open → `implement`, mode `resolve` while `misses` is empty, `finish` after a
     miss.
   - b. `HEAD` = `catchup.head` → `git fetch origin main` unless this call already fetched
     (fault `catchup.after_fetch_merge`); `origin/main` an ancestor of `HEAD` → `catchup.from`
     `conflict`: **stale** — one write, `catchup` = `null`, `last` = `{trigger, "wait",
     wait(catchup_head: false, head: HEAD)}`; `base_merge` untouched (fault
     `catchup.after_stale`); answer it — `from` `done` → step 5. Otherwise `git merge --no-ff
     --no-edit origin/main` (fault `catchup.after_merge`): exit 0 → one write, `merge` = `HEAD`,
     `clean` = true (fault `catchup.after_record`), then step 4 (which answers `implement`
     `gate`); conflicts → one write, `clean` = false (fault `catchup.after_conflict_record`), then
     3a's rule (`resolve` while `misses` is empty, `finish` after a miss), so the first answer and
     a replay's agree.
   - c. `HEAD` ≠ `catchup.head` → the lookup `git log -1 --first-parent --merges --format=%H
     <catchup.head>..HEAD`: found, and its second parent an ancestor of `origin/main` → one write,
     `merge` = it, `clean` = false (unknown, so reviewed) (fault `catchup.after_lookup_record`);
     found with a foreign second parent → `blocked(error, "a merge that is not origin/main's")`;
     empty, no `MERGE_HEAD` → `blocked(error, "HEAD moved without a merge")`.
   - An aborted merge (`git merge --abort`: `HEAD` = `catchup.head`, no `MERGE_HEAD`) after an
     `--implemented` report has counted its miss in step 1, so 3b merges again once; the second
     miss blocks. A resume without a report never counts.
4. **After the merge** (`merge` set), the first that holds:
   - `MERGE_HEAD` open → `blocked(error, "a second merge is open")`.
   - `merge` not an ancestor of `HEAD` (a `reset --hard`, a rebase) → `blocked(error, "the
     catch-up merge is no longer in HEAD")`.
   - `green` ≠ `HEAD` → `implement` mode `gate` (the open code-level fixes). Re-running a gate is
     always safe.
   - review needed — `clean` is false, or `HEAD` ≠ `merge`, or `merge^1` ≠ `catchup.head` — and
     `reviewed` ≠ `HEAD` → `review`, `diffs`: `git show --remerge-diff <merge>`; `git diff
     <head>..<merge>^1` when `merge^1` ≠ `catchup.head`; `git diff <merge>..HEAD` when `HEAD` ≠
     `merge`. (Python never runs them; the node and `qs-node-edge-case` do, as today.)
   - remote ahead → `blocked(error, "the remote branch is ahead of HEAD")`; not pushed → `push`
     (`head` = `HEAD`).
   - else the **push write**, one write: `base_merge` = `{merge, head: HEAD}`, `catchup` =
     `null`, `last` = `{trigger, "wait", wait(catchup_head: true, head: HEAD)}`; `catchups` kept
     (fault `catchup.after_push_write`). Answer it.
5. **Done checks** (from step 2's pre-check, 3b's `done` ancestor, or a replayed `done` /
   `fixes`; a catch-up still in progress here — an uncounted one, or a counted one whose fetch
   found nothing to merge — is ended by this step's write): remote ahead → `blocked(error, "the
   remote branch is ahead of HEAD")`; not pushed → `blocked(error, "HEAD is not pushed")`; no
   write either way. Here `trigger` is the catch-up's, or the call's when none is in progress.
   `pending.json` read against the ledger (D2): open entries → one write,
   `catchup` = `null`, `last` = `{trigger, "fixes", null}`, `catchups` kept (fault
   `catchup.after_fixes_write`); answer `fixes`. None → one write, `catchups` = 0, `catchup` =
   `null`, `last` = `{trigger, "done", null}`, `done_report` = the task's highest `reports.id`
   (fault `catchup.after_done_write`);
   answer `done` with `left` = `[digest, report, state]`, `objections` = `[]`, `drop` = the
   dropped ids. `base_merge` is kept (a fix sent back after done still has its `--base`).

**Fault points** (`faults.hit`, the existing crash seam: `FaultInjected` is a `BaseException`, so
it passes `cli.main`'s `except Exception`, the lock's `with` unwinds, and a test re-issues the
call in-process). One per write or git effect site, each name used at exactly one site:
`catchup.after_adopt`, `after_intake`, `after_reviewed`, `after_unblock`, `after_bound`,
`after_count`, `after_fetch_precheck`, `after_fetch_merge`, `after_stale`, `after_merge`,
`after_record`, `after_conflict_record`, `after_lookup_record`, `after_push_write`,
`after_fixes_write`, `after_done_write` — the `FAULTS` tuple of `catchup.py`. Every site is
`faults.hit("catchup.<name>")` with a **string literal** (no f-string, no constant). A meta-test
checks `FAULTS` = the names the tests arm = the literals of the `faults.hit(...)` calls in the
source (read with `ast`). The atomic save itself is unit-tested apart (a crash before `os.replace` leaves the old
file intact).

**Node-side reap points** (between the node's own effects and the next call) are tested as
re-issued calls: the trigger write → the call (`test_reap_after_trigger_write`); the implementer's
commit → its report (AC4.8); the report call → the node acting on its answer (each answer
replayed by a re-issued call); `tool push` → the next call (`test_reap_after_push_before_call`);
the `wait` answer → the node's `round.json` write (`test_reap_after_push_before_wait_write`); the
`done` answer → `step: done` (`test_reap_after_done_answer`, main moved meanwhile: the replay
recomputes step 5, no count, no merge).

### D5 — `catchup fixes` and `catchup base`

`catchup fixes` is step 6's pending-fix check: `{"next": "fixes", "open": […], "drop": […]}` per
D2's rule (`open` empty means "no fix"); read-only, so allowed at any time, a catch-up in progress
included. `catchup base` → `base_merge.merge` while it is
unconsumed and an ancestor of `HEAD`, else `null` (a reap after `round start --base M`: the
round is visible in the ledger, and the template's existing rule — a round the Control Plane shows
is never started again — keeps step 2's resume from calling `catchup base` / `round start`
again); `INVALID_STATE` while `MERGE_HEAD` is open or a
catch-up with a recorded merge is in progress (a build round never starts over an unpushed
catch-up merge). Neither op writes.

### D6 — `catchup done`: step 8's resume (read-only)

At `step: done` the node calls `catchup done` instead of re-deriving the rule from prose. A
catch-up in progress → `INVALID_STATE`. Otherwise Python reads, in one `db.read`, the latest
report of the latest build round (`ledger.latest_round`, then `SELECT id, status FROM reports WHERE
task_id = ? AND phase = 'build' AND round = ? ORDER BY id DESC LIMIT 1` — the rule
`ledger.convergence` applies: a later `blocked` supersedes a `converged`; `convergence` itself
returns no id and stays as it is), the task state and `pending.json`. The report counts as
**converged for this done** only when its status is `converged` and its `id` > `done_report` (a
done after a post-done catch-up opens no build round, so an older round's `converged` must not
count); `done_report` `null` (no done recorded) → not converged. Step 8's `report` is posted on
the latest build round (as today), so it is the report this reads:

- converged → `done` with `left` = `[state]` (or `[]` when the task is already
  `ready_to_merge`), `objections` = the open entries (the node posts one objection each, leaves
  the finding open and drops the entry: "a `fix` after done"), `drop` = the dropped ids;
- not converged, an open entry → `fixes` (the same action as everywhere: the fix protocol);
- not converged, none open → `done` with `left` = `[digest, report, state]` (`digest put`
  replaces: a second put after a reap is harmless).

## Post-review changes (fix plans #01–#02)

The reviewed text above is kept as shipped at v6; these rules supersede it where they differ.
`docs/workflow/control-plane.md` ("The catch-up (#440)") is the current reference.

**Fix plan #01** (PR review round 1):

- **D2 `misses` kinds**: a third kind, `"changes not committed"` — a green gate over tracked
  changes left uncommitted (a commit hook refused the commit) records no `green`; a tree dirtied
  after the green gate answers `implement` `gate` again, never `push`.
- **A killed merge** (the runner's exit 124 / 127) is `TOOL_FAILED`, never read as conflicts, even
  when it left `MERGE_HEAD`; an open merge with `.git/index.lock` present → `error` "a stale
  index.lock".
- **D4 step 5, a replayed `done`**: a re-issued `step` on the trigger whose `last` is `done` is
  recomputed read-only by D6's rule (`done_report` and `catchups` never move again) instead of
  re-running step 5's writes. AC3's `test_reap_after_done_answer` therefore asserts the replay's
  `done`, not a recomputed step 5.
- **D6**: a task already `ready_to_merge` is never asked for `state`; with `done_report` `null` (a
  deleted `catchup.json`) the latest build round's `converged` counts; a later `blocked` report on
  that round supersedes the converged one, so the `report` is asked again (`[digest, report]` for
  a `ready_to_merge` task). `done_report` is the latest **build** round's highest report id.
- Commit probes: `git cat-file -e` is "missing" only on exit 1 or 128 "Not a valid object name";
  `symbolic-ref -q HEAD` is the branch check; git output is decoded with `surrogateescape`.

**Fix plan #02** (PR review round 2):

- **`catchup end`** (a sixth op, fault `catchup.after_end`): at an `error` block's re-entry whose
  repair moved and pushed `HEAD`, the node calls it before dropping its trigger. It clears the
  catch-up in progress, records `base_merge` = `{merge, head: HEAD}` when the recorded merge is in
  `HEAD` and pushed, and stores `last` = the `wait` at `HEAD` under the ended trigger (a reap
  before the node's write replays it). It closes two dead ends: `catchup base` refusing "a
  catch-up merge is not pushed yet" forever, and a later trigger adopted by a catch-up on the old
  head. The template's re-entry rule now covers any `error` block met at `step: catchup` (a
  `catchup` answer, or a `catchup` / `tool push` call failing twice).
- **The lookup** (both sites, step 3 and the report intake) records a merge only when it descends
  from the catch-up's head: after an abort and a rebase onto `origin/main` it finds one of
  `main`'s own merges → `error` "the catch-up head is no longer in HEAD", nothing written.
- **The `done` replay** runs step 5's push checks first (read-only): the remote ahead → `error`
  "the remote branch is ahead of HEAD", `HEAD` unpushed → `error` "HEAD is not pushed".
- **Start guards**: `.git/index.lock` → `error` "a stale index.lock"; tracked changes uncommitted
  → `error` "uncommitted changes outside a catch-up"; both before any write, so no count is spent.
  The `index.lock` check also runs before any merge of a catch-up whose merge is not recorded (a
  merge killed before it wrote `MERGE_HEAD`).
- **A ref lock on the fetch** is `cannot lock ref` or `Unable to create '<path>.lock'` only; any
  other `Unable to create` (a full disk) is `TOOL_FAILED`. The `BUSY` tail is cleaned like a
  `TOOL_FAILED` one.
- The git env contract (`cwd`, `env_remove`, `env_extra`, `decode_errors`) is pinned by a test.
