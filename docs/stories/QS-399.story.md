## Problem

The second pipeline (epic #369) needs a **Control Plane**: Python, no LLM, one for all runs. It holds the runtime state, the run queues, the commands that LLM sessions call, the tools layer and the hooks. None of it exists today.

The spike (#382) used throwaway stand-ins: a `state.json`, an `events.jsonl` and ad-hoc scripts. They break with two orchestrators, and have no fencing, no idempotency, no locks and no tests.

Every later child builds on this core:

- #375: the ledger
- child 14: the active loop
- children 6a and 6b: the orchestrator and the nodes
- child 7: the merge
- child 8: the board
- child 12 / #400: item worktrees

It must therefore ship a **stable, tested, documented interface with explicit seams**.

Two gaps in today's tooling leave the Control Plane untested:

- The CI 100% coverage gate, ruff and mypy cover only `custom_components/quiet_solar/` (`.github/workflows/pr-quality.yml`).
- The local gate classifies every `scripts/` change as dev-only: the full gate skips coverage, ruff and mypy, and `--impacted` measures only `custom_components/quiet_solar/` (`quality_gate.py` `_DEV_ONLY_PATTERNS`, `_detect_scope`, `_build_testmon_cmd`).

## Goal

A package, `scripts/qs/control_plane/`, plus a thin entry script, `scripts/qs/cp.py`, providing:

1. **The state:** a versioned task-tree schema in `harness_state.db`, complete enough for the board. It includes a seam for #375's ledger and the work-item fields #400 needs.
2. **The queues:** one per recipient, in order of arrival. Messages go `queued → in_flight` (with a visibility timeout and a receipt) `→ acked`, or `dead` after too many attempts. Plus `wait`, `ensure` and a minimal daemon skeleton.
3. **Identity, leases and the fencing token** on every action with an effect; a superseded session ends itself.
4. **Locks and caps.** Three locks: the main-checkout lock, the keyed `integration:<branch>` family and the `main-merge` lock. A lock is held by a process group, so it is freed when the holder dies. Caps on node sessions and on gate runs.
5. **The tools layer:** idempotent by `(tool, key)`, recorded, run under the right lock or cap, with a frozen registration API.
6. **The hooks:** `Stop`, `PreToolUse` and `pre-push` handlers, plus their installer and the settings generator.
7. **Only `main`'s code touches the live DB.** `schema_version` is checked on every write, and the schema migrates itself.
8. **The per-merge export** of a task summary to `docs/stories/`.
9. **CI coverage, ruff and mypy extended to the Control Plane**, in CI and in the local gate (full and `--impacted`), from the first checkpoint on.
10. **This child's decisions recorded in the epic document.**

## Design

### 1. Layout, imports, invocation, exit codes

```text
scripts/qs/cp.py                      # entry shim, no logic: `from control_plane.cli import main` + `if __name__ == "__main__": raise SystemExit(main())`
scripts/qs/control_plane/
    __init__.py                       # public names (re-exports SCHEMA_VERSION from migrations.py once it exists, checkpoint 4)
    errors.py                         # CpError(code) hierarchy → exit code + JSON error code
    clock.py                          # Clock protocol: SystemClock (now, sleep), FakeClock
    faults.py                         # faults.hit(name) points; faults.arm(name, exc) context manager (tests)
    paths.py                          # code root, main checkout, its HEAD branch, live-DB path, path guard, backup dir
    db.py                             # connect(mode), write() with the per-transaction schema check
    schema_v1.py                      # DDL of v1, a tuple of single statements
    migrations.py                     # MIGRATIONS registry, migrate()
    liveness.py                       # ProcessProbe, ClaudeCli
    runner.py                         # Runner: subprocess seam with env injection
    procsetup.py                      # ProcessSetup seam: become_group_leader() (real: no-op if os.getpgid(0) == os.getpid(), else os.setpgid(0, 0)), install_sigterm(fn) (real: signal.signal)
    tokens.py                         # mint / parse / require
    runs.py tasks.py nodes.py         # state domain logic (task and node TRANSITIONS tables)
    messages.py questions.py decisions.py reports.py
    locks.py                          # named locks, LOCK_ORDER, caps
    daemon.py                         # skeleton + ensure()
    wait.py
    merge_policy.py                   # merge-policy registry (default refuses)
    tools.py                          # ToolSpec, Step, register(), invoke(), run_recorded(), the built-in tools
    hooks.py                          # Stop / PreToolUse / pre-push handlers, install_pre_push(), hooks_settings()
    export.py                         # task summary → <worktree>/docs/stories/
    snapshot.py                       # read-only board-complete view
    cli.py                            # COMMANDS dispatch table (argparse); JSON out; exit codes
tests/qs/control_plane/__init__.py
tests/qs/control_plane/conftest.py    # see §14
tests/qs/control_plane/test_<module>.py  (one per module) + golden/ files
docs/workflow/control-plane.md        # reference (§16)
```

#### Imports

- Inside the package, imports are **relative only**: `from . import paths`.
- Cross-module calls go through the module attribute, as in `paths.code_root()`, **never** `from .paths import code_root`. This keeps the conftest's monkeypatches effective.
- The package never imports sibling `scripts/qs` modules such as `utils` or `targets`. Everything external goes through `Runner`, so the fakes count every effect.

#### Module identity

The package has two names, and both are valid:

- **At runtime:** `cp.py` puts `scripts/qs` on `sys.path`, and the tests do the same, so the package is the top-level `control_plane`.
- **Under mypy:** `mypy scripts/qs/control_plane/` names it `qs.control_plane`, because `scripts/qs/__init__.py` exists and `scripts/__init__.py` does not.

Relative imports resolve identically under both names. Only `cp.py`'s single absolute import, `from control_plane.cli import main`, is left unresolved by mypy, and `ignore_missing_imports` covers it.

**Checkpoint 1 runs the pinned mypy invocation (§15) on the scaffold.** If it reports any error that comes from module identity, switch the pin to `MYPYPATH=scripts/qs mypy --explicit-package-bases …`, update the pin and its test, and note the switch in the story.

#### Invocation

Every session runs:

```bash
<MAIN>/venv/bin/python <MAIN>/scripts/qs/cp.py <command> …
```

- `<MAIN>` is the main checkout's absolute path, given at spawn.
- The tools run the wrapped scripts with `<MAIN>/venv/bin/python <MAIN>/scripts/qs/<script>.py`. `setup_task.py` needs jinja2, so there is no `python3` fallback for tools.
- The hooks may fall back to `python3`: they use the stdlib only.
- Output is one JSON object on stdout: either `{"ok": true, …}` or `{"ok": false, "error": "<CODE>", "detail": "…", …}`.
- `cli.main` calls `procsetup.become_group_leader()` **only for `tool …` commands**.
- `daemon.run` and `wait` install their SIGTERM handlers **only** through `procsetup.install_sigterm(fn)`.
- Both go through the `ProcessSetup` seam, which the tests fake (§14), so pytest's own process never changes group and never gets a signal handler.

#### Exit codes

| exit | codes | meaning |
|---|---|---|
| 0 | — | ok. For a hook: allow, or its JSON decision |
| 1 | `INTERNAL`, `TOOL_FAILED` | unexpected error, or a wrapped tool failed (recorded) |
| 2 | `USAGE` | bad arguments, or no session id available (§6.1) |
| 3 | `STALE_TOKEN` | the caller's token is superseded. The payload carries the self-end instructions (§6.4) |
| 4 | `STOPPED` | the caller's **node** is `stopped`. A `dropped` task is `INVALID_STATE` instead |
| 5 | `SCHEMA_TOO_NEW`, `SCHEMA_PENDING` | this code is older than the DB, or a migration did not complete in time |
| 6 | `BUSY` | a lock, a cap or an in-flight call of the same tool and key was not obtained in time, or the node cap is reached |
| 7 | `PATH_GUARD` | this copy of the code may not open this DB |
| 8 | `NOT_FOUND`, `CONFLICT`, `INVALID_STATE` | unknown id; uniqueness, argument or receipt mismatch; forbidden transition |
| 9 | `POLICY_REFUSED` | merge policy, a foreign hook, `core.hooksPath` set, a write into the main checkout, main not on branch `main`, … |

### 2. Paths and the path guard

- **`paths.code_root()`:** the repo root that contains this package, derived from `Path(__file__)`.
- **`paths.main_checkout(root)`:** computed with no subprocess.
  - If `root/.git` is a directory, the answer is `root`.
  - If it is a file, parse its `gitdir:` line, read that gitdir's `commondir` file, and return the parent of the resolved common dir.
- **`paths.is_main_checkout(root)`:** `main_checkout(root) == root`.
- **`paths.main_head_branch(main)`:** reads `<main>/.git/HEAD`. It returns `main` for `ref: refs/heads/main`, and `None` for a detached HEAD or another branch.
- **`paths.live_db(main)`:** `main / "harness_state.db"`.
- **`paths.is_live_db_path(p)`:** true when `p.name == "harness_state.db"` and `p.parent` contains a `.git` entry.

**DB selection and the guard: `paths.select_db()`.**

- **`QS_CP_DB` set:** use it, unless the guard refuses it with `PATH_GUARD`:
  - `is_live_db_path(resolved)` is true, **unless** this code is the main checkout's (`code_root() == main_checkout(code_root())`) **and** `resolved == live_db(code_root())`;
  - under `PYTEST_CURRENT_TEST`, any `is_live_db_path` is refused.
- **`QS_CP_DB` unset:** the code must be the main checkout's, otherwise `PATH_GUARD` with the hint "call `<MAIN>/scripts/qs/cp.py`, or set `QS_CP_DB` to a temporary DB". The DB is then `live_db(code_root())`.
- **The test-DB exemption** used by `migrate` and `ensure` (§5) is "the selected DB is not a live-DB path". It is never "the env var is set".

**Backups: `paths.backup_dir()`.** It is `QS_CP_BACKUP_DIR`, defaulting to `~/.local/state/quiet-solar/cp-backups/`. A path inside `main_checkout(code_root())` or `code_root()` is refused with `POLICY_REFUSED`.

### 3. Connections and the schema check

**`db.connect(path, *, mode)`:**

- uses `isolation_level=None`: autocommit, with explicit transactions only;
- sets `PRAGMA busy_timeout=5000`, `foreign_keys=ON` and `journal_mode=WAL` **before** any transaction;
- opens `file:<path>?mode=rw` by URI, so it **never creates** the file. Only `migrate()` creates it, with `mode=rwc`. `mode="ro"` opens `?mode=ro`.

**`with db.write(conn):`** issues `BEGIN IMMEDIATE`, then **reads `PRAGMA user_version` and raises `SCHEMA_TOO_NEW` if it differs from `SCHEMA_VERSION`**, then `COMMIT`, or `ROLLBACK` on an exception.

- A long-lived old-code process can therefore never write to a migrated DB. This covers `wait`, a 30-minute `gate` run and a tool blocked on a lock.
- Every token check runs **inside** the write transaction it guards.
- **No subprocess ever runs inside a write transaction.** Liveness probes and tool effects run outside it. The transaction then re-validates what the probe assumed, compare-and-set style (§6.2, §8, §9.2).

**The entry schema check, `db.check_schema(conn_or_path, *, wait)`:**

| DB state | result |
|---|---|
| version equal to the code's | proceed |
| DB newer than the code | `SCHEMA_TOO_NEW`: this code is too old, refuse |
| DB older or missing, `wait=True` | call `daemon.ensure()`, then **poll** existence and `user_version` every 0.5 s, up to `MIGRATE_WAIT_S` (60 s). Each read takes a shared `flock` on the migration lock. At the timeout: `SCHEMA_PENDING` |

This is a decision, recorded in the epic, and a deviation from "refuses on a mismatch": "too old" waits for the self-migration and then proceeds, while "too new" refuses.

**Bootstrap.** On a missing DB, `run open` (the first write ever) runs this check before its insert. `ensure` starts the daemon, the daemon creates and migrates the DB, and the insert follows.

**Exempt commands** never call `ensure` and never wait. They treat a missing DB as "nothing registered":

- `hook stop`, `hook pre-tool-use`, `hook pre-push`: on a schema mismatch they **fail open immediately**, except `pre-push`'s DB-free item-ref check (§10.3);
- `hooks-settings` and `version`: no DB at all;
- `daemon`: it migrates;
- `ensure`: it reads `daemon_lease` defensively, and treats a missing file or table as "stale";
- **the read-only commands of §12** run `check_schema(wait=False)`:
  - missing DB → an empty answer (`session status` → `role: none`);
  - older DB → `SCHEMA_PENDING` at once;
  - newer DB → `SCHEMA_TOO_NEW`.

  So 6a's `SessionStart` call never hangs, and no read ever starts a daemon.

#### Task states

`tasks.TRANSITIONS` is the only source of truth; any other transition raises `INVALID_STATE`.

```text
proposed → ready → planning → contracted → building → ready_to_merge → merged → validated
non-terminal → blocked   (stores blocked_from; unblock returns to blocked_from)
non-terminal → dropped   (terminal; so are merged, validated)
```

A **node token** may move **its own** task only along these transitions:

- `planning → contracted → building → ready_to_merge`;
- into `blocked` from one of those states;
- out of `blocked` only when `blocked_from` is one of them.

Every other transition needs the run token. The `merge` tool's `ready_to_merge → merged` runs under the run token that `merge` requires (§9.4).

#### Node states

`nodes.TRANSITIONS`, enforced the same way:

```text
spawning → reaped            (its spawn/resume tool call's holder is dead, that call is not `succeeded`, its name is absent from a successful liveness listing, AND `launch_at` is NULL or older than LAUNCH_SETTLE_S; a same-key replay first probes and may complete it instead)
running/idle → reaped        (absent from a successful liveness listing)
reaped → spawning            (resume's reserve step, or a replayed spawn/resume re-taking its own reaped row; the same generation)
spawning → running ⇄ idle   (spawn or resume completed; on a resume, session_id / short_id may be updated, and the token stays valid)
running/idle → taken_over → running   (hand-back)
any non-terminal → stopped
any non-terminal → superseded         (a newer generation of the same task was registered)
```

`stopped` and `superseded` are terminal.

### 5. Migrations, the daemon skeleton, `ensure`

#### 5.1 `migrations.py`

- `MIGRATIONS: tuple[Migration, ...]`, with `Migration(version, name, statements: tuple[str, ...])`.
  - Statements are **single SQL statements, run with `execute`**, never `executescript`, which commits implicitly.
  - `SCHEMA_VERSION = MIGRATIONS[-1].version`.
- **Seam:** #375 and later children append `Migration(n+1, …)`. A test asserts that the versions are exactly `1..N`.

`migrate(db_path, *, role)`:

1. **Refuses** with `POLICY_REFUSED` unless one of these holds:
   - `role == "daemon"`, this code is the main checkout's, **and** `paths.main_head_branch(main) == "main"`, so a feature branch checked out in the main checkout can never migrate the live DB irreversibly;
   - the DB is not a live-DB path (tests).
2. Takes an exclusive `flock` on `<db>.migrate.lock`, blocking with a timeout.
3. Opens or creates the DB with `mode=rwc` and reads `user_version`.
   - Newer than the code: `SCHEMA_TOO_NEW`.
   - Equal: returns `noop`.
4. If the file existed with `user_version > 0`, **backs it up first**: `sqlite3.Connection.backup` to `<backup_dir>/harness_state.v<from>.<UTC stamp>.db`, then `fsync`.
5. Applies each pending migration in **its own** `BEGIN IMMEDIATE`: its statements, then `PRAGMA user_version = v`, then `COMMIT`.
   - The fault point `faults.hit("migrate.mid_step")` fires **after the first statement** of each step.
   - A failure rolls back that step; the DB stays at the last committed version, the backup is kept, and the error is raised.
6. Returns `{from, to, backup}`.

#### 5.2 The daemon skeleton (`cp.py daemon`): the core of child 14's active loop

`daemon.run(clock, *, tick_hooks=(), max_ticks=None)`:

1. Takes a **non-blocking** exclusive `flock` on `<db>.daemon.lock`. If it is held, exits 0 with `{"singleton":"held_elsewhere"}`.
2. Runs `migrate(role="daemon")`. **On failure, or a refusal:** it writes the error to the log and to the sidecar file `<db>.migrate-error.json` (`{at, error}`), then exits 1. It uses a sidecar, not the DB, because a `db.write` would refuse on the mismatched version and a missing DB has no `meta` table. On success it deletes the sidecar.
3. Upserts `daemon_lease` with its pid, its pid start time and `schema_version = SCHEMA_VERSION`.
4. Installs its SIGTERM handler, the named function `daemon._on_sigterm`, which sets a stop flag. It does so through `procsetup.install_sigterm`.
5. Loops:
   - write `heartbeat_at`;
   - call each tick hook;
   - exit on the stop flag, or when no run has been `open` for `IDLE_EXIT_S` (default 30 min, the epic's view 7);
   - `clock.sleep(TICK_S)` (default 5 s).
6. On exit, sets `pid` and `heartbeat_at` to NULL in `daemon_lease` and releases the lock.

Child 14 owns:

- `tick_hooks`, its extension point;
- tuning the idle exit;
- restarting on *any* code change;
- the self-check after a merge.

This skeleton is replaced on a schema bump only through `ensure` (§5.3).

#### 5.3 `ensure`

`daemon.ensure(*, popen, clock, probe)`:

- **The lease is fresh** (`heartbeat_at` within `STALE_AFTER_S`, 30 s; all `*_S` timings and `MAX_ATTEMPTS` are module constants, overridable by function argument, §16) **and** `daemon_lease.schema_version == SCHEMA_VERSION`: return `already_running`.
- **The lease is fresh, but its `schema_version` is lower:** send SIGTERM to `daemon_lease.pid`, after verifying its pid and start time through `ProcessProbe`. Then poll until the lease is **cleared** (`pid IS NULL`) or `DAEMON_RESTART_WAIT_S` (15 s) elapses, and start a new daemon either way. The singleton lock arbitrates: if the old daemon still holds it, the new one exits `held_elsewhere`, and the next `ensure` retries. Return `restarted`.
- **`<db>.migrate-error.json` exists with an `at` younger than `MIGRATE_BACKOFF_S` (300 s):** do not respawn. Return `migrate_failed` with the error. A waiting command's `SCHEMA_PENDING` detail carries that error, so a failing migration never loops spawning daemons that each back up the DB.
- **The lease is stale, missing or cleared:** spawn `[<MAIN>/venv/bin/python if it exists, else sys.executable, <code_root>/scripts/qs/cp.py, "daemon"]` with:
  - `start_new_session=True`, `stdin=DEVNULL`;
  - stdout and stderr appended to `<MAIN>/harness_state.daemon.log`;
  - `cwd=<MAIN>`, `close_fds=True`.

  Return `started`.
- **Against a live DB,** `ensure` is refused unless this code is the main checkout's.

**Who calls `ensure`:** `run open`, `run claim`, `wait` (§7.3), and the non-exempt entry schema check. `snapshot` does **not**: it is read-only, with no hidden side effect.

### 6. Identity, run leases, the fencing token

#### 6.1 Tokens and session ids

**Token format:** `<subject>.<epoch>.<nonce>`, for example `run:R7.3.9f2c…` or `node:N12.1.a41b…`, where `N12` is the row of one node generation.

- **Nonce:** 128 random bits (`secrets.token_hex(16)`), stored on the subject's row.
- **Valid** iff the subject row exists, the epoch matches (`run_leases.epoch`, or `nodes.generation` with a row that is not `superseded`), and the nonce matches.

**Where a token may appear:**

- **Only in the responses** of `run open`, `run claim`, `tool spawn` and `tool resume`.
- No read command ever outputs a nonce.
- No token is stored outside its subject row. In particular, a `spawn` or `resume` replay rebuilds the token from the `nodes` row at response time, and only for a run-token caller.

**Transport:**

- **`--token` is required** on every effectful command, with **no** environment fallback on the CLI.
- `QS_CP_TOKEN` exists only for git. `Runner` injects it **only into steps marked `inject_token=True`**: the steps that may push (`worktree-create`'s `setup`, `pr-create`, `push`, and #400's `integrate`). That lets `create_pr.py`'s internal `git push` and #400's scripts pass the `pre-push` hook.
- Every **`claude` launch** (`spawn`, `resume`, `ClaudeCli`) **removes** `QS_CP_TOKEN` from the inherited environment, so a node session can never read a run token from it.
- Nothing relies on an environment variable reaching a `claude --bg` session.

**Session ids:**

- `--session-id` defaults to `$CLAUDE_CODE_SESSION_ID`.
- If neither is present, the command fails with `USAGE`.
- **Stated assumption:** the hooks' stdin `session_id`, `$CLAUDE_CODE_SESSION_ID` and the `sessionId` in `claude agents --json` are the same identifier.
  - Verified on 2026-10-03 for the env var against `claude agents --json`, in a desktop session.
  - Checkpoint 9 re-checks the hook field once, with a live `Stop` hook run, **if one can be triggered from the implementing session**. Otherwise it records "unverified, relies on the §16 convention" and proceeds.
- Interactive sessions have no short id: `short_id` is NULL.

#### 6.2 Run lease and the run-name takeover rule (the epic's rule)

**Liveness evidence.**

- `ClaudeCli.agents()` lists **interactive and background sessions**. Verified on 2026-10-03: desktop sessions appear with `kind:"interactive"`, `sessionId`, `pid`, `startedAt` and `status`; background ones also have `id`, `state` and `name`.
- "Absent" means a successful listing that does not include that `sessionId`. **A failed listing is never absence.**

**`run open --name <slug> --title … [--session-id …] --session-name … --permission-mode … [--full-grant]`**

- Creates the run, its lease at epoch 1 and a `run_sessions` row, then calls `ensure`.
- Returns `{run_id, token}`.

**`run claim <run> [--session-id …] … [--takeover]`**

The liveness listing runs **before** the transaction. Inside `BEGIN IMMEDIATE`, the claim proceeds only if `(epoch, session_id)` still matches what was probed; otherwise it fails with `CONFLICT` ("lease changed, retry"). Then, depending on what the listing showed:

- **The caller *is* the holder** (same `session_id`, e.g. an orchestrator that lost its token after compaction):
  - epoch+1 and a new nonce, re-issued to the same session;
  - no supersede, no rebind, no `--takeover` needed.
- **The holder is absent:**
  - epoch+1, a new nonce, the new session recorded, and `name_bound_session_id` set to the new session.
- **The holder is alive and `--takeover` was not given:**
  - `CONFLICT`, reporting the holder's id, name and short id.
- **The holder is alive and `--takeover` was given:**
  - epoch+1, so the old token is stale at once;
  - the old session is marked superseded in `run_sessions`;
  - `pending_bind_session_id` is set to the new session, and **the run name is not rebound**;
  - the response tells the new session to ask the maintainer to archive the old one, then call `run bind-name`.

**`run bind-name <run> --token`**

- Succeeds iff `name_bound_session_id` is absent from a successful listing. It then promotes `pending_bind_session_id` into `name_bound_session_id`.
- Otherwise `CONFLICT`.

**`run set-mode --token --permission-mode … [--full-grant|--no-full-grant]`**

- Records the orchestrator session's permission mode, and whether the maintainer gave it a session-level full grant. This is the epic's spike decision **T2**: the state DB records each session's permission mode, so a restarted orchestrator knows which nodes need the human approval step.
- The mode can change **without a new claim**: in the spike, the maintainer granted a running session every permission mid-run. `run open` and `run claim` record the initial mode, and `set-mode` records later changes.

**`run close --token`.**

**Takeover is the maintainer's act.** A superseded session must not claim the run back. That is a convention (§16), backed by the self-end payload.

**Concurrent-claim tests** use threads with a `Barrier` and fake liveness:

1. Two `--takeover` claims probed at the same epoch: exactly one succeeds, the other gets `CONFLICT`.
2. Two plain claims on a dead holder: exactly one succeeds. The other re-probes, sees the winner alive, and gets `CONFLICT`.

#### 6.3 Fencing scope: every action with an effect

`tokens.require(conn, token, *, kinds, task_id=None)` runs inside the write transaction. It raises:

- `STALE_TOKEN` when the token is stale;
- `CONFLICT` for a node token used on a task other than its own;
- `STOPPED` when the token's node is stopped, except for its own reads, `msg pop` and `msg ack`.

| action | token kinds |
|---|---|
| `run set-mode/set-plan/close/bind-name`, the task-tree commands of §6.5 (except the node-allowed `task state` transitions), `question ask/answer`, `decision add`, `node stop/take-over` | run |
| `report post`, `digest put`, `question open`, `task state` (node-allowed transitions), `node hand-back` | run, or node (**its own task only**) |
| `msg post` | the sender's: run (any recipient in the run), or node (to `orchestrator` only) |
| `msg pop` / `msg ack` | the recipient's |
| `wait` | run |
| tools | per tool (§9.4 "token" column). A node token is accepted only for **its own task** |
| taking a lock or a gate slot | the holding tool's token, at acquire time; the holder re-checks it before each step |
| `lock acquire` / `lock release` (session-held `integration:*`, §8.4) | run, or node (its own task); bound to the token's own session and deliverable branch |
| `git push` from a registered worktree | the `pre-push` hook (§10.3). A valid token may push **only its task's branch** |
| `SendMessage` from a registered session | the `PreToolUse` hook (§10.2) |

**Known limit.** Fencing an external effect is check-then-act: GitHub never sees the token. A superseded session's **already-started** step can still land; its next step is refused. This is documented in §16. `merge` narrows the window with `gh pr merge --match-head-commit <sha>`.

**Test.** One test is parametrized over the CLI command table. For every effectful command and every tool, it builds a stale token by bumping the epoch or generation, and asserts:

- exit 3;
- unchanged row counts in every table;
- zero `Runner` effects and zero `Popen` calls.

A second test uses a node token on another task, or on a run-only tool, and asserts `CONFLICT` with nothing written.

#### 6.4 A superseded session ends itself

The `STALE_TOKEN` payload contains:

- `superseded_by`: the session id, or the node generation;
- `at`;
- the fixed `instructions` text: "You were superseded. Stop your event loop now: do not start `wait` again. Tell the maintainer this session was superseded and ask them to archive it. Take no further action, including after an app restart."

What the code enforces:

- `wait` exits 3, having checked the token **first** (§7.3).
- The `Stop` hook **allows** a superseded orchestrator to stop, and never blocks it.
- `cp.py session status [--session-id …]` returns `{"role":"orchestrator|node|none","state":"current|superseded|stopped", run_id, task_id}`. For a node, `superseded` and `stopped` map to themselves, and every other node state maps to `current`. 6a's `SessionStart` calls it, so a restarted superseded session stays idle.
- The same applies to a superseded node generation: its tools and its `pre-push` are refused.

All of these take `--token`; the token kinds are those of §6.3. Each writes `task_history` where a state changes.

### 7. Queues and `wait`

#### 7.1 Messages

**`msg post --run R --to orchestrator|node:<task> --kind K --payload-file F [--dedupe-key D] --token`**

- `kind` is free text, 1 to 32 characters. The vocabulary belongs to 6a and 6b.
- An existing `(run, dedupe_key)` returns the existing id with `deduped:true`.

**`msg pop --run R --as orchestrator|node:<task> [--visibility S] --token`** runs in one `BEGIN IMMEDIATE`:

1. Select the **lowest `id`** for this recipient with `state='queued'`, or `state='in_flight' AND visible_at <= now`. The fault point `pop.after_select` fires here, inside the transaction.
2. If that message's `attempts >= MAX_ATTEMPTS` (default 5), mark it `dead` and select the next one. A poison message therefore never blocks its queue forever. `snapshot` shows the `dead` count, and child 14 alerts on `dead` rows.
3. Update the selected message:
   - `state='in_flight'`;
   - `visible_at = now + visibility` (default `VISIBILITY_S`, 900 s);
   - `attempts += 1`;
   - a **new `receipt`** (`secrets.token_hex(8)`);
   - `popped_by`.
4. Return the message with its `receipt`, or `{"empty":true}`.

A redelivery comes back first, because its id is lower.

**`msg ack <id> --receipt R --token`**

| message state | result |
|---|---|
| `in_flight`, matching receipt | becomes `acked` |
| `acked`, same receipt | no-op |
| receipt mismatch (it was redelivered) | `CONFLICT` |
| `queued` or `dead` | `INVALID_STATE` |

There is no `msg release`: not acking within the timeout is the requeue path.

**Tests:**

- **Concurrent pop:** 8 threads, each with its own connection, synchronised on a `Barrier`, pop and ack 200 messages. Each id comes back exactly once.
- **Expiry and receipts** (FakeClock): an un-acked message is redelivered, the late ack is refused, an acked message never returns, and the 6th attempt becomes `dead`.
- **Queue replay** (the issue: "tests replay a popped message"):
  1. pop M;
  2. run `tool issue-create --key msg:M`; it succeeds;
  3. no ack; the visibility timeout expires;
  4. pop M again;
  5. run the same tool with the same key.

  Exactly one `gh issue create` effect, and `replayed:true`. The same scenario runs for `spawn` and `merge`.

#### 7.2 Questions, decisions, reports, digests

- **`question open --task --text-file --blocking --token`** creates `Q-n` in state `open` **and** posts a `question` message, in one transaction.
- **`question ask Q-n`** sets `asked`.
- **`question answer Q-n --answer-file --reason --token`** sets `answered`, and posts an `answer` message to the asking node, if any.
- **`decision add --text --reason --source [--task] --token`.**
- **`report post --task --phase --round --status --summary --fields-file --token`** inserts a `reports` row **and** posts a `report` message to `orchestrator`, in one transaction.
- **`digest put --task --file --token`** replaces the digest, subject to the cap.

#### 7.3 `wait`

`wait --run R --token [--timeout S] [--poll S]`:

1. **Verify the token first.** A stale token exits 3 with no write and no `ensure`.
2. Register a `waiters` row, then call `ensure()`.
3. Every `poll` (default 1 s):
   - refresh `heartbeat_at`;
   - re-verify the token: stale → exit 3;
   - re-read `user_version`: a mismatch → exit 5 with `{"restart_wait":true}`, so the orchestrator restarts `wait` with new code;
   - if any visible message is waiting for `orchestrator`, print `{"ok":true,"pending":n}` and exit 0 **without popping**;
   - if the daemon heartbeat is stale, call `ensure()`, at most once per `STALE_AFTER_S`.
4. At the timeout (default 6 h), return `{"timeout":true}` with exit 0.
5. The `waiters` row is always deleted on exit: a `finally` clause, plus `wait._on_sigterm`, installed through `procsetup.install_sigterm`, which raises `SystemExit`.

A `waiters` row whose pid is dead counts as absent.

### 8. Locks and caps

#### 8.1 Named locks, held by a process group

- **Names:** `main-checkout`, `main-merge`, and `integration:<branch>` (for example `integration:QS_400`).
- **`LOCK_ORDER`:** `integration:*` first (lexical among themselves), then `main-merge`, then `main-checkout`. A gate slot comes last, as a leaf.

**The holder is the tool process and its process group,** never an LLM session across turns.

- For `tool …` commands, `cli.main` makes the process a group leader through the `ProcessSetup` seam (§1), and every effect subprocess inherits the group.
- A lock row records the holder's `pid`, `pid_start` and `pgid`.
- **The holder is dead** iff its pid is dead (pid plus start time) **and** `os.killpg(pgid, 0)` raises `ProcessLookupError`. Orphaned `git` or `gh` children therefore keep the lock held until they finish.

**API.** `locks.hold(names: Sequence[str], *, conn_factory, token, actor, purpose, timeout, clock, probe, claude)` is a context manager. `claude` serves the session-holder liveness of §8.4, and its listing runs outside the transaction.

- It **asserts** that `names` is sorted by `LOCK_ORDER`, and raises `INTERNAL` otherwise. This is a static, per-call check; there is no thread-local state.
- For each name, in order:
  1. probe the current holder **outside** the transaction;
  2. in `BEGIN IMMEDIATE`, verify the token, then take the lock if the row is absent or still equal to the probed dead holder (compare-and-set);
  3. otherwise back off and poll until `timeout` (default `LOCK_WAIT_S`, 600 s), then raise `BUSY` with the holder's actor and purpose.
- On exit, it deletes only the rows it still holds.
- `locks.recheck(token)` raises `STALE_TOKEN` when the token is stale **or** when any lock this call holds or co-holds is no longer owned by it (re-verified in a transaction).

**No CLI acquires a process-held lock.** A CLI process would die at once, freeing it. Lock holders are visible in `snapshot`. The only CLI acquire is the **session-held** `integration:*` lock (§8.4).

**Why `main-merge` exists** (S2 rejected):

- #400 asked for keyed integration locks.
- A per-branch key alone cannot serialise two deliverables' "head contains `origin/main`, then merge".
- Fixing its name and its place in the order now lets #400 and child 7 code against one order.

#### 8.2 The open points of child 5, settled

**A holder restarted by the app resumes safely.**

- Sessions never hold `main-checkout` or `main-merge`; the tool's process group does, for one operation. The only session-held locks are `integration:*` ones (§8.4). They survive an app restart as long as the session is listed again before a contender probes, because the session keeps its id (limits: §16).
- If an app restart kills the group, the lock is free at once. If the group survives, it finishes and releases.
- The restarted session re-invokes the tool with **the same key**:
  - `succeeded` → the recorded result;
  - `started` with a dead holder → the probe, then the missing steps only (§9.2);
  - `started` with a live holder → `BUSY`.

**The main-checkout lock is fenced by the run lease, not owned by it.**

- Acquiring needs a valid token, and the holder re-checks it before each step.
- A superseded run's in-flight tool aborts at its next step boundary and releases.
- The lock spans one operation (fetch, fast-forward, worktree setup), never a run.

#### 8.4 Session-held integration locks (for #400's integration across commands)

#400 integrates a work item in **several commands**:

1. start: merge in a scratch worktree;
2. **conflict resolution by the node session**, over several turns;
3. finish (gate, then move `QS_<N>`), or abort.

The lock must stay held between those commands, which a process-held lock (§8.1) cannot do. So **the `integration:*` family only** also supports a **session holder**.

**`cp.py lock acquire --name integration:<branch> --purpose … --token`**

- **Token:** a run token, or a node token on its own task.
- **Binding.** The caller is accepted only if both hold, otherwise `CONFLICT`:
  - **Session:** the caller's session (`--session-id`, default `$CLAUDE_CODE_SESSION_ID`) is **the token's own session**: `nodes.session_id` for a node token, `run_leases.session_id` for a run token.
  - **Branch:** `<branch>` is the branch of the token's own deliverable. For a node token, that is its task's deliverable (the task itself, or its `deliverable_id`). For a run token, it is any deliverable of its run.
- **Liveness:** a successful `claude agents --json` listing, made **before** the transaction, must show that session. If the listing fails, `lock acquire` returns `BUSY` ("liveness unknown, retry") and takes nothing.
- **What the row records:** `holder_kind='session'`, `holder_session_id`, the session's `pid` (from the listing) with `holder_pid_start = ProcessProbe.start_of(pid)`, `token_subject`, and `holder_epoch`, the token's current epoch or generation.
  - The start time is read **outside** the transaction.
  - The listing's `startedAt` is **never** stored as the pid start: it is a different clock.
- **Race and re-acquire:** the compare-and-set is the same as in §8.1.
  - The same `token_subject` **and** the same session → `already_held`, with `holder_epoch` refreshed, `holder_pid` re-stamped from the current listing, and `holder_pid_start` re-stamped through a fresh `ProcessProbe.start_of(pid)`, never from the listing's `startedAt`. After an app restart, a session keeps its id but gets a new pid.
  - Any other live holder → `BUSY`, after `--timeout` (default 0).
- **Names:** any name outside `integration:*` → `POLICY_REFUSED`.

**`cp.py lock release --name … --token`**

- Only the holder (same subject and same session) can release; anyone else → `CONFLICT`.
- Releasing a lock that is not held is a no-op.
- There is no force release. Stopping the node, closing the run, or a terminal task frees the lock (below).

**When a session holder is dead.** The lock is free iff **the holder is dead and no co-holder is alive**. The holder is dead iff **any** of these is true:

- **Token superseded.**
  - Node token: its node row is `superseded` or `stopped`.
  - Run token: `run_leases.epoch > holder_epoch` **and** `run_leases.session_id != holder_session_id`. When the same session re-claims its own run (§6.2), the lock carries forward, and its next use refreshes `holder_epoch`.
- **Session gone.**
  - A **successful** listing is authoritative: the session is listed → alive; absent → dead.
  - **Only when the listing fails** does the recorded pid decide, through `ProcessProbe` (pid plus the start time recorded at acquire): a dead pid → dead.
  - So a live session whose pid changed (an app restart) is never judged dead while the listing works. Its own next use re-stamps the pid.
- **Owner finished.** The run is `closed`, or the deliverable task is terminal (`dropped`, `merged`, `validated`).

A co-holder is alive while its process group exists (§8.1 rule).

**Nested use by the holder's own tools.** A tool may need `integration:<b>` (through `ToolSpec.locks` or `locks.hold`) while that lock is session-held by **the same subject and the same session**. Then `hold()`:

1. **Takes it as co-holder.**
   - It stamps `cohold_pid`, `cohold_pid_start` and `cohold_pgid`, and re-stamps the holder's epoch, pid and pid start as in `already_held`, with the pid start from `ProcessProbe.start_of`.
   - The stamp is a compare-and-set that succeeds **only when the slot is empty, or its co-holder is dead**. A live co-holder, for example a second tool of the same session, makes it **wait**, like any other caller, and `BUSY` at the timeout.
   - On exit it clears the slot by compare-and-set **on its own stamp only**.
   - It never releases the lock itself.
   - While the co-holder lives, the lock is held, even if the session dies mid-step, for example during a 30-minute gate.
   - Any other caller, such as child 7's `merge`, waits as usual.
2. **Re-checks ownership before every step.** `locks.recheck(token)` checks, in a transaction, that every lock the call holds or co-holds is still owned by it. If not → `STALE_TOKEN`, with no further effect.

**Moving the branch is a compare-and-swap.** #400's branch-move step must use `git update-ref refs/heads/QS_<N> <new> <old>`, where `<old>` is the tip recorded at start. Even a lost-lock race then cannot overwrite a branch someone else moved.

**`LOCK_ORDER` across commands.** `lock acquire` and `hold()` look up the session-held `integration:*` locks that the same `token_subject` already holds, and refuse with `CONFLICT` ("release `integration:<a>` first") any name that sorts **before** one of them.

- This keeps the global order across separate commands. For example, two orchestrators each merging the other's deliverable cannot deadlock.
- `main-merge` and `main-checkout` sort after every `integration:*`, so child 7's `merge` of its own held branch stays allowed.

**Scope of this exception.** It amends §8.2 ("sessions never hold locks") for the `integration:*` family only. `main-checkout` and `main-merge` stay process-held, one operation at a time.

#### 8.3 Caps

**Gate cap.**

- `QS_CP_MAX_GATES` slots (default 2) in `cap_slots`, taken like a lock: probe outside the transaction, compare-and-set inside.
- Waiting is bounded by `GATE_WAIT_S` (30 min), then `BUSY`.
- Users: `tool gate`, and #400's `integrate`.

**Node cap: `QS_CP_MAX_NODES` (default 4), counted across all runs.** A node counts when it is:

- `spawning`, while the holder of its spawn tool call (`nodes.spawn_tool_key` → `tool_calls` holder pid, start and pgid) is alive. A `spawning` row whose tool call is not `succeeded`, whose holder is dead, **whose name is absent from a successful listing, and whose `launch_at` is NULL or older than `LAUNCH_SETTLE_S`** moves to `reaped` (§4) inside the next cap transaction, and stops counting. A listed one, or any one when the listing failed, keeps counting: its session may be running;
- `running`, `idle` or `taken_over`, if present in the liveness listing taken **before** the transaction. **If the listing fails**, every such row counts (fail-safe).

`tool spawn` inserts its `spawning` row, and `tool resume` moves its node `reaped → spawning`, **in the same transaction** that counts. So no two concurrent spawns or resumes can both pass. At the cap it returns `BUSY`, and never queues; retrying is 6a's policy.

`tool resume` applies only to a **`reaped`** node, and needs a free slot. A node that is still listed is live: it is woken with `SendMessage`, never resumed. The spike showed that `--resume` on a running session forks a copy, so `resume` refuses a live node with `INVALID_STATE`.

### 9. The tools layer

#### 9.1 `Runner`

`Runner.run(argv, *, cwd, env_extra, timeout) -> RunResult(returncode, stdout, stderr)`:

- runs `subprocess.run` with `text=True`;
- adds `env_extra` to the inherited environment, which contains `QS_CP_TOKEN` only for `inject_token` steps;
- removes the names in `env_remove` (`claude` launches always remove `QS_CP_TOKEN`);
- leaves its children in the tool's process group, **except** for a step marked `detach=True`, which runs with `start_new_session=True`.

**Rule:** a step must not leave long-lived descendants in the tool's group. A lingering descendant would keep the claim and its locks "alive" forever. Every `claude --bg` launch (`spawn`'s `launch`, `resume`) is `detach`.

`FakeRunner` records each call (argv, cwd, environment delta) and returns scripted results. In tests, **an effect** is a `FakeRunner` call whose argv matches the tool's effecting command, for example `gh issue create` or `claude --bg`.

#### 9.2 `run_recorded`

`run_recorded(spec, *, key, task, args, token, actor, ctx)`, where `ctx` bundles `runner`, `conn_factory`, `clock`, `probe` and `claude`:

1. **Verify the token.** Check `spec.token_kinds`, check that a node token targets its own task, and refuse a stopped node when `spec.refuse_when_stopped`.
2. **Claim the call.**
   - Compute `args_hash = sha256(json.dumps(args, sort_keys=True, separators=(",", ":"), ensure_ascii=False))`.
   - Read `tool_calls(tool, key)`:
     - **absent:** insert it as `started`, with this pid, pid start and pgid, and `outputs={}`, **before any effect**;
     - **`succeeded`:** same `args_hash` → return the recorded result with `replayed:true` and **no effect**; different hash → `CONFLICT`;
     - **`failed`:** return the recorded failure. The caller retries with a new key;
     - **`started`, holder alive** (pid **or** group, probed outside the transaction): `BUSY`;
     - **`started`, holder dead:** compare-and-set the holder to this process (a takeover).
3. **Probe.** If `spec.probe` exists, call `spec.probe(stepctx) -> dict[str, Any | None]` on **every** claim, fresh or taken over. **The probe is authoritative for each step name it returns**, over what earlier attempts recorded:
   - a value: the step is done in the real world, with that output (for example a worktree a previous key half-created);
   - `None`: the step is **not** done, and is removed from `outputs`, so it re-runs (for example a reserved node row that was reaped meanwhile).

   Step names the probe does not return keep their recorded `outputs`.

   A call already recorded `succeeded` never reaches the probe or the guard: step 2 returns its recorded result.

   **Guard.** If `spec.guard` exists, `spec.guard(stepctx)` runs after the probe and again before each effect step. It reads the entity the tool acts on (the node row, the task) and checks that it is still in a state this call may act on, for example "spawning under my key, or reaped" for `spawn`. On a mismatch it raises `INVALID_STATE`. The call is then recorded **`failed`**, with no further effect, and is never left `started`. **State drift fails cleanly. It never wedges, and never acts on a row the call no longer owns.**
4. **Run.** Take `spec.locks(task, args)` (a sorted sequence) and the cap. Then run each step whose name is **not in `outputs`**:
   - before the step: `locks.recheck(token)` and `faults.hit(f"{tool}.before_effect")`;
   - `step.run(stepctx)`, which returns a JSON-able output;
   - after the step: `faults.hit(f"{tool}.after_effect")`, then `outputs[step.name] = output`, persisted.
   - **A DB-only step persists its own output inside the same `stepctx.write()` transaction as its effect**, through `stepctx.record_output(value)`. A crash can therefore never separate the two.

   `stepctx` gives each step `task`, `args`, the earlier `outputs`, `runner`, `claude`, `main` (the main checkout path) and `write()` / `record_output()` for DB-only steps.
5. **Record.** On success, mark the call `succeeded`. `spec.on_success(conn, stepctx)` runs **inside** that final write transaction and returns the result payload. Every state change it makes is a **compare-and-set from the state the guard expects**. A miss raises `INVALID_STATE`, the transaction rolls back, and the call is recorded `failed` in a second transaction. The record keeps who, when and the result (exit code, last 60 lines); tokens are never recorded.

**Outcomes.** What becomes of a claimed call when something goes wrong:

| what happened | the `tool_calls` row | caller sees |
|---|---|---|
| a step's own failure: non-zero exit, `{"error"}`, bad status; or a guard / `on_success` `INVALID_STATE` (state drift) | `failed`, with the output; the key is spent, and a retry uses a new key | exit 1 `TOOL_FAILED` |
| `BUSY` (lock, cap), `POLICY_REFUSED`, `STALE_TOKEN` or `STOPPED`, **before any effect** (`outputs` empty) | **deleted**: the claim is released, so the same key can be retried | that error's exit code |
| one of those **after** an effect (`outputs` not empty) | left `started` with this holder; the next same-key call takes it over once this process has exited, and probes | that error's exit code |
| a crash, or an armed test fault | left `started` (the process dies, or the fault propagates) | — |

**Keys** are chosen by the caller and scoped per tool by PK(`tool`, `key`). The usual key is the popped message's id (`msg:<id>`); a task-derived key (`task:<id>:<purpose>`) is used when no message drives the call. A replay of the same message reuses the same key.

#### 9.3 `ToolSpec`: the frozen API for #400 and later tools

```python
@dataclass(frozen=True)
class StepCtx:
    task: TaskRow; args: Mapping[str, Any]; outputs: Mapping[str, Any]
    runner: Runner; claude: ClaudeCli; main: Path
    def write(self) -> ContextManager[sqlite3.Connection]: ...   # a db.write() transaction (DB-only steps)
    def record_output(self, value: Any) -> None: ...            # inside write(): persist this step's output atomically

@dataclass(frozen=True)
class Step:
    name: str
    run: Callable[[StepCtx], Any]           # returns the step's output (JSON-able), stored in tool_calls.outputs
    inject_token: bool = False              # Runner adds QS_CP_TOKEN (steps that may git push)
    detach: bool = False                    # Runner uses start_new_session=True (claude --bg launches)

# Helper — NOT part of the frozen API (may evolve):
def argv_step(name: str, argv: Callable[[StepCtx], list[str]], cwd: Callable[[StepCtx], Path],
              *, check: Callable[[RunResult], Any] | None = None, inject_token: bool = False,
              detach: bool = False) -> Step: ...

@dataclass(frozen=True)
class ToolSpec:
    name: str
    steps: Callable[[TaskRow, Mapping[str, Any]], Sequence[Step]]
    locks: Callable[[TaskRow, Mapping[str, Any]], Sequence[str]] = lambda t, a: ()   # sorted by LOCK_ORDER (asserted)
    cap: str | None = None                                                           # "gates"
    probe: Callable[[StepCtx], dict[str, Any | None]] | None = None   # authoritative per returned step: value = done, None = re-run (§9.2)
    guard: Callable[[StepCtx], None] | None = None                    # raises INVALID_STATE on state drift (§9.2)
    on_success: Callable[[sqlite3.Connection, StepCtx], dict[str, Any]] | None = None
    refuse_when_stopped: bool = True
    token_kinds: frozenset[str] = frozenset({"run"})

def register(spec: ToolSpec) -> None         # CONFLICT if the name exists
def invoke(name: str, *, key: str, task_id: str, args: Mapping[str, Any], token: str, actor: str) -> dict
```

- **Frozen:** `StepCtx`, `Step`, `ToolSpec`, `register` and `invoke`. `argv_step` is a convenience helper and is not frozen.
- The CLI exposes every registered tool as `cp.py tool <name> --task T --key K [--args-file F] --token`.
- Every built-in tool is a `ToolSpec`.
- A static test asserts that each registered spec's `locks` are sorted by `LOCK_ORDER`.

#### 9.4 Built-in tools

Default `token_kinds` is `run` only. The **token** column gives the exceptions.

**Every built-in tool has a guard** on its task's state, in addition to the per-tool guards below:
- `worktree-create`, `issue-create`, `gate`, `push`, `pr-create`, `spawn` and `resume`: the task is **non-terminal** (not `dropped`, `merged` or `validated`);
- `merge`: `ready_to_merge` (see below);
- `worktree-cleanup`: any state, including terminal ones.

These checks come from one shared helper, `tools.task_state_guard(allowed=…)`, composed with each tool's own guard. A `ToolSpec` registered by #400 declares its own `guard` (the helper is available to it); the default is `None`.

**`worktree-create`**

- **Arguments:** `phase` is **required**. The caller passes the lane's first phase: `/create-plan`, `/diagnose-task`, or `/decompose-epic`.
- **Runs in:** `<MAIN>`, under the `main-checkout` lock. **Token:** run.
- **Steps:**
  1. `pre_push`: `hooks.install_pre_push(common_dir)`. If the install is refused, the tool fails **before** any effect.
  2. `setup` (`inject_token`): `<MAIN>/venv/bin/python <MAIN>/scripts/qs/setup_task.py <issue> --harness claude-code --next-cmd <phase>`. The script is idempotent: it recovers partial state, and exits early when the worktree is already set up.
- **Probe:** `{}`. Step 2 always re-runs (it is idempotent); step 1 is a no-op when the shim is already installed.
- **`on_success`:**
  - `worktree` comes from the script's JSON `worktree_path`; `branch` from `branch`.
  - Both are written **after** the script's own `git push -u`, so that push happens while the task is still unregistered (§10.3, step 2).
  - A non-zero exit or `{"error"}` → `failed`, with the output.

**`worktree-cleanup`**

- **Runs in:** `<MAIN>`, under the `main-checkout` lock. **Token:** run.
- **Steps:**
  - If the directory exists: `<MAIN>/venv/bin/python <MAIN>/scripts/qs/cleanup_worktree.py --work-dir <wt> --issue <N> --force`. The script normally exits 0, so the result is read from its JSON `status`. A non-zero exit, unparseable stdout, or any `status` other than `removed` → `failed`, pinned by a test.
  - If the directory is absent but still registered: `git -C <MAIN> worktree prune`.
- **Probe:** the directory is absent **and** missing from `git worktree list --porcelain` → both steps are done.
- **Records:** clears `worktree`. There is no `--delete-branch`: deleting branches is child 7's job, or the final cleanup's.

**`gate`**

- **Arguments:** `mode` (`impacted` or `quick`), plus `paths` for `quick`.
- **Runs in:** the task worktree, with a slot of the `gates` cap. **Token:** run or node (its own task only).
- **Steps:** `<wt>/venv/bin/python scripts/qs/quality_gate.py --impacted`, or `--quick <paths>`. `refuse_when_stopped`.
- **Probe:** none; the gate is safe to re-run.
- **Records:** the exit code and the last 60 lines.

**`spawn`**

- **Arguments:** `agent`, `model?`, `permission_mode`, `prompt_file`, `replace?`.
- **Runs in:** the task worktree, under the node cap (§8.3). **Token:** run.
- **Steps:**
  1. `reserve` (DB-only), inside the cap transaction. When it re-takes its own reaped row, it resets `launch_at` to NULL. Otherwise it inserts a `nodes` row in state `spawning`, with `generation = max+1`, a nonce, `spawn_tool_key`, and the name `<run.name>-<task.id>-g<gen>`. Its output is `{node_id, name}`.
     - A **live generation** is any row not `stopped` and not `superseded`, `reaped` included. So `--replace` on a reaped node supersedes it, while `resume` reclaims it.
     - With `replace`, the previous live generation becomes `superseded`.
     - Without `replace`, an existing live generation → `CONFLICT` ("resume it, or `--replace`").
  2. `launch`: first commits `nodes.launch_at = now` in its own small transaction, then runs `claude --bg --agent <agent> -n <name> [--model M] --permission-mode <P> --settings '<hooks_settings(node)>' --add-dir <MAIN> "<prompt>\n\nControl Plane: <MAIN>/scripts/qs/cp.py · run <R> · task <T> · token <token>"`. The token is built from the reserved row.
  3. `identify`: polls `claude.agents()` until `launch_at + LAUNCH_SETTLE_S`, for `sessionId` and `id` by name. If the name is not visible by then, or the listing keeps failing, it raises a **retryable** `BUSY`: the call stays `started` (§9.2 outcome table), the key is not spent, and the next same-key call takes it over.
- **Probe:** looks up `nodes WHERE spawn_tool_key = <tool>/<key>`.
  - If that row exists **and is `spawning`**, `reserve` counts as done with its `{node_id, name}`, so a replay **never reserves again**, even after a crash.
  - If the row exists but was **`reaped`** meanwhile, the probe returns `reserve: None`. `reserve` then re-runs and **re-takes that same row** (`reaped → spawning`) inside the cap transaction, counting it again. When it finds its own row through `spawn_tool_key`, it never inserts a second generation.
  - **`launch`:**
    - a listing shows the row's `name` → done;
    - the row is **`reaped`**, or `launch_at` is NULL (never attempted) → `None`, so it re-runs;
    - otherwise → done-pending (`{"pending": true}`), and `identify` polls.
    - A session is therefore never relaunched on one listing's word. Only a deliberate reap, which waits out `LAUNCH_SETTLE_S`, re-opens `launch`.
- **Guard:** the row found through `spawn_tool_key` is absent (before `reserve`), `spawning` under this call's key, or `reaped`. Any other state (`running`, `superseded`, `stopped`, …) → `INVALID_STATE`, which fails cleanly.
- `reserve` persists its output with `record_output`, inside its own transaction.
- `launch` is `detach`, and removes `QS_CP_TOKEN` from the environment.
- **Records:** `state=running`, `session_id`, `short_id`. The response carries the token, rebuilt from the row.

**`resume`**

- **Arguments:** `message_file`.
- **Runs in:** the node's worktree, under the node cap (§8.3). **Token:** run.
- **Steps:**
  1. `reserve` (DB-only), inside the node-cap transaction.
     - **Preconditions:** the node is `reaped`, has a non-NULL `session_id` (a node that never launched → `INVALID_STATE`: "re-spawn with `--replace`"), and is absent from a successful listing (a live node → `INVALID_STATE`: "wake it with `SendMessage`").
     - **When `launch` is already in `outputs`** (a replay), the liveness precondition is skipped: the node is live because this very call launched it.
     - It moves the node to `spawning`, sets `spawn_tool_key` to this call, and resets `launch_at` to NULL. If the row is already `spawning` under this call's key, it only rewrites the holder; that is not a state transition. It saves its output with `record_output`.
  2. `launch` (`detach`): first commits `nodes.launch_at = now`, then runs the **bare** `claude --bg --resume <session_id> "<msg>"`, with `QS_CP_TOKEN` removed. The spike found that any extra flag forks a copy.
  3. `identify`: polls `claude.agents()` until `launch_at + LAUNCH_SETTLE_S` for the node's current `sessionId` and `id`, matched by its name, with a `startedAt` later than `launch_at`. A different session id is recorded on the same row. If not visible, it raises a retryable `BUSY`, as for `spawn`.
- **Probe** (on every claim, run **before** the precondition):
  - `reserve`: done if the node is `spawning` with `spawn_tool_key` equal to this call; `None` if it was reaped meanwhile;
  - **`launch`:**
    - a listing shows the node's name with a `startedAt` later than `launch_at` → done;
    - the row is `reaped`, or `launch_at` is NULL → `None`;
    - otherwise → done-pending, and `identify` polls.
  - **Guard:** the node is `reaped`, or `spawning` under this call's key. Otherwise → `INVALID_STATE`, which fails cleanly. For example, a stale key A replayed after key B already resumed the node to `running` fails instead of wedging.
  - **The name survives a bare resume.** The spike recorded this: "a bare `claude --bg --resume <full id> \"<msg>\"` continues the session, which keeps its saved options and its name". `identify` and the reap rule rely on it.
  - The takeover compare-and-set rewrites only the holder columns, **never `started_at`**.
  - Delivery is at least once.
- **Records:** `spawning → running` on the **same generation**. If `identify` finds a different session id, `session_id` and `short_id` are updated **on the same row**, so the token in the session's transcript stays valid. Generations are bumped only by `spawn --replace`.

**`issue-create`**

- **Arguments:** `title`, `body_file`, `labels`.
- **Runs in:** `<MAIN>`. **Token:** run.
- **Steps:** `<MAIN>/venv/bin/python <MAIN>/scripts/qs/create_issue.py --title … --body "<file text>\n\n<!-- qs-cp-key: <tool>/<key> -->" --labels …`.
- **Probe:** `gh issue list --state all --limit 50 --json number,url,body`, filtered on the marker in `body`. It reads the issue bodies directly, so there is no search-index lag.
- **Records:** `issue_number`, `url`.

**`pr-create`**

- **Arguments:** `title`, `summary_file`.
- **Runs in:** the task worktree. **Token:** run or node (its own task only).
- **Steps:** `<MAIN>/venv/bin/python <MAIN>/scripts/qs/create_pr.py --title … --summary "<file text>\n\n<!-- qs-cp-key: <tool>/<key> -->" --issue <N>`. The step is `inject_token`, so its internal `git push` gets `QS_CP_TOKEN`. `refuse_when_stopped`.
- **Probe:** `gh pr list --head <branch> --state all --json number,url,body` through `Runner`, filtered on **this call's marker** in `body`. A new key never matches a PR from another key, closed or not. If `create_pr.py` itself finds an existing open PR for the branch, it reports it, and that is recorded.
- **Records:** `pr_number`, and `pr_url`, read from the script's `url`.

**`push`**

- **Runs in:** the task worktree. **Token:** run or node (its own task only).
- **Steps:** `git push -u origin <branch>` (`inject_token`). `refuse_when_stopped`.
- **Probe:** `git ls-remote origin refs/heads/<branch>` equals `git rev-parse HEAD` → done.
- **Records:** the pushed sha.

**`merge`**

- **Runs in:** `<MAIN>`. **Locks:** `integration:<branch>`, then `main-merge`. **Token:** run.
- **Steps:**
  1. `policy` (no effect): `merge_policy.check(task)`. A refusal → `POLICY_REFUSED`, and the claim is **released** under the §9.2 outcome table, so the key can be retried once the conditions hold.
  2. `head`: `gh pr view <pr> --json headRefOid` → output `oid`.
  3. `merge`: `gh pr merge <pr> --merge --match-head-commit <outputs.head.oid>`.
- **Probe:** `gh pr view <pr> --json state,mergeCommit`.
  - `MERGED` → `policy`, `head` and `merge` are **all** done, and the probe outputs `merge_sha`. A PR that has already merged is never re-judged by the policy.
  - Not merged → `policy: None` and `head: None`. Both are effect-free and always re-judged, so a replay never merges on a stale verdict or a stale head.
- **Guard:** the task is `ready_to_merge`, unless the probe found the PR `MERGED`. Otherwise → `INVALID_STATE`, which fails cleanly.
- **Records:** `merge_sha`, and the task state `ready_to_merge → merged`.

#### 9.5 Stopping, take-over, and the merge-policy seam

**`node stop --task T --token(run)`**

- Marks the task's current node `stopped` and posts a `stop` message to `node:<T>`.
- From then on, that node's `refuse_when_stopped` tools (`gate`, `push`, `pr-create`, and later #400's `integrate`), its `pre-push` and its state writes all exit 4.
- **Its reads, and `msg pop` / `msg ack` on its own queue, stay allowed**, so it can take its `stop` message.

**`node take-over --task T --token(run)`**

- Moves `running`/`idle` → `taken_over`, records `taken_over_at`, and posts an `info` message to the orchestrator.

**`node hand-back --task T --summary-file F --token(run, or node on its own task)`**

- Moves `taken_over` → `running`, and posts a `hand_back` message that carries the summary.

**`merge_policy`**

- `check(task) -> PolicyResult(ok, reason)` dispatches to the installed policy (`merge_policy.install(fn)`).
- **The default refuses, with "merge conditions are child 7's".**
- Tests install an allow-all policy through the reset fixture.

### 10. Hooks

The I/O formats are pinned from the Claude Code hooks reference (code.claude.com/docs/en/hooks, read 2026-10-03). The implementation re-checks the page **as a confirmation only**; if WebFetch is unavailable, the shapes below are authoritative.

**Settings fragment.** `Stop` takes no matcher:

```json
{"hooks": {"<Event>": [{"matcher": "<regex>", "hooks": [{"type": "command", "command": "<cmd>", "timeout": <s>}]}]}}
```

**`Stop`.**

- **Input:** stdin JSON with, among other fields, `session_id`, `cwd`, `permission_mode`, `hook_event_name: "Stop"` and `stop_reason`.
- **No `stop_hook_active` field is relied on.** It is absent from the current reference, so the loop guard uses `hook_events` instead.
- **Output:** to block, `{"decision": "block", "reason": "…"}` with exit 0. Otherwise, exit 0 with no output.

**`PreToolUse`.**

- **Input:** `session_id`, `cwd`, `hook_event_name: "PreToolUse"`, `tool_name` and `tool_input` (`command` for Bash, `file_path` for Edit/Write).
- **Output:** to deny, `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "…"}}` with exit 0. Otherwise, exit 0 with no output.

**Failure policy.**

- `Stop` and `PreToolUse` **fail open**. On an internal error or a schema mismatch they exit 0, record the event in `hook_events` if the DB is usable, and write one line to stderr.
- `pre-push` **fails closed** only when it can prove the worktree is registered; otherwise it fails open.

#### 10.1 `hook stop` (the orchestrator's)

1. Look up `session_id` in `run_leases.session_id`, then in `run_sessions`.
   - Not an orchestrator, or a superseded one → allow. This is the self-end rule.
2. If a visible message waits for `orchestrator` in its run → block, with the reason "N message(s) wait in run R's queue: pop the next with `<MAIN>/venv/bin/python <MAIN>/scripts/qs/cp.py msg pop --run R --as orchestrator --token …`, handle it, ack it."
   - **Loop guard:** the hook records each block in `hook_events`, with the head message id. If the previous **two** blocks for this session have the same head id, and nothing was acked in between, the hook **allows** the stop instead. It then records a `hook_events` row with `decision='alert'` ("queue not draining"), which child 14's watchdog will read.
   - **No message is posted**, so the hook never re-arms itself.
3. If the run is open and no live `waiters` row exists → block **once**, with "start `cp.py wait --run R --token …` in the background". If the previous `hook_events` row for this session is already this block, allow the stop instead, and record a `decision='alert'` row ("orchestrator idle with no wait").
4. Otherwise → allow.

#### 10.2 `hook pre-tool-use`

**For every session the hook runs in:**

- **Bash.** The command is split into segments on `;`, `&&`, `||`, `|` and newlines, with a plain regex (no `shlex`).
  - A segment is **denied** when it mentions `harness_state.db` **and** does not mention `scripts/qs/cp.py` **and** its first word is not in the read-only allowlist: `grep`, `rg`, `git`, `ls`, `sed` (with `-n`), `cat`, `head`, `tail`, `wc`, `find`, `echo`.
  - Documentation and `.gitignore` work therefore goes through. `sqlite3`, `rm`, a `python -c` or a redirection onto the DB do not.
- **Edit and Write** of a `file_path` whose basename is `harness_state.db`, `harness_state.db-wal` or `harness_state.db-shm` → deny.
- **Read** is not denied: reading is harmless, and `cat` is allowed anyway.

**For registered sessions only:** current or superseded orchestrators, and nodes of any generation.

- A Bash segment `gh pr merge …` → deny ("merges go through `cp.py tool merge`").
- `SendMessage` from a superseded or stopped session → deny. This fences node messages, which the epic names in the fencing scope.

**Unregistered sessions** (the frozen pipeline) keep `gh pr merge`.

**Matcher:** `Bash|Edit|Write|SendMessage`.

#### 10.3 `pre-push` (git)

**The installer, `install_pre_push(common_dir)`.** It **refuses** with `POLICY_REFUSED` in three cases:

- `git config core.hooksPath` is set;
- a **foreign** `pre-push` exists (one without the marker);
- under `PYTEST_CURRENT_TEST`, `common_dir` is not under a temporary directory.

Otherwise it writes the shim with mode 0755. It is idempotent: the same marker version is a no-op, and an older one is rewritten.

**The shim** is POSIX sh, with the marker `# qs-control-plane pre-push shim v1`:

- `MAIN` is the parent of `git rev-parse --path-format=absolute --git-common-dir`;
- it runs `exec "$MAIN/venv/bin/python" "$MAIN/scripts/qs/cp.py" hook pre-push "$@"`, falling back to `python3`;
- it exits 0 when `cp.py` is missing.

Linked worktrees share the common hooks dir, so this one shim covers every worktree.

**`hook pre-push`** reads git's stdin lines (`<local ref> <local sha> <remote ref> <remote sha>`):

1. **In every worktree, without the DB:** refuse any line whose local or remote ref is `refs/heads/QS_<digits>_<digits>`. Work items are never pushed (#400). Other refs are unaffected.
2. If the DB is missing or its schema mismatches, or the worktree's toplevel is not the `worktree` of any task → allow. This covers the frozen pipeline, the maintainer, and `worktree-create`'s own first push.
3. For a registered task, refuse:
   - when its current node is `stopped`;
   - when the remote ref is anything other than `refs/heads/<task.branch>`;
   - when `QS_CP_TOKEN` is missing, or not valid for that task's run or current node. The refusal hints: "push through `cp.py tool push`".

`git push --no-verify` bypasses the hook. That is documented as a convention.

#### 10.4 `hooks-settings` and the wiring

`cp.py hooks-settings --role node|orchestrator` prints the fragment above, with absolute `<MAIN>` paths:

- `node`: `PreToolUse` only;
- `orchestrator`: `PreToolUse` and `Stop`.

It needs no DB.

**Wiring** (maintainer, 2026-10-03; recorded in the epic):

- **Nodes:** `claude --bg --settings '<json>'` at spawn. No file is written.

### 13. Liveness

**`ProcessProbe.alive(pid, start) -> bool`**

1. Calls `os.kill(pid, 0)`. `ProcessLookupError` → dead. `PermissionError` → **alive**.
2. Compares the start time read from `ps -o lstart= -p <pid>`, run with `LC_ALL=C` and parsed as `%a %b %d %H:%M:%S %Y` (works on both macOS and Linux). A mismatch means the pid was reused → dead.

**`ProcessProbe.group_alive(pgid)`** uses `os.killpg(pgid, 0)`. **`ProcessProbe.start_of(pid)`** returns the same `ps` value. If the pid no longer exists, it returns `None`, and the caller treats the session as dead: `lock acquire` gets `USAGE`, "session not running".

**`ClaudeCli`**, behind a `Runner`:

- `agents()` runs `claude agents --json` and parses `sessionId`, `id`, `name`, `cwd`, `kind`, `status`, `state`, `pid` and `startedAt`. Any parse or exec failure raises `CpError("INTERNAL")`, which callers treat as "unknown".
- `spawn_bg(argv, cwd, env)` and `resume_bg(session_id, msg, cwd)` launch and resume background sessions.

## Acceptance criteria

1. **Schema v1.**
   - Every table of §4 exists.
   - `nodes.TRANSITIONS` and `tasks.TRANSITIONS` refuse illegal moves with `INVALID_STATE`.
   - `snapshot` returns the key set of §12, with no nonces. A golden test pins it. `task show` returns a task with its digest body.
2. **Self-migration.**
   - A fresh DB is created and migrated only by `migrate(role="daemon")` from main code with `main` checked out, or on a non-live test DB. A feature branch on main, or another caller, gets `POLICY_REFUSED`.
   - A backup is written **before** each migration of an existing DB, outside the checkout.
   - A fault at `migrate.mid_step`, after a real DDL statement, leaves `user_version` at the previous value with **no partial table**, and the backup present.
   - Two concurrent migrators: one migrates, the other gets `noop`.
   - Non-exempt commands poll until the DB is migrated, or return `SCHEMA_PENDING` at the timeout.
   - The registry has no version gap.
3. **Schema mismatch.**
   - With `user_version = SCHEMA_VERSION + 1`, every **non-exempt** command exits 5 `SCHEMA_TOO_NEW` and writes nothing. This is a test parametrized over the CLI table.
   - A write transaction opened before a migration fails with `SCHEMA_TOO_NEW` (`db.write` re-check).
   - An older DB with a migrating (fake) daemon: the command proceeds.
   - The exempt commands (§3) are asserted separately:
     - the hooks fail open, except `pre-push`'s item-ref refusal;
     - `hooks-settings` and `version` work;
     - the read-only commands answer at once: empty on a missing DB, `SCHEMA_PENDING` on an older one;
     - none of them waits or calls `ensure`.
4. **Path guard.** Each of these exits 7:
   - worktree code naming main's live DB through `QS_CP_DB`;
   - worktree code with no `QS_CP_DB`;
   - any code naming a non-main checkout's `harness_state.db`;
   - any live-DB path under pytest.

   A `QS_CP_DB` on a temporary path works. `paths.main_checkout` is tested on both layouts: a `.git` directory, and a `.git` file resolved through `gitdir:` and `commondir`.
5. **Queues.**
   - Order of arrival is kept per recipient.
   - `pop` moves a message to `in_flight` with a visibility timeout and a receipt.
   - An expired message is redelivered first.
   - `ack` needs the current receipt: a late ack gets `CONFLICT`, and a repeated ack is a no-op.
   - A message past `MAX_ATTEMPTS` becomes `dead` and stops blocking its queue.
   - `dedupe_key` makes `post` idempotent.
   - **The concurrent pop test** (8 threads, 200 messages, each popped exactly once) passes.
   - **The queue-replay test** (§7.1) passes: one effect for `issue-create`, for `spawn` and for `merge`.
6. **`wait`.**
   - It checks the token first: a stale token exits 3, with no write and no `Popen`.
   - It returns when the run's orchestrator queue is not empty, without popping.
   - It calls `ensure` before blocking, and on a stale heartbeat (rate-limited).
   - It exits 5 with `restart_wait` after a migration.
   - It times out cleanly.
   - Its `waiters` row is added, then removed on exit and on SIGTERM.
7. **`ensure` and the daemon.**
   - `ensure` is a no-op on a fresh lease at the same schema version.
   - On a stale, absent or cleared lease, it starts the daemon detached (`start_new_session`, `DEVNULL` stdin, output to the log file).
   - On a **lower schema version in the lease**, it sends SIGTERM to the old daemon, waits for the lease to clear or for `DAEMON_RESTART_WAIT_S`, then starts a new one, and the pending migration completes.
   - A second daemon exits with `held_elsewhere`.
   - The daemon migrates, heartbeats and runs its tick hooks; it exits on idle and on SIGTERM, and clears its lease.
   - A failing migration, or a refusal, including against a missing DB, writes `<db>.migrate-error.json` and exits 1. `ensure` does not respawn within `MIGRATE_BACKOFF_S`, and a waiting command's `SCHEMA_PENDING` carries the error.
   - Against a live DB, `ensure` from non-main code is refused.
8. **Idempotency by construction.** For **each** built-in side-effect tool (`worktree-create`, `worktree-cleanup`, `spawn`, `resume`, `issue-create`, `pr-create`, `push`, `merge`):
   - replaying a `succeeded` key gives exactly one effect and `replayed:true`;
   - the same key with different args → `CONFLICT`;
   - the same key under different tools are independent calls;
   - a fault at `before_effect`, then a replay, gives one effect;
   - a fault at `after_effect`, then a replay, gives **one effect** (`gate` is excluded: no probe, and safe to re-run);
   - **two concurrent same-key calls** → one runs, the other gets `BUSY`;
   - a holder whose pid is dead but whose **group** is alive still gives `BUSY`;
   - a **fresh** key with a probe sees effects already in place (for example a pre-existing worktree);
   - `spawn` replayed after a fault **at `reserve.after_effect`** or between `reserve` and `launch` reuses the reserved row (found through `spawn_tool_key`): no second generation, no `CONFLICT`;
   - the same replay after **another cap transaction reaped that row** gets `reserve: None` from the probe, re-takes the row (`reaped → spawning`), launches once and ends `running`. The same holds for a `resume` replayed after a crash past `launch` whose row was reaped: no `INVALID_STATE`;
   - the outcome table of §9.2 holds: a step failure spends the key; a `BUSY`, `POLICY_REFUSED` or `STALE_TOKEN` before any effect releases it, so the same key works on retry;
   - `merge` replayed after the PR merged is recorded `succeeded`, without consulting the policy. Replayed before the merge, it re-runs `policy` and `head`;
   - **state drift fails cleanly**: a replay whose node or task changed state (superseded, stopped, resumed by another key, task blocked) is recorded `failed` with `INVALID_STATE`, with no further effect and no wedge, for `spawn`, `resume` and `merge`;
   - a replay after `launch` whose session then died **and whose row was reaped** gets `launch: None`, relaunches once, and ends `running`;
   - a replay **right after `launch`, before the session is listed**, does not relaunch: done-pending. `identify` polls, and a timeout leaves the call `started` with the key unspent. Within `LAUNCH_SETTLE_S` the row is not reaped;
   - every built-in tool on a `dropped` or `merged` task fails with `INVALID_STATE` and no effect, except `worktree-cleanup`;
   - `pr-create` with a new key on a branch whose earlier PR was closed creates a new PR;
   - every call leaves a `tool_calls` row with actor, timestamps, result and exit code, and **no token or nonce**.
9. **Identity.**
   - `spawn` records, per generation row: name, full session id, short id, permission mode, generation, nonce and state.
   - The lease records the orchestrator's session id, name, short id (NULL for an interactive session), permission mode and full grant.
   - `take-over`, `hand-back` and `stop` move the states as in §4, and post their messages.
   - A missing session id gives `USAGE`.
10. **Run lease and takeover.**
    - The two concurrent-claim tests of §6.2 pass.
    - A live holder without `--takeover` → `CONFLICT`.
    - `--takeover` bumps the epoch and leaves the name binding pending.
    - `bind-name` succeeds only once the old session is absent from a successful listing.
    - The holder re-claiming its own run gets a new token, with no supersede and no rebind.
    - A failed listing is never treated as absence.
11. **Fencing.**
    - With a stale token, each of these exits 3 and changes no row:
      - every effectful command;
      - `msg post`, `pop` and `ack`;
      - `wait`;
      - every tool, with **no `Runner` effect and no `Popen`**;
      - acquiring `main-checkout`, `integration:<b>`, `main-merge` or a gate slot.

## Risks

1. **Size.** This is the largest factory task so far. Mitigation: 12 committed, green checkpoints, with resumable progress notes, and the local gate sees the Control Plane from checkpoint 1.
2. **SQLite under many processes.** WAL, `BEGIN IMMEDIATE` and `busy_timeout`, and no subprocess inside a transaction. A `database is locked` past the timeout becomes `BUSY`, never a crash.
3. **Drift in Claude Code's hook format or in `claude agents --json`.** The formats are pinned by tests, the hooks fail open, and a failed liveness listing is never read as absence.
4. **The common-dir `pre-push` shim affects the maintainer's own pushes.** It is inert outside registered worktrees, except for `QS_<N>_<k>` refs, which nobody pushes.
5. **CI time.** The concurrency tests are bounded at ≤ 2 s each, and the real-seam tests use temporary fixtures.
