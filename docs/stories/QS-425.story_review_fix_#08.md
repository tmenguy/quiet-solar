## Root cause of most round-8 findings

Fix #07 used one field, `catchup`, for two different things:
- the **catch-up in progress** (entered, not yet pushed);
- the **last pushed catch-up merge**, which the next build round needs as `--base`, and which step 6 also used as the
  marker for "this is a catch-up's own wait".

So whenever a new catch-up overwrote the field (at the bound, or on a stale conflict), the `--base` was lost. And
whenever the field survived (after a block), step 6 took a stale value as "a catch-up's own wait" and went to done.
Splitting the field fixes R8 items 1, 2 and 3 together.

## The design change

### `round.json`: two fields instead of one
- `"base_merge"`: `null`, or the merge commit of the **last pushed** catch-up.
  - Set by the catch-up push write.
  - Consumed as `--base` by the next build round's `round start`, and cleared in the write right after it. A resume
    at `step: pushed` whose round is already visible **still does that clearing write**.
  - Also cleared by step 8's first write.
  - While it is set, the current `head` is a catch-up head.
- `"catchup"`: `null`, or **only the catch-up in progress**: `{"from": "conflict"|"done", "counted": true|false,
  "merge": <sha>|null, "clean": true|false|null, "reviewed": true|false}`.
  - Set when step 7 is entered.
  - The catch-up push write sets it to `null`, in the same write that sets `base_merge` = its `merge`.

Update the field description so it states these lifetimes exactly.

### Step 7, items 1 and 2 (R8 edge S2, R8 blind 2, R8 edge S1)
- **`done` trigger:** run `git fetch origin main` and the ancestor test **first**.
  - Ancestor → step 8 directly. Its first write clears `catchup` and `base_merge`. There is no other write and no
    count.
  - Otherwise → item 1.
- **`conflict` trigger:** item 1 first, as now. A stale exit is still counted, which bounds a stale `mergeable` spin.
- **Item 1:**
  - If `catchups` is already 3: one write, `step: catchup` and `catchup` = `{from, "counted": false, "merge": null,
    …}`, then blocked (cause `catchups`), with no merge.
  - Otherwise: one write, `step: catchup`, `catchups` + 1 and `catchup` = `{from, "counted": true, "merge": null,
    "clean": null, "reviewed": false}`.
- **Item 2:** `git fetch origin main`, unless the `done` path already did it.
  - Ancestor and `from` `conflict` → one write, `catchup` = `null` and `step: wait`. **`base_merge` is untouched**, so
    a pushed merge survives a stale conflict.
  - Not an ancestor → `git merge --no-ff origin/main`, so a merge commit always exists.

### Step 7, items 3–5 (R8 edge S3, nice-to-haves N3/N4)
- **Item 3:** record `catchup.merge` and `catchup.clean` in one write.
  - Clean merge: `git rev-parse HEAD` right after the merge.
  - Conflicts: after the implementer's resolution commit, `git log -1 --merges --format=%H <round.json head>..HEAD`.
    An empty result means no merge was made: back to item 2.
- **Item 4:** unchanged, except that **any implementer invocation that moves `HEAD` sets `catchup.reviewed` =
  false** in the write that follows it.
- **Item 5** runs when `catchup.reviewed` is false **and** either `catchup.clean` is false or `HEAD` ≠
  `catchup.merge`. It ends with `catchup.reviewed` = true.

### Start-up rule 5, `catchup` (R8 CodeRabbit and auditor: the contradiction with case 2)

4. `catchup.merge` is set → finish the remaining sub-steps in order:
