## Findings to fix

### [should-fix] SF-1 — Pass-2 offset must dominate the aggregate base spread (path A)
- File: `custom_components/quiet_solar/ha_model/home.py:2705`
  (`compute_and_set_best_persons_cars_allocations`, pass-2 `penalty`);
  `custom_components/quiet_solar/const.py:499-501` (relation (i) text);
  `tests/test_person_car_allocation.py` (new regression pin);
  `tests/test_hungarian_algorithm.py` (replica `_run_two_pass` pass-2 offset,
  keep in sync per round-3 N-2).
- Severity: should-fix
- Source: qs-review-coderabbit (Major, `home.py:2705`) + qs-review-edge-case-hunter
  (independent confirmation, `const.py:499-501`)
- Description: Shipped `penalty = n*E_max + 1.0 + PASS2_PREFERRED_CAR_OFFSET_EPS_WH`
  exceeds one cell's spread (`E_max + 1.25`) but Hungarian minimises **total**
  cost, so two assignments whose preferred-count differs by one can differ in
  base cost by up to `(n-1)*(E_max + 1.25)`. CodeRabbit's counterexample
  (E_max == 0, n == 4, penalty 2.0): preferred-bearing assignment costs 9.0 vs
  four covered non-preferred cells 8.0 → Hungarian drops the preferred match.
  Edge-case-hunter reproduced a confirmed 3×3 case at E_max == 0
  (`pref=[2,1,2]`, rows `[unauth,0.0,1.25] / [0.0,0.25,0.0] / [1.25,0.0,0.25]`)
  returning 1 preferred match where 2 are achievable. `len(p_s)` is the correct
  multiplier (one decision per person; extra cars add unused columns only);
  padding (`home_utils.py:165/185`) and the `1e12` `maxi_val` floor are safe
  (~6 orders of magnitude margin) — the multiplier and shape are NOT the defect.
- Proposed fix (path A): make the pass-2 offset dominate the summed spread:
  ```python
  penalty = (
      len(p_s) * (E_max + 1.0 + PLUGGED_COVERED_CAR_PENALTY_WH)
      + PASS2_PREFERRED_CAR_OFFSET_EPS_WH
  )
  ```
  (`n*(E_max + 1.25) + 1.0`; worst case n == 1, E_max == 0 → 2.25 > 1.25; and
  for the summed spread `n*(E_max+1.25) + 1.0 > (n-1)*(E_max+1.25)` strictly
  for all n >= 1, E_max >= 0.) Re-verify `maxi_val` still dominates the new
  largest legitimate pass-2 cell `(E_max+1.25) + n*(E_max+1.25) + 1.0`
  (`1e12` floor — trivially yes; state it). Rewrite const.py relation (i) to
  state the **aggregate** guarantee (offset > summed differing-cell spread ⇒
  pass 2 maximises preferred-car count for all n, E_max), replacing the
  per-cell "max_base − min_base = E_max + 1.25" argument. Update the
  `home.py:2699-2704` comment accordingly. Sync the `test_hungarian_algorithm.py`
  replica offset. **Red-test protocol:** add
  `TestSentinelAndPass2Ordering::test_pass2_offset_dominates_aggregate_spread`
  (or similar) driving the n == 4, E_max == 0 counterexample (and/or the 3×3
  case) through the real pipeline, asserting the maximum preferred-count
  assignment is returned and (via `caplog`) that the preferred pass is adopted;
  run it red first against the shipped offset (baseline `62b24385`), record the
  **full verbatim** `pytest tests/...::Class::test -v` transcript (file-prefixed
  node line + `FAILED` + assertion block + `1 failed in …s`) in the story
  progress note and PR body. Confirm the existing round-3 pass-2 pins and the
  E_max == 0 invariant pin still pass.
