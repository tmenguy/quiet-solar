# QS-404 — Diagrams as first-class files: `epic_doc.py land` carries an epic's generated SVGs, and every SVG stays up to date

**Issue**: [#404](https://github.com/tmenguy/quiet-solar/issues/404) ·
**Lane of this task**: feature-factory (`target:factory`) ·
**Parent epic**: #369 (child 19, wave 4, first)

Status: planned (story v4 — converged after 3 review rounds)

## Problem

An epic document's SVG diagrams are generated from its Mermaid blocks by
`scripts/qs/mermaid_svg.py`. It renders every block that carries an `@out`
hint. Three things keep those SVGs from staying up to date:

1. **`land` cannot carry them.** `scripts/qs/epic_doc.py land` is the only
   way an **epic session** gets its document onto `main`. It lands exactly
   `docs/epics/QS-<N>.md` and refuses every other changed path
   (`out-of-scope`, the N6 rule in `cmd_land`). So an epic session can
   land an edited Mermaid block but not its SVG. CI's
   `tests/qs/test_mermaid_svg.py::test_every_svg_in_docs_is_up_to_date`
   then goes red on `main`.
   (A child's PR may also amend its epic's document, under the
   project-rules "Epic documents" rule. This child takes that path for its
   first-use fix.)
2. **The agent's rules forbid writing them.** The rule "the only file you
   write is `docs/epics/QS-<N>.md`" appears in three places: the template
   `scripts/qs/agent_templates/qs-decompose-epic.md.j2`, the lane file
   `docs/workflow/lanes/epic-factory.md`, and
   `docs/workflow/project-rules.md` → "Epic documents".
3. **The pre-commit gate cannot see them.** `quality_gate.py --impacted`
   misses a stale SVG. testmon fingerprints only `.py` files, so a
   Markdown-only change set takes the non-`.py` early exit, and only CI
   finds the stale SVG.

As a result, view 1 of `docs/epics/QS-369.md` still reads "Run queues · one
per run". #399 built one queue per **recipient** in a run ("What wave 3
built" under "Evidence"). The epic's round-1 review rejected the fix for
exactly the reason in point 1.

## Goal

Maintainer, 2026-10-06: "the graph files are first-class citizens now, I
want them always up to date."

- `epic_doc.py land` lands an epic's document **with** the SVGs that its
  own `@out` hints declare, **always freshly rendered**. It still refuses
  every other path.
- The epic agent may write those SVGs, and re-renders after editing a
  diagram.
- `--impacted` fails on a stale SVG before commit, as CI already does.
- First use: fix view 1's label, and check both epic diagrams against what
  wave 3 built.

## Decisions

These answer the issue's open points and record the choices this plan
adds.

- **D1 — `land` renders the SVGs; it does not refuse a stale one.** "Always
  up to date" favours rendering: the agent cannot forget it.

- **D2 — `land` renders in memory, never into the working tree.**
  - The landing rule promises: "the working tree is never modified before
    the push is verified". So `land` renders each declared SVG in memory.
    The landing commit gets the **rendered** bytes, whatever the
    working-tree SVG holds.
  - The rendered text is written to a temp file **outside** the repository
    and hashed with `git hash-object -w --path <svg> -- <tmp>`.
    - `--path` applies the same `.gitattributes` filters as the
      working-tree hash (`_worktree_blob`).
    - `utils.run` has no `input=` argument, so stdin is not used.
  - The final `reset --hard origin/main` then brings every working-tree SVG
    that is on `main` to the landed bytes. A reset never touches an
    untracked file that `main` lacks, which is why D5 step 6 treats such a
    file specially. An SVG is derived data, so ignoring a stale local copy
    loses nothing.
  - The agent still renders to disk (D6), so the user sees the picture in
    the editor.

- **D3 — What `land` may land: the doc, plus the SVGs it declares.**
  - **Declared SVGs.** These are the repo-relative paths of the `@out`
    hints in the **landed doc's** Mermaid blocks (D4), resolved against
    `docs/epics/`.
  - **Repo-relative form.** The form is
    `Path(os.path.relpath(svg_path, Path(root).resolve())).as_posix()`. A
    hint that escapes the repo therefore shows as `../x.svg` rather than
    raising.
  - **Allowed target.** Each path must `fullmatch` the `_svg_pattern(issue)`
    regex: `docs/epics/img/QS-<N>-[A-Za-z0-9._-]+\.svg`. Otherwise `land`
    refuses `out-of-scope`. The offender is the repo-relative path, and the
    detail says an epic's `@out` must target `docs/epics/img/QS-<N>-*.svg`.
  - **Undeclared SVGs.** Any other changed path is still `out-of-scope`,
    including an SVG that matches the pattern but that no hint declares.
    That refusal carries a hint: "a leftover render — delete it, or
    restore main's copy with `git checkout origin/main -- <path>`".
  - **Deletions.**
    - Deleting an **undeclared** pattern SVG is refused (`out-of-scope`).
    - A locally deleted **declared** SVG is not a deletion: `land` lands
      its rendered blob. `_build_commit` checks `path in contents` before
      its `is_file()` branch, so an absent declared SVG is never removed
      from the tree.
  - **Orphans.**
    - When a hint is removed or renamed, the old SVG file stays as it is,
      so it remains on `main` as an orphan.
    - CI's every-SVG test checks only declared outputs, so an orphan never
      turns it red.
    - Cleaning up orphans is out of scope.

- **D4 — `land` renders the doc that will land, with `main`'s renderer.**
  - **Source text** (`_landed_doc_text`).
    - If the doc is in the git change set, `land` renders the working-tree
      doc. The change set is computed against the merge-base with
      `origin/main` (`_changed_paths`).
    - Otherwise it renders `origin/main`'s blob of the doc. That doc is the
      one that lands, so a stale local doc never produces an SVG.
    - If `main` has no doc, the text is `None` and declares nothing.
  - **When the renderer is loaded.** Only when the source text contains the
    substring `@out`. That is the single rule, and `land` calls no other
    predicate.
    - A doc that only mentions `@out` in prose (QS-369 does) loads the
      renderer and finds no declared block. That is harmless.
    - A doc without `@out` lands exactly as today.
  - **Which renderer.** `origin/main`'s `scripts/qs/mermaid_svg.py`, read
    with `git show` (`_main_renderer`).
    - `_load_renderer(source)` `compile`s and `exec`s it into
      `types.ModuleType(f"qs_mermaid_svg_main_{uuid.uuid4().hex}")`. That
      name is registered in `sys.modules`, because `dataclasses` resolves
      string annotations through it.
    - **Who removes it.** `_load_renderer` removes the name on **any**
      failure (an exception in `exec`, a missing `outputs_from_text`) before
      it raises. On success it returns `(module, key)`.
    - `_declared_svgs` sets `key = None` before its `try` and removes the
      name in its `finally` only `if key`, once rendering is done. No
      `sys.modules` entry is ever left behind.
    - This is exactly what CI on `main` checks, so `land` needs no
      "stale renderer" refusal.
    - The renderer's import contract makes this safe: stdlib-only imports,
      no `__file__` / `__spec__` / data-file use, and no side effect at
      import. The contract is stated in the renderer's docstring and
      pinned by a test (AC 12).
  - **Two renderers, by design.** `land` always uses `main`'s renderer,
    because what it lands must pass CI on `main`. The `--impacted` check
    (D8) uses the worktree's renderer, which is what CI on the PR runs.
  - **`diagram-error` refusals:**
    - `origin/main` has no renderer;
    - `main`'s renderer has no `outputs_from_text` (it predates this
      child);
    - any exception while loading or rendering, including a duplicate
      `@out` (raised by `outputs_from_text`, see §1). The detail is
      `str(exc)`. The catch is a broad `except Exception`, as in `_drift`,
      to keep the contract "JSON refusal, never a traceback".
  - **Effective change set.**
    - It starts from the git-changed paths.
    - It adds every declared SVG whose rendered blob differs from its
      `origin/main` blob, even when the working tree never touched that SVG
      (the agent forgot to render).
    - Computation: `main_blobs` is taken over `set(changed) | set(rendered)`.
      Then `effective = sorted(set(changed) | {p for p in rendered if
      rendered_blobs[p] != main_blobs[p]})`.
    - The "local blob" of a declared SVG is its **rendered** blob. That is
      the blob used by the rendered-blob shortcut, the build and `paths`.
    - An empty git change set is still `already-landed` / `missing-doc`
      exactly as today, without rendering.

- **D5 — The refusal order of `cmd_land`.** Rendering never blocks the
  cleanup of a worktree that has already landed, when the doc is in the
  change set: the usual landed-but-not-reset state. When only SVGs
  changed, the shortcut has nothing to compare, so `land` renders. A broken
  `main` renderer then gives `diagram-error`, which is acceptable: that
  state means a re-render without a doc change.
  1. Arguments: `--merged`, empty `--message`.
  2. `_toplevel`, `_issue_info`, `_require_epic`, `_fetch_main`.
  3. `_changed_paths`.
  4. **Pre-render scope.** Any changed path that is neither the doc nor a
     `_svg_pattern` match is `out-of-scope`. The existing offender tests
     keep their exact `offenders`: `.QS-900.md.swp`, `QS-900.md.orig`,
     `docs/epics/tool.py` and `docs/epics/QS-1.md` all fail here.
  5. Empty change set → `already-landed` (`paths: []`) or `missing-doc`. A
     doc missing from the working tree → `missing-doc`. Both are unchanged.
  6. **Working-tree shortcut.** `_all_blobs_on_main` runs over the changed
     paths **that do not match `_svg_pattern`**, under two conditions:
     - that list is non-empty;
     - **every** changed `_svg_pattern` path exists in `origin/main`'s tree
       (`main_blobs[p] is not None`), so the reset really overwrites it.

     Otherwise the shortcut is skipped and `land` goes on to step 7. That
     way:
     - an untracked leftover SVG that `main` lacks reaches step 8's
       refusal, with the leftover hint;
     - a declared SVG that `main` lacks gets landed.

     SVGs are derived, so a local SVG on `main` that was drawn by a
     different renderer is simply discarded by the reset (D2). The result
     is `already-landed`, with a reset and `paths: changed`, as today. A
     dry-run gives `ok-dry-run` with `already_landed: true` and no reset.
  7. **Render** (D4): `undecodable` / `diagram-error` / `out-of-scope` (a
     bad `@out`).
  8. **Declared-set scope.** A changed `_svg_pattern` path that the doc
     does not declare → `out-of-scope`, with the leftover-render hint.
  9. Effective set, then the **rendered-blob shortcut**: `_all_blobs_on_main`
     over the effective blobs → `already-landed` with a reset (dry-run as
     in step 6).
  10. `_validate_decomposition`, **only when the doc is in the change set**.
      Otherwise the doc that lands is `main`'s, which was validated when it
      first landed.
  11. `_drift`, then conflicts (D13), dry-run → build → push → verify →
      reset. All unchanged, except that they now run over the effective
      set.

- **D6 — The agent rule.** The epic agent writes two kinds of file:
  `docs/epics/QS-{{issue}}.md`, and the SVGs its `@out` hints declare
  (`docs/epics/img/QS-{{issue}}-*.svg`).
  - It writes the SVGs only through
    `python scripts/qs/mermaid_svg.py render docs/epics/QS-{{issue}}.md`,
    never by hand.
  - It re-renders after any change to a Mermaid block that has an `@out`
    hint. `land` re-renders anyway (D2, D4).

- **D7 — Permissions.**
  - **OpenCode.** The `edit` permission stays `docs/epics/**`, which
    already allows `docs/epics/img/` (template frontmatter L32).
    `"python scripts/qs/*": allow` (L51) already allows the render command.
    Narrowing the permission to issue-numbered globs would break the
    unbound renders (the main checkout, item worktrees), which have no
    issue. `land` remains the enforcer.
  - **Claude.** `.claude/settings.json` allow-lists
    `Bash(python scripts/qs/epic_doc.py:*)` and its `**/` variant, but not
    the renderer. Add `Bash(python scripts/qs/mermaid_svg.py:*)` and
    `Bash(python **/scripts/qs/mermaid_svg.py:*)` next to them, so the epic
    agent can re-render without a prompt. The command writes only the SVGs
    a document declares. No write hook restricts these paths.

- **D8 — `--impacted` gets a standalone diagram check, not a fifth cheap
  gate.**
  - The cheap-gate machinery (`_CHEAP_GATE_ORDER`,
    `_run_cheap_gates_parallel`) is shared with the full gate. The full
    gate already runs `test_every_svg_in_docs_is_up_to_date` in its pytest
    pass.
  - So `_impacted_diagram_check(paths)` runs right after
    `_impacted_cheap_checks`, before the non-`.py` early exit, on the warm
    and the cold baseline alike.
    `_impacted_early_exit_paths()` is computed on both paths, and returns
    `None` only on a git failure.
  - On failure it adds `"diagrams"` to `cheap_failed`. The `_with_cheap`
    wording stays as it is, so the final line reads
    `[impacted] FAIL (cheap checks failed: diagrams)`.
  - The check renders with the worktree's renderer (see D4, "Two
    renderers").

- **D9 — How `--impacted` detects a Markdown file with `@out` blocks.**
  The check uses the same `docs/` scope as CI.
  - **Sources.** The sources are every path of the
    `_impacted_early_exit_paths()` union that starts with `docs/`, ends in
    `.md`, and is an existing file.
    - The union covers four sets: the merge-base vs the working tree, the
      committed range, the index, and untracked files.
    - All of them go to `mermaid_svg.run(sources, check=True)`. A file
      without an `@out` block renders nothing and passes, so no extra
      predicate is needed.
  - **Fail-closed.** A `None` listing (a git failure) uses every
    `docs/**/*.md` as a source.
  - **Not covered on purpose.**
    - A changed `.svg` without a changed `.md` (hand-edited): left to CI.
    - A change to `scripts/qs/mermaid_svg.py`: testmon selects
      `tests/qs/test_mermaid_svg.py` for that `.py` change, and that file
      includes the every-SVG test.
  - **A trap for doc authors.** `mermaid_blocks` uses a plain regex, not a
    Markdown parser. Any line in `docs/` that starts with three backticks
    and `mermaid` opens a real block, even when it is nested inside a
    longer fence. Write examples of `@out` blocks indented, or in prose,
    never as a column-0 fence. This story does exactly that (AC 20).

- **D10 — `status` keeps its generic logic.**
  - `changed` already lists every changed path, SVGs included.
  - `safe_to_discard` / `landed_not_reset` compare working-tree blobs.
  - `status` never renders: it is a read-only snapshot, and a broken
    diagram must not make it refuse.
  - **Conservative corner.** A land whose reset never ran, with a stale
    local SVG, reads `safe_to_discard: false`. Re-running `land` recovers
    it through the D5 step-6 shortcut.
  - Tests pin that SVG paths are counted.

- **D11 — Where the `--impacted` tests live.**
  - They go in `tests/test_quality_gate.py`, the gate's existing test home.
    It already has the warm-baseline fixture, the `_seams` helpers and the
    autouse isolation stubs. It groups its tests in classes, so the new
    class follows the file's convention, not the plain-function default in
    `project-context.md`.
  - The issue says "covered in `tests/qs`". Only the renderer helpers are
    covered there (`tests/qs/test_mermaid_svg.py`). This is a recorded
    deviation.
  - The impacted run ignores `tests/test_quality_gate.py`, so the gate's
    tests run through `--quick tests/test_quality_gate.py` (AC 21).
  - **Coverage.** `scripts/qs/*.py` outside `scripts/qs/control_plane/` is
    in no gate's coverage scope. That includes `epic_doc.py`,
    `mermaid_svg.py` and `quality_gate.py`. So no command enforces their
    changed-line coverage; TDD still applies.

- **D12 — View 1's queue title drops "· popped one by one".**
  - A chip queue's title is drawn on one line, unwrapped, at 12.5 px bold,
    in a 370 px box.
  - At about 7.2 px per character plus 12 px, "Run queues · one per
    recipient in a run · popped one by one" (59 characters) overflows.
    "Run queues · one per recipient in a run" (39 characters) fits.
  - View 2 keeps "in order of arrival".
  - The non-SVG views 2, 5 and 6, which still say "run queue" / "the run's
    queue", are out of scope.

- **D13 — Declared SVGs never conflict.**
  - A declared SVG is derived from two things: the landed doc and `main`'s
    renderer.
  - A change to `main`'s SVG since the base can come from three places:
    - a doc change, which the doc's own conflict entry already covers, or
      D4 renders `main`'s doc;
    - a renderer change, which `land` already uses;
    - a hand edit, in which case `main` is already red.
  - So the conflict loop runs over the effective paths minus `rendered`,
    and `--merged` applies to the doc alone. When `main` changes an SVG,
    `land` simply re-renders it.
  - **This is a recorded deviation from the issue's literal text**, as D11
    is. The issue's "the `conflict` refusal and the `--merged` re-run cover
    the SVGs too" therefore holds in this sense: those paths land the doc
    **with** its re-rendered SVGs. Without this, a renderer change on
    `main` would force every open epic into an SVG conflict with nothing to
    merge.

## Design

### 1. `scripts/qs/mermaid_svg.py`

The current API, which keeps its signatures:

- `render_block(block: str) -> tuple[str | None, str]` returns the `@out`
  path and the SVG text.
- `mermaid_blocks(markdown: str) -> list[str]`.
- `outputs(md_path: Path) -> list[tuple[Path, str]]` returns resolved
  absolute paths with their SVG text.
- `run(paths: list[Path], check: bool) -> tuple[int, dict]`. The report is
  one of `{"status": "ok", "written", "up_to_date"}`,
  `{"status": "stale", "stale", "up_to_date"}` or
  `{"status": "error", "message"}`, with absolute paths as strings.
  `main()` prints the report.

Changes:

- **New `outputs_from_text(markdown: str, base_dir: Path) -> list[tuple[Path, str]]`.**
  It holds the body of today's `outputs()`, with
  `(base_dir / out).resolve()`. Two blocks declaring the same `@out` raise
  `MermaidSvgError("duplicate @out: …")`. `outputs(md_path)` becomes
  `outputs_from_text(md_path.read_text(encoding="utf-8"), md_path.parent)`.
- **`render_block` wraps** `parse` / `parse_hints` /
  `Renderer(...).render()` in `except Exception`. A `MermaidSvgError` is
  re-raised unchanged. Anything else becomes
  `MermaidSvgError(f"bad Mermaid block or hint: {exc}")`. Today these
  cases crash with a traceback:
  - `%% @node a at=1` raises `ValueError` in `_pair`;
  - a bare `%% @` and `@canvas 100` raise `IndexError`;
  - `vhv` without `x1=` raises `KeyError`;
  - an unclosed `shlex` quote raises `ValueError`;
  - `fs=0` raises `ZeroDivisionError` in `wrap`.
- **`run()` catches** `(MermaidSvgError, OSError, UnicodeDecodeError)`; a
  non-UTF-8 existing SVG raises the last one.
- **The module docstring** names the two new callers and states the import
  contract that D4 relies on.

### 2. `scripts/qs/epic_doc.py` — `land` carries the declared SVGs

New stdlib imports: `types` and `uuid`. `os`, `sys`, `tempfile` and
`shutil` are already imported. There is no module-level import of
`mermaid_svg`: `land` uses `main`'s renderer (D4).

New helpers:

- `_svg_pattern(issue: int) -> re.Pattern[str]`.
- `_landed_doc_text(root, doc, changed) -> str | None` (D4):
  - `_read_doc` when `doc in changed`;
  - otherwise `_blob_content(root, _main_blob(root, doc))`, which is `None`
    when `main` has no doc.
- `_load_renderer(source: str) -> tuple[types.ModuleType, str]` (D4).
  - It `compile`s and `exec`s `source` into a unique `types.ModuleType` and
    registers it in `sys.modules`.
  - A missing `outputs_from_text` → `diagram-error`.
  - On any failure it removes the name before it raises, so no
    `sys.modules` entry is left behind.
  - It needs no git, so a test can load the worktree's own source.
- `_main_renderer(root) -> tuple[types.ModuleType, str]`:
  - `_main_blob(root, "scripts/qs/mermaid_svg.py")` being `None` →
    `diagram-error`;
  - otherwise it reads the source with `git show` and returns
    `_load_renderer(source)`.
- `_declared_svgs(root, issue, text) -> dict[str, str]` maps each
  repo-relative SVG path to its rendered SVG text.
  - `text is None` or `"@out" not in text` → `{}`, without loading the
    renderer.
  - Otherwise, with `key = None` set before its `try`, it calls
    `_main_renderer`, then
    `outputs_from_text(text, Path(root).resolve() / "docs/epics")`, then
    applies D3 (`relpath`, `fullmatch`).
  - It turns any `Exception` other than its own `Refusal` into
    `diagram-error`.
  - Its `finally` removes the module's name only `if key`.
- `_text_blob(root, path, text, *, write=False) -> str` (D2).
  - It runs `Path(tmp).write_text(text, encoding="utf-8")` inside a
    `tempfile.mkdtemp` directory. That is the same call `mermaid_svg.run`
    uses to write an SVG.
  - It hashes with `hash-object [-w] --path <path> -- <tmp>` and removes the
    directory in a `finally`.

`cmd_land` follows D5's order:

- **Scope detail.** The step-4 detail names both kinds of landable path.
- **Effective set and blobs.** Built as in D4. `local_blobs[p]` is
  `rendered_blobs[p]` for a declared SVG, and `_worktree_blob` otherwise.
- **Conflicts.** The loop runs over `[p for p in effective if p not in
  rendered]` (D13). The conflict detail is unchanged.
- **Build.** `_build_commit(root, effective, message, contents=rendered)`
  takes a new keyword parameter, `contents: dict[str, str] | None = None`.
  - A path in `contents` is written with `_text_blob(..., write=True)`.
    This check comes **before** the `is_file()` branch.
  - Other paths are handled as today, so the existing direct calls (test
    L532/L638) and the `lambda *a, **k: None` monkeypatch (L626) keep
    working.
- **Payloads are unchanged.** `paths` lists the effective set, SVGs
  included.
- **Comments.** The `# noqa: C901` comment ("the nine steps") is updated.
  The N4/N6 comments are reworded for a multi-path set. The invariant still
  holds: the rendered-blob shortcut compares the same blobs the build
  writes.
- **Docs.** The module docstring and `land`'s argparse help now say: "lands
  the epic's own `docs/epics/QS-<N>.md` and the SVGs its `@out` hints
  declare, re-rendered with `main`'s renderer".

`cmd_status` gets a docstring; it has none today. The docstring says that
SVG paths count in `changed` / `safe_to_discard`. There is no logic change
(D10).

### 3. `scripts/qs/quality_gate.py` — the stale-diagram check under `--impacted`

- **New `_impacted_diagram_check(paths: list[str] | None, root: Path | None = None) -> list[str]`.**
  - `root = root or REPO_ROOT` is resolved inside the function, so a test
    can redirect it.
  - `import mermaid_svg` is done inside the function. It is a sibling
    import, the same mechanism as `import targets`. As a result the gate's
    light modes never load the renderer.
  - **Sources** (D9): `[root / p for p in paths if p.startswith("docs/")
    and p.endswith(".md") and (root / p).is_file()]`. With `paths is None`,
    the sources are `sorted((root / "docs").rglob("*.md"))`.
  - **No source** → print `[diagrams] SKIP (no docs/ Markdown changed)` and
    return `[]`.
  - Otherwise call `code, report = mermaid_svg.run(sources, check=True)`
    inside `except Exception`. An exception produces an `error` report.
  - Every line is written with `_emit("diagrams", …)`, which goes to
    stderr like the cheap checks. Nothing uses `print`.
  - **Pass**: `code == 0` → `[diagrams] PASS`, and the function returns
    `[]`.
  - **Fail**, printed in order:
    - one `[diagrams] stale: <os.path.relpath(p, root.resolve())>` line per
      stale path, or one `[diagrams] error: <message>` line;
    - then `[diagrams] fix: python scripts/qs/mermaid_svg.py render <md…>`,
      with the sources relative to `root`;
    - then `[diagrams] FAIL`. The function returns `["diagrams"]`.
- **`check_impacted`** sets
  `cheap_failed = _impacted_cheap_checks(early_exit_paths) +
  _impacted_diagram_check(early_exit_paths)` at today's call site, after
  the lane check and before `_check_impacted_tail`.
