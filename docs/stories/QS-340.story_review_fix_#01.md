### [must-fix] M2 — Test pins the live, evolving `docs/epics/QS-369.md`
- File: `tests/qs/test_epic_doc.py` (~800–804,
  `test_the_real_qs369_doc_parses_as_is`)
- Source: qs-review-acceptance-auditor
- Description: the test asserts `len(rows) == 7` and
  `[r.issue for r in rows[:3]] == [371, 372, None]` against the live doc.
  `main` has already filed child 3 as #375 (`d6984476`), so this fails as

  `rows` is non-empty, every row has a non-empty `child`, and

  change). Freeze any exact-shape assertion on an **inline fixture string**
  copied from the current table, not on the live file.

### [must-fix] M3 — `land` pushes any untracked file under `docs/epics/` to main
- File: `scripts/qs/epic_doc.py` (~346, `cmd_land` scope check;
  `_changed_paths`)
- Source: qs-review-edge-case-hunter
- Description: the scope check is `p.startswith("docs/epics/")`, and
  `_changed_paths` uses `--untracked-files=all`. Editor swap files
  (`.QS-N.md.swp`), `QS-N.md~`, and merge-tool `*.orig` / `*.bak` files are
  not gitignored, so they land on `main` unreviewed.
- Proposed fix: accept only paths matching `^docs/epics/QS-\d+\.md$`.
  Anything else, including other files under `docs/epics/`, refuses with
  `out-of-scope`, and the refusal detail lists the offending paths. Add
  tests for an untracked `.QS-N.md.swp` and a `QS-N.md.orig`: each must
  refuse and leave the tree byte-identical (use the existing `_refused()`
  snapshot helper).

### [should-fix] S1 — `land --dry-run` can run `git reset --hard origin/main`
- File: `scripts/qs/epic_doc.py` (~361–367 vs ~401)
- Source: qs-review-edge-case-hunter
- Description: the "every changed path already equals main" shortcut runs
  `_reset_to_main` before the `if dry_run` check. The docstring promises that
  dry-run stops before building the commit.
- Proposed fix: on dry-run, return
  `{"status": "ok-dry-run", "already_landed": true, "reset": false, ...}`
  and never call `_reset_to_main`. Test: in a landed-but-not-reset state,
  `--dry-run` leaves HEAD and the tree unchanged.

### [should-fix] S2 — The `land` preflight doesn't validate the Decomposition table
- File: `scripts/qs/epic_doc.py` (`cmd_land`, before the dry-run return at
  ~401)
- Source: qs-review-edge-case-hunter
- Description: a table cell such as `TBD` or `#371 (merged)` passes the
  preflight. Children get filed, `land` pushes, and then `sync-issue` refuses
  with `unparseable-decomposition`, which leaves FINALIZE half-done.
- Proposed fix: in `cmd_land`, dry-run and real alike, run
  `parse_decomposition` on each landing doc. Turn `UnparseableDecomposition`
  into a `Refusal("unparseable-decomposition", ...)` before any plumbing.
  Add a test.

### [should-fix] S3 — `cleanup_worktree.py --delete-branch` hides failures and can't be retried
- Files: `scripts/qs/cleanup_worktree.py` (~147, ~150–156, ~210–237),
  `scripts/qs/agent_templates/qs-finish-task.md.j2` (epic Case A report
  step)
- Source: qs-review-blind-hunter + qs-review-edge-case-hunter (deduplicated)
- Description:
  - `branch -D` runs even when worktree removal failed (`wt_error`), which
    masks the real error.
  - `status` stays `"removed"` when `branch_deleted` is false, and the finish
    template then reports "Worktree and branch removed".
  - The "worktree directory does not exist" early return skips the branch
    deletion, so a failed first run can never be retried.
  - With `--force`, a mismatched `--issue` force-deletes an unrelated
    `QS_<N>` branch.
- Proposed fix:
  - (a) Skip `delete_local_branch` when `wt_error` is set.
  - (b) When `args.delete_branch and not branch_deleted`, return a distinct
    status `"removed-branch-kept"` that includes `branch_error`.
  - (c) When `args.delete_branch` is set and `work_dir` is gone, run
    `git worktree prune` followed by `delete_local_branch` from the main
    worktree, then report.
  - (d) Before removal, read the worktree's checked-out branch
    (`git -C <wd> rev-parse --abbrev-ref HEAD`). Refuse the branch deletion
    if it isn't `QS_<issue>`.
  - (e) The finish-task template checks `branch_deleted` / `status` and
    reports a kept branch honestly.
  - Tests for each.

### [should-fix] S4 — `status`: the `behind` field is wrong and `safe_to_discard` is too strict
- File: `scripts/qs/epic_doc.py` (~232–244, `cmd_status`)
- Source: qs-review-blind-hunter + qs-review-edge-case-hunter (deduplicated)
- Description:
  - `behind` means "the doc differs between HEAD and origin/main", in either
    direction. As a result, `--sync` never fast-forwards a clean worktree
    that is stale only on other paths (lane files, `docs/agents/`, templates).
  - After a landed-but-not-reset run, `safe_to_discard` is false even though
    every changed byte is already on main.
- Proposed fix:
  - Compute `behind` as `rev-list --count HEAD..origin/main > 0`. If a
    distinct signal is useful, expose the doc-differs signal as
    `doc_differs`.
  - `--sync` fast-forwards when `safe_to_discard and behind`.
  - When every changed path's worktree blob equals its main blob, report
    `safe_to_discard: true` plus `landed_not_reset: true`. This is the same
    test `cmd_land` already uses; factor it into a helper.
  - Update any lane / agent-template prose that names `behind`, and update
    the tests.

### [should-fix] S5 — `_drift` can leak a traceback
- File: `scripts/qs/epic_doc.py` (~292–300)
- Source: qs-review-blind-hunter
- Description: only `json.JSONDecodeError` is caught. A `SystemExit` (from
  argparse) or any other exception inside `check_doc_drift.main` escapes the
  module's "JSON refusal, never a traceback" contract.
- Proposed fix: catch `SystemExit` and `Exception`, and raise
  `Refusal("drift", detail=str(exc))`. Add a test.

### [should-fix] S6 — `setup_task.py` accepts `--next-cmd decompose-epic` for a non-epic issue

- Source: qs-review-blind-hunter + qs-review-edge-case-hunter (deduplicated)
- Description: `refuse_if_epic` returns early for non-epics. Setup then cuts

### [should-fix] S7 — `sync_body` anchors outside `## Children`, and duplicates split blocks
- File: `scripts/qs/epic_doc.py` (~613–638, `sync_body`)
- Source: qs-review-edge-case-hunter
- Description:
  - (a) The anchor is the first block anywhere in the body that mentions a
    table issue number. A "Decomposition sketch" list (from the issue form)
    therefore captures new children, and `## Children` goes stale. This was
    reproduced.
  - (b) Only the anchor block is regenerated. A list split by a blank line
    duplicates `(not filed)` lines, and they never go away. This was also
    reproduced.
- Proposed fix: when a `## Children` heading exists, pick the anchor from
  blocks inside that section first. Fall back to the body-wide search only
  when there's no heading. When the anchor is owned, strip `_OWNED_RE` lines
  from **every** block between the heading and the section end, then append
  the regenerated lines once to the anchor. Add tests from the two
  reproductions in the review. Keep the CRLF and byte-preserve tests green.

  scopes the allow-list to the `epic_doc.py` pair. The prompt-level FINALIZE

  user.

  fail-open on a lookup failure.
- **`sync-issue` read-modify-write race, fenced `##` in the Decomposition
  section, symlink/mode handling, narrow fetch refspec, `--merged` path/sha
  normalisation, silent `owned=[]` / non-standard table header, and
  `parent_epic_doc` upstream fallback.** Low-probability polish; deferred.
- **`_splice` leaves a double blank line / an unterminated-last-line shape
  change.** Cosmetic; idempotent and byte-safe as required.
- **Unparenthesised `except A, B:`.** Valid on py314, which the repo targets.
- **CodeRabbit.** The repo's check reports "manual review required"; there's
  no review to triage.
