# QS-421 — Fix review sessions broken by #407's T13 live check

- Issue: [#421](https://github.com/tmenguy/quiet-solar/issues/421) · lane `bug-factory` · `target:factory` · parent epic #369 · refs #407
- Evidence: [#407 T13 comment](https://github.com/tmenguy/quiet-solar/issues/407#issuecomment-6224986717) (2026-10-16, Claude Code 2.1.299, `main` at `e4133842`)

## Problem

The post-merge live check T13 of #407 ran one real global review. Five
defects stop a review session from completing end to end:

1. **`Write(…)` in the allowlist is ignored.** `reviews.allowed_tools`
   emits `Write(//<abs dir>/in/**)`. Claude Code matches only `Edit(path)`
   rules for file permissions ("`Write(//…)` is not matched by file
   permission checks — only Edit(path) rules are"); a T13 probe showed
   `Edit(//<dir>/**)` allows the Write tool and `Write(//<dir>/**)` does
   not. Under `dontAsk` the session cannot write its `in/` files, so
   `finding open --input` and `review finish --input` are unreachable.
2. **`claude --bg` refuses an untrusted folder.** Observed with 2.1.299:
   exit 1, `Workspace not trusted. Run claude in … once and accept the
   trust prompt`. Trust is inherited from a parent: trusting
   `~/.local/state/quiet-solar` once (by hand, in T13) fixed it, and that
   folder is also the default parent of `cp-messenger/` (the #406
   watchdog messenger runs `claude --bg` there too). Nothing documents
   this and nothing says so on failure.
3. **The cause is dropped.** `reviews._launch` records only
   `claude --bg exited 1` in `reviews.error`; the output naming the cause
   is lost.
4. **A finished session keeps the review `running` for an hour.** After
   the session ended, `claude agents` still lists it (`idle` / `done`).
   `reviewpilot._session_move` only counts *absence* from the listing, so
   a listed-but-`done` session is "alive" until `REVIEW_TTL_S` (1 h).
5. **`review read grep` patterns fail on `\(`.** The pattern goes to
   `git grep -e`, a basic regex by default: `\(` opens a group, so an
   unbalanced one fails ("parentheses not balanced", git exit 128 →
   `NOT_FOUND`, which the agent's rules say to drop, not fix). The review
   agents are not told, and the flavour is not even pinned (a user's
   `grep.patternType` config changes it).

## Goal

A review session launched by `cp.py tool review` can read and write its
`in/` files, open findings and `review finish`; once its session is done
it is `abandoned` within ~90 s (`LIVENESS_CONFIRM` = 2 listings ×
`PILOT_EVERY_S` = 30 s, plus up to one tick) instead of 1 h; a launch
refused for folder trust says so, in `reviews.error` and in the docs.
Smallest change per defect — no new `review read` flag, no programmatic
trust.

## Design

### 1 — `Edit(…)` instead of `Write(…)` (`reviews.allowed_tools`)

`scripts/qs/control_plane/reviews.py`, `allowed_tools` (L329–342):
`in_dir` is absolute (and resolved: `paths.state_dir` calls `.resolve()`,
paths.py:130), so the rules are `f"Read(/{in_dir}/**)"` and now
`f"Edit(/{in_dir}/**)"`, i.e. `Read(//abs/…/in/**)` and
`Edit(//abs/…/in/**)` (the `//` spelling everywhere, docs included). The
six `Bash(…)` rules are unchanged; no `Write(` rule is kept (the issue
says "instead"; it matches nothing). Docstring: "`in/` read and write
(an `Edit` rule also covers the Write tool)".

The agent prose ("`Read` / `Write` inside your `in/` directory", pinned
by `test_render_agents.py` L1126–1135) and frontmatter
`tools: Bash, Read, Write` stay: the agent still uses the Write tool.

**The `auto` fallback** (`--disallowedTools=Edit,NotebookEdit`, L350) is
left unchanged in code, but by the same matching rule a bare `Edit` deny
may also block Write, i.e. `auto` may not be a working fallback. Not
verifiable while planning: one sentence in `control-plane.md` says so
(today L899 presents `auto` as a working fallback), and the T13 re-run
probes it; a failure there opens a follow-up bug.

### 2 + 3 — the `claude --bg` failure text (`liveness`, `reviews`, `watchdog`)

New in `scripts/qs/control_plane/liveness.py` (it already imports
`runner` and `Path`; `liveness` cannot import `tools`, which imports it):

```python
UNTRUSTED = "Workspace not trusted"  # Claude Code's refusal of `--bg` in an untrusted folder (2.1.299)

def untrusted(res: runner.RunResult) -> bool:
    return UNTRUSTED in res.stderr or UNTRUSTED in res.stdout

def trust_hint(trust_dir: Path) -> str:
    return (
        f"the folder is not trusted: run `claude` once in `{trust_dir}` or a parent folder"
        " and accept the trust prompt"
    )

def bg_failure(res: runner.RunResult, trust_dir: Path, limit: int) -> str:
    """``claude --bg exited N: <tail>`` (+ ``; <trust hint>`` when refused for trust).

    At most ``limit`` characters, unless the prefix and the hint alone exceed it (an unusually long
    ``trust_dir``): then exactly prefix + hint, with no tail.
    """
```

- `head = f"claude --bg exited {res.returncode}"`;
  `output = res.stderr.strip() or res.stdout.strip()` (stderr first; stdout
  only when stderr is empty — T13 did not record which stream carried the
  refusal); the **tail** is kept, as the issue asks;
- `hint = "; " + trust_hint(trust_dir) if untrusted(res) else ""`;
- `budget = limit - len(head) - len(": ") - len(hint)`;
  `tail = output[-budget:] if budget > 0 else ""` (the guard matters:
  `output[-0:]` is the whole output);
- result `head + (f": {tail}" if tail else "") + hint`.

**`reviews.ERROR_MAX = 500`** (new, `reviews.py`): `close_locked`'s cut
becomes `tools.redact(error)[-ERROR_MAX:]` (L289) and `_launch` passes the
same constant as `limit` — one number, and the prefix and the hint both
survive the cut.

`reviews._launch` (L645–646): the `not res.ok` branch becomes

```python
clean = dataclasses.replace(res, stdout=tools.redact(res.stdout), stderr=tools.redact(res.stderr))
raise tools.StepFailed(
    liveness.bg_failure(clean, directory.parents[1], ERROR_MAX), {"exit_code": res.returncode}, res.returncode
)
```

- **Redact before cutting**: the session token is in the launch prompt
  (argv), so the output can echo it; cutting first could split a
  `review:V<n>.<0|1>.<hex>` token so `tools.redact` (tools.py:69) no longer
  matches its hex. `RunResult` is a frozen dataclass (runner.py:12–16);
  `reviews` imports `dataclasses` (new) and already imports `tools`.
  Downstream, `_Call.fail` redacts the detail again without cutting
  (tools.py:566–567; the CLI detail is `review: <detail>`, tools.py:577),
  `close_locked` redacts then cuts, and the `review_failed` payload is
  built from that `error` — so `reviews.error` == payload `error`, and the
  tool call's detail ends with it.
- `directory.parents[1]` is the review root (`review_dir` builds
  `root / db_tag() / review_id`, L46–48) — not `paths.review_root()`,
  which re-reads the env and can raise a `CpError` that `_guarded` (L565,
  it catches only `StepFailed`) would let escape. The hint names this
  narrowest folder; the docs say the shared parent covers the messenger too.
- The exit-124 branch (L643–644, the settle window) is unchanged and does
  not use `bg_failure`.

`watchdog._launch` (the messenger, L261–316; `watchdog` already imports
`liveness`) already stores `stderr_tail` in its `tool_calls.result`; that
row is unchanged. Added only: in the `else` branch (the spawn returned a
`RunResult`), when `not res.ok and liveness.untrusted(res)`,
`_log_once(f"messenger launch refused: {liveness.trust_hint(directory)}")`
— `directory` is the local from `paths.ensure_private_dir(paths.messenger_dir())`
(L271). The message is fixed per directory (no stderr), so `_log_once`
(dedupes on the message, `watchdog._logged`) logs it once per daemon run
to the daemon's stderr, i.e. `harness_state.daemon.log` next to the DB
(daemon.py:46, 453); a trust lost again later is logged after the next
daemon restart (accepted). `_log_once` writes `sys.stderr` directly (no
`%` formatting).

The node spawn's identical `claude --bg exited N` (tools.py:1036) is out
of scope.

### 4 — a `done` session is ended (`reviewpilot._session_move`)

`scripts/qs/control_plane/reviewpilot.py`, `_session_move` (L160–179).
`liveness.Agent.status` / `.state` are `str | None` (`_opt_str`):

```python
found = liveness.find(listing, session_id=row["session_id"])
if found is not None and "done" not in (found.status, found.state):
    _state.unlisted.pop(row["id"], None)
    return None
seen = _state.unlisted[row["id"]] = _state.unlisted.get(row["id"], 0) + 1
if seen < LIVENESS_CONFIRM:
    return None
error = "the review session ended without finishing" if found is not None else "the review session is gone"
return _Move(row["id"], "abandoned", error, "state = 'running' AND session_id IS ?", (row["session_id"],))
```

- A `done` session walks the same `LIVENESS_CONFIRM` counter as an absent
  one; the `_State.unlisted` shape is unchanged (`review id → count`), and
  the error text comes from the **latest** listing (`found` is in scope),
  so no new state. Absent then `done` → "ended without finishing"; `done`
  then absent → "is gone"; a failed listing neither counts nor resets
  (unchanged early return).
- Why `done` only: it is the one end value observed (T13: `idle` / `done`);
  which field carries it is not pinned, hence the `(status, state)` pair,
  mirroring `nodes.refresh`'s `"idle" in (agent.status, agent.state)`
  (nodes.py:91). An allowlist of live states would abandon a live session
  on any value not yet seen. A review session is single-turn (one prompt,
  never resumed or messaged), so `done` means it ended.
- A review that called `review finish` is `finished` before its session
  goes `done`, so it is not a `running` row here; the guarded
  `UPDATE … WHERE state = 'running'` covers the race.
- The move goes through `close_locked` as today: one `review_failed`
  alert per open run of the scope; no `claude stop` (the token is void).
- Update the `_State.unlisted` comment (L65: "listings in a row without it
  live (absent or `done`)"), the `_session_move` docstring (L161) and the
  module docstring (L11–12).
- Adoption of a `launching` review and `_identify` are unchanged (a `done`
  session they adopt is `running`, then abandoned by this rule).

### 5 — the grep pattern: pinned to BRE, and the agents told

**Code** — `scripts/qs/control_plane/gitread.py` L94: the grep argv only
gains `-c grep.patternType=basic` (a top-level option, valid anywhere
before the subcommand; an explicit `basic` wins over
`grep.extendedRegexp`):

```python
return [*git, "-c", "grep.patternType=basic", "grep", "-n", "--no-color", "-e", given["pattern"], rev, *tail]
```

(internal, no new `review read` flag; ~117 characters, within ruff's 120).
Module docstring row L11 (an RST simple table: the last column is
unbounded, E501 is ignored there — do not re-wrap) and the
`control-plane.md` grep row updated. A pattern git cannot compile exits
128 → `NOT_FOUND` with `git grep exited 128: <git's message>`
(gitread.py:127–130); no match is exit 1 → empty `output`.

**Agents** — `scripts/qs/agent_templates/_macros.md.j2`, macro
`review_session` (called by exactly `qs-global-review.md.j2:38` and
`qs-cross-run-review.md.j2:39`), step 3: after step 3's last line
(L242, "… is reviewed from its plan (digest, criteria).") insert a blank
line, these six lines (3-space indent, a list-item continuation, not a
blockquote), and a blank line before `4. The lens:` (L243):

```text
   `--pattern` is a basic regular expression (git's BRE): never escape
   `(`, `)`, `|`, `+`, `?`, `{` or `}` (`\(`, `\{`, `\|`, `\+`, `\?` are
   operators); `.`, `*`, `[`, `^`, `$` and `\` are special — escape one
   with `\` to match it. A pattern git cannot compile comes back
   `NOT_FOUND` with git's message: fix the pattern and retry once (the one
   exception to the `NOT_FOUND` rule below).
```

(six lines; no `[[`, `[%`, `{#` or `#}`, so no Jinja collision; the em
dash is fine in a Markdown agent file). The `NOT_FOUND` rule at L287–288
(pinned at test_render_agents.py:1155) and the step-3 pins (L1157–1158)
stay byte-identical.

## Acceptance criteria

1. `allowed_tools(...)` returns `Read(//…/in/**)`, `Edit(//…/in/**)` and
   the six `Bash(…)` rules; no `Write(` rule. `launch_args("dontAsk", …)`
   carries it.
2. A failed `claude --bg` (exit ≠ 0 and ≠ 124) leaves `reviews.error` =
   `claude --bg exited <N>: <stderr tail>`; with empty stderr the stdout
   tail; with neither, `claude --bg exited <N>`. The tool call's detail
   (`out["detail"]`) ends with the same text, and the `review_failed`
   payload's `error` equals `reviews.error`.
3. With `Workspace not trusted` in stderr or stdout and a 1000-character
   stderr, `reviews.error` starts with `claude --bg exited 1: ` and ends
   with `trust_hint(<the review root>)`, ≤ `ERROR_MAX` characters. A
   non-empty stdout without the phrase adds no hint.
4. A full session token in a long stderr, placed across the cut point,
   leaves no 8+-character run of its nonce in `reviews.error`.
5. Two messenger launches in one tick failing with `Workspace not trusted`
   log `messenger launch refused: <hint naming the messenger dir>` exactly
   once; each `tool_calls.result` keeps the keys
   `{"stdout_tail", "stderr_tail"}`; a failure without the phrase logs no
   hint.
6. A `running` review whose session is listed with `status` or `state`
   `done` is `abandoned` after `LIVENESS_CONFIRM` successful listings in a
   row with error `the review session ended without finishing` (also
   absent then `done`); `done` then absent ends with
   `the review session is gone`; a listed live session resets the count; a
   failed listing changes nothing.
7. `review read grep` runs `git … -c grep.patternType=basic grep -n
   --no-color -e <X> <rev> [-- P]`; in a real repo with
   `grep.patternType=extended` configured, `f(x)` matches literally and
   `\(` is `NOT_FOUND`.
8. Both rendered review agents carry the BRE paragraph verbatim (the whole
   block, indent included).
9. **(Manual review check.)** `docs/workflow/control-plane.md` states each
   of: the `Edit(//<dir>/in/**)` rule and why (L506 and L899); the `auto`
   fallback's write is unverified (L507, L899); the Folder trust
   paragraph; a failed launch's `error` keeps the output tail and the
   trust hint (L482); `running` + listed `done` → `abandoned` (L546); `grep`
   is a pinned BRE (L519) and a pattern git cannot compile is `NOT_FOUND`
   (L523). No mermaid diagram exists in the file (checked), so no SVG to
   re-render.
10. Quality gate green: `--impacted` and `--quick tests/qs`.

**Done-when (decision, as #407 Q3):** the issue's "T13 re-run passes end
to end" is the maintainer's **post-merge** check, not a PR criterion — a
real `claude --bg` launch cannot run in the PR. The PR says
**`Refs #421`** (not "Fixes"); the maintainer closes #421 once T13 passes,
and a T13 failure opens a follow-up bug under #369. The PR body carries

in `auto` mode — can it write `in/`? (a "no" opens the follow-up);
(c) a deliberately untrusted `QS_CP_REVIEW_DIR` shows the hint in
`reviews.error`; (d) the messenger launches from the trusted
`cp-messenger/`; (e) a session that stops without `review finish` is
`abandoned` within ~90 s.
