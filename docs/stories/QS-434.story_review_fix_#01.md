## Fix

| # | Finding (source) | Fix |
|---|---|---|
| F1 | `gh run list` labels overlap: "a run is listed" also matches queued, in-progress and failed runs; `cancelled` has no label (BH, ECH) | First-match order: unavailable (`gh` errors) → pending (nothing listed, or listed and not completed) → passed (completed, success) → failed (completed with any other conclusion, including cancelled) |
| F2 | The pre-real-run check is local only. `release.py` pulls and recomputes the tag (date, refreshed tags), so the approved tag/HEAD can drift. A dirty tree loops "dry-run again, ask again" forever and overrides the agent's refuse-if-dirty rule (ECH) | Split it: a dirty tree means STOP. Otherwise run `--dry-run` again right before the real run (it pulls); its tag must equal the approved tag and HEAD must equal the noted SHA, otherwise show it and ask again |
| F3 | Unpushed local commits on `main` would be published by the real run's `git push origin main` without the user seeing them (ECH) | After each dry run, `git log --oneline origin/main..main` must print nothing, otherwise STOP |
| F4 | The failure evidence misses "main pushed, tag push failed" (ECH) | Add `git tag --list <dry-run tag>` and `git ls-remote origin refs/tags/<dry-run tag>` to the evidence |
| F5 | The tag-vs-remote-main check fails falsely if main moves right after the release (ECH) | The tag SHA must equal local `git rev-parse HEAD`; remote main is compared with it too, but a mismatch there is reported as "main has moved on", not as a failure |
| F6 | A stale rendered `.claude/agents/qs-release.md` is read when the pull brought a newer template (BH, ECH) | Always run `python scripts/qs/render_agents.py` after the pull, then read the file |

Test: a new `test_release_guards_real_run` pins the F1–F4/F6 wording
(it fails before the fix).
