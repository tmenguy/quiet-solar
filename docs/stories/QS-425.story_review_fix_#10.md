## Findings to fix

### [should-fix] R10-S1 — a fix that was rejected, settled or deferred never leaves `pending.json`, so step 6 never reaches done
- File: `qs-node.md.j2` step 6 (~:386-389), Blocking "Clearing `objection`" (~:761-762), "The `fix` protocol" (the
  "An applied fix leaves `pending.json`" sentence)
- Source: qs-review-edge-case-hunter (S2). Fix #09's R9-S4 check introduced it.
- Description: in the objection path, the orchestrator rejects, settles or defers the fix's finding. Clearing the
  block re-reads the finding and goes on without it, but the entry stays in `pending.json`. From then on every step 6
  posts `continuing`, and the implementer is handed a rejected fix again.
- Fix:
  - **The `fix` protocol:** "A fix leaves `pending.json` once applied, or once its finding is no longer open
    (`rejected` / `settled` / `deferred` by the orchestrator)".
  - **Clearing `objection`:** that removal happens in the same write.
  - **Step 6's check becomes** "`pending.json` holds a fix whose finding is still open". Entries whose finding is no
    longer open are dropped in the same pass.
  - **Pin** both.

### [should-fix] R10-S2 — commits made beside an aborted merge can be pushed without review
- File: `qs-node.md.j2` item 3's empty-lookup rule (~:427-433), item 5 (~:450-456), rule 5 case 3 (~:243-248),
  Blocking (~:758-760)
- Source: qs-review-edge-case-hunter (S1) and qs-review-blind-hunter (stuck `retried`), merged
- Description: if the resolution implementer aborts the merge but still commits the pending fixes, the empty-lookup
  retry merges on top of those commits. They then sit in `<head>..<merge>^1`, which item 5 never looks at, and they
  are pushed without review. Separately, after a "merge not committed" block, `retried` stays true, so every unblock
  blocks again at once.
- Fix, which keeps the retry and makes the review cover those commits:
  - **Item 5** runs when (`catchup.clean` is false, or `HEAD` ≠ `catchup.merge`, or `<catchup.merge>^1` ≠
    `round.json`'s `head`) and `HEAD` ≠ `catchup.reviewed`. It reviews:
    - `git show --remerge-diff <catchup.merge>`;
    - `git diff <head>..<catchup.merge>^1`, the commits beside the merge, when that range is not empty;
    - `git diff <catchup.merge>..HEAD`.
  - **Blocking:** clearing a `catchups` block also sets `catchup.retried` = false, when `catchup` is not null.
  - **Mirror** both in `control-plane.md:657`.
  - **Pin** both.

### [should-fix] R10-S3 — a fix popped when resuming at `step: done` is acked and then lost
- File: `qs-node.md.j2` step 8 (~:479-485)
- Source: qs-review-edge-case-hunter (S3). This is a narrow window that predates #09, but it breaks the same
  invariant.
- Fix: on a resume at `step: done`:
  - **no `converged` report is visible and `pending.json` holds a fix whose finding is open** → one write back to
    `step: triage`, then step 6's routing;
  - **a `converged` report is visible** → handle such a fix as "a `fix` after done", which posts an objection.

  Pin it.
