# QS-383 — Epic lane: let the epic agent rewrite its epic's issue body

Issue: [#383](https://github.com/tmenguy/quiet-solar/issues/383) ·
Lane: feature × factory · Target: factory

## Problem

The epic × factory lane (QS-340) makes `epic_doc.py sync-issue` the
**only** writer of an epic's issue body, and that writer only **adds**
lines. When an epic is redesigned, its issue body keeps text that is no
longer true (the #369 re-entry of 2026-09-28 needed a hand rewrite with
the maintainer's authorisation).

## Goal

`qs-decompose-epic` may rewrite its epic's issue body so it matches the
rationale document — through code, not prose (the module's principle:
destructive steps are code). `sync-issue` still adds the task-list lines
for newly filed children. The body conventions stay.

## Design

Mechanism: a new option **`sync-issue --issue N --rewrite-from <FILE|->`**
in `scripts/qs/epic_doc.py`.

- Without `--rewrite-from`: behaviour and JSON output unchanged.
- With `--rewrite-from FILE` (`-` = stdin): the text replaces the current
  issue body **as the base**, and the usual `sync_body` pass then runs on
  it — the conventions stay enforced by code (rationale link prepended if
  the text lacks the doc path; missing `- [ ] #n — <child>` lines added;
  `- (not filed)` lines regenerated). One `gh issue edit --body-file`
  (same `_edit_body`); none when the result equals the current body.
- `carry_ticks(current, new)`: a `- [ ] #n` line in the new text is
  ticked when `#n` is ticked in the current body — a rewrite never
  silently un-ticks a finished child.
- Preconditions run first, unchanged (`not-an-epic`, `missing-doc`,
  `unparseable-decomposition`).
- New refusals (exit 1, nothing written): `missing-body-file` (not
  found / directory / not UTF-8), `empty-body-file` (whitespace only).
- Output in rewrite mode only gains `"rewrite_from": "<FILE|->"`.
- The agent passes the body on **stdin via a quoted heredoc**
  (`<<'QS_EPIC_BODY'`), built from the current body
  (`gh issue view <N> --json body -q .body`) — no scratch file, so the
  OpenCode `edit` permission (`docs/epics/**` only) and the "only file you
  write" rule stay as they are.

## Acceptance criteria

1. `sync-issue --rewrite-from FILE` replaces the body with FILE's text,
   then applies the link + children sync; output `status: synced`,
   `rewrite_from: FILE`; the old body's stale lines are gone. `-` reads
   stdin. Children ticked in the current body stay ticked.
2. A FILE equal to the current body → `unchanged`, no `gh issue edit`.
3. A FILE lacking the rationale link / a filed child line → both are
   added (`link_added: true`, `added: [..]`).
4. Missing / unreadable FILE → `missing-body-file`; blank FILE →
   `empty-body-file`; both exit 1 and write nothing.
5. Plain `sync-issue` output is unchanged; all existing tests pass.
6. The "only writer" rule is removed and the rewrite step is documented
   in every place the issue lists: `project-rules.md` (Epic documents),
   `lanes/epic-factory.md` (FINALIZE procedure + Issue-body
   conventions), `epic_doc.py` (module docstring + `sync-issue` argparse
   help), `qs-decompose-epic.md.j2` (FINALIZE bullet + hard rules — the
   body goes through stdin, never a scratch file),
   `.claude/commands/decompose-epic.md` (Expected outcome).
7. The `### Issue-body conventions` / `epic_doc.py sync-issue` sentinels
   in `tests/qs/docs/test_lanes.py` keep passing; `--quick tests/qs`
   green.
8. The epic issue is still never closed by the lane.
