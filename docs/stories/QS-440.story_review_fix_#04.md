## Findings to fix

### [should-fix] X1 — git's messages are matched in English, but the locale is not pinned
- File: `catchup.py:319-326` (`_Git.call`). The matchers `_REF_LOCK`, `_NO_OBJECT` and `_UNTRACKED` are at `:83-86`.
- Severity: should-fix
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter (the edge-case hunter confirmed a French `git merge` message)
- Description: under a non-English `LANG`, git translates the messages
  these matchers look for. Then `known()` raises TOOL_FAILED on a
  missing object (which breaks `remote_state` "ahead", the rewind and
  `end`). The untracked-files refusal becomes TOOL_FAILED, and a ref
  lock becomes TOOL_FAILED instead of BUSY.
- Proposed fix: `env_extra={"GIT_TERMINAL_PROMPT": "0", "LC_ALL": "C"}`
  (`liveness.py:134` already does the same). Extend
  `test_every_git_call_runs_under_the_env_contract` to pin it. Update
  the D4 "Git" contract line in `control-plane.md` if it lists the env.

### [should-fix] X2 — The rewind has no bound
- File: `catchup.py:578-596` (`intake`), `:719-725` (the `after_merge` rewind)
- Severity: should-fix (raised from nice-to-have: an unbounded loop breaks the catch-up's bounds)
- Source: qs-review-edge-case-hunter
- Description: after a clean merge M is recorded, the implementer may
  `git reset --hard <cu.head>` and report green. Intake records
  `green`, and `after_merge` rewinds and merges again. The answer is
  `implement gate` again. Neither `catchups` nor `misses` grows, so the
  loop never stops.
- Proposed fix: in `intake`, when `cu["merge"]` is set but is unknown
  or is not an ancestor of HEAD, count a miss
  (`MERGE_NOT_COMMITTED`) and do not record `green`. The `misses` block
  then bounds the rewind. Test: run the reset-and-green cycle twice and
  expect the `misses` block. The existing single-rewind test should
  still pass, or be adjusted to the miss count.
