## Findings to fix

### [must-fix] M5 — unsorted import blocks fail the ruff gate (CI-blocking)
- File: `tests/qs/launchers/test_next_step_cli.py:500,522,545,571`
- Severity: must-fix
- Source: quality-gate verification (`ruff check` → 4× I001)
- Description: Four test bodies added across review-fixes #01/#02/#03
  contain a function-local import block written as:

  ```python
      import next_step

      import render_agents
  ```

  The blank line between the two imports makes ruff raise
  `I001 Import block is un-sorted or un-formatted` at each site
  (lines 500, 522, 545, 571). Ruff fails on this file, so the CI
  whole-repo gate goes red. The round-4 `--impacted` gate did not catch
  it because testmon only selected the files that round touched
  (`render_agents.py`, `test_render_agents.py`), never
  `test_next_step_cli.py`.
- Fix: collapse each block to a single sorted import group (remove the
  blank line between `import next_step` and `import render_agents`), e.g.

  ```python
      import next_step
      import render_agents
  ```

  Equivalent to `ruff check --fix tests/qs/launchers/test_next_step_cli.py`.

## Deferred (not fixed — recorded for completeness)

- **[nice-to-have] fd-leak in `_atomic_write`** (`render_agents.py` ~L309):
  if `os.fdopen(fd, ...)` raised between `mkstemp` and the `with`, the raw
  fd would leak. Both the blind-hunter and edge-case-hunter classified
  this as theoretical/unreachable (mode and encoding are constants, so
  `fdopen` cannot fail here; any error is still caught and re-raised as
  `RenderError`, so nothing escapes the handoff). Deliberately NOT fixed:
  a defensive fd-close branch would be uncoverable, forcing coverage
  below 100% or a `# pragma: no cover` that is not authorized. Left as
  documented residual.
