# QS-357 — Templated agents: render the harness agent dirs per worktree from Jinja templates

- **Issue**: [#357](https://github.com/tmenguy/quiet-solar/issues/357)
- **Lane**: feature × factory (`area:dev-pipeline`, `kind:feature`, `target:factory`, `scale:task`)
- **Parent epic**: [#321](https://github.com/tmenguy/quiet-solar/issues/321) (wave 3 — "Speed: per-phase model selection")
- **Sibling**: [#358](https://github.com/tmenguy/quiet-solar/issues/358) — Part B, the model policy that rides on this task
- **Story status**: v4 — finalized after three adversarial review rounds

## Problem

The pipeline ships **one static agent file per phase, hand-maintained in
per-harness copies** (`.claude/agents/`, `.opencode/agents/`, and — until
commit 0 of this task — `.cursor/agents/`). Three costs:

1. **No per-task or per-lane knob.** A tracked file is lane-agnostic, so
   anything that must vary by lane — the model (#358), the lane protocol,
   the task facts — cannot live in the agent definition. Every agent
   starts its session by *hoping* to run `python scripts/qs/context.py`,
   read `docs/workflow/lanes/<lane>.md`, and read the rules — 5–8 tool
   calls whose outcome the harness cannot guarantee.
2. **Harness sync is a human discipline.** Harness-specific sections
   legitimately differ, so `check_doc_drift.py` can only enforce
   *co-modification*; content parity is unenforced.
3. **The retired per-task rendering worked** (the `legacy/` OpenCode
   pipeline rendered `{{VAR}}` templates per task). It was dropped for
   reasons that no longer apply — suffixed per-task names, hand cleanup,
   an OpenCode server that needed a restart — not because rendering was
   wrong. `docs/workflow/overview.md` § "Static agents — no rendering"
   records the replacement but gives no rationale.

## Goal

Make **one Jinja template per agent** (`scripts/qs/agent_templates/`) the
single tracked source of truth and **render** the harness agent
directories per worktree — gitignored outputs — with the task facts and
the lane protocol inlined into the lane-aware orchestrators, so that:

- an orchestrator's session starts with its facts and its phase protocol
  already in the system prompt (deterministic orientation), leaving only
  *volatile* facts to runtime lookup;
- a lane-dependent knob (model, first consumer: #358) is a template
  variable with a **per-agent** Python seam
  (`build_render_context(model=<str | Mapping[stem, str]>)`), not a file
  edit;
- harness sync becomes a rendering concern, not a discipline.

Behaviour of every phase is otherwise **unchanged**: same agent names,
same protocols, same handoff, same GUI pin, same effective model.

## Non-goals

- Model selection itself (#358).
- Inlining `project-rules.md` / `project-context.md`, or the lane
  protocol into sub-agents.
- Behavioural edits to any protocol. The templates are a **faithful
  merge** of the two tracked bodies; the *only* body deltas allowed are:
  the enumerated rendered blocks (GENERATED header, Task facts, Lane
  protocol, Reference map), the lane-paragraph macro substitution in the
  six lane-aware orchestrators (task 6), the post-merge render line in
  `qs-finish-task` (task 7), and trailing-newline normalisation.
- Rendering the existing `{{issue}}`-style placeholders (see Delimiters).
- `.claude/commands/*.md` slash wrappers (tracked, unchanged).
- Extending the QS-332 task-agnostic fallback text: both existing
  variants are reproduced exactly (§2).

## Design

### 1. Templates — `scripts/qs/agent_templates/`

- `_base.md.j2` (skeleton), `_macros.md.j2` (the `lane_paragraph` macro)
  and 21 templates `qs-<name>.md.j2`. **Discovery**: `render_all` renders
  the sorted glob `*.md.j2` **minus leading-underscore files**; a stem
  not in the registry renders as a plain sub-agent (this is what lets the
  synthetic test template work). The registry ↔ glob equality is asserted
  by a **test**, not by `render_all`.
- Jinja2 `Environment(loader=FileSystemLoader(templates_dir),
  undefined=StrictUndefined, trim_blocks=True, lstrip_blocks=True,
  keep_trailing_newline=True, autoescape=False,
  variable_start_string="[[", variable_end_string="]]",
  block_start_string="[%", block_end_string="%]")`.
- **Registry** (`render_agents.py`): `ORCHESTRATORS =
  frozenset(PHASE_TO_AGENT.values())` (imported from
  `launchers/phases.py`, which imports nothing from the renderer — no
  cycle; 9 stems); `LANE_AWARE: frozenset[str]` = {`qs-create-plan`,
  `qs-diagnose-task`, `qs-implement-task`, `qs-implement-setup-task`,
  `qs-review-task`, `qs-verify-task`}; `SUBAGENTS: frozenset[str]` = the
  12 listed below. Invariants (tested, not asserted at module level):
  `LANE_AWARE ⊆ ORCHESTRATORS`, `ORCHESTRATORS ∩ SUBAGENTS = ∅`,
  `|ORCHESTRATORS ∪ SUBAGENTS| = 21 = |glob|`. Sub-agents:
  `qs-plan-{critic,concrete-planner,dev-proxy,scope-guardian,delta-auditor}`,
  `qs-diag-{root-cause-skeptic,fix-minimalist}`,
  `qs-review-{blind-hunter,edge-case-hunter,acceptance-auditor,coderabbit,regression-proof}`.
  `render_all` injects `harness`, `stem`, `orchestrator = stem in
  ORCHESTRATORS`, `lane_aware = stem in LANE_AWARE`, and the per-stem
  `model` per output; templates carry **no flag logic**.
- Each template `[% extends "_base.md.j2" %]` and fills three blocks:
  `frontmatter_claude`, `frontmatter_opencode` (the two current
  frontmatter shapes as literal YAML) and `body`. Inside `body`,
  harness-specific passages are wrapped in
  `[% if harness == "claude" %] … [% else %] … [% endif %]`. The six
  lane-aware templates additionally `[% import "_macros.md.j2" as m with
  context %]` and call `[[ m.lane_paragraph(tail) ]]` (§2) on its own
  line at the spot of today's `**Lane (QS-332).**` paragraph.
- `_base.md.j2` emits, in order:
  1. the frontmatter block for `harness`;
  2. `<!-- GENERATED by scripts/qs/render_agents.py from
     scripts/qs/agent_templates/<template> — harness=[[ harness ]]
     lane=[[ lane or "none" ]] issue=[[ issue or "none" ]]. DO NOT EDIT;
     edit the template and re-render. -->` (after the closing `---`; no
     timestamps → deterministic);
  3. `[% if orchestrator %]` the **Task facts** block (§2);
  4. the `body` block;
  5. `[% if orchestrator and lane_aware and lane_protocol %]`
     `## Lane protocol (rendered from docs/workflow/lanes/[[ lane ]].md)`
     + the file contents verbatim (a **value**, never `include`d as
     template source — placeholders inside lane files stay inert; the
     lane file's own headings are kept as-is);
  6. `[% if orchestrator %]` the **Reference map** — literal Markdown, 7
     entries: `docs/workflow/project-rules.md`, `project-context.md`,
     `adversarial-review.md`, `harness.md`, `phase-protocols.md` (+
     `docs/workflow/lanes/`), `docs/agents/index.md`, `docs/stories/`,
     each with a one-line "what you find there".
  Sub-agents render as frontmatter + header + body only.
- Claude frontmatter: today's `name`, `description`, `tools` lines
  verbatim, then `model: [[ model ]]`. OpenCode frontmatter: today's
  lines verbatim, with the existing
  `# model: github-copilot/claude-sonnet-4.5  # uncomment to override
  project default` line replaced by `[% if model != "inherit" %]model:
  [[ model ]][% else %]<today's comment line verbatim>[% endif %]`.
- Whitespace: macros are declared `[%- macro … -%] … [%- endmacro -%]`;
  the writer normalises the tail (`text.rstrip("\n") + "\n"`).
- Template hygiene rule (recorded in `project-rules.md`): inside a
  template never write `[[` or `[%` literally; Markdown links such as
  `[[x]](…)` must be avoided. A violation fails loudly
  (`TemplateSyntaxError` → `RenderError`) in the template tests.

### 2. Render context

`build_render_context(work_dir, *, bound=None, issue=None, title=None,
labels=None, fetch=True, model="inherit", lanes_dir=None) -> dict` —
**always returns every key** (`None` where unresolved; `StrictUndefined`
only guards missing names). `bound=None` derives from the branch;
`bound=False` **forces the unbound render** (needed by task 5 and by the
fixture while on branch `QS_357`).

| Key | Task-bound | Task-agnostic |
|---|---|---|
| `branch` | `run_git(["-C", work_dir, "branch", "--show-current"], check=False)` — the renderer's own call (`utils.get_current_branch()` takes no `cwd` and raises); non-zero / empty / no git → `None` | same |
| `issue` | `utils.get_issue_from_branch(branch)` when the branch is `QS_<N>` (pure parsing, `None` otherwise); `issue` kwarg overrides | `None` |
| `title`, `labels` | kwargs if given (setup_task passes `title=args.title or f"Issue #{issue}"` and `labels` from `check_declaration` → **no second `gh` call**); else, when `fetch=True`, one `context.fetch_issue_fields(issue)` call (today's `_issue_fields`, **renamed public** — same `check=False`, `stdin=DEVNULL` semantics). `title is None` on a bound task → `f"Issue #{issue}"` | `None` |
| `lane` | `labels is None → None`; else `targets.parse_axes(labels)["lane"] or None` (**`parse_axes` returns `""` for an incomplete/ambiguous declaration — coerce**) | `None` |
| `worktree` | `str(Path(work_dir).resolve())` | same |
| `story_file` | `docs/stories/QS-<N>.story.md` (stable path; *existence* is volatile and stays runtime) | `None` |
| `lane_protocol` | contents of `lanes_dir / f"{lane}.md"` when `lane` is set and the file exists; else `None` | `None` |
| `lane_protocol_state` | `"inlined"`; `"file_missing"` when `lane` is set but the file is absent (stderr warning); `"no_lane"` otherwise | `"no_lane"` |
| `model` | kwarg (`str` or `Mapping[stem, str]`; `render_all` resolves `model.get(stem, "inherit")` per output) | same |
| `facts_state` | `"bound"`; `"lookup_failed"` when the branch is `QS_<N>` but the fields could not be fetched (stderr warning from the hook) | `"unbound"` |

Pinned **Task facts** texts (tested verbatim against literal constants):

- `bound`: `## Task facts (rendered)` / `- Issue: #<N> — <title>` /
  `- Branch: <branch> · Worktree: <worktree>` / `- Lane: <lane or
  LANE_NONE> · Story (path; may not exist yet): <story_file>` /
  `Volatile facts (PR number, latest review fix, story existence) are not
  rendered — run `python scripts/qs/context.py` for those.` where
  `LANE_NONE` is `none (labels incomplete — see the Lane paragraph below)`
  when `lane_aware`, else plain `none`.
- `lookup_failed`: `## Task facts (rendered)` / `Task QS_<N> is bound but
  the issue lookup failed at render time — run `python
  scripts/qs/context.py`.`
- `unbound`: `## Task facts (rendered)` / `No task bound (branch
  `<branch or "unknown">` is not `QS_<N>`). Run `python
  scripts/qs/context.py` from a task worktree.`

**`lane_paragraph(tail)` macro** (`_macros.md.j2`). Today's paragraph
beginning `**Lane (QS-332).**` is identical across both harnesses per
agent, and identical across the six agents **up to its last sentence**,
which has two variants (verified):

- `tail="readonly"` (create-plan, diagnose-task, review-task,
  verify-task): `… (`gh issue edit <N> --add-label ...`). This phase is
  read-only with respect to the gate, so it may proceed on the fallback.`
- `tail="implement"` (implement-task, implement-setup-task): `… (`gh
  issue edit <N> --add-label ...`). In this implement phase the labels
  must be resolved **before the first commit** — the first `--impacted`
  run fails otherwise (the gate is the backstop, not a parallel path).`

Macro output:

- when `lane_protocol` is set: `**Lane (QS-332).** This task's lane is
  `[[ lane ]]`; its phase protocol is rendered below under "Lane
  protocol" — do not re-read the lane file.`
- otherwise (unbound, lookup failed, bound with `lane=None`, or lane file
  missing): today's paragraph **verbatim** with the agent's tail — so the
  unbound render is byte-identical to today's text (the test compares to
  the two literal constants, not to the tracked files).

**Not rendered** (volatile → would become *incorrect information*):
`pr_number`, `pr_url`, `story_exists`, `latest_review_fix`, and the
`kind`/`target`/`scale` axes.

**Roots** (resolved by `render_all` for templates, by the context builder
for lanes): `work_dir / "scripts/qs/agent_templates"` when that
directory exists (a task branch that edits a template sees its own
templates), else `Path(__file__).parent / "agent_templates"`; lane files
likewise from `work_dir / "docs/workflow/lanes"` else
`Path(__file__).parents[2] / "docs/workflow/lanes"`. `templates_dir` /
`lanes_dir` kwargs override for tests.

### 3. Renderer — `scripts/qs/render_agents.py`

- Python API: `build_render_context(...)` and
  `render_all(work_dir, *, context=None, out_root=None,
  templates_dir=None) -> list[Path]`; `context=None` means
  `build_render_context(work_dir)` with defaults. Hooks call
  `render_all(wd, context=build_render_context(wd, …))`. `render_all`
  writes **nothing to stdout**.
- Output: `<out_root or work_dir>/.claude/agents/<stem>.md` and
  `.opencode/agents/<stem>.md`; directories created with `mkdir(parents,
  exist_ok)`; each file written atomically (temp sibling + `os.replace`,
  temp unlinked in `finally`; precedent `launchers/claude.py::
  _write_phase_agent`). Always written.
- **Tracked-target guard**: before writing, `render_all` runs `git -C
  <out_root> ls-files -- .claude/agents .opencode/agents` (`check=False`);
  if any target path is **tracked in the index** it raises `RenderError`
  ("refusing to overwrite tracked agent files; untrack them first").
  This makes the commit-1 discipline mechanical and retires itself after
  commit 2 (the files become untracked). Non-git `out_root` → no guard.
- Deterministic: same context → identical bytes.
- **`RenderError(RuntimeError)`**: raised at the two API boundaries
  (`build_render_context` wraps lane-file read failures;
  `render_all` wraps `jinja2.TemplateError`, output `OSError`, the
  tracked-target guard). A missing `jinja2` surfaces as `ImportError`
  when `render_agents` is imported — which is why hooks import it
  **function-locally** (§4).
- `jinja2` declared in `requirements_test.txt` (the file CI and the dev
  venv install; already present via Home Assistant).
- CLI: `python scripts/qs/render_agents.py [--work-dir <wd>]` (default
  cwd), one plain line per file written, exit 0 (exit 1 with the
  `RenderError` message on failure); `main(argv)` tested **in-process**
  for coverage plus **one subprocess run** for the real argv/exit-code
  contract (`test_next_step_cli.py` precedent; no coverage exclude for
  `__main__`; `--impacted` covers changed lines under `scripts/qs/`, as
  commit 0 demonstrated).

### 4. Hook points

| When | Where | Contract |
|---|---|---|

| Fresh clone / manual | `python scripts/qs/render_agents.py` (documented in `CLAUDE.md`) | the only manual step |

**Hook shape** (both scripts): the `try:` wraps a **function-local
`import render_agents`** (so a missing `jinja2` is caught as
`ImportError` *inside* the hook; `# noqa: PLC0415` with a one-line
justification if ruff enables that rule), `build_render_context(...)`
and `render_all(...)`. Tests simulate each arm by monkeypatching the
import target to raise `ImportError` and `render_all` to raise
`RenderError`.

`.claude/settings.json` allowlist gains
`Bash(python scripts/qs/render_agents.py:*)` and
`Bash(python **/scripts/qs/render_agents.py:*)` (the pair every script
ships; the finish-task step is a Bash call from an agent session). No
test enumerates the allowlist exactly (verified).

Live reload: `next_step.py` runs inside a live session; Claude Code
re-reads `.claude/agents/` within seconds for directories present at
session start — always true here because every session is opened by a
handoff that rendered first, or by a documented manual render. The
running orchestrator's system prompt is unaffected; later sub-agent
spawns pick up the new definitions. OpenCode discovers agents at server
start — `harness.md` states "restart OpenCode to pick up re-rendered
agents".

### 7. Tests

with `bound=True, issue=42, title="…", labels=[…feature-factory…]`.
