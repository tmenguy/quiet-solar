### [nice-to-have] J2 — `_stop_superseded` may stop a same-named session of another checkout or DB
- File: `scripts/qs/control_plane/tools.py:~902-907`
- Source: edge-case-hunter
- Proposed fix: stop a listed earlier launch only when its `cwd`
  resolves to the task's worktree (`Agent.cwd` is already parsed). If
  `cwd` is missing, don't stop it. Test: a same-named session with a
  different `cwd` is not stopped; one with the task's worktree as `cwd`
  is stopped.

### [nice-to-have] J3 — The adopt branch never stops older listed launches
- File: `scripts/qs/control_plane/tools.py:~1000-1008`
- Source: blind-hunter + edge-case-hunter
- Proposed fix: in the adopt branch, call
  `_stop_superseded(ctx, listing, own["name"])`. It is best-effort and
  never raises. Prefer calling it after the write transaction. Test:
  adopt `base-r1` while `base` is listed, and `base` gets stopped (with
  J2's `cwd` rule).

### [nice-to-have] J4 — The tick-hook time budget doesn't match the SIGKILL threshold
- File: `scripts/qs/control_plane/daemon.py:~282-287` (the `hung`
  condition), and the `tick_hooks` seam row in
  `docs/workflow/control-plane.md` plus the daemon docstring
- Source: blind-hunter
- Proposed fix: add to `hung` the condition that the heartbeat's age is
  ≥ `STALE_AFTER_S`. The documented contract, "a tick hook returns
  within `STALE_AFTER_S` or beats", is then exactly what protects a
  healthy daemon. Test: an older-schema daemon whose last beat is
  younger than `STALE_AFTER_S` at the deadline is not SIGKILLed
  (`restart_pending`); one with a beat at least `STALE_AFTER_S` old is
  SIGKILLed.

### [nice-to-have] J5 — A stale but live newer-schema daemon: `ensure` spawns a pointless daemon and says `started`
- File: `scripts/qs/control_plane/daemon.py:~334-366`
- Source: blind-hunter
- Proposed fix: when the lease's schema is greater than the target and
  the pid is not proven dead, return `{"status": "newer_running", "pid":
  …}` without spawning. Callers (`wait` and the write path) already get
  `SCHEMA_TOO_NEW` from the version check. Document it in the `ensure`
  answers list. Test.
