## Findings to fix

### [should-fix] G1 — A link line inside a subgraph silently changes membership
- File: `tests/qs/docs/test_overview_structure.py` (`_parse_pipeline_diagram`)
- Source: edge-case-hunter E1
- Description: Mermaid makes both endpoints of any link line inside a
  `subgraph … end` block members of that subgraph. This covers `-->`,
  `-.->` and `~~~`. Two edits pass the test today, and both draw an
  outside node inside a lane box:
  - moving `setup --> plan` into `STD`, which counts as a declaration-order
    change, and the Free list allows those;
  - adding `impl ~~~ rev` inside `STD`.
- Fix: the parser rejects any edge line or `~~~` line while a subgraph is
  open, with `AssertionError("links must be declared outside subgraphs: ...")`.
  To do this, `~~~` gets its own regex (`^(\w+)\s*~~~\s*(\w+)$`), checked
  before the ignore list. A `~~~` line stays allowed at top level and is
  still not counted as an edge.
- Mutation cases to add:
  - `edge-inside-subgraph`: move `setup --> plan` to just before the
    first `end`;
  - `invisible-link-inside-subgraph`: insert `impl ~~~ rev` just before
    the first `end`.

  Also add a **positive** check that a top-level `plan ~~~ diag` line
  is still accepted: parse it and assert that nothing is raised and
  that the edges are unchanged.
