### [should-fix] V1 — `catchup end` ignores a merge that is in HEAD but was never recorded
- File: `catchup.py:812-839` (`_Op.end`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description:
  - In a `from: conflict` catch-up, `cu["merge"]` stays `None` until
    the tool looks up the resolution commit. If the catch-up then
    blocks `error` and the maintainer merges or resolves `origin/main`
    by hand and pushes, `end` answers `base: null`.
  - It can also leave an earlier catch-up's `base_merge` in place.
  - Either way, the next build round's `catchup base` gives the wrong
    base. The reviewers then get all of main's changes in their diff.
- Proposed fix:
  - In `end()`, when `cu["merge"]` is `None` or not in HEAD, run the
    same read-only `self.git.lookup(cu["head"])` and the
    `self.foreign(found, cu["head"])` checks.
  - If a valid merge is found and HEAD is pushed, record
    `base_merge = {merge: found, head: HEAD}`.
  - Update the `catchup end` paragraph (`control-plane.md:738`).
  - Test: a conflict, then `merge --abort`, then a manual
    `git merge origin/main` with the conflict resolved, then push and
    `end`. Expect `base` to be that merge, and `catchup base` to
    return it.

### [should-fix] V2 — The repair for "the catch-up merge is no longer in HEAD" loops forever
- File: `catchup.py:711-712` (`after_merge`), `control-plane.md:733` (the repair line)
- Severity: should-fix
- Source: qs-review-edge-case-hunter, qs-review-acceptance-auditor
- Description:
  - The documented repair is "restore `HEAD` to the recorded head".
    Following it leaves remote = HEAD = `round.json`'s head, so the
    re-entry rule does not call `catchup end`.
  - Rule 5 then re-runs the trigger, and `after_merge` gives the same
    error again, because `cu["merge"]` is still recorded and is not in
    HEAD.
  - The only way out is deleting `catchup.json`, which loses the
    counter. If the merge object has also been gc'd, there is no way to
    restore it.
- Proposed fix (Python preferred):
  - In `after_merge`, handle the case where the recorded merge is no
    longer in HEAD but HEAD == `cu["head"]`, no `MERGE_HEAD` is open,
    the tree is clean and there is no `index.lock`.
  - In that case, reset `merge`, `clean`, `green` and `reviewed` to
    `None` in one write, then go back to `progress`, which merges
    again.
  - `catchups` is unchanged, and HEAD's history still holds only one
    catch-up merge.
  - When HEAD ≠ `cu["head"]`, keep the error.
  - Split the repair line at `control-plane.md:733` into one repair per
    guard:
    - "the catch-up merge is no longer in HEAD": `git reset --hard` to
      the catch-up's head (the catch-up merges again), or to
      `catchup.merge`.
    - "the catch-up head is no longer in HEAD" and "HEAD moved without
      a merge": reset to the catch-up's head.
    - "a second merge is open" and "a merge is open outside a
      catch-up": finish or abort the open merge.
    - "a merge that is not origin/main's": reset to the catch-up's
      head.
  - Test: the reset-away case, then reset to the catch-up's head, then
    the call. Expect a fresh merge, `implement gate`, `catchups`
    unchanged, and one merge.
