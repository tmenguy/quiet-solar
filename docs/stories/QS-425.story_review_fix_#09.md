## Findings to fix

### [should-fix] R9-S1 — an empty merge lookup is not guarded: a merge over an open `MERGE_HEAD`, or an unbounded abort loop
- File: `qs-node.md.j2` item 3 (~:414-419), item 2 (~:407-413), rule 5 case 3 (~:240-244);
  `qs-node-implementer.md.j2` (~:177-183)
- Source: qs-review-blind-hunter and qs-review-edge-case-hunter, merged
- Description: an empty `--merges` result sends the node "back to item 2" with no guard.
  - (a) The resolution implementer returns without committing, so `MERGE_HEAD` is still open. Item 2 then runs
    `git merge` over it. Git refuses, the node ends in a generic `error` block, and it may `merge --abort` and
    throw the resolution away.
  - (b) The implementer runs `git merge --abort` itself. Item 2 then merges again, the implementer aborts again, and
    so on. Nothing bounds this.
- Fix:
  - **Item 3:** treat an empty result as a red gate under item 4's rule:
    - `MERGE_HEAD` is still open → the "finish the open merge" invocation, which counts as item 4's "one more
      invocation";
    - no merge and no `MERGE_HEAD` → back to item 2 **at most once per catch-up**, recorded as `catchup.retried` =
      true;
    - a second empty result → blocked (cause `catchups`, "merge not committed", plus the implementer's output tail).
  - **Item 2:** add "never start a new merge over an open `MERGE_HEAD`".
  - **`qs-node-implementer.md.j2`:** add "never abort it" to "resolve the merge conflicts", as "finish the open merge"
    already says.
  - **Rule 5 case 3:** name the empty-result exception.
  - **`round.json`:** add `"retried"` to the `catchup` keys, and to the `control-plane.md` mirror.

### [should-fix] R9-S2 — `catchup.reviewed` as a boolean loses "HEAD moved" across a double reap
- File: `qs-node.md.j2` item 4 (~:430-432), item 5 (~:436-442), rule 5 case 4 (~:245-250), the `catchup` field
  description; `control-plane.md` ~:650
- Source: qs-review-edge-case-hunter
- Description: the gate commits a fix and the node is reaped before the "`reviewed` = false" write. The next
  resume's gate sees the fix already applied and does not move `HEAD`. `reviewed` stays true, so the fix is pushed
  unreviewed.
- Fix: `catchup.reviewed` becomes `<sha>|null`, the `HEAD` the resolution review covered. Item 5 sets it to `HEAD`,
  and runs when (`catchup.clean` is false or `HEAD` ≠ `catchup.merge`) **and `HEAD` ≠ `catchup.reviewed`**.
  - Remove the "any implementer invocation that moves `HEAD` is followed by a write with `catchup.reviewed` = false"
    rule, and its use in rule 5 case 4. They are no longer needed.
  - Item 1's entering write sets `reviewed: null`.
  - Rule 5 case 3's recording no longer sets `reviewed`.

### [should-fix] R9-S3 — the `--merges` lookup can record a merge commit from `main`
- File: `qs-node.md.j2` item 3 and rule 5 case 3; `control-plane.md` ~:657; the story's #08 note
- Source: qs-review-blind-hunter. Also raised by the edge-case hunter and the acceptance auditor as a nice-to-have.
- Description: `<head>..HEAD` also contains `main`'s own merge commits. `-1` picks by committer date, so with clock
  skew a merge from main could be recorded as `catchup.merge`, which gives the wrong `--remerge-diff` and `--base`.
- Fix: `git log -1 --first-parent --merges --format=%H <head>..HEAD`, which walks only the task branch's own line.
  Update the pin.

### [should-fix] R9-S4 — step 6 can reach done with a plan-level `fix` still pending
- File: `qs-node.md.j2` step 6 (~:381-388); "The `fix` protocol" (~:760-765)
- Source: qs-review-blind-hunter (should-fix) and qs-review-edge-case-hunter (N2), merged
- Description: a plan-level `fix` popped during a final wait, or a catch-up's own wait, opens its finding on
  `--phase plan`. So `convergence.build.blocking` stays empty, and step 6 goes to step 7 or 8, with the fix
  unapplied.
- Fix: in step 6, before the step 7 / step 8 routing, add: "`pending.json` holds a fix → the round's `continuing`
  report (unless already posted), then the `fix` protocol (a plan-level fix: the plan loop on the delta; a code-level
  fix: the next round)". Item 2's "from `done`, step 8", reached only on a resume, applies the same check first (N3).
