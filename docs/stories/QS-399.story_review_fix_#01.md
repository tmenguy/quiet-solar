## Findings to fix

### [must-fix] F1 — Text-id ordering picks the wrong deliverable in `session_holder_dead`
- File: `scripts/qs/control_plane/locks.py:140-144`
- Source: blind-hunter + edge-case-hunter (both confirmed by running it)
- Description: `ORDER BY id DESC LIMIT 1` sorts the TEXT ids `T<n>` as
  text, so `"T9" > "T10"`. With T9 (dropped) and T10 (building) on the
  same branch `QS_42`, the check reads T9, decides the owner is
  terminal, and the live session's `integration:QS_42` lock gets taken.
- Proposed fix: decide "the owner is finished" as "no non-terminal
  deliverable has this branch": `NOT EXISTS (SELECT 1 FROM tasks WHERE
  branch=? AND is_deliverable=1 AND state NOT IN (<terminal>))`. Grep the
  package for any other `ORDER BY id` on TEXT ids and use `rowid`
  instead. Test: T9 dropped plus T10 building on the same branch, and
  the lock is NOT taken.

### [must-fix] F2 — PreToolUse lets the DB-access deny through when the DB can't be used
- File: `scripts/qs/control_plane/hooks.py:244-256`
- Source: blind-hunter
- Description: `db_access_denial()` never touches the DB, but its deny
  is returned only after `_db_if_current()` and `_record()` succeed. With
  `SCHEMA_PENDING`, `BUSY` or a connect error, the broad `except` returns
  allow, so the guard switches off exactly while the DB is migrating or
  under contention.
- Proposed fix: compute the static denial first. Wrap only the DB part
  (`registered_denial` and `_record`) in its own try/except. When the
  static rule fired, always return `_deny(reason)`. Tests: monkeypatch
  `_db_if_current` to raise `CpError("SCHEMA_PENDING")` and
  `CpError("BUSY")`; a `rm harness_state.db` command is still denied.

### [must-fix] F3 — `spawn --replace` is refused with BUSY when the node cap is full
- File: `scripts/qs/control_plane/tools.py:815-817`
- Source: blind-hunter
- Description: `locks.admit_node` runs before `nodes.move(live →
  "superseded")`, so the node being replaced still counts against the
  cap. With `QS_CP_MAX_NODES` live nodes, a replace always fails.
- Proposed fix: supersede `live` before `admit_node`, in the same
  transaction, so a later BUSY rolls the supersede back. Test:
  `MAX_NODES=1` with one live node; `spawn --replace` succeeds. Also
  assert that a BUSY on another path leaves `live` un-superseded.

### [should-fix] F4 — `ps -o lstart=` depends on TZ and locale; a failed `ps` counts as dead
- File: `scripts/qs/control_plane/liveness.py:62-71` (callers:
  `locks.py:119`, `wait.live_waiter`, `daemon.ensure`)
- Source: blind-hunter + edge-case-hunter (TZ dependence confirmed)
- Description: `pid_start` changes with the caller's `TZ`, so a live
  holder can look dead. `start_of` also returns `None` both for "no such
  process" and for a timeout or exec failure (rc 124/127), so a failed
  probe reads as "dead". That contradicts the rule that a failed probe
  is never treated as absence.
- Proposed fix: run `ps` with `env_extra={"LC_ALL": "C", "TZ": "UTC0"}`.
  Make `start_of` / `alive` tri-state: `True`, `False`, or unknown (for
  example `None`). Callers treat unknown as alive (never take over on
  unknown). Tests: the env is passed; rc 124 or a timeout gives unknown;
  each caller keeps the holder on unknown.

### [should-fix] F5 — A session-held lock can be stolen after one transient listing failure
- File: `scripts/qs/control_plane/locks.py:119` (`probe_row`)
- Source: edge-case-hunter
- Description: when `claude agents --json` fails, `pid_alive` alone
  decides, and with F4 "unknown" also counted as dead.
- Proposed fix: if `listing is None`, keep the session-held row unless
  the pid is *proven* dead (F4's tri-state). Test: listing fails and
  liveness is unknown, so the lock is kept.

### [should-fix] F6 — The daemon can't start unless the main checkout is on `main`, even with no migration
- File: `scripts/qs/control_plane/migrations.py:84` (plus
  `daemon.py:69-76`)
- Source: edge-case-hunter
- Description: `_authorise` runs before the `current == target` noop
  check. A detached HEAD or a feature branch in the main checkout gives
  `POLICY_REFUSED`, then `migrate-error.json`, then 300 s of
  `migrate_failed`.
- Proposed fix: take the lock, read `user_version`, and return noop if
  it equals the target. Call `_authorise` only when `current < target`
  or the DB is missing. Test: the DB is current and the main checkout
  is on a feature branch, so `migrate` is a noop and the daemon starts.

### [should-fix] F7 — `migrate`: lock contention becomes a 5-minute outage; a bare ROLLBACK can hide the error
- File: `scripts/qs/control_plane/migrations.py:101,109-111`
- Source: edge-case-hunter
- Description: `BEGIN IMMEDIATE` sits outside the try, so a raw
  `OperationalError` lands in the backoff sidecar and causes 300 s of
  `SCHEMA_PENDING`. The unguarded `ROLLBACK` raises "no transaction is
  active" after SQLite has already rolled back by itself.
- Proposed fix: map SQLITE_BUSY to `CpError("BUSY")`. The daemon retries
  on BUSY without writing the backoff sidecar. Guard the rollback with
  `if conn.in_transaction`. Tests: a BUSY `BEGIN` writes no sidecar; an
  auto-rolled-back step keeps the original error in the sidecar.

### [should-fix] F8 — One BUSY on a heartbeat kills the daemon or ends a `wait`
- File: `scripts/qs/control_plane/daemon.py:95-96`,
  `scripts/qs/control_plane/wait.py:67-70`
- Source: blind-hunter + edge-case-hunter
- Proposed fix: catch `CpError` with code BUSY around the heartbeat
  write, log it, and continue to the next tick or poll. Tests for both
  loops.

### [should-fix] F9 — `ensure` never kills a daemon that is alive but stale; a slow restart spawns a daemon that exits at once
- File: `scripts/qs/control_plane/daemon.py:182-205`
- Source: edge-case-hunter
- Proposed fix: send SIGTERM whenever `probe.alive(lease.pid,
  lease.pid_start)` is true and `lease.schema_version < target`, not
  only when the lease is fresh. If the restart deadline passes while the
  old daemon is still alive, return status `restart_pending` instead of
  spawning. `wait` treats `restart_pending` like `restart_wait`. Tests
  for both paths.

### [should-fix] F10 — Replaying a successful key can fail with USAGE / INVALID_STATE; `args_hash` ignores file content
- File: `scripts/qs/control_plane/tools.py:434-436` (and the
  `_read_arg_file` / `_need(...)` uses at 544-551, 785, 916, 1023, 1074,
  1107)
- Source: edge-case-hunter
- Description: `spec.steps()` and `spec.locks()` run before `claim()`,
  so a replay needs the temp `prompt_file` and the task columns to still
  exist. `args_hash` covers only the file path.
- Proposed fix: do the replay lookup (`claim()`'s "already succeeded"
  check) before building steps and locks. A replay of a succeeded call
  returns the recorded result without calling `steps()` or `locks()`.
  Include a content hash of each argument file in `args_hash`: the same
  key with the same path but edited content gives CONFLICT. Keep the
  frozen `ToolSpec` API signature unchanged. Tests: replay after
  deleting `prompt_file` returns the recorded result; replay of `push`
  after `worktree-cleanup` cleared `worktree` returns the recorded
  result; an edited file under the same key gives CONFLICT.

### [should-fix] F11 — Failed `gh` listing is read as "not created": duplicate issue
- File: `scripts/qs/control_plane/tools.py:554-564` (issue-create probe
  1009-1013)
- Source: edge-case-hunter
- Proposed fix: when `res.ok` is false or the output can't be parsed,
  raise `CpError("BUSY")` ("probe unknown, replay later"). Search by the
  marker (`--search "<marker> in:body"`) instead of a fixed
  `--limit 50` window. Tests: a failed listing gives BUSY and no
  `create_issue.py` call; the marker search argv is asserted.

### [should-fix] F12 — `worktree-cleanup` can force-remove the main checkout or a live task's worktree
- File: `scripts/qs/control_plane/tools.py:615-646`
- Source: blind-hunter + edge-case-hunter
- Proposed fix: before removing, check four things:
  - the resolved path is not `ctx.main`, else POLICY_REFUSED;
  - `<wt>/.git` is a file (a linked worktree), else POLICY_REFUSED;
  - no other non-terminal task has the same resolved `worktree`, else
    clear only this task's column and return a noop with
    `shared_with: <task>`, without removing anything.

  Tests cover each refusal and the shared-path noop.

### [should-fix] F13 — Pre-push `_registered_task` picks the oldest task on a shared worktree path
- File: `scripts/qs/control_plane/hooks.py:271-275`
- Source: edge-case-hunter
- Proposed fix: prefer non-terminal tasks, newest first (order by
  non-terminal first, then `rowid DESC`). Test: T5 is dropped with a
  stopped node and T12 is building on the same path, so a push from
  T12's node is allowed.

### [should-fix] F14 — `_merge_success`: the PR merged but the call is recorded as failed when the task changed state mid-merge
- File: `scripts/qs/control_plane/tools.py:1163-1168`
- Source: edge-case-hunter
- Proposed fix: once the `merge` output exists, always record
  `merge_sha`. If the task is still `ready_to_merge`, move it to
  `merged`. Otherwise, succeed the call with a `state_conflict:
  {"expected": "ready_to_merge", "actual": <state>}` field, so the
  maintainer or orchestrator reconciles it, and never `call.fail`.
  Test: the task is moved to `blocked` during the merge step, so the
  call succeeds with `state_conflict` and `merge_sha` is recorded.

### [should-fix] F15 — Gate and node caps read each process's own env
- File: `scripts/qs/control_plane/locks.py:59-72`
- Source: edge-case-hunter
- Proposed fix: enforce the cap by counting live rows (`count(*)` of
  live slots for that cap compared with the limit) instead of scanning
  `range(limit)`. A process with a smaller limit then never exceeds it,
  and a larger limit can't push the others over theirs. Test: one
  process holds slot 3 under limit 4, so a process with limit 2 and
  two live rows gets BUSY.

### [should-fix] F16 — Locks and cap slots taken by CLI tools have an empty `holder_actor`

  `self.actor = self.actor or who.actor` so `locks.hold` gets the

### [should-fix] F17 — The `cp.py` exemption is checked before the redirect check in `db_access_denial`
- File: `scripts/qs/control_plane/hooks.py:200`
- Source: blind-hunter
- Proposed fix: test `_REDIRECT_ONTO_DB` before the `cp.py` exemption.

### [should-fix] F18 — The pre-push / hook shim falls back to a system `python3` that may be too old for py314 syntax, blocking every push
- File: `scripts/qs/control_plane/hooks.py:39,379`
- Source: blind-hunter
- Description: the project targets py314 (PEP 758 `except A, B:` in
  `db.py:136` is valid there, so keep it). But the shim, installed in
  the shared git dir, falls back to `python3`. On macOS that is
  `/usr/bin/python3` 3.9, which hits a SyntaxError, exits 1, and every
  push is refused, which contradicts "fail open unless proven
  registered".
- Proposed fix: in both shims, if the venv python is missing, try
  `python3` only if `python3 -c 'import sys; sys.exit(sys.version_info
  < (3, 14))'` succeeds. Otherwise print a one-line warning to stderr
  and `exit 0` (fail open). Test: the rendered shim text contains the
  version guard, and the e2e shim test with a fake old `python3` exits 0.

### [should-fix] F19 — Spawn replay can return BUSY forever when the launched session never appears
- File: `scripts/qs/control_plane/tools.py:719-739,764-776`
- Source: blind-hunter + edge-case-hunter
- Proposed fix: in the spawn probe, reap your own `spawning` row
  (move it to a terminal state such as `failed` or `superseded`) when
  three things hold: it is past the identify or settle deadline, the
  listing succeeded (not None) and the session is not in it, and the
  launching holder is proven dead. Then report "not launched" so the
  replay relaunches. Test: a pending launch whose holder is dead and
  which is not listed gets relaunched on replay.

### [nice-to-have] F20 — `db.write`: a failed COMMIT leaves the connection in a transaction; every OperationalError is reported as BUSY
- File: `scripts/qs/control_plane/db.py:49-53,75`
- Source: blind-hunter + edge-case-hunter
- Proposed fix: on COMMIT failure, `ROLLBACK` if `conn.in_transaction`,
  then re-raise. In `_begin`, map only SQLITE_BUSY / SQLITE_LOCKED
  (`sqlite_errorcode`) to BUSY and raise anything else as INTERNAL with
  the message. Tests for both.

### [nice-to-have] F21 — `locks.hold` finally: `release()` can raise BUSY and mask the tool's result
- File: `scripts/qs/control_plane/locks.py:353-357`
- Proposed fix: catch `sqlite3.Error` / `CpError("BUSY")` in the release
  inside `finally` and log it to stderr (liveness recovers the rows
  later). Test.

### [nice-to-have] F22 — `rowcount` is not checked on claim updates
- File: `scripts/qs/control_plane/tools.py:250,255,389,400`
- Proposed fix: if `rowcount != 1`, raise `CpError("STALE_TOKEN")` (the
  claim was taken over). Test: another holder takes over between claim

### [nice-to-have] F23 — Input validation: pid ≤ 0 from the listing; numeric CLI flags

## Deliberately not fixed (recorded so the next review doesn't re-raise them)

- **`models.py` Opus 5.5 change** (CodeRabbit, blind-hunter): the
  maintainer's own commit `24f79b44` ("maintainer 2026-10-04"), made on
  purpose on this branch. Not scope creep.
- **Export not called on merge** (CodeRabbit): calling it after a merge
  is child 7's job (story §"Seams" line 60). This PR ships
  `export.write_summary()` as the seam.
- **`run claim --session-id` trusts the caller** (blind-hunter): the
  threat model covers agent mistakes, not adversarial sessions. A node
  has to guess and forge another session's id on purpose. Record it as
  a convention in `docs/workflow/control-plane.md` "Conventions: what no
  hook enforces". No code change.
- **Node token in `claude --bg` argv** (blind-hunter): passing the
  token in the prompt is the AC14 design. Single-user machine.
- **DB-access allowlist misses `find -delete`, `sed -i`, `$(…)`, `git
  rm`; `gh pr merge` wrapper forms** (both hunters): the hook is a guard
  against accidents, not a sandbox. Record the known gaps in the
  "Conventions" list of `docs/workflow/control-plane.md`. Pragmatic
  hardening is optional; don't grow the parser.
- **`edit_dep` cycle check**: nothing reads `task_deps` yet (YAGNI). The
  scheduler child adds it.
- **`group_alive` pgid reuse, `file_lock` starvation, `--paths` values
  starting with `-`**: low likelihood. Leave them for later.
