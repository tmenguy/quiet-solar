## Findings to fix

### [should-fix] Step 4 says a closed review's session is always idle — an `abandoned` one may still be busy
- File: `docs/workflow/control-plane.md:578` (review pilot step 4 intro); `scripts/qs/control_plane/reviewpilot.py:19-20` (module docstring step 4, "has nothing left to do")
- Severity: should-fix
- Source: qs-review-coderabbit (+ qs-review-edge-case-hunter #4, folded in)
- Description: a `running` review whose `launch_at` passes `REVIEW_TTL_S` is moved to `abandoned` by `_session_move` while its session may still be **busy**. Step 4 then stops it, which interrupts that turn. The doc says "its `claude --bg` process is idle and listed `done` (L1)", which is wrong for this case. Separately, a maintainer who resumes a closed review's session by hand (`claude --resume <id>`) inside the 7-day window gets it stopped on the next tick, because `_matches` ignores the listing's kind. That is undocumented.
- Proposed fix (docs/docstring only, no behaviour change):
  - control-plane.md step 4 intro: a `finished` or `failed` review's session is idle, listed `done` (L1); an `abandoned` one may still be busy (a `REVIEW_TTL_S` expiry), and the stop interrupts it on purpose, since its token is void. Keep the rest of the step as it is.
  - reviewpilot.py module docstring: replace "has nothing left to do" with wording that covers both (idle, or an expired session whose token is void).
  - control-plane.md, the "review-session stop window" Conventions bullet: add one sentence saying a closed review's session resumed by hand inside the window is stopped on the pilot's next tick.

### [should-fix] `word_tail` can drop almost the whole tail when the cut falls inside a long token
- File: `scripts/qs/control_plane/liveness.py:42-57` (`word_tail`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter #1
- Description: nothing bounds the partial word that gets dropped. `word_tail("failed: " + "/a"*40 + " x", 50)` returns `"x"`, losing 48 of 50 characters. `bg_failure`'s realistic stderr (a long folder path followed by a short suffix) loses exactly the most useful part, the path.
- Proposed fix: drop the partial word plus its whitespace run (`gap.end()`) only when `gap.end() <= limit // 2`. Otherwise keep the raw cut. Update the docstring to match. Every existing `test_word_tail` case keeps its expected value (`"alpha beta gamma", 8` drops 3 ≤ 4; `"ab cd", 3` drops 1 ≤ 1). Add parametrized cases:
  - `("failed: " + "/a" * 40 + " x", 50, ("/a" * 40 + " x")[-50:])`: a long partial token is kept (raw cut).
  - A boundary pair at exactly `limit // 2` (dropped) and `limit // 2 + 1` (kept raw).
  - Keep the `len(out) <= limit` and non-empty invariants.

### [nice-to-have] A failed stop with an empty stderr logs a dangling `": "` and ignores stdout
- File: `scripts/qs/control_plane/reviewpilot.py:580-587` (`_log_stop_failure`)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter #3
- Description: `claude stop` exiting non-zero with an empty stderr logs `... claude stop exited 1: ` (trailing separator), and a diagnostic printed on stdout is lost. `bg_failure` already falls back to stdout.
- Proposed fix: `output = res.stderr.strip() or res.stdout.strip()`; `tail = liveness.word_tail(output, STOP_TAIL)`; write `: {tail}` only when `tail` is non-empty. Add tests for an empty stderr with a non-empty stdout (the stdout text is logged) and for both empty (the line ends at `exited <code>`, no `": "`). Update the logged-line format in control-plane.md step 4 if needed (`[: <tail>]`).

### [nice-to-have] The stop budget never trips if the wall clock steps backwards
- File: `scripts/qs/control_plane/reviewpilot.py:~613-616` (`stop_closed` budget check)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter #2
- Description: `elapsed = (clock.now() - started).total_seconds()` goes negative when the system clock steps back (NTP), so the `>= HOOK_SUBPROCESS_S` check never breaks and every match is stopped in one tick.
- Proposed fix: keep the clock seam, and treat a negative elapsed time as the budget being spent: `if elapsed < 0 or elapsed >= ticks.HOOK_SUBPROCESS_S: break`. Add a test where the fake clock steps back after the first stop: exactly one stop is sent and the rest wait for the next tick.
