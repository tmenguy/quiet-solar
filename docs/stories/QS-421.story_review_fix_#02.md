### [should-fix] A `--pattern` starting with `-` is rejected by argparse
- File: `scripts/qs/agent_templates/_macros.md.j2:244-252` (+ pin in `tests/qs/test_render_agents.py`, `test_review_agents_pin_the_contract`)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: `cp.py review read` parses with argparse (`scripts/qs/control_plane/cli.py`
  `_conf_review_read`): `--pattern '--bg'` fails with "expected one argument" (the shell
  strips the quotes), a `USAGE` the agents' Errors section does not cover for `review read`.
  `--pattern='--bg'` parses fine and still matches the `Bash(<prefix> review read:*)` rule.
- Proposed fix: add one sentence to the BRE paragraph: "a pattern starting with `-`: use the
  `=` form, `--pattern='--bg'`." Verify the claim with a quick argparse check (or an existing
  cli test) before writing it. Extend the whole-block pin. Mirror in the `docs/workflow/control-plane.md`
  grep row if that row describes how agents pass the pattern.

### [should-fix] No T13 check that a single-quoted `--pattern` with metacharacters passes `dontAsk`
- File: PR #422 body ("T13 re-run pending" checklist) and `docs/stories/QS-421.story.md` (Done-when checklist + T7 "(a)–(f)")
- Severity: should-fix
- Source: qs-review-edge-case-hunter, qs-review-blind-hunter
- Description: the new guidance tells agents to single-quote patterns that may hold `(`, `|`,
  `;`, `$` or a backtick. Under `dontAsk`, a command Claude Code's Bash check sends to "ask" is
  silently denied; this is unverified.
- Proposed fix: add "(g) under `dontAsk`, `review read grep` with a single-quoted `--pattern`
  holding `(`, `|`, `;`, `$` and a backtick runs without a denial (a denial opens the follow-up)".
  Update the PR body via `gh pr edit 422 --body-file …` (only the checklist) and the story
  (checklist + T7 "(a)–(g)"). No code change.
