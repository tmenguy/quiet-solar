# QS-424 — The nodes, Control Plane side: trusted worktrees, the launch's output, `done` sessions, the report and digest vocabulary

Issue: [#424](https://github.com/tmenguy/quiet-solar/issues/424) · Parent epic: #369 (child 6b-1) ·
Lane: feature-factory · Target: factory · Wave 5, merged first (6b-1 → 6b-2 → 6a → 9).

## Problem

Before a node agent (6b-2) can run, the Control Plane must:

- launch a node in a worktree Claude Code accepts, and say why when it refuses
  one. Today `tools._launch` raises a bare `claude --bg exited N` and drops the
  output, unlike `reviews._launch` since #421;
- deliver the node its prompt at all (L8 below: today it does not);
- not mistake an idle node for a dead one (#421 left open whether a listed
  `done` means "ended" for a multi-turn session);
- give a node an **exact interface** to report in. #399 built `report post` and
  `digest put` and left their vocabulary to 6b on purpose ("the vocabulary of
  its `fields` is 6b's"). So today `--phase` is free text, `--fields-file` takes
  any JSON, and `digest put` takes any text. A report with phase `Build` is
  stored and then silently ignored by the convergence check, which compares
  `phase = 'build'` exactly;
- record the resume, hook and effort checks that #399/#405 left "unverified" in
  `control-plane.md` and `harness.md`.

## Goal

The Control Plane side of a node is ready for 6b-2:

- a failed node launch carries the redacted output tail and the trust hint;
- a spawned node receives its prompt;
- `done` handling rests on a recorded live result;
- `report post` and `digest put` accept only a closed, exact contract: enums for
  the phase and the status, and closed JSON schemas for `fields` and for the
  digest, with no text parsing;
- the node's worktree-local files are named and gitignored;
- the live checks are recorded.

**Trust inheritance** is already proven live. #421's re-run (2026-10-17)
launched review sessions in fresh `cp-reviews/<db>/V<n>` folders, each created
just before its launch, under the once-trusted `~/.local/state/quiet-solar`. AC9
confirms the same for a new `QS_<N>` under `quiet-solar-worktrees`.

**Conclusion on `done`:** a listed `done` means **the turn finished**, whatever
the kind of session. The default listing (what `ClaudeCli.agents` reads, no
`--all`) shows `done` for a live, idle session and never lists an ended or killed
one. So for a node, `done` does not mean ended. As the issue requires, the five
sites stay as they are:

- `nodes.refresh` is the only one that reads `status`/`state`. It maps `idle` in
  either field to `idle`, and anything else listed to `running`. An unexpected
  pair such as `busy/done` or `null/null` reads as live, the fail-safe side.
- `tool resume`'s live check, `locks.admit_node` and `tool spawn`'s late-launch
  adoption test presence in the listing only.
- `locks.session_holder_dead` tests presence by session id and reads no
  `status`.

For a single-turn review, "turn finished" is treated as "review over" (#421),
which stays right. A finished review's process stays alive, though; stopping it
is [#423](https://github.com/tmenguy/quiet-solar/issues/423)'s item 4, high
priority, right after #424. An ended node is already resumed by its full id
(`tool resume` → `resume_bg(session_id)`), never respawned.

**L8 is a latent bug in `tool spawn`.** Its argv ends `… --settings S --add-dir
<MAIN> "<prompt>"`, so every node spawned today starts with no prompt and no
token (exit 0, listed, idle). It is fixed here (D2, the maintainer's decision).
The other `claude --bg` launchers are safe: `reviews._launch` ends
`… --settings <json> "<prompt>"`, and the watchdog's messenger uses the
one-word `--allowedTools=SendMessage` form.

## Design

### D1 — the launch's failure text (`tools._launch`, shared by `tool spawn` / `tool resume`)

- **Node tokens are redacted.** The node token rides in the spawn's prompt
  (argv), so a failed launch's output may echo it. The run token never reaches a
  launch: it is removed from the launched environment (`TOKEN_ENV`) and is not in
  the argv. Node tokens are minted by `tokens.mint` (`f"{kind}:{subject}.{epoch}.{nonce}"`)
  and parsed by `tokens._TOKEN_RE`. A new
  `tools._NODE_TOKEN_RE = re.compile(r"\bnode:([A-Z]\d+)\.(\d+)\.[0-9a-f]+")` mirrors
  it, and `tools.redact` substitutes `r"node:\1.\2.<redacted>"` (giving
  `node:N1.1.<redacted>`), the same marker as review tokens. `<` is not hex, so
  `Call.fail`'s second pass is a no-op. `test_redact`'s run-token pin stays as it
  is: run tokens are not redacted, as before.
- **Where `redact` runs (error paths only):** `Call.fail` (a failed call's
  `detail` and `result`), `reviews.close_locked` (`reviews.error`) and `reviews._launch`.
  No success or replay path calls it, so a spawn's answer still carries the full
  node token. A review error now also scrubs a node token, which is harmless.
- `_launch(ctx, start, *, trust_dir: Path)`: on `not res.ok` (any non-zero exit,
  timeout 124 included; `RunResult.stdout`/`stderr` are always `str`, the
  timeout result included), build
  `clean = dataclasses.replace(res, stdout=redact(res.stdout), stderr=redact(res.stderr))`
  (redact **before** the cut, as in `reviews._launch`) and raise
  `StepFailed(liveness.bg_failure(clean, trust_dir, liveness.BG_ERROR_MAX), {"exit_code": res.returncode}, res.returncode)`.
  `tools.py` gains `import dataclasses`: `replace` alone would shadow the local
  `replace` flag of `_spawn_steps`.
- **One cap:** `liveness.BG_ERROR_MAX = 500`, and `reviews.ERROR_MAX = liveness.BG_ERROR_MAX`
  (an alias; its other uses are unchanged). The `bg_failure` docstring says
  `BG_ERROR_MAX`.
- **The texts:** the call's recorded `result["detail"]` (in `tool_calls`) is
  exactly the `bg_failure` text, `claude --bg exited N: <tail>[; <trust hint>]`,
  at most `BG_ERROR_MAX` characters. `bg_failure` keeps the head and the hint
  whole and cuts the tail. The answer's `detail` is that text prefixed by
  `"spawn: "` (or `"resume: "`), added by `Call.fail`.
- `trust_dir = wt.parent`, where `wt = Path(_need(task, "worktree"))` is the
  worktree both callers already use as the launch's `cwd`. The `worktree` column
  holds the absolute path `setup_task.py` returns. For every worktree that
  `tool worktree-create` / `tool item-create` make (`QS_<N>`, `QS_<N>_<k>`),
  this is `utils._worktrees_root()` = `quiet-solar-worktrees`, the folder the
  maintainer trusts once. The Control Plane does not import `scripts/qs/utils`
  (import purity).

### D2 — the prompt after `--add-dir` (L8)

In `_spawn_steps.launch.start`, move `"--add-dir", str(ctx.main)` to right after
`--model <m>`, before `--permission-mode`, so the argv ends
`… --settings <json> "<prompt>"`. This is the reorder L8 verified live; `--` was
not checked live and is not used. The positional test helpers still hold:
`_assert_policy_argv`'s `argv[6:8] == ["--model", m]` and `_settings` (which
finds `--settings` by index), and `toolsim._claude_bg` reads `-n` and
`--resume` by `argv.index`, not by position. A comment cites L8 and the
watchdog's `--allowedTools=` precedent. `tool resume` passes no `--add-dir`,
since the bare resume restores it (L7).

### D3 — `done` for a node: recorded, no behaviour change

No change at the five sites. Added:

- a docstring line in `nodes.refresh`: "a listed `done` is a finished turn, not an
  ended session (#424 L1/L3/L9); contrast `reviewpilot._session_move`";
- **three pin tests**, one per site that reads a listed session for a node row,
  each with a session listed `status: idle, state: done` (`conftest.agent(…, state="done")`;
  `status` defaults to `"idle"`). Maintainer's decision A: these three.
  1. `nodes.refresh` keeps it `idle`, never `reaped`;
  2. `tool resume` refuses it as live (`"is live"` in the detail, no `claude --bg`);
  3. `tool spawn`'s late-launch adoption adopts it (the same session, the old
     token, exactly one `claude --bg`).

The other two sites are covered by their existing tests, which pass unchanged.

### D4 — the report contract (`reports.post_report`)

**The phase** is an enum: exactly one of `schema_ledger.PHASES` (`plan`,
`build`), else `USAGE` (maintainer's decision B). `reports.py` imports `PHASES`
from `schema_ledger`, which imports nothing, so there is no cycle. **The status**
is already an enum (`reports.STATUSES` = `converged`, `continuing`, `blocked`,
refused with `USAGE`), and it stays so. `round` stays an int ≥ 0, as today.

**`fields`** is a closed JSON schema. The constants live in `reports.py`:

```python
FIELDS = ("blocking", "questions", "discovered")   # every key optional; `{}` is valid
DISCOVERED_KEYS = ("title", "why", "shrinks")      # title, why required; shrinks optional
FIELDS_MAX_BYTES = DIGEST_MAX_BYTES                # 16 KiB, both already in reports.py
QUESTION_ID_RE = re.compile(r"Q-[1-9][0-9]*")      # `question open`'s ids, fullmatch
```

| key | type | meaning |
|---|---|---|
| `blocking` | list of positive `int`s (a `bool`, `0`, a negative or a float is refused) | the finding ids of `convergence.blocking` the node saw when it posted (the evidence child 17 reads) |
| `questions` | list of strings, each `QUESTION_ID_RE.fullmatch` (a non-string or `"Q-1 "` is refused) | the open questions (`question open`) this round raised or still waits on |
| `discovered` | list of objects | tasks found outside the task. Each item is checked in order: it is an object; it has no key outside `DISCOVERED_KEYS`; it has `title` and `why`; `title` and `why` are non-empty strings (after `.strip()`); `shrinks`, if present, is a real `bool` (`0`, `1` and `null` are refused). `shrinks: true` means the discovery shrinks this task, the one case where the node waits for the answer |

`validate_fields(fields: Any) -> None` raises `CpError("USAGE", …)` naming the
first violation, in this order: not a `dict`; an unknown key; then each key in
`FIELDS` order (its type, then its items). The size,
`len(messages.canonical(fields).encode()) > FIELDS_MAX_BYTES`, is checked last
and refused with `CONFLICT`, the code the digest's cap already uses. Shape is
`USAGE`, size is `CONFLICT`, on purpose, for both. `messages.canonical` writes
compact, sorted, `ensure_ascii=False` JSON, so accented text costs its UTF-8 size.
Strings are stored as given, never stripped. The checks are of type and shape
only: like `review finish`, nothing cross-checks ids against the DB, and
duplicates are harmless. `--fields-file` stays required, and non-JSON content in
it is already `USAGE` (`messages.parse_payload`). The phase, status and fields
checks all run before the transaction, so a refusal writes no row and posts no
message.

The `report` message payload stays short and unchanged. The orchestrator reads
`fields` through `task show` / `snapshot`, which already return the `reports`
rows in full.

### D5 — the digest contract: JSON, not Markdown (`reports.put_digest`)

**What the digest is for.** It is the task's short memory, replaced on every put
and capped at 16 KiB. Its readers are:

- the global and cross-run review sessions;
- the run's final review;
- a fresh node session that resumes a rotated task from its digest, plan and
  ledger;
- the exported task summary.

No reader is code that parses it, so its values are plain text. But the digest is
validated against an exact interface, not by parsing headings (maintainer's
decision C: JSON, any order).

```python
DIGEST_KEYS = ("goal", "why", "plan", "done", "problems", "decisions", "questions", "discovered")
```

| key | holds |
|---|---|
| `goal` | the goal and the validated acceptance criteria |
| `why` | the use case, or the root cause for a bug (the final review reads it) |
| `plan` | approach, modules, interfaces, assumptions |
| `done` | what was done |
| `problems` | major problems |
| `decisions` | decisions and rejected findings, with their reasons |
| `questions` | open questions |
| `discovered` | discovered tasks |

- `digest put --file F` reads F as JSON (`cli._digest_put` → `messages.parse_payload`;
  non-JSON is `USAGE`). The function becomes
  `put_digest(conn, clock, *, token, task_id, digest: Any, max_bytes=DIGEST_MAX_BYTES)`.
- `validate_digest(digest)` raises `USAGE` when the value is not an object, a key
  is missing or unknown, or a value is not a string. Every key is required; a
  value may be empty (`""`: nothing to say). Order is irrelevant, since it is a
  JSON object. Values may hold free Markdown.
- The size check becomes `len(messages.canonical(digest).encode()) > max_bytes`
  → `CONFLICT` (the same code and cap as today, now on the canonical JSON),
  checked after the shape. The canonical JSON is stored in the existing
  `digests.body` column, with no migration. The answer stays `{task_id, bytes}`,
  with `bytes` the canonical length.
- **One rule for reading a stored body**, shared by `task show` and the export:
  `reports.parse_digest(body: str) -> dict | None` returns the object when the body
  parses as JSON and `validate_digest` accepts it, else `None`.
  - `snapshot.task_show` returns `digest.body` as that object, or as the raw text
    when `parse_digest` returns `None`. `snapshot` itself carries no digest body
    (only `task_id`, `bytes`, `updated_at`), so it is unchanged.
  - `export.render_summary` (new imports: `from . import reports`; no cycle)
    renders a parsed digest under its `## Digest` heading as, for each key in
    `DIGEST_KEYS` order, `### {key.capitalize()}`, a blank line, the value, and a
    blank line. Inside a value, every line that starts with `#` gets `###`
    prepended, so a value's own headings sit below level 3. A node that writes
    `## Decisions` inside a value cannot add a second `## Decisions` to the
    summary. When `parse_digest` returns `None`, the raw body is rendered as
    today.
  - Both fallbacks stay for a digest stored before this change (a text digest put
    by hand on an existing DB). They are tested with bodies inserted by raw SQL,
    since `put_digest` now refuses them.

### D6 — what a node keeps in its worktree

Documented in `control-plane.md`, with no Python constants, since nothing in the
Control Plane reads or writes these files:

- the directory `.qs-node/` at the worktree's top level, holding `plan.md` (the
  plan, the contract once the plan loop converges), `digest.json` (its digest as
  last put: `digest put --file .qs-node/digest.json`), `binding.json` and
  `round.json`;
- the node writes them (6b-2). The layouts suggested for 6b-2, which may adjust
  them, are `binding.json` = `{"run", "task", "node", "generation"}` (**never the
  token**) and `round.json` = `{"phase", "round"}`. Child 18 defines what it
  reads; nothing else is persisted for it;
- `.gitignore` gains `/.qs-node/` with a `# QS-424` comment, keeping one trailing
  newline;
- it is removed at cleanup with no new code. `tool worktree-cleanup` runs
  `cleanup_worktree.py --force`, whose `git worktree remove --force` (plus an
  `rmtree` fallback for a leftover directory) deletes the whole worktree
  directory, ignored files included.

### D7 — trusted worktrees

No code. Nothing reads or writes Claude Code's trust store, as for #421. The
maintainer trusts `quiet-solar-worktrees` once (`claude` in that folder, accept
the prompt), and D1's hint names that folder when a launch is refused.

## Acceptance criteria

1. **[CI]** A `tool spawn` whose `claude --bg` exits non-zero (exit 1, and exit 124)
   fails `TOOL_FAILED`. Its `tool_calls.result["detail"]` is the `bg_failure`
   text `claude --bg exited N: <tail>`. When the output (stderr or stdout) says
   "Workspace not trusted", the text ends with `; ` + `liveness.trust_hint(<worktree parent>)`.
   Its length is ≤ `liveness.BG_ERROR_MAX`, and the answer's `detail` is
   `"spawn: "` + that text. The same holds for `tool resume`, with `"resume: "`.
2. **[CI]** A node token minted by `tokens.mint` and echoed in a failed launch's
   output is redacted before the cut. This holds even when the tail cut falls
   inside the token's `node:N<n>.` prefix: no 8-character slice of its nonce
   appears in the answer or in `tool_calls.result`. Review-token redaction is
   unchanged, and run tokens are still not redacted.
3. **[CI]** `tool spawn`'s argv ends with the `--settings` value and then the
   prompt (`argv[-3] == "--settings"`), with `--add-dir <MAIN>` before
   `--permission-mode`.
4. **[CI]** A node listed `status: idle, state: done` stays `idle` through
   `nodes.refresh`, is refused by `tool resume` as live, and is adopted by
   `tool spawn`'s late-launch replay. The existing tests of the five `done` sites
   pass unchanged.
5. **[CI]** `report post` refuses (no row, no message) with `USAGE`:
   - a phase other than exactly `plan` / `build`;
   - a `fields` value that is not an object, or that has an unknown key;
   - a `blocking` that is not a list of positive ints (a `bool`, `0`, a negative or
     a float);
   - a `questions` item that is not a string or does not fully match `Q-<n>`;
   - a `discovered` item that is not an object, has an unknown key, misses
     `title` or `why`, has an empty `title` or `why`, or has a non-`bool` `shrinks`.

   An over-size canonical form is refused with `CONFLICT`. `{}` and every valid
   key are accepted and stored canonically.
6. **[CI]** `digest put` refuses with `USAGE` (nothing written) a file that is not
   JSON, or a digest that is not an object with exactly the `DIGEST_KEYS` as
   string values; any key order is accepted. An over-size digest is `CONFLICT`. A
   valid one replaces the previous one, and `bytes` is its canonical length.
   `task show` returns it as an object, and the export renders it as `### <Title>`
   blocks under `## Digest`. Even with `## Decisions` inside the `decisions`
   value, the summary has exactly one line `## Decisions`. A stored body that is
   not JSON, or JSON that is not a digest, is returned and rendered as raw text.
7. **[CI]** `.qs-node/plan.md`, `.qs-node/digest.json`, `.qs-node/binding.json`
   and `.qs-node/round.json` are ignored by the repository's `.gitignore`:
   `git check-ignore -v` names `.gitignore` and the `/.qs-node/` pattern as the
   source, so no global or `info/exclude` rule can make the test pass.
8. **[docs]** `control-plane.md` and `harness.md` record D1–D7 and L1–L9 at the
   sections listed in task 8. The resume, effort and `--settings`-hook lines change
   from "unverified" to the L6/L7 results. The hooks for a node started from a
   terminal and after `/desktop` stay listed as open until AC9.
9. **[live, after merge]** Driven by hand from a terminal with a run token, after
   the maintainer trusts `quiet-solar-worktrees`. The node agent ships with 6b-2,
   so the run uses a hand-written probe agent: `.claude/agents/qs-node.md` in the
   new worktree (gitignored, never rendered over, since `qs-node` has no
   template), with tools `Bash, Read` and the probe steps as its body. `tool spawn`
   is called with no `model`, so the policy's `qs-node` model and its `effortLevel`
   are sent. The probe steps:
   1. run `cp.py session status`;
   2. run `sqlite3 <db> 'select 1'`, which the node's `PreToolUse` hook must deny
      ("DB access outside `cp.py`");
   3. post `report post --phase plan --round 1 --status continuing` with fields
      `{}`, then stop.

   What is checked, with its evidence:
   - `tool worktree-create` + `tool spawn` in a new worktree launches (the
     answer; no trust refusal);
   - the prompt and token arrived (the `reports` row in `snapshot`);
   - the hooks fired (the deny in `claude logs <id>`);
   - the model and effort (the banner in `claude logs`);
   - `claude agents --json` shows the node `idle/done` between turns and absent
     after `claude stop`, and the next listing-taking call (`tool resume`'s
     reserve runs `nodes.refresh`) moves its row to `reaped`;
   - `tool resume` with a message that repeats step 2 brings back the same session
     id (`snapshot`), the hook denies again, and the banner shows the same model
     and effort;
   - the hooks for the same session opened from a terminal inside its worktree
     (`claude --resume <id>` and step 2) and after `/desktop`.

   The results go on [#424](https://github.com/tmenguy/quiet-solar/issues/424) as
   a comment (as #421 did) and into `control-plane.md` / `harness.md` in 6b-2's PR
   (#425), never as a direct commit to `main`. The PR body says AC9 is carried
   this way.

## Implementation notes (2026-10-21)

Built as planned (tasks 1–9). Where the code refines the plan, on purpose:

- **`_NODE_TOKEN_RE` has no `\b`.** With `\bnode:…`, a token glued to the text
  before it (`xxnode:N1.1.<nonce>`, as AC2's own cut-boundary output builds it)
  is not redacted and leaks. Over-redacting is harmless, and `_REVIEW_TOKEN_RE`
  has no `\b` either. `test_redact` pins the glued case.
- **An empty digest value renders `_None._`** under its `### <Key>` heading,
  instead of an empty paragraph (three blank lines), like the export's other
  placeholders.
- **A digest value is rendered as a blockquote** (review fixes #01–#05; the
  review rounds probed it on GitHub's own renderer). Every value line is
  quoted, so the blank line after it closes whatever the value left open (a
  fence inside a list item, an HTML block), and the summary's own `###` /
  `##` sections always survive. Inside the quote, line by line and with no
  Markdown state: every `#` heading, nested in a quote or a list item or not,
  at any indentation, is pushed three levels down (capped at 6); a setext
  underline gets a blank line before it; a footnote or link-reference
  definition is escaped. No code fence is tracked (fix #04: rounds 1–4 each
  found a new way a tracker falls out of step with the renderer), so a
  `# comment` inside a code block reads `#### comment` — cosmetic, the safe
  side.
- **Raw HTML, NULs and definitions in a value** (review fix #05): a `<` that
  opens a tag, a comment, `<?` or `<!` (not a URI autolink) renders `&lt;`
  (an unclosed `<!--` would hide every later section); a NUL renders U+FFFD;
  a setext underline gets its blank line unless the line before is already
  empty (a `    >` line is text); a definition label may span lines or hold an
  escaped `]`, so a line-start `[` whose label runs past the line is escaped.
- **`--round` and question ids are bounded** (review fix #05): `--round` must
  be `0..SQL_INT_MAX` (`USAGE`, before the transaction; an SQLite overflow
  was `INTERNAL`), and `QUESTION_ID_RE` is `Q-[1-9][0-9]{0,18}` with its
  number `<= SQL_INT_MAX`.
- **A failed node launch's output is also scrubbed of the node's own nonce**
  (review fixes #01, #03, #04), before `redact`: whole, whitespace allowed
  between its characters, then any 8-character window of it, so an echo
  wrapped inside the token (a line end, an ANSI code, a box border, a
  zero-width space) records no 8 characters of it.
- **`reports.parse_digest` also returns `None` on a `RecursionError`** (a
  deeply nested JSON body stored by hand), so `task show` and the export never
  fail on an old body.
- **The fields' first-violation order:** a key that is not a list is named
  `fields.<key> must be a list`, before its items.
