## Findings to fix

### [should-fix] The BRE paragraph never says to single-quote `--pattern`
- File: `scripts/qs/agent_templates/_macros.md.j2:244-249` (+ pin in `tests/qs/test_render_agents.py`, `test_review_agents_pin_the_contract`)
- Severity: should-fix
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter
- Description: the pattern goes through the Bash tool's shell. Followed literally,
  `--pattern foo\.bar` loses its backslash (git gets `foo.bar`, wrong hits, no error),
  `--pattern f(x)` is a bash syntax error before `cp.py` runs (not `NOT_FOUND`, so the
  retry-once exception never applies), and `--pattern *.py` is glob-expanded.
- Proposed fix: add one sentence to the paragraph, e.g. "Pass the pattern in single
  quotes (`--pattern 'f(x)'`); a pattern holding `'` cannot be single-quoted: pick
  another one." Keep the block's indent; extend the render-agents pin (which asserts the
  whole block verbatim) to the new text. Mirror in `docs/workflow/control-plane.md` if
  the grep row / bad-pattern sentence (≈L511/L516) describes how agents write a pattern.

### [should-fix] `bg_failure` can exceed `limit`, then `close_locked` cuts the head
- File: `scripts/qs/control_plane/liveness.py:40-50` (consumer `scripts/qs/control_plane/reviews.py:291` `[-ERROR_MAX:]`), doc `docs/workflow/control-plane.md:482`
- Severity: should-fix (flagged by 3 reviewers; contradicts the doc's "the prefix and the hint always kept")
- Source: qs-review-blind-hunter, qs-review-edge-case-hunter, qs-review-coderabbit
- Description: when prefix + hint alone exceed `limit` (a `QS_CP_REVIEW_DIR` longer than
  ~380 chars), `bg_failure` returns them whole; `close_locked` then keeps the last 500
  chars, dropping `claude --bg exited N` and the start of the hint from `reviews.error`
  and the `review_failed` payload.
- Proposed fix: make `bg_failure` never exceed `limit` (for any `limit` large enough to
  hold the prefix and the fixed hint text): when prefix + hint > limit, shorten the
  `trust_dir` shown in the hint to its last characters with a leading `…` so the result
  is exactly `limit` and has no tail. Update the docstring (drop the "unless … exceed"
  exception) and the test in `tests/qs/control_plane/test_liveness.py` (over-limit case:
  `len(result) == limit`, starts with `claude --bg exited 1`, ends with the hint's
  closing text, contains `…`). Add a `test_reviews.py` case proving `reviews.error`
  starts with `claude --bg exited 1` for a long review dir (or a monkeypatched small
  `ERROR_MAX` if a long tmp path is impractical). Keep control-plane.md L482 accurate.

### [should-fix] T13 checklist does not probe the "listed `done` = finished turn" assumption
- File: PR #422 body ("T13 re-run pending" checklist) and `docs/stories/QS-421.story.md` (the same checklist)
- Severity: should-fix
- Source: qs-review-blind-hunter
- Description: `reviewpilot.py:174` now abandons a `running` review on any listed `done`.
  If Claude Code ever lists `done` between turns of a still-working background session,
  a live review is abandoned in ~90 s. The rationale is documented but not verified.
- Proposed fix: extend check (e) (or add (f)): "a review doing several tool calls is never
  listed `done` before `review finish`". Edit the PR body with `gh pr edit 422 --body-file …`
  (keep everything else verbatim) and the story checklist to match. No code change.

### [nice-to-have] `//<dir>` placeholder reads as `///x/…`
- File: `docs/workflow/control-plane.md:506` (and the L899-area bullet with the same spelling)
- Severity: nice-to-have
- Source: qs-review-blind-hunter
- Description: `<dir>` is an absolute path, so `Read(//<dir>/in/**)` taken literally is
  `///x/V1/in/**`; the example right after shows the intended `//x/V1/in/**`.
- Proposed fix: say `<dir>` is the directory without its leading `/` (e.g.
  "`Read(//<dir>/in/**)`, `<dir>` without its leading `/`"). Do not touch the story's
  historical wording.

### [nice-to-have] AC2 stdout-fallback / no-output only tested at unit level
