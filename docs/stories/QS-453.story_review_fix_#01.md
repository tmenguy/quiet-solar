### [must-fix] F-001 — cmd_set supersede depends on decision order
- File: `scripts/qs/review_ledger.py:510`
- Severity: must-fix
- Source: qs-review-edge-case-hunter (co: qs-review-acceptance-auditor)
- Description: accepting a FLIP-FLOP F-y supersedes F-x only when F-x is
  `accepted`/`resolved`. If F-x was reopened in the same round, accepting
  F-y first then F-x leaves both `accepted` ("fix A" and "undo A").
- Proposed fix: accepting F-y supersedes its ref also when the ref is
  `open` (`open → superseded`), so the order no longer matters and F-x
  can no longer be decided afterwards. Add the row to the D2 transition
  table and a named test for both orders.

### [should-fix] F-002 — _superseder follows only one step
- File: `scripts/qs/review_ledger.py:325`
- Severity: should-fix
- Source: qs-review-edge-case-hunter (co: qs-review-acceptance-auditor)
- Description: in an A → undo → redo chain, re-raising A is downgraded to
