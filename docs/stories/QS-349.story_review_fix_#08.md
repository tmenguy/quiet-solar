## Findings to fix

### [should-fix] Y1 — X5 sanity bound missing on the warning path
- File: `custom_components/quiet_solar/ha_model/battery.py:~395-410` (`_number_entity_target` warn block, `snap_step_w = _to_w(step)`)
- Severity: should-fix
- Source: qs-review-blind-hunter
- Description: X5's `_step_sanity_bound_w` guard was applied to the
  echo-tolerance (probe/skip) path but not to the warning-tolerance
  path: a corrupt oversized step (e.g. the 1e307 kW case X5 guards)
  converts to `inf`, making `_snap_dir_diverges(delta) = delta >= inf`
  永-false — all snap-direction divergence warnings are silently
  suppressed for that entity.
- Proposed fix: Apply the same sanity bound in the warn block — when the
  converted step exceeds `_step_sanity_bound_w` (or is non-finite),
  treat the step as absent for tolerance purposes (falls back to the
  ~1.0 W opposite-direction tolerance in both directions). Test: corrupt
  100 kW step + landed far above request → warning fires.

### [nice-to-have] Y2 — Denormal-tiny corrupt step crashes write/probe with OverflowError
- File: `custom_components/quiet_solar/ha_model/battery.py:349, :352, :230` (`_entity_step` consumers)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: A corrupt denormal-tiny step attribute (e.g.
  `step: 1e-320`; any step < ~5e-304 for W-scale values) makes
  `write_value / step` overflow to `inf`, and `math.ceil(inf)` /
  `round(inf)` raise `OverflowError` (verified) — the exception escapes
  `set_max_discharging_power` / `probe_if_command_set`. X5 hardened the
  corrupt-huge twin; the tiny twin crashes instead of degrading.
- Proposed fix: One guard covering all three sites — in `_entity_step`,
  treat a step as absent when its W conversion is below a sane floor
  (e.g. `step_w < 1e-6`) or when `write_value / step` would be
  non-finite. Test: `step: 1e-320` → raw passthrough write, probe exact,
  no raise. Design this together with Y1 so "corrupt step ⇒ treat as
  absent" is one consistent rule (tiny, huge, non-finite) across snap,
  match, and warn paths.

### [nice-to-have] Y3 — Pin the `_step_sanity_bound_w` boundary decision with a test
- File: `custom_components/quiet_solar/ha_model/battery.py:224, :235-239`
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: When the configured domain max is legitimately smaller
  than the entity's advertised step (config max 50 W, entity
  `{step: 100}`), exact match is forced, so a device that up-echoes 50 →
  100 never confirms → rate-limited write churn. Never confirming a
  reading above the configured hardware max is the safety-correct
  choice — but it is currently an implicit side effect, not a pinned
  decision.
- Proposed fix: Keep the behavior; add a test pinning it (config max 50,
  step 100, device echoes 100 → probe False) plus a one-line comment
  stating the never-confirm-above-configured-max rationale. Do NOT widen
  the bound.
