### [should-fix] Restore guard is inert when a user target is present — `_next_charge_target` keeps the person value
- File: `custom_components/quiet_solar/ha_model/charger.py:4195`
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: the person push site (`~4137`,
  `set_next_charge_target_percent(person_min_target_charge)`) overwrites
  `_next_charge_target` regardless of `user_target`, while the user
  branch (3756-3758) only sets the local `target_charge` and the native
  limit, never `_next_charge_target`. The new restore runs only when
  `user_target is None`, so with a user target present the constraints
  correctly follow the user value but `_next_charge_target` stays at the
  person value indefinitely — the "next charge target" select
  (`get_car_target_charge_option`) and `get_autonomy_to_target_soc_km`
  (`car.py:2034`) show the person's target. Two reproductions:
  (A) user selects 60 → not-covered person assigned (car → 41) → person
  removed; (B) far more common: after any HA restart,
  `QSSimpleSelectRestore.async_added_to_hass` (`select.py:397`)
  unconditionally routes through `user_set_next_charge_target`
  (`select.py:82` ignores `for_init`), which calls
  `set_user_originated("charge_target_percent", 80)`; from then until
  the next physical unplug `user_target == 80` and the new block is
  inert, so the exact incident sequence post-reboot leaves the select
  at 41 %. Test 2 pins only leak→user-set, not user-set→leak→removal,
  and no test seeds the post-boot state. This is not the #353 snapshot
  path (nothing promotes 41 into user intent) — it is a hole in the
  same "after removal" symptom this issue owns.
- Proposed fix: add a sibling branch after the existing guard:
  `elif user_target is not None and int(self.car.get_car_target_SOC()) != int(user_target): await self.car.set_next_charge_target_percent(user_target)`
  (no `target_charge` reassignment needed — it already equals
  `user_target` from 3756). Log at INFO with a distinct message
  ("restoring user charge target"). Add two red tests in
  `tests/test_qs352_person_target_leak.py`, both with the restore spy
  and the `reallocated_covered` step-2 tuple:
  - `test_user_target_set_before_person_restores_user_value`: before
    `_run_step1`, `await car.set_next_charge_target_percent(60)` then
    `car.set_user_originated("charge_target_percent", 60)`; after step 1
    assert `car._next_charge_target == 41` (the leak); after step 2
    assert `spy.assert_awaited_once_with(60)`,
    `car._next_charge_target == 60`, `car.get_car_target_SOC() == 60`,
    single non-person filler `37.0/60`.
  - `test_post_reboot_user_default_restores_after_person_removed`: seed
    the post-boot state `car.set_user_originated("charge_target_percent", 80)`
    (int, as the select restore writes it) before `_run_step1`; after
    step 2 assert `spy.assert_awaited_once_with(80)` and
    `car._next_charge_target == 80`.
  Record the reasoned file-list/progress note in the story.

### [should-fix] Leak survives an unplug before the person is re-allocated
- File: `custom_components/quiet_solar/ha_model/charger.py:3610-3630` (unplug branch)
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: on unplug, `self.reset(keep_commands=True)` wipes the
  person constraint and `clear_all_user_originated()` drops the user
  target, but nothing touches `_next_charge_target` (`QSCar.reset`,
  `car.py:1448`, does not; only `_reset_charge_targets`, `car.py:2840/2853`,
  does). Sequence: step-1 leak (41) → car unplugged → select / autonomy
  sensor show 41 % for the whole time the car is away.
  `home.py:2775-2781` cannot help because `_next_charge_target is not None`;
  the restore only runs on the first plugged cycle of the next session.
- Proposed fix: in the `if self.car:` unplug branch, **before**
  `clear_all_user_originated()`, if
  `not self.car.has_user_originated("charge_target_percent")` and a live
  constraint for this car carries `CONSTRAINT_FORECASTED_PERSON_KEY`
  (i.e. a person constraint was live at unplug), set
  `self.car._next_charge_target = None` (lazy default — do **not** call
  `set_next_charge_target_percent` here: the charger is still attached
  and it would write the native limit on unplug). Log at INFO. Add a
  red test `test_unplug_with_live_person_constraint_clears_leaked_target`:
  run step 1 (leak = 41), then flip the plug mocks to unplugged
  (`is_not_plugged → True`, `is_plugged → False`) and run
  `check_load_activity_and_constraints(now + 3min)`; assert
  `car._next_charge_target is None` and
  `car.get_car_target_SOC() == car.car_default_charge`. Add the
  complementary guard `test_unplug_with_user_target_keeps_next_charge_target`
  (user target 60 present → `_next_charge_target` untouched by the
  unplug branch). Record the reasoned progress note in the story.
