## Findings to fix

### [should-fix] The value-based stale test drops a fresh split budget and starves an unrelated charger
- File: `custom_components/quiet_solar/ha_model/charger.py:2729-2732` (`is_phase_snapshot_stale`, widened in fix #04), with `apply_budget_strategy` ~:2225/:2240-2241 and the replay drop ~:2259-2275
- Source: qs-review-edge-case-hunter. Reproduced with a local, uncommitted
  scratch test. The red test that replaced it is
  `test_fresh_post_adoption_split_replay_is_not_dropped` in
  `tests/test_bug_381_non_converging_group.py`.
- Description: fix #04 assumed a fresh budget never reaches this check.
  That is wrong: `apply_budget_strategy` stores the fresh increasing half
  in `remaining_budget_to_apply`, and the next cycle replays it through
  the check.
  - A snapshot taken **after** an adoption with current 3 / budget 1 is
    field-for-field identical to the stale one, so a fresh post-adoption
    request is dropped.
  - The drop is whole-replay, so another charger's legitimate amps
    increase is discarded every cycle for up to 30 min.
  - Reachable via a consign command (`get_consign_amps_values`, not
    spacing-gated) asking for the other phase count during a live
    adoption. It also hits a fresh 1→3 consign after a 1-phase adoption.
- Proposed fix: make staleness **time-based**, not value-based.
  1. Stamp each `QSChargerStatus` when it is built (e.g.
     `cs.snapshot_time = time` in `get_stable_dynamic_charge_status`).
     Carry it through `duplicate()` / the `cs_copy` path.
  2. Keep a charger-side `_phases_observed_change_at: datetime | None`.
     Set it wherever the expected phase count is changed from an
     observation, not a budget: the D1 adoption and the follow branch,
     i.e. in `_follow_observed_num_phases` or its callers. Clear it
     alongside `_phases_adopted_at` in `_reset_state_machine`.
  3. `is_phase_snapshot_stale(cs)` then means: an adoption is live **and**
     `cs.snapshot_time` is earlier than `_phases_observed_change_at`.
     This drops only snapshots taken before the latest observation-side
     change.
  4. Drop the fix #04 value clauses (current / budgeted ≠ expected), since
     the time test covers them.
  5. Check that the idle-path set (~:6053) doesn't need stamping. The
     fix #03 idle-path test must stay green; stamp there too if needed
     for correctness.
- Tests:
  - **Red:** after an adoption, a fresh `apply_budget_strategy` split with
    the adopted charger in `increasing_cs` only (budget ≠ expected) plus a
    healthy charger's increase goes through the real
    `apply_budget_strategy` → `remaining_budget_to_apply` →
    `apply_budgets(..., check_charger_state=True)`. The replay must NOT be
    dropped and the healthy charger's amps increase must land. This also
    answers the acceptance auditor's note that the stale tests
    hand-built snapshots.
  - The fix #03 case (follow after the snapshot) and the fix #04 case
    (3→1 split, then D1 adoption after the snapshot) must still be
    dropped. Adapt `test_stale_replayed_budget_after_follow_does_not_revert_adoption`
    and `test_stale_replay_budgeted_phase_differs_is_stale` so they carry
    snapshot times taken before the observation change.
  - A fresh 1→3 split after a 1-phase adoption is not dropped.
  - Existing split tests (`test_split_inc_dec`,
    `test_splits_increasing_decreasing`, and the coverage_deep /
    ha_tests split-replay tests) stay green.

### [should-fix, promoted] The consign path still offers the other phase count on a phantom switch
- File: `charger.py:590-615` (`get_consign_amps_values`), reached from ~:2806 / ~:2845
- Source: qs-review-edge-case-hunter (nice-to-have). Promoted because it is
  the consign twin of fix #04-4, and a phantom switch can never succeed
  (unlike a real `off` that refuses, which stays #388).
- Description: when the reading is phantom, a consign that can't be met
  on the current phases still offers the other count with no spacing.
  Each consign then gives: request, marker cleared, 4 launches (~196 s
  group block), D1 adoption, repeated while the consign lasts.
- Proposed fix: in `get_consign_amps_values`, when
  `not self.charger._has_real_phase_reading()`, keep
  `possible_num_phases = [self.current_active_phase_number]` and clamp
  `consign_amp` using the current-phase steps. A real-reading consign is
  unchanged; that part is #388's scope.
- Tests: a phantom-reading consign offers only the current phase count and
  gives a clamped amp. A real-reading consign is unchanged.
