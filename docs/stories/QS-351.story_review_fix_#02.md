### [should-fix] SF-A — `PASS1 == PLUGGED_COVERED == 0.5` creates an exact pass-1 tie → order-dependent allocation
- File: `custom_components/quiet_solar/const.py:498-499`;
  `custom_components/quiet_solar/ha_model/home.py:2551-2560` (`_finalize_cost_matrix`, pass 1);
  `docs/stories/QS-351.story.md:355,364,377,395,496` (stale text)
- Severity: should-fix
- Source: qs-review-regression-proof + qs-review-edge-case-hunter (found independently)
- Description: A *preferred, covered, plugged* cell (`0.5`) now ties a
  *non-preferred, covered, unplugged* cell (`0 + 0.5`); pass 1 resolves it by the
  Hungarian zero-scan order (`_try_assign` takes `available_cols[0]`). Verified by
  both reviewers with the energy pass adopted: car order `[X, Y]` → P stays on
  preferred plugged X; `[Y, X]` → P moves to unplugged Y. Under the round-1 value
  the result was order-independent, so this is a determinism regression
  introduced by review-fix #01. Not an energy defect (both cells 0 Wh, no
  constraint) but user-visible: `changed_car` notification, the preferred car
  falls into the no-person default-charge path (`home.py:2786-2796`), and the
  pick can flap when unrelated persons/cars enter or leave the pool. Not caught
  by `test_all_covered_preferred_plugged_car_kept_when_e_max_is_zero` (E_max = 0
  there, pass 2 decides). Root: `PLUGGED < PASS1` and `PLUGGED + PASS1 <= 1.0`
  are mutually exclusive at PLUGGED = 0.5; (ii)'s lower bound was dropped
  silently, and the story still says PASS1 = 100 / "PASS1 moves from below to
  above the plugged tie-break".
- Proposed fix: `PLUGGED_COVERED_CAR_PENALTY_WH = 0.25`, keep
  `PASS1_PREFERRED_CAR_PENALTY_WH = 0.5` (regression-proof option a; edge-case-hunter:
  any strict inequality works). This restores strict `PLUGGED < PASS1`, makes
  relation (i) strict (0.75 < 1.0 at E_max = 0 instead of a tie), leaves `n·PASS1`
  unchanged, keeps the E_max==0 pin and test A's flip point (`4950 + 2·PASS1`)
  intact. Add a pin in `tests/test_person_car_allocation.py` that runs **with the
  energy pass adopted** (another person's saving > 1000 Wh flips the gate) and
  asserts the same assignment for both car orders `[X, Y]` and `[Y, X]`. Strike
  the stale PASS1 = 100 text and the `:377` blast-radius sentence via a progress
  note (do not rewrite history; amend).

### [nice-to-have] NTH-A — Epsilons stack; the invariant bound in the const comment is off
- File: `custom_components/quiet_solar/const.py:485-496` (relations (ii)/(iii));
  same wording in `docs/stories/QS-351.story.md:625` and PR body
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter (absorbs regression-proof's "n = 2000 is off
  by one" nit — same lines)
- Description: On a non-preferred covered-plugged cell both epsilons apply
  (`PASS1 + PLUGGED`), so the per-person corruption bound on
  `total_energy_optimal` is their sum, not `PASS1` alone; the binding relation is
  `n·(PASS1 + PLUGGED) < THRESHOLD`. The current text "0.5·n < 1000 up to
  n = 2000" is also off by one (0.5·2000 = 1000 is not < 1000). Relation (iii)'s
  boundary for that comparison is `PASS1 + PLUGGED`, not `PLUGGED`. Verified: a
  preferred car needing 0.9 Wh wins pass 1 over a non-preferred covered plugged
  car. Still downstream-harmless.
- Proposed fix: Rewrite (ii) as `n·(PASS1 + PLUGGED) < THRESHOLD` and give the
  correct n bound for the SF-A values (with 0.5 + 0.25 = 0.75:
  n <= 1333, since 0.75·1333 = 999.75 < 1000 <= 0.75·1334 = 1000.5); state
  (iii)'s boundary as the summed epsilon. Mirror in the story
  progress note and PR body. Comment-only.
