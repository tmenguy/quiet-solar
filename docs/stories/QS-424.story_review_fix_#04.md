### [must-fix] I1 — any code-fence tracker falls out of step with the renderer
- File: `scripts/qs/control_plane/export.py` (`_value_lines`)
- Source: blind-hunter (3 causes), edge-case-hunter (10 inputs, each an h1 under `## Digest` on GitHub), acceptance-auditor (HTML types 1–5)
- Description: the only unsafe state is "the tracker thinks it is in a fence, the renderer does not": a later `#` line then stays raw. Rounds 1 to 4 each found a new way in (tabs measured without the `> ` prefix, a less-indented closer, `<` lines that are no HTML block, an opener behind a marker with a bare closer, HTML comments with blank lines…).
- Proposed fix: drop fence and HTML tracking entirely. Every line is rewritten the same way: headings demoted at any nesting and indentation, setext underlines neutralised, footnote **and link-reference** definitions escaped (blind-hunter: a `[foo]: url` acts on the whole summary). Inside a code block this is cosmetic (`# comment` → `#### comment`), the side every round accepted. Tests: the 10 inputs (no h1/h2 line left), the round-4 cases, a code comment.
