## Findings to fix

### [should-fix] G1 — The issue-create probe depends on GitHub's search index (lag, result cap, key characters)
- File: `scripts/qs/control_plane/tools.py:1110-1115` (also
  `_gh_list_by_marker`)
- Source: blind-hunter + edge-case-hunter + acceptance-auditor
- Description: F11 replaced the consistent `--limit 50` body listing
  with `gh issue list --search`. The search index lags, so a replay
  right after a crash past `create_issue.py` finds nothing and creates a
  duplicate issue (the AC8 case). It also returns 30 results by default,
  and a `"` in the key breaks the query.
- Proposed fix:
  1. First scan a consistent listing of recent issues
     (`gh issue list --state all --limit 100 --json number,url,body`,
     no `--search`) for the exact marker.
  2. Only on a miss, run the marker `--search` with an explicit
     `--limit 100` and match the marker exactly in the returned bodies.
  3. Either call failing or returning unparseable output → `BUSY`.
  4. Restrict tool keys to `[A-Za-z0-9._:/-]+` at `run_recorded` / CLI
     entry (`USAGE` otherwise). Every documented key form (`msg:<id>`,
     `task:<id>:<purpose>`) fits.
- Tests: a marker found in the listing makes no search call. A miss
  then a search hit counts as done. A listing failure and a search
  failure each give BUSY. A key with `"` or a space gives USAGE.

### [should-fix] G2 — A spawn relaunch reuses the same node row, nonce and name, so two sessions can hold one valid token
- File: `scripts/qs/control_plane/tools.py:824-827,902-906`
  (`_reap_own`, `reserve`)
- Source: edge-case-hunter
- Description: after a reap, `reserve` moves the same row back to
  `spawning` and relaunches `claude --bg -n <same name>`. If the first
  launch appears late, two sessions share one name and one valid node
  token.
- Proposed fix: when `reserve` re-takes a reaped spawn row, rotate the
  row's `nonce`, which invalidates the first launch's token. Launch
  under a distinct name, for example a relaunch-counter suffix stored on
  the row; if there is no column, derive it from a counter in the
  row's existing JSON or meta. Prefer no schema change: schema v1 is not
  released yet, so a column may be added to `schema_v1.py` if it is
  cleaner, but keep `SCHEMA_VERSION = 1`. `_identify` then looks for the
  new name only. Also route `_reap_own` through `nodes.move(...,
  expect="spawning")` instead of a raw UPDATE, so `TRANSITIONS` stays
  the single source of truth (acceptance-auditor nice-to-have).
- Tests:
  - After reap and relaunch, the old token gives `STALE_TOKEN` and the
    relaunch argv carries a different name.
  - A late listing of the old name is not adopted.

### [should-fix] G3 — `ensure` can SIGTERM a reused pid when the lease has a NULL `pid_start`
- File: `scripts/qs/control_plane/daemon.py:207-214`;
  `scripts/qs/control_plane/liveness.py` `me()`
- Source: edge-case-hunter
- Proposed fix:
  - `ensure` signals the old daemon only when `lease.pid_start` is not
    None, or when the lease is fresh.
  - `daemon.run` retries `start_of(me)` a few times and refuses to start
    (log it, then exit) rather than write a NULL `pid_start`.
  - In the same restart path:
    - skip the wait entirely when `alive is False`;
    - break the wait loop when `current.pid != old_pid`, not only when
      it is NULL;
    - catch `ProcessLookupError` from `kill`.
- Tests: one for each branch.

### [should-fix] G4 — A hung older daemon gives `restart_pending` forever
- File: `scripts/qs/control_plane/daemon.py:213-224`,
  `scripts/qs/control_plane/wait.py:36-40`
- Source: edge-case-hunter (plus acceptance-auditor nice-to-have on
  broken `ps`)
- Proposed fix: once the restart deadline passes, check three things:
  the old pid is still *proven* alive (`alive is True`), it has the same
  `pid_start`, and its heartbeat has not moved since the SIGTERM. If all
  three hold, send SIGKILL (`probe.kill(pid, SIGKILL)` through the seam),
  wait briefly, and continue to start the new daemon. Keep
  `restart_pending` only for the unknown-liveness case. Record that
  remaining limit, a permanently unknown `ps` keeping `restart_pending`,
  in the "Conventions" section of `docs/workflow/control-plane.md`.
- Tests:
  - A hung daemon (alive, heartbeat frozen) gets SIGKILL, then the new
    daemon starts.
  - Unknown liveness gives `restart_pending`.

### [should-fix] G5 — Taking over an in-flight call still needs the argument files; `_files_digest` reads files twice
- File: `scripts/qs/control_plane/tools.py:202-211,891,1018,1088,1130`
- Source: edge-case-hunter
- Description: `_spawn_steps`, `_resume_steps`, `_issue_create_steps`
  and `_pr_create_steps` read their files while the steps are built,
  which happens before `claim()`. A crash after the effect, followed by
  deleting the temp file, makes the takeover replay fail with USAGE. The
  digest also reads each file a second time, which empties FIFOs and
  `/dev/stdin`.
- Proposed fix:
  - Read every `*_file` once, when the call starts, into a bytes cache
    on the call (absent file: no cache entry).
  - Compute `_files_digest` from that cache.
  - Steps read lazily, from the cache, inside the step that uses the
    content (`launch` / `create`), so a takeover whose effect step is
    already recorded never needs the file.
  - Refuse non-regular files with `USAGE`.
  - Validate "file required" only when the effect step actually runs.
  - A fresh call with a missing file still fails before any effect.
- Tests:
  - Crash after the effect, then delete the file, then replay with the
    same key: the replay completes with no second effect.
  - A FIFO argument gives USAGE.
  - A fresh call with a missing file gives USAGE with no effect.

### [should-fix] G6 — `task add --parent/--item-of` is not scoped to the caller's run
- File: `scripts/qs/control_plane/tasks.py:~147` (`add`)
- Source: CodeRabbit (inline comment, missed in round 1)
- Description: a run token for run A can attach to run B's deliverable
  and consume B's `next_item_k`.

- Tests: a cross-run `--item-of` and a cross-run `--parent` each give
  CONFLICT, and `next_item_k` is unchanged.
