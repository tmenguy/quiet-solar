### [should-fix] SF-2 — Reconcile the story Design/AC exception-surface text with the shipped `except Exception`
- File: `docs/stories/QS-359.story.md:276-281` (fallback Design bullet); AC5 body
- Severity: should-fix
- Source: qs-review-acceptance-auditor
- Description: The story Design section still states the fallback uses
  `except HomeAssistantError as e:` and "**No** bare `except Exception` — this
  runs in the load-management cycle." Review fix #05 (SF-1) intentionally
  broadened the `ocpp.set_charge_rate` service-call handler to
  `except Exception` because the fallback is reachable with `blocking=True`
  once the station profile is latched (the branch order evaluates
  `_ocpp_station_profile_rejected` before `if blocking:` and forwards
  `blocking`), so a non-HAE runtime error (`asyncio.TimeoutError`,
  `ConnectionError`) must not escape the load-management cycle. The story now
  contradicts the shipped code.
- Proposed fix: Documentation-only. Update the fallback Design bullet to
  describe the two-try structure: the clamp keeps `except (ValueError,
  TypeError)` ("bad current" → `False`), and the service call uses
  `except Exception` (warn-once-then-debug → `False`, ack untouched), annotated
  "revised in review fix #05". Do a sweep of the Design + AC5 sections for any
  other stale `except HomeAssistantError`-only wording so no contradiction
  remains.
