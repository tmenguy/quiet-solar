# QS-428 — The board: a static, multi-run page the daemon keeps fresh, and the `board` command

Issue: [#428](https://github.com/tmenguy/quiet-solar/issues/428) · Parent epic: #369 (child 8) ·
Lane: feature-factory · Target: factory · Wave 5, in parallel with 6b-2 → 6a → 9 (depends on none of them).

## Problem

The second pipeline runs **several runs in parallel, with one orchestrator per run**. Each
orchestrator is its own GUI chat session, named after its run. By design ("one voice"), each chat
knows only its own run: its node questions, its alerts and its tasks.

So nothing shows the maintainer **all runs at once**. Nothing shows the case where the single voice
goes silent either:

- `orchestrator_not_listening` is posted to the orchestrator's own queue, which nobody is reading
  at that point;
- a merge halt raised with no open run reaches no queue at all.

`snapshot` (#399, #406, #407) already returns a complete, read-only view of the state, but only as
JSON on a command line.

## Goal

A **read-only board** for every run. In order, it shows:

1. at a glance, **what is waiting for the maintainer, and in which chat session**;
2. per run: the task graph and its dependencies, the task states, what is done and what remains,
   the PRs and CI, the questions, the alerts and the reviews;
3. the cross-run alerts and reviews;
4. the system's health, in one short block.

Every row the maintainer may act on carries a **ready-to-copy prompt or command**. It is aimed at
the right orchestrator chat, or at a terminal (`claude attach …`). The board itself never acts.

## Decisions

### Maintainer, 2026-10-26 (this session; translated from French)

- **How the maintainer interacts.** Everything goes through each run's orchestrator chat, so the
  "one voice" rule is unchanged. The board adds **no channel**: "just prompts to copy can be
  perfect". Actions stay at **level 0**, meaning links and prompts or commands to copy. Writes from
  the board (clearing the merge halt, restoring, answering a question, validating criteria) stay a
  later child, with its own security model. This confirms the decision of 2026-10-18 (Q4).
- **No HTTP server: a static HTML file.** "The board could be static HTML/JS without even needing an
  HTTP server." With no socket there is no bind, no `Host` check and no DNS-rebinding surface. The
  board is read-only by construction, because a static file cannot take a POST. This **replaces**
  the issue's "the server on port 0" and "binds `127.0.0.1` only".
- **The daemon regenerates the file**, through a tick hook (option A). `cp.py board` calls `ensure`,
  renders once, prints the path and opens the file. There is no long-running `board` process.
- **A single page**, with a `<details>` per task.
- **Multi-run, hence multi-orchestrator.** The page leads with a cross-run "waiting for you" list.
  Each line names the chat session to open.
- `snapshot` gains the merge-gate records and the backup state, both read-only from `meta`.

### Maintainer, 2026-10-27 (triage of review round 1: "go", everything as recommended)

- **(A) The scope is trimmed** to what the issue and the decisions need.
  - Cut:
    - locks, cap slots, tool calls in flight, the per-queue table and "tasks without a run";
    - the run's decisions and the `review_triggers`;
    - per-task history, report summaries and blast radius;
    - the edges from a work item to its deliverable;
    - `repo_url` (issue numbers stay plain text);

- **(B) Merge gate**: show the three records raw, and derive only `failed` and `stuck` for "waiting
  for you". There is no second classifier.
- **(C) "Criteria to validate"** applies only to tasks in `proposed` or `ready`. The maintainer
  validates criteria at start-up, before a node is spawned (epic, "The orchestrator: a GUI session
  and an event loop").

### Maintainer, 2026-10-27 (triage of review round 2: "yes", everything as recommended)

- **Tolerance.** `board.model` never raises on a value read from the DB.
- **The banner.** Its age check runs on every timer tick, and the reload is forced after 60 s of

## Design

### D1 — modules (stdlib only; the import-purity test holds unchanged)

| module | role | side effects |
|---|---|---|
| `scripts/qs/control_plane/board.py` | `model(snap, *, now, main, code_schema) -> dict`, the pure, tolerant view model (D4, D5); `board_path(db_path)`; `write(html, dest) -> Path`; `render_to(conn, clock, db_path, main) -> Path`; `board_hook(conn, clock)`; the `BOARD` name and the constants of D10 | `write`, `render_to` and the hook |
| `scripts/qs/control_plane/board_render.py` | `render(model) -> str`: HTML, inline SVG and one fixed inline script; `scrub(text) -> str`; `SCRIPT`; `CSP` | none (pure) |

**Imports.**

- `board` imports `snapshot`, `board_render`, `activeloop`, `alerts`, `mergegate`, `migrations`,
  `paths`, `db`, `errors`, `ticks` and `clock`, all at module top.
- None of those imports `board`. `activeloop` imports `board` lazily, inside `_builtin()`, as it
  does for `detectors` and `watchdog`. So there is no cycle.
- `board_render` imports nothing from `board`. Everything it needs is in the model dict, constants
  included (`model["refresh_s"]`, `model["stale_s"]`). It is therefore testable on a fixture model
  alone.

### D2 — the file: where, and how it is written

- **The directory.** `paths.board_dir()` = `state_dir("QS_CP_BOARD_DIR", DEFAULT_BOARD_DIR)`, with
  `DEFAULT_BOARD_DIR = ~/.local/state/quiet-solar/cp-board`. Like the other state directories, it
  is refused inside any checkout or linked worktree: `POLICY_REFUSED`, naming the variable.
- **The path.** `board.board_path(db_path)` =
  `board_dir() / sha256(<resolved db path>)[:8] / "index.html"`. This is the same per-DB split as
  `backups.db_dir`, so a temporary DB's board never overwrites the live one.
- **The write.** `board.write(html, dest) -> Path`:
  1. `paths.ensure_private_dir` on `board_dir()` and on `dest.parent` (0700);
  2. `fd, tmp = tempfile.mkstemp(dir=dest.parent, prefix="index.html.", suffix=".partial")`. The
     file is 0600, and each writer gets its own, so the hook and `cp.py board` never share one;
  3. write the UTF-8 bytes, close, then `os.replace(tmp, dest)`. The mode is kept;
  4. on any exception before the replace, unlink `tmp` and re-raise (the `backups.write_copy`
     pattern);
  5. return `dest`. There is no fsync, because the file is disposable.

  A browser reload therefore always reads a whole page. A `.partial` left by a killed writer is a
  0600 file in a 0700 directory, and nothing more, so it is not swept.
- **The hook and the command write the same file.** The hook resolves its DB path with
  `db.path_of(conn)` (`restore._db_path`, made public in `db.py`). `cp.py board` uses
  `paths.select_db()`. Both name the same file for the same DB (tested in AC6). The daemon that
  `ensure` starts serves the DB that `select_db()` names; its singleton lock sits next to that DB.
- **A caveat to document.** A daemon started under another `QS_CP_BOARD_DIR` writes elsewhere. The
  page the command printed then goes stale, and its banner (D8) says so.

### D3 — `snapshot` gains two keys (read-only, no migration)

- **`merge_gate`**:
  ```python
  {"selfcheck": mergegate.get(conn, mergegate.RECORD),
   "override":  mergegate.get(conn, mergegate.OVERRIDE),
   "pending":   mergegate.get(conn, mergegate.PENDING)}
  ```
  Each value is `None` when absent or unreadable (`mergegate.get` returns `None` for a non-dict).
  It never calls `merge_allowed`, which writes.
- **`backup`**:
  `{"last_at": restore.meta_value(conn, restore.LAST_AT), "last_error": restore.last_error(conn)}`.
  `restore._meta` and `restore._last_error` are made public under these names. Their callers inside
  `restore` (restore.py:57, :92, :95) are updated. As a result, `last_error` is set exactly when
  `backup_failed` would be raised, a non-object value included.
- **The shape.** `empty()` returns the **same shape** with every inner value `None`:
  `{"selfcheck": None, "override": None, "pending": None}` and
  `{"last_at": None, "last_error": None}`.
- **The key list.** `KEYS` gains both keys. `golden/snapshot_keys.json` is updated, and the empty
  shape is asserted explicitly (`sorted(empty()["merge_gate"]) == [...]`).
- **No `--run` filter.** Both keys are global, like `hook_alerts`.
- **No new cycle.** Neither `mergegate` nor `restore` imports `snapshot`; checked in T1.

### D4 — the page, top to bottom (`board.model`)

**Tolerance (critical).** `board.model` **never raises on a value read from the DB**:

- every timestamp goes through `_age(now, text) -> float | None`, which returns `None` on `None`,
  `ValueError` or `TypeError`. A value it cannot read is shown raw, escaped;
- every `meta` record is checked with `isinstance` before it is read. A field of the wrong type
  reads as absent;
- integers (`tries`, `blocking`, `generation`) go through `mergegate.int_or`, which is made public
  from `_int_or` (its callers are at mergegate.py:111 and :140);
- sorting uses `str()` keys.

**Column keys** are indexed with `row["key"]`. A renamed column is a code bug, and it fails loudly in
AC4's real-DB render.

**Definitions:**

| term | meaning |
|---|---|
| terminal | `tasks.TERMINAL`: `merged`, `validated`, `dropped` |
| a task's node | the `nodes` row with the highest `generation` for that task |
| live node | node state in `nodes.LIVE_STATES` (`spawning`, `running`, `idle`, `taken_over`) |
| a run's chat | the run lease's `session_name`, else the run's `name` |
| daemon running | **mirrors `daemon._fresh`**: `snap["daemon"]` is not `None`, its `pid` is not `None`, and `_age` of its heartbeat is not `None` and below `daemon.STALE_AFTER_S` (30 s). Shown in System only |
| open findings of a task | one integer: the rows of `findings` whose `task_id` is that task, with `state = 'open'` and `coalesce(classification, severity) != 'out_of_scope'` |
| criteria count | `met + waived` out of the total |
| order | the order `snapshot` returns (its queries sort by `rowid` or `id`) |

**The page:**

1. **Header.** The generated-at time (UTC ISO, plus `data-generated-at` in epoch seconds), and the
   "waiting for you" count.
2. **"Waiting for you"**, across all runs. Items are sorted by **rule number**, then by the key of
   each rule below. Each item has a "where", a text shown escaped, and a copy block (D6).
   1. **An orchestrator is not listening, or is gone.** An open alert `orchestrator_not_listening`
      sends you to the run's chat. An open `orchestrator_dead` sends you to a new session on the
      main checkout. Only open runs count. Sorted by the alert's `first_seen`.
   2. **A question asked of you.** A question in state `asked`, on an open run: the orchestrator put
      it to the maintainer. Its "where" is the run's chat. Blocking questions first, then the oldest
      `created_at`.
   3. **Criteria to validate.** A task of an open run, in state `proposed` or `ready`, with at least
      one criterion and at least one criterion whose `validated_at` is NULL. Its "where" is the
      run's chat. Sorted in snapshot order.
   4. **A merge halt**: `halt` (D5) is `failed` or `stuck`. Its "where" is any orchestrator chat,
      else a new session on the main checkout when no run is open. It is shown whether or not a run
      is open.
   5. **A backup failure**: `backup.last_error` is not `None`. The "where" is the same as rule 4,
      and it is likewise shown whether or not a run is open.

   An empty list renders "Nothing is waiting for you."
3. **One section per open run** (`runs.state = 'open'`, in snapshot order):
   - **orchestrator:** the run's chat, the lease's `short_id`, and "not listening" or "gone" when
     rule 1 holds for this run;
   - **progress:** a count per task state over the run's tasks, work items included (each one is a
     task). "Done" = `merged` + `validated`. "Dropped" is counted apart. "Remaining" is the rest,
     `blocked` included;
   - **graph** (D5);
   - **tasks table:**
     - id, issue (`#N` as text), title, kind or lane, state (with `blocked_from`);
     - node: its state, name and `short_id`; `taken_over` is shown as "taken over (you)";
     - PR: a link per D7, plus the CI state and the first 7 characters of `ci_sha`;
     - the criteria count, and whether the criteria are validated;
     - the open findings count;
   - **one `<details id="task-<id>">` per task:** its criteria (text and state), its open and asked
     questions (state, blocking, text) and its copy blocks (D6);
   - **alerts of the run**: the open alerts, then the cleared ones `snapshot` returns. The kinds in
     `alerts.CROSS_RUN_KINDS` are left out. Each row shows the kind, the subject, first and last
     seen, and `alerts.severity(kind)`;
   - **reviews touching the run**: every review with a `review_tasks` row of this `run_id`. Shown:
     kind, state, the per-task outcome and reason, the summary, and recorded at.
4. **Cross-run:**
   - the alerts whose kind is in `alerts.CROSS_RUN_KINDS`, grouped by `fingerprint`, each group
     listed once with every run it was raised on;
   - the reviews of kind `cross_run`, with their per-task outcomes.
5. **System:**
   - the daemon: running or not, pid, heartbeat age, and the DB schema against `code_schema`;
   - the three merge-gate records, raw but escaped;
   - the backup state;
   - `hook_alerts`: the `ALERTS_LIMIT` newest raw ones.
6. **Closed runs:** one collapsed `<details>` holding **one summary row per closed run**. Each row
   shows the name, title, `closed_at`, and the done, dropped and remaining counts. An unfiltered
   `snapshot` returns every run's tasks, so these counts need nothing more.

**Placement.** A row goes by its own `run_id`. A row of a closed run only feeds that run's summary
row.

**Empty snapshot.** When `snap["schema_version"] is None` (`snapshot.empty()`: no DB yet, or a
migration in progress), the page shows only the header and the single line "no state readable yet —
the daemon refreshes this page".

### D5 — derived values

- **`halt`** is read-only. It is either `None`, `"failed"` or `"stuck"`, and it feeds rule 4 only.
  It is decided in this order:
  1. if `pending` is a dict: `"stuck"` when `_age(now, pending.since) > mergegate.PENDING_ESCALATE_S`
     (`since` is ISO, written by `db.now`), else `None`. A `pending` that exists is always newer
     than the record and the override, because `record()` and `override()` delete it;
  2. else `"failed"` when all of these hold:
     - `selfcheck` is a dict with `ok is False`;
     - `mergegate.int_or(selfcheck.get("tries"), 1) >= mergegate.SELFCHECK_ESCALATE_AFTER`;
     - no override is a dict whose `code_version == selfcheck.get("code_version")`;
  3. else `None`.

  An unreadable `since` gives `None`. Everything else about the gate is shown only as the raw
  records in System, with the note "the authority is `tool merge`".
- **The graph layout** is layered and deterministic.
  - The nodes are the run's tasks.
  - An edge runs from dependency to dependent (`task_deps`) **when both ends are tasks of this
    run**. Any other edge is dropped and counted in a note, "N dependencies outside this run".
  - Layering uses Kahn's algorithm. Layer 0 is the set of tasks with no in-run dependency. Once all
    of a task's dependencies are placed, its layer is `1 + max` of their layers.
  - The tasks never placed (in a cycle, or downstream of one) go in one extra last layer, drawn
    with an "unresolved dependencies" border. A self-loop is impossible: `CHECK (task_id !=
    depends_on)`, schema_v1.py:98.
  - Inside a layer, tasks keep snapshot order. Boxes have a fixed size.
  - Titles are cut to `GRAPH_TITLE_MAX` characters **in the model**, and the full title goes in an
    SVG `<title>` element (element content, never an attribute).
  - The fill comes from a fixed map from state to colour. Each box is an `<a href="#task-<id>">`.
  - A run with no task renders "no task yet".

### D6 — the copy blocks (level 0: text only; the board never runs anything)

**The markup.** Each block is a `<pre data-copy>` holding the exact text, plus a sibling
`<button data-copy-btn>`. `SCRIPT` wires the button to `navigator.clipboard.writeText`. If that is
refused, the button selects the `<pre>` text so ⌘C works.

**Ids and fixed vocabulary only.** **No LLM-written text ever goes inside a copy block**: no title,
no question text, no reason, no name. A block may hold only:

- ids that match their shape: `T\d+`, `Q-\d+` and `R\d+`, plus a node `short_id` matching
  `[0-9a-zA-Z-]{1,64}`;
- the fixed English words below;
- the `halt` word.

The title or question is shown **beside** the block, escaped. An id that fails its shape gives no
block. In a terminal command, `shlex.quote` covers **every variable part as a whole**: an id, or the
full interpreter path `shlex.quote(f"{main}/venv/bin/python")` and the script path
`shlex.quote(f"{main}/scripts/qs/cp.py")`.

| where | when | text |
|---|---|---|
| the run's chat | rule 2 | `Answer to <Q-id>: ` |
| the run's chat | rule 3 | `Show me the acceptance criteria of <T> so I can validate them.` |
| the run's chat | every task, in its `<details>` | `Where is <T>? Summarise its state, its open findings and what it waits for.` |
| the run's chat (`not_listening`) / a new session on the main checkout (`dead`) | rule 1 | `Resume the run <R>: claim it and drain its queue.` |
| any orchestrator chat, else a new session on the main checkout | rule 4 | `The merge gate is <failed\|stuck>. Show me the self-check record, then clear the halt with cp.py halt clear only if I agree.` (the orchestrator runs `halt clear` behind the `PreToolUse` `ask` prompt; control-plane.md, "Clearing a halt") |
| any orchestrator chat, else a new session on the main checkout | rule 5 | `The Control Plane backup is failing. Show me the last backup error from the snapshot.` |
| a terminal | a live node of a task | `claude attach <short_id>`; no block when `short_id` is null or fails its shape (`claude attach <id\|name>`, Claude Code 2.1.302) |
| a terminal | the stale banner (D8) | `<python> <cp.py> board`, both paths quoted as above |

### D7 — security (read-only by construction)

- **No socket, no server**: nothing listens.
- **A private file**: 0600, in a 0700 directory outside every checkout (D2). It holds session ids,
  paths and question texts, but never a token or a nonce.
- **Every value is escaped** (`html.escape(…, quote=True)`), attribute values included. LLM-written
  text goes into element content only. Titles, questions, payloads and summaries are LLM-written
  and treated as hostile.
- **No inline event handler**: no attribute whose name starts with `on`. `SCRIPT` attaches handlers
  with `addEventListener`.
- **A CSP, as defence in depth**, capped here. A `<meta http-equiv="Content-Security-Policy">`
  placed **before** the `<script>` sets
  `default-src 'none'; style-src 'unsafe-inline'; script-src 'sha256-<b64>'`.
  - `<b64>` is the hash of the fixed `SCRIPT`, computed at import.
  - `SCRIPT` holds no data. Every dynamic value it needs (generated-at, the stale threshold, the
    refresh period) sits in `data-` attributes on `<body>`.
  - The page loads no external resource.
- **`scrub`** runs over the final HTML string, again as defence in depth. It replaces with
  `[redacted]`:
  - the token shapes `(run|node):[A-Z]\d+\.\d+\.[0-9a-f]{32}` and
    `review:V[1-9]\d*\.[01]\.[0-9a-f]{32}`;
  - any standalone 32-hex run, `(?<![0-9a-f])[0-9a-f]{32}(?![0-9a-f])`.

  Git shas (40 hex) and UUIDs (dashed) are not matched. `scrub(SCRIPT) == SCRIPT`, so the hash
  stays valid.
- **One link rule.** A URL becomes `<a href rel="noreferrer">` only when it starts with
  `https://github.com/`. Anything else renders as text. The only other links are in-page
  `#task-<id>` anchors.

### D8 — freshness

- **The hook.** `board_hook(conn, clock)` takes its `ticks.Throttle(BOARD_EVERY_S)` turn **first**:
  a raising board is retried only every 10 s. It then calls
  `render_to(conn, clock, db.path_of(conn), activeloop.seams().main)`.
- **`render_to(conn, clock, db_path, main) -> Path`.** It takes `conn = None` for "no readable
  state". It builds `snap`, either `snapshot.snapshot(conn, clock)` (one `db.read`, released before
  rendering) or `snapshot.empty()`. It then runs `board.model(snap, now=clock.now(), main=main,
  code_schema=migrations.current_schema_version())`, then `board_render.render`, then
  `board_render.scrub`, then `board.write(…, board_path(db_path))`. It returns the path. It is the
  single render-and-write path for both the hook and the command.
- **Registration.** The hook is registered **last** in `activeloop._builtin()`, and `"board"` is
  added to `BUILTIN_NAMES`. `activeloop._reset_for_tests` calls `board._reset_for_tests`, which
  forgets the logged error; `ticks._reset_for_tests` already re-arms every throttle.
- **Cost.** The hook runs no subprocess. Its cost is **one full `snapshot` read every
  `BOARD_EVERY_S`**: every table, unfiltered, in one read transaction. That is accepted, and
  documented in T7; a board projection of `snapshot` is a follow-up if it gets slow. The render
  itself is linear in that snapshot.
- **Failures.**
  - `OSError`, `errors.CpError` and `sqlite3.Error` are caught and logged once per distinct message
    (`[cp-board] …`). The logged message is forgotten on success, as in `backup_hook`.
  - Any other exception is left to the active loop, which logs and skips a raising hook
    (control-plane.md, "Registering a tick hook"; daemon.py:219-224). Such a log line is accepted
    once per throttle period; the tolerant model of D4 removes the likely causes.
  - **No alert** is raised: a failed board must not page an orchestrator. The stale banner shows it.
- **Activity.** The hook returns `None`. The daemon's idle exit counts open runs only, not hook work.
- **The refresh is driven by `SCRIPT`.** A `setTimeout` loop runs every `refresh_s` (10 s). On each
  tick it does two things:
  - it **checks the page's age** from `data-generated-at` and shows the banner when the age is past
    `data-stale-s`;
  - it **reloads**, unless the document has a non-empty selection or a copy button was clicked less
    than 5 s ago. A reload skipped for 60 s in a row is forced.
- **The banner** (`BOARD_STALE_S` = 120 s) is red and reads: "**last known state** as of HH:MM:SS —
  the daemon is stopped or the board write is failing". It carries the D6 `cp.py board` block, which
  sits in the HTML and stays hidden until shown.
  - The threshold is 120 s and not 3 × 10 s because one tick can take about 60 s: #423's review
    pilot stops review sessions within a `HOOK_SUBPROCESS_S` budget (PR #432, "worst case: about 60
    s in one tick"), and the board hook runs after it.
  - A tick slower than that can show a false banner. That is accepted, since the next reload clears
    it.
- **Open `<details>`** are kept across reloads by id, in `sessionStorage`. Without this, a reload
  every 10 s would collapse the task being read. Nothing else is persisted: the browser restores the
  scroll position on `location.reload()`.
- **Browsers.** Chrome and Safari on macOS over `file://` are expected; AC9 checks them. Firefox's
  per-file origin may drop the kept `<details>`, which is accepted.
- **A halt raised with no open run.** The hook renders it while the daemon runs, that is until the
  daemon's idle exit after `IDLE_EXIT_S`. After that, the page keeps showing it under the "last
  known state" banner, and `cp.py board` starts the daemon again (epic, view 7).

### D9 — `cp.py board [--no-open]`

`Command("board", "exempt", _board, _conf_board)`. It is exempt because it runs its own checks;
like `ensure`, it starts the daemon. Its inputs are `path = paths.select_db()`, `main =
paths.main()` (the same value as the hook's `seams().main`) and `clock = io.deps.clock`.

1. **Schema check, before anything starts.** `db.check_schema(path, wait=False,
   clock=io.deps.clock)`:
   - it returns `"ok"`, or `"missing"` for no DB;
   - `SCHEMA_TOO_NEW` propagates (exit 5) before any `ensure`, like `halt clear` and `restore`;
   - `SCHEMA_PENDING` is caught here.
2. **`ensure_daemon(io, path)`.** A start error is reported as `"daemon": "error"` plus
   `daemon_error`, and the command goes on (the `_daemon_status` pattern).
3. **Render and write**, through `render_to`:
   ```python
   try:
       with connection(io, "read") as conn:
           schema = "missing" if conn is None else "ok"
           dest = board.render_to(conn, clock, path, main)
   except errors.CpError as exc:
       if exc.code != "SCHEMA_PENDING":
           raise
       schema, dest = "pending", board.render_to(None, clock, path, main)
   ```
   An `OSError` raised by `render_to` becomes `CpError("INTERNAL", "board write failed: …",
   hint="check QS_CP_BOARD_DIR")` (exit 1). `"schema"` is the state that was **rendered**, not step
   1's answer.
4. **Open the file**, unless `--no-open`, through the new seam `Deps.open_url: Callable[[str],
   bool]`.
   - In `make_deps` it is `_open_url`, a module function in `cli.py`: `import webbrowser` inside it
     (lazy), then `return bool(webbrowser.open(url))`.
   - In tests it is a `FakeOpenUrl` (`.calls: list[str]`, `.result = True`).
   - The result is reported as `"opened"`.
5. **Print**:
   ```json
   {"ok": true, "path": "<abs>", "url": "<Path(abs).as_uri()>", "daemon": "<status>",
    "schema": "ok"|"pending"|"missing", "opened": bool}
   ```

It runs from the main checkout's copy, like every command. In a worktree with `QS_CP_DB` set, the
board goes to that DB's own subdirectory (D2).
