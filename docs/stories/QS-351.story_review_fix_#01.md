## Findings to fix

### [should-fix] Pass-1 `PASS1_PREFERRED_CAR_PENALTY_WH = 100.0` is a 100 Wh energy bias, not a tie-break
- File: `custom_components/quiet_solar/ha_model/home.py:2688` (pass-1 call to
  `_finalize_cost_matrix` with `preferred_car_penalty=PASS1_PREFERRED_CAR_PENALTY_WH`);
  constant at `custom_components/quiet_solar/const.py` (`PASS1_PREFERRED_CAR_PENALTY_WH`,
  `PREFERRED_CAR_ENERGY_THRESHOLD_WH`).
- Severity: should-fix
- Source: qs-review-edge-case-hunter
- Description: Adding 100 Wh to non-preferred cells means pass 1 does not find
  the true energy optimum for per-person needs below 100 Wh, so `total_energy_optimal`
  is corrupted and the 1000 Wh gate under-measures the real aggregate saving.
  Repro: ~11+ persons each with a preferred plugged car needing 50–99 Wh plus a
  covered non-preferred alternative → pass 1 keeps everyone on preferred, gate
  diff ≈ 0 ≤ 1000 → preferred adopted, spreading ~1080 Wh of charging the true
  optimum (0 Wh) would avoid. The const comment's invariant (ii) only asserts
  `PASS1 < THRESHOLD`; the binding relation for this failure is `n·PASS1` vs
  `THRESHOLD`, which is not guarded. Not triggerable in the 4-person incident
  household (4×99 < 1000) but is a residual of the same defect class.
- Proposed fix: Make the pass-1 preferred-car bias a genuine ordering tie-break
  rather than an energy-scale bias so it cannot corrupt `total_energy_optimal`.
  Options for the implementer to choose (minimum-diff, decide in-session):
  (a) reduce `PASS1_PREFERRED_CAR_PENALTY_WH` to a sub-need epsilon (e.g. 0.5,
  matching `PLUGGED_COVERED_CAR_PENALTY_WH`) so `n·PASS1 << THRESHOLD` holds for
  any realistic `n`; or (b) keep a larger nudge but guard the binding relation
  `n·PASS1 < THRESHOLD` explicitly (assert/comment) and document the max-n
  assumption. Update the `const.py` invariant comment to state the
  `n·PASS1 < THRESHOLD` relation, not just `PASS1 < THRESHOLD`. Add a regression
  test in `tests/test_person_car_allocation.py` reproducing the multi-person
  (needs 50–99 Wh) under-measurement and asserting the true optimum is adopted.

### [nice-to-have] Pass-1 cross-order reversal vs no-forecast / data-error sentinels
- File: `custom_components/quiet_solar/ha_model/home.py:2547-2553` (`_finalize_cost_matrix`)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: With `PASS1=100` added to non-preferred cells, a non-preferred
  covered-plugged cell (`0.5 + 100 = 100.5`) now prices above a preferred
  no-forecast (`-1`) / data-error (`-2`) sentinel (`E_max + 1.0`) whenever
  `E_max < 99.5`. Pre-fix that covered cell was cheaper (`E_max + 0.6`). A person
  whose preferred car has an unknown forecast is now kept aimed at it instead of
  yielding to a covered non-preferred car. Low harm (sentinel pairs carry 0 real
  energy at the gate; default-charge is person-independent) and arguably the
  intended "respect preference" behavior — but the story's "sentinel pairs carry
  0 real energy so the gate adopts pass 2" argument does not cover this
  cross-order case.
- Proposed fix: Largely resolved by the should-fix if option (a) is taken
  (a 0.5 penalty can no longer cross the `E_max + 1.0` sentinel). If option (b)
  is taken, add a note/guard that the penalty must stay below the sentinel
  offset. Either way, extend the `const.py` invariant comment to cover the
  penalty-vs-sentinel ordering across pass 1, and add/adjust a test asserting the
  preferred-unknown-forecast person yields to a covered non-preferred car.

### [nice-to-have] Boundary at exactly the plugged-covered penalty value
- File: `custom_components/quiet_solar/ha_model/home.py:2551-2553` (`_finalize_cost_matrix`)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: A real `diff_energy` in the open interval `(0, 0.5)` Wh (uncovered
  pair, `car.py:1996-2001`) is priced strictly below the plugged-covered penalty
  `0.5`, so a car needing a tiny real charge is ordered cheaper than an
  already-covered plugged car, inverting the "save plugged cars for those who
  need them" intent right at the boundary. Reproduces when a plugged car's
  `needed_soc − current_soc` is below `50 / car_battery_capacity` percent. Story
  argues downstream-harmless via `is_car_charged(accept_bigger_tolerance=True)`.
- Proposed fix: Confirm/strengthen the harmlessness argument. Preferred minimal
  fix: document (const.py comment) that a real need below the penalty is
  guaranteed absorbed by `is_car_charged(accept_bigger_tolerance=True)` and
  therefore never becomes a constraint, and pin it with an invariant test
  asserting that a sub-penalty real need does not produce a charge constraint.
  Only change the penalty value if the implementer finds the tolerance argument
  does not actually hold.

### [nice-to-have] FP-epsilon at the two-pass gate comparison
- File: `custom_components/quiet_solar/ha_model/home.py:2698` (`compute_and_set_best_persons_cars_allocations`)
- Severity: nice-to-have
- Source: qs-review-edge-case-hunter
- Description: `total_energy_preferred - total_energy_optimal <= 1000.0` compares a
  floating-point subtraction of Wh sums against the threshold; a saving landing
  within FP epsilon of exactly 1000.0 could tip either way. Negligible in
  practice given real-need magnitudes; no rounding guard.
- Proposed fix: Optional hardening — the comparison already uses `<=` and the
  threshold is far from real-need granularity, so the safest minimal change is a
  brief comment documenting that exact-boundary ties resolve to the
  preferred-car assignment by design (the `<=` side). Only add explicit rounding
  if the implementer judges it warranted.
