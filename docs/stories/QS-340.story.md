# QS-340 — Epic × factory lane: codify the epic procedure, add `qs-decompose-epic`

**Issue**: [#340](https://github.com/tmenguy/quiet-solar/issues/340) ·
**Lane of this task**: feature-factory · **Parent epic**: #321 ·
**Folds in**: #370 (decompose-epic agent) · **Sequencing**: none — no

## Problem

An epic (`scale:epic`) is the one lane with no working flow. Running
#321 and #369 by hand surfaced the nine gaps listed in the issue
("Gaps found while running epic #369"). They are the starting point of
this plan; the table below maps each one to where it is handled.

| # | gap (issue) | handled by |
|---|---|---|
| 1 | epic lane files are copies of `phase-protocols.md` | D7 — `epic-factory.md` rewritten; `epic-product.md` explicitly deferred to #339 (the issue: "this PR diverges exactly one of them") |
| 2 | no workflow doc covers the epic lifecycle | D7 — overview, phase-protocols (+ its 4 identical copies), project-rules, project-context |
| 3 | setup-task 1c says what, not how | D6 — 1c routes `epic-factory` to `decompose-epic` with a worktree + launcher |
| 4 | no standing rule for landing the epic doc on `main` | D4 — "Epic documents" rule in project-rules, enforced by `epic_doc.py land`; `create_pr.py` refuses epics |
| 5 | no epic doc template | D5 — template in the lane file, extracted from QS-321.md and QS-369.md |
| 6 | issue-body conventions implicit; stray `Refs #N` hazard | D5 — conventions + warning in the lane file; D3 child body form; D6 setup-task writes `### Parent epic` |
| 7 | file children just in time | D3 — only the current wave is filed; re-entry via RESUME |
| 8 | child agents can't find the parent epic doc | D6 — `context.py` `parent_epic_doc`; create-plan / diagnose-task read it |
| 9 | epic-scoped decisions need a home | D5 — "Decisions" section in the template; D2 DISCUSS writes decisions there |

## Goal

Make the epic × factory lane a **one-command flow**:

`setup → decompose → finish (cleanup)` — re-entered the same way for
just-in-time child filing.

- A new interactive orchestrator **`qs-decompose-epic`** (mirrors
  `qs-create-plan`'s DISCUSS / REVIEW / TRIAGE / FINALIZE loop) drafts
  `docs/epics/QS-<N>.md`, runs the PR-less plan-reviewer fan-out on it,
  files the children whose turn it is, lands the doc on `main`, and
  syncs the epic issue.
- A standing, script-enforced **epic-doc landing rule**.
- The lane file, workflow docs, epic doc template and issue-body
  conventions written down where agents actually read them.

epic × product (#339) then inherits the mechanics by copying the lane
file and flipping one guard.

## Decisions (maintainer, 2026-09-26)

- **Session location**: a short-lived docs-only worktree (D1).
- **Review pattern**: today's plan-review pattern, the same as
  `qs-create-plan` — the 4 plan reviewers (+ delta-auditor from round 2)
  and the `open` / `resolved` / `rejected` finding states. No dependency
  on the #369 loop engine (#375); moving create-plan and the decompose
  agent onto it comes later and is out of scope. No new ledger format is
  introduced.
- **No ordering constraint** between #340 and #369 / #375.
- **"Pin the epic"** meant the stale-bot exemption, which `scale:epic`
  already provides (`.github/workflows/stale.yml` exempts it). No
  `pinned` label and no `gh issue pin` (GitHub caps repo pins at 3).
- **Permissions**: `.claude/settings.json` gains the `epic_doc.py` allow
  pair (same pattern as every other `scripts/qs/` script); the OpenCode
  frontmatter of `qs-decompose-epic` allows edits under `docs/epics/**`
  only. No direct `gh issue edit` grant — `epic_doc.py sync-issue` is the
  only writer of the epic body.
- **`docs/epics/QS-369.md` is not modified by this PR** (it evolves on
  `main` in parallel). It and `QS-321.md` are the two real examples the
  template is extracted from; neither is edited.

## Design

### D1. Where the session runs — a short-lived docs-only worktree

**Short-lived worktree `QS_<N>`**, created by `setup_task.py` as for a
task, discarded by `qs-finish-task` (Case A, epic variant) once the doc
is on `main`.

Why, versus a main-checkout session:

- The living doc can stay uncommitted **across several sessions**
  (QS-321 took several) without dirtying the main checkout —
  `qs-release` refuses a dirty `git status`, and `finish-task`'s
  post-merge `pull --ff-only` runs there.
- Task-bound rendering (task facts + lane protocol inlined),
  `context.py`, the launcher and the GUI pin work as-is; `setup_task.py`,
  `finish-task`, `cleanup_worktree.py` and `context.py` need only the D6
  changes. A main-checkout agent is rendered task-agnostic and would
  need the issue passed as a prompt.
- Two epics can be drafted in parallel.
- A fresh worktree carries no tracked or untracked setup artifacts
  (rendered agents and the GUI pin are gitignored — verified with
  `git status --porcelain --untracked-files=all`). `qs-decompose-epic`
  itself writes **only** `docs/epics/QS-<N>.md` (hard rule, D2), so the
  landing script's `docs/epics/`-only check is not polluted.

Accepted costs: QS-321's "no branch, no worktree" becomes **"no PR; a
short-lived docs-only worktree, discarded after the doc reaches
`main`"**. The branch `QS_<N>` is published to origin by
`worktree-setup.sh` for the session's lifetime and deleted by
`finish-task` (no `--no-publish` flag is added). The epic never has a PR
and never closes through one.

Re-entry when a previous session did not reach `finish-task` (e.g. a
failed FINALIZE): `setup-task --issue <epic>` reuses the existing
worktree exactly as it does for a task; `epic_doc.py status` then picks
the mode (D2) and `land` copes with a stale branch (D4).

### D2. `qs-decompose-epic` — the orchestrator

New template `scripts/qs/agent_templates/qs-decompose-epic.md.j2`,
rendered for both harnesses, registered as phase `decompose-epic`.
Model class `frontier` (confirmed in `models.CLASSES`; the class
`qs-create-plan` gets on non-bug lanes). Claude `tools: Bash, Read,
Edit, Write, Grep, Glob, Agent, TodoWrite, LSP`. Lane-aware: in an epic
worktree it inlines `epic-factory.md`, which is the **single home of the
FINALIZE procedure (D3)** — the template points to its "Lane protocol"
section instead of repeating it. In non-epic worktrees it renders with
that worktree's lane but is never invoked there. The unbound render uses
`m.lane_paragraph("readonly")`.

**Hard rules in the template**:
- Refuse unless `context.py` reports `scale == "epic"` and
  `target == "factory"`.
- The only file it writes is `docs/epics/QS-<N>.md` — **no story file**
  (the template's own body block never mentions `docs/stories/`;
  `_base.md.j2` drops the "Story (path…)" task fact for `epic-*` lanes).
- Hand off to `finish-task` only after `epic_doc.py land` succeeded.

**Mode selection at session start** —
`python scripts/qs/epic_doc.py status --issue <N> --sync` (fetches
`origin/main` first; JSON `{local, on_main, local_modified, behind, mode,
safe_to_discard, diff}`). `--sync` fast-forwards a reused worktree that
is behind `origin/main` and has nothing local (`safe_to_discard`), so a
doc amended on `main` since the last session is what RESUME starts from:

| local doc | on `origin/main` | mode |
|---|---|---|
| absent | absent | **DECOMPOSE** — new draft |
| present | absent | **DECOMPOSE** — continue the draft (reached only when a previous session did not finish): load it, show its review-record state; never overwrite it blindly |
| — | present | **RESUME** — only if `local_modified` (unlanded local edits), show `diff` and continue from the local version; otherwise start from the `origin/main` version |

**Mode loop** (same shape, banner and three intents as `qs-create-plan`:
REVIEW / back to DISCUSS / FINALIZE):

- **DISCUSS** — read the epic issue, glob the relevant areas, discuss
  goal, evidence, design, decisions and the decomposition (each child:
  title, `kind`, `wave`, one-paragraph scope). Write the doc from the
  template (D5) as soon as the first round converges; overwrite on every
  change; uncommitted until FINALIZE. Maintainer decisions go into the
  doc's **Decisions** section (gap 9), not only chat.
- **REVIEW** — the same fan-out as `qs-create-plan`: round 1 the 4 global
  plan reviewers (`qs-plan-critic`, `qs-plan-concrete-planner`,
  `qs-plan-dev-proxy`, `qs-plan-scope-guardian`) on the doc; round 2+
  plus `qs-plan-delta-auditor` with the in-context diff. Same artifacts
  per reviewer (the epic issue body for scope-guardian).
- **TRIAGE** — the same finding-state model (`open` / `resolved` /
  `rejected`), recorded in the doc's **Adversarial review record**.
- **FINALIZE** — the create-plan advisory gate (if the doc changed since
  the last review, or `critical` findings are still `open`, ask "ship
  anyway?"; never hard-block), then D3, then the hand-off.

**RESUME** (re-entry, e.g. to file the next wave): show the
decomposition table (filed vs. `not filed`), ask what to do — file the
next child(ren), amend the doc (a new decision, a re-plan), or both —
then FINALIZE. Review in RESUME runs **only on the explicit REVIEW
intent**; it is never automatic.

**Hand-off** — the standard two-block payload every orchestrator emits
(Preferred `claude --agent` line + slash-command fallback, plus the GUI
block on Claude), built by a per-harness fenced `next_step.py
--next-cmd finish-task --harness …` block **in the template only**.

### D3. FINALIZE procedure (lives in the lane file; replaces QS-321 § "How this epic runs")

1. **Preflight**: `python scripts/qs/epic_doc.py land --issue <N>
   --message "…" --dry-run` must pass before any issue is created.
2. **File the children whose turn is now** (**File children just in
   time** — gap 7). Default: every `not filed` row of the lowest `wave`
   that still has one; with no `wave` column (legacy docs), the
   maintainer names the rows. **Only rows marked `not filed` are
   filed**, and the doc is rewritten with the new number **after each
   issue is created**. Before creating one, the agent searches
   (`gh issue list --state all --search "\"<title>\" in:title"`) for an
   existing issue with that exact title whose body declares
   `### Parent epic` `#<N>`, and adopts it instead (covers a crash
   between create and rewrite). Each via
   `python scripts/qs/create_issue.py --title … --body …
   --labels "kind:<k>,target:factory,scale:task[,<epic's area:* labels>]"`
   (target is always inherited — never set per child). Child body
   convention (gap 6), in order:
   - first line: link to `docs/epics/QS-<N>.md` on `main` (the URL is
     known before landing);
   - the child's scope;
   - a `### Parent epic` section whose next line is `#<N>`;
   - **no other `Refs #…` line anywhere** (the parser fallback reads the
     first one as the parent when the section is absent).
3. **Land the doc**: `python scripts/qs/epic_doc.py land --issue <N>
   --message "…"` (D4) — one direct commit on `main`.
4. **Sync the epic issue**: `python scripts/qs/epic_doc.py sync-issue
   --issue <N>` (D4); its JSON must report `state: OPEN`.
5. **Hand off** to `finish-task` (the template's hand-off block — prose
   here, no fence, so the lane file stays harness-agnostic). The issue
   sketched the epic flow as "setup → decompose → file children → stop";
   children are filed inside decompose, and the final `finish` only
   discards the short-lived worktree (D1).

If step 3 fails after step 2 filed children, they link a not-yet-landed
doc: the agent stops and reports; re-running FINALIZE is safe (filed
rows are skipped, `land` is idempotent). Last-resort fallback,
documented not automated: a hand-opened PR with `Refs #<N>` — never
`create_pr.py`.

### D4. The landing rule, enforced by `scripts/qs/epic_doc.py` (gap 4)

**Rule** (new `project-rules.md` section "Epic documents"): an epic doc
reaches `main` by **direct commit, `docs/epics/` only**, through
`epic_doc.py land` only; never through `create_pr.py` (its `Fixes #<N>`
would close the epic). Amendments to an existing epic doc follow the
same rule, or ride a child's own PR when that child changes the design
(the QS-321 practice stays valid). Gated by `check_doc_drift.py`; if a
`docs/epics/` path ever becomes `tests/qs`-pinned, `--quick tests/qs`
is added to the gate. **Precondition**: `main`'s branch protection has
`enforce_admins: false`, so the maintainer's push is accepted (as for
QS-321 / QS-369); a non-admin push is rejected and surfaces as
`status: push-rejected` → the documented PR fallback.

**Module contract**: JSON out (`utils.output_json`), non-zero exit on any
refusal. Every git / gh call goes through `utils.run_git` / `utils.run_gh`
with `check=False` on probes, push, plumbing and `status --sync`'s
`merge --ff-only` (a failure becomes a JSON
refusal, never a traceback); no side effects at import. `utils.run`
gains one additive kwarg, `env: dict[str, str] | None = None` (merged
over `os.environ`; unit-tested in a new `tests/qs/test_utils.py` —
factory-classified, unlike `tests/test_qs_utils.py`), used only
for `GIT_INDEX_FILE` (pointed at a not-yet-existing path such as
`mkdtemp()/index` — a pre-created empty file makes git fail). Tests
patch `utils.run` (the
`tests/qs/test_create_pr.py::_make_fake_run` pattern) **plus one
real-git integration test** (tmp bare origin + clone, no network):
first landing, `already-landed`, `--merged` conflict, push rejected by a
moved `main` then re-run, reused behind worktree + `status --sync`,
**push accepted but worktree not reset, then re-run** (→ `already-landed`
+ reset, `status.safe_to_discard: true`), `main` moved again after a
`conflict` refusal (→ refused again).
Issue labels are fetched with a direct `gh issue view N --json
labels,state,body` (`check=False`): a lookup failure is
`status: lookup-failed`, never "not an epic".

**Changed paths** (shared by all subcommands): after `git fetch origin
main`, `base = git merge-base HEAD origin/main`;
committed = `git diff --name-only -z --no-renames base HEAD`;
uncommitted = `git -c core.quotepath=false status --porcelain -z
--untracked-files=all` (rename entries contribute both paths).

**`epic_doc.py status --issue N [--sync]`** — `local` / `on_main`
(`docs/epics/QS-<N>.md` in the worktree / in `origin/main`);
`local_modified` (that path is in the changed set); `behind`
(`git diff --quiet HEAD origin/main -- docs/epics/QS-<N>.md` exits 1);
`safe_to_discard` (changed set empty and `HEAD` is an ancestor of
`origin/main` — nothing local would be lost); `mode` per the D2 table;
`diff` (unified diff local vs `origin/main` when `local_modified`, so
the agent needs no `git show`). `--sync`: when `behind` and
`safe_to_discard`, `git merge --ff-only origin/main`. Used by
`qs-decompose-epic` at start and by `finish-task` Case A.

**`epic_doc.py land --issue N --message MSG [--merged PATH]... [--dry-run]`**
— the working tree is **never modified before the push is verified**, so
a failure at any step cannot lose the draft:

1. Issue must be `scale:epic`.
2. Every changed path under `docs/epics/`; else refuse
   (`status: out-of-scope`, listing offenders).
3. Changed set empty → `already-landed` (exit 0) if
   `origin/main:docs/epics/QS-<N>.md` exists, else `missing-doc`.
   Non-empty → `docs/epics/QS-<N>.md` must exist locally, else
   `missing-doc`. Drift is never called with an empty path list.
3b. **Already on main**: if every changed path's working-tree content
   equals `origin/main:P` (both absent counts as equal) → `git reset
   --hard origin/main` (safe: those bytes are on `main`) and
   `already-landed`. Covers a push that reached `main` while the local
   reset never ran.
4. Doc drift: `check_doc_drift.main(["--json", "--paths", *changed])`
   inside `contextlib.redirect_stdout(io.StringIO())`; the decision is
   taken **on the parsed report**, not the exit code: `stale_docs`
   non-empty → refuse (`status: drift`); malformed / missing-covers
   entries elsewhere → `warnings`. The report is embedded as `drift`.
   Tests monkeypatch `check_doc_drift.main`.
5. **Conflict check**: a changed path P conflicts if `git diff --quiet
   base origin/main -- P` exits 1 (main touched P since the worktree's
   base — e.g. a child PR amended the same epic doc), unless the local
   content already equals `origin/main:P`, or `--merged P=<blob>` is
   given **and `<blob>` still equals the current `origin/main:P` blob**
   (after this run's fetch); exit ≥ 2 is an error (`status: git-error`).
   Conflicts → refuse with `status: conflict` and, per path, the current
   `origin/main` blob sha and content — **that** is what the agent merges
   into the local file (never an older `status` diff), then it re-runs
   with `--merged P=<that blob>`. If `main` moved on P again meanwhile,
   the blob no longer matches and `land` refuses again with the fresh
   content — no lost update.
6. `--dry-run` stops here with `status: ok-dry-run`.
7. **Build the landing commit on `origin/main` with plumbing**, via a
   temporary index in `$TMPDIR` (`GIT_INDEX_FILE`): `git read-tree
   origin/main`; per changed path, `git hash-object -w -- P` + `git
   update-index --add --cacheinfo 100644,<blob>,P` if it exists in the
   working tree, else `git update-index --force-remove -- P`; `git
   write-tree`; `git commit-tree <tree> -p origin/main -m MSG` (MSG
   verbatim — the agent supplies the attribution trailer). A tree equal
   to `origin/main`'s → `git reset --hard origin/main` and
   `already-landed`. Leftover local commits from an
   earlier failed run are irrelevant: only the working-tree bytes of the
   changed paths are used.
8. `git push origin <sha>:main` (a fast-forward by construction).
   Rejected → `status: push-rejected` (main moved or protection); no
   automatic retry — a re-run rebuilds on the new `origin/main`.
9. `git fetch origin main`; `git merge-base --is-ancestor <sha>
   origin/main` must succeed (someone may already have pushed on top),
   else `status: verify-failed`. Only then `git reset --hard origin/main` (the
   worktree now matches `main`, the draft is on `main`; step 2
   guarantees nothing else local exists). Output `{status: landed, sha,
   paths, drift, warnings}`.

**`epic_doc.py sync-issue --issue N`** — the only writer of the epic
issue body (the most destructive FINALIZE step, so it is code, not
prose). **Additive, marker-free**, anchored on the conventions the issue
states:

- **Parsing contract**: every Markdown table under the doc's
  `## Decomposition` heading (including `###` subsections) whose header
  row has `child` and `issue` columns (case-insensitive; `#`, `kind`,
  `wave` optional — QS-369.md parses as-is). Issue cell: `#123`,
  `[#123](url)` or `not filed`; anything else → `status:
  unparseable-decomposition`, **nothing written**.
- **Task-list match**: regex `^\s*[-*] \[[ xX]\] #(\d+)\b` — `#37` never
  matches `#371`.
- **Anchor**: the first task-list block containing a `#n` from the
  table; else an existing `## Children` section; else a new
  `## Children` section appended at the end. An unrelated checklist
  (e.g. acceptance boxes) is never used.
- Doc link: prepended as the first line
  (`**Rationale document:** [docs/epics/QS-<N>.md](<repo url>/blob/main/docs/epics/QS-<N>.md)`,
  repo URL from `gh repo view --json url`) iff the body does not already
  contain `docs/epics/QS-<N>.md`.
- For each filed child whose `#n` matches no task-list line: add
  `- [ ] #n — <child>` at the end of the anchor block.
- **Owned lines** `- (not filed) <child>`: script-owned and regenerated
  in full from the table on every run (dropped when the child is filed
  or no longer in the table; added when missing) — **only** when the
  anchor block sits directly under a `## Children` heading (created by
  `sync-issue` or already present). Ownership is keyed on that heading,
  never on owned lines being present, so a fully filed wave followed by
  new `not filed` rows gets its owned lines back. Other anchors (legacy
  hand lists such as #369's, whose `## Children` section starts with
  prose) get none.
- **Never deletes or rewrites any other line**: ticks, trailing text
  ("(PR #373)"), children dropped from the table — all kept.
  Idempotent: a second run is a no-op (no `gh issue edit` call).
- Writes via `gh issue edit N --body-file <tmp>` with a
  `tempfile.NamedTemporaryFile` in the system temp dir (outside the
  worktree), removed afterwards.
- JSON `{status, state, added, owned}`.

**`create_pr.py` guard**: split `_epic_and_lane_note` into
`_fetch_issue(issue) -> tuple[str, list[str]] | None` (body, labels —
all current degrade branches; skipped when `issue` is None), called
right after the issue is resolved and **before** `find_pr_for_branch`
and `git push`, and `_epic_and_lane_note(body, labels, changed)`, called
where it is today. `scale == "epic"` → exit 1, JSON error. Lookup
failure keeps today's fail-open behaviour. Still one `gh` call.

### D5. Epic doc template and issue conventions (gaps 5, 6) — in the lane file

`docs/workflow/lanes/epic-factory.md` carries (the QS-335 pattern),
extracted from the shape QS-321.md and QS-369.md share:

- **`### Epic doc template`** — `# Epic QS-<N> — <title>`, status banner,
  header table (Issue · Classification · Branch/worktree/PR — "no PR; a
  short-lived docs-only worktree" · Live state · This document · Builds
  on), then **Goal · Evidence · Design · Decisions · Decomposition ·
  Adversarial review record · Doc maintenance**. Decomposition table
  columns: `# · child · kind · wave · issue` (issue cell `#123` or
  `not filed`) — the table `sync-issue` parses.
- **`### Issue-body conventions`** — epic: rationale-doc link as the
  first line; filed children as `- [ ] #N` task-list lines; unfiled as
  `- (not filed) <child>`. Child: doc link, `### Parent epic` section,
  no stray `Refs #…`; plus the parser-fallback warning (how #370 got
  attached to #369).
- **`**File children just in time**`** and **re-entry**: to file the
  next wave, run `setup-task --issue <epic>` → `decompose-epic`
  (RESUME) → `finish-task`.

`qs-setup-task` switches its own parent-epic declaration from a
`Refs #<epic>` body line to a `### Parent epic` section (new issues and
the backfill path) — a writer contradicting the convention being
codified would be incoherent; flagged in the PR body as "beyond the
issue text". `targets.parse_parent_epic` already gives the section
precedence over any `Refs` (verified); the parser is not touched.
